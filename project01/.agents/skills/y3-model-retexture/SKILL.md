# Y3 模型贴图重绘

交付基于实际原贴图的颜色图，保留原 UV 布局、宽高比和必要的 Alpha。风格由本次用户要求决定，不默认沿用吕布示例的银白冰蓝。

## 定位原资源

1. 优先调用 `mcp__y3editor__get_map_info` 获取当前项目；用物编列表定位单位，再用 `get_editor_unit_custom_data` 读取 `model`。通过 `get_official_editor_model` 核对名称与官方模型 ID。工具缺失时读取用户给出的项目文件，不假定当前项目就是过去的项目。
2. 区分单位物编 ID、官方模型资源 ID 和引擎内部 `model_id`。原模型物编 JSON 中的 `model_id` 才是缓存中常见的名称线索。
3. 优先使用用户提供的原图或模型导出资源。需要查本机缓存时，沿实际安装位置查 `LocalData/Patch`、`LocalData/OfficialShopResource`，记录来源；不要遍历整盘。`download_editor_model_resource` 返回“已尝试下载”不证明已拿到文件，应检查缓存。
4. 资源名称可能隐藏在 `resource.repository` 中，磁盘文件是 GUID 加类型后缀。只有遇到这种缓存时读 [缓存格式与脚本](references/cache-format.md)。不要把某张名字含 `_d` 的图直接当成目标材质；核对材质实例的 `tBaseMap` 引用及材质顺序。

吕布的已验证线索及生成参数见 [吕布案例](references/lvbu-case.md)，只在处理该模型或需要实例时读取。模型升级后重新核实。

## 分析与重绘

- 在生成前读取图片尺寸、模式、Alpha 范围，并用 `view_image` 打开每张原图。区分身体、武器等材质；记录原材质中的法线和高光/混合图引用。
- 原展开图的区域识别可依据视觉，但没有网格 UV 验证时不要声称每个区域已确认。单改颜色贴图不能改变模型轮廓，也不能保证改变原高光或金属参数。
- 用本会话可用的 `imagegen` 技能及内置图像生成工具编辑实际原图，每张材质单独编辑。局部换色的提示词应明确：原图是编辑目标；只改变指定材质颜色；保留每个 UV 岛、边缘、接缝、雕纹及五官的相对坐标；不裁切、翻转、重排、不增加边框或文字；输出平面展开图。提示词示例在 [吕布案例](references/lvbu-case.md)。
- 未指定风格时可问一次简短偏好，同时继续资源分析。不要用立绘或完整角色渲染替代 UV 贴图。
- 保留生成母版和提示词。生成尺寸可能不同，交付时仅做等比例尺寸和格式规范化，不用自动裁切补救比例错误。错误布局要回到原图重新编辑。
- Alpha 全不透明时可交付 RGB PNG；原 Alpha 有透明或裁切用途时必须保留该信息。附带脚本只处理原图全不透明的规范化，遇到有用 Alpha 会拒绝，不能直接转 RGB。

## 检查与交付

1. 将输出规范化为原宽高，重开文件检查尺寸、模式与透明度，并逐张对照原图检查布局、脸/头发、布料及武器边缘。脚本的尺寸检查不能证明 UV 对齐。
2. 将新版文件放在本项目 `assets/art/characters/<角色>/y3-texture-<风格>-vNN/` 或用户指定目录，保留原图及元数据，避免覆盖旧版。提供文件链接；需要时打包到 `deliverables/`。
3. 说明导入图片/图标资源后，在“替换模型贴图”中选择目标单位、该单位模型、对应材质序号、颜色贴图、新图片资源。读取实际动作 JSON核对参数，不凭名称猜枚举。
4. 只要任务是交付文件供用户替换，就交付文件与操作说明。用户另行要求导入或修改触发器时按其授权执行。需要编辑 ECA 时使用 `y3-eca` 技能；本 skill 不授权批量替换触发器。
5. 创建事件中的替换需要新建单位才能验证。明确区分“图片与格式已检查”“Y3 导入已确认”“游戏内接缝与材质已确认”。未经实际检查不要宣称运行验证完成。

## 可复用脚本

`scripts/y3_texture.py` 提供 `repository`（查名称/GUID）、`material`（读取材质贴图引用）、`extract`（已知缓存格式解码）和 `prepare`（不透明贴图输出规范化）。参数见 `--help` 与 [缓存格式与脚本](references/cache-format.md)。脚本不会修改 Y3 安装缓存或自动导入项目，也不会生成艺术内容。使用当前环境可用的 Python/Pillow，运行时路径由依赖工具发现，不硬编码用户机器的 Python 路径。
