# Y3 英雄核心循环与六技能实装

把已审核的循环设计落成可追溯的对象、事件、表关系和战斗表现。先确认本次范围：哪位英雄、哪个星级、资源获取与消耗、目标/人数、数值、波次重置、UI 与表现；未确认的参数明确标为暂定。遵守 `docs/agents.md` 的落档审批边界。审查或对比请求默认只读；不要把 skill 当作改动许可。

## 定位当前地图与依据

1. 用 Y3 编辑器 MCP 的 `get_map_info` 确认正在编辑的项目和地图；没有连接时从用户指定的项目路径定位。不要沿用上次的地图路径或对象 ID。项目检索跳过 `D:\codex` 下所有 `.git` 目录，除非用户明确要求读取 Git 历史。
2. 读取最新获批设计、单位技能表当前行和同类已实装英雄。文档与地图现状冲突时先报告，不凭历史记忆替换设计。只进入本次需要的 ECA、物编、表及 UI 文件，不全盘扫图。
3. `y3-eca` 插件适合索引/检查独立的 `global_trigger`；它目前不覆盖物编对象内嵌的 `ability/<id>.json`、`modifier/<id>.json`。内嵌 ECA 要直接核对当前地图实例，并以编辑器加载结果验证。

## 还原现有管线

先画清 `单位技能配置表` 技能槽 -> `技能特有循环机制表` 的关联技能与 Buff -> 赋予循环 Buff 的公共函数 -> Buff/技能内嵌 ECA -> 层数 UI/技能描述表 -> 波次切换的调用链。记录用到的单位、技能、Buff、资源和自定义事件 ID；检查新 ID 不冲突。

当前项目的星级映射是 `技能1/2/3 = 1/3/5 星主动`、`技能5/6/7 = 2/4/6 星被动`，`技能4/8` 为占位。落表前再核对目标地图的字段和空技能 ID，不按设计文档的星级顺序直接填列。详细的 map3 线索和许褚案例见 [map3 实例](references/map3-core-loop.md)，只在处理这张图或需要实例时读取。

## 写 ECA 与物编

- 按**触发语义**选模板。普攻击中应核对伤害事件和“普通攻击命中”条件；不能把出手、释放技能、受击事件当成命中。复制动作时逐个检查叠层的正负号、事件上下文、目标、伤害类型与递归触发条件。
- 明确 Buff 内部初始层数与玩家可见层数的换算、上限、满层判定、清层动作和 UI 更新。它们取决于本地图实例，不能把许褚的 `1` 层基数或 3 点上限泛化给所有英雄。
- 主目标优先于附近单位；范围、最多人数和伤害系数分别校验。触发效果自身不得再次获得资源。波次重置要追到实际移除/重建 Buff 的调用点，仍须实机验收。
- 同步物编名、描述、`suffix`、技能/Buff 图标、特效和编辑器文件夹。查资源 ID 的实际名称及归属，不沿用模板英雄的头像或不合角色的特效。只创建本次需要的技能/被动对象，不提前接入未批准的高星联动。
- 表数据用 JSON/表格的结构化读写校验；保留原记录和空行布局。技能作用描述表从单位技能表中的有效技能 ID 建行，遵守 `docs/design/skill-description-table-authoring-guide-v1.md`。

## 配套六技能实装

- 先把每一星设计逐条映射到对应技能物编与 ECA：主动伤害、附加状态、被动监听和高星联动各归其所属技能。核心 Buff 只保留蓄能、结算等公共循环；不要用空被动占位，也不要把六个技能的效果全塞进核心 Buff。用户手写的循环 ECA 默认保留，确需改动时先说明具体原因、范围并取得同意。
- 关键系数、比例、持续时间、目标上限与循环间隔用技能 KV 表达；在获得技能时初始化，并在等级变化阶段按各等级写入。即使当前物编只有 1 级，也预留后续等级可调整的数值入口；不能只改描述或只填物编默认 KV。主动技能核对冷却、施法距离、伤害类型和动画槽。动作槽先查当前地图的动作模组映射表，可暂填合法值；具体画面表现以人工预览选定为准，不从动作名猜测哪段动画最合适。
- 主动技能沿用本图可工作的目标搜索与自动施法链。施法阶段通常读取已搜索的 `目标单位`，手动指定目标时再从施法事件覆盖；不要把“目标单位”、伤害来源、受击单位或当前选中单位混用。范围技能分别检查主目标、额外目标数量、去重、敌我过滤与无有效目标的分支。
- 按技能语义保留完整阶段：主动技能通常有获得、等级变化、施法、失去；被动技能通常有获得、等级变化、事件响应、失去。定时器和事件监听要有对应清理，且不能为凑阶段复制无用动作。跨事件读取伤害技能、来源单位或 Buff 实例前先做存在性判断，避免普通攻击或环境伤害的空引用。
- 一次性特效明确播放时长并核对自动销毁设置；附着在 Buff 上的持续特效保存实体句柄，Buff 失去时主动删除。需要弹道的技能应核对创建投射物、追踪、命中结算与删除的时序，不能只用目标点特效代替飞行过程。特效资源名称、比例、挂点和实际持续时间都要与技能表现匹配，编辑器里显示有效不代表战斗里视觉正确。
- 复制模板后逐项核对 ECA `valid`、属性内部名、关联技能、事件上下文与所有残留 ID。属性百分比先区分引擎内置属性和项目自定义属性：内置属性的百分比参数按 `10=10%` 核算；自定义属性名称含 `%` 不代表引擎会自动按百分比计算，应核对其实际存储与公式。未实测的属性类型或数值只标待验证，不写成正确范例。
- `远程普攻` 标签仅判远程普通攻击，不用于推断远程技能。若设计需要区分远程技能，应先规避这种未有可靠判定依据的机制；不得用攻击距离代理精确分类。韩当六技能的具体排错线索见 [map3 实例](references/map3-core-loop.md)。

## 编辑器同步与验收

先在可写工作区生成候选、备份将改的原文件，对旧/新 JSON 做语义差异检查，确认没有动其他英雄。优先使用编辑器支持的导入/保存流程。若必须直接改正在打开的地图文件，先确认没有用户未保存的编辑器改动；旧内存可能在下一次保存时覆盖磁盘表。重载地图前是否保存由当时状态决定，不能盲目使用 `save_before_restart:false`。地图位于工作区外时照常取得文件系统授权。

验收分层报告，不互相冒充：

1. **结构**：ECA/物编/表可解析；ID、技能槽、Buff 关联、描述、图标与特效引用正确；复制模板的遗留字段已清理。
2. **编辑器**：对象可查询；重载、再次保存后新增 ECA 和三张表仍保留，逐个检查触发器 `valid`。MCP 返回“已尝试”不等于成功，要回读文件和对象；文件夹索引可能被编辑器重排，应核对映射而非只比较数组顺序。投射物查询若与物编文件、目录索引或已观察的实机表现不一致，记录为 MCP 查询待排查，不仅凭“查不到”断言资源无效。
3. **战斗**：分别测未解锁/解锁、逐次获取、满层结算、单目标/多目标上限、伤害类型与系数、自触发防护、波次清空、UI 和实际特效。没有打到战斗就明确写“未实机验收”。

交付时列出修改对象与 ID、已验证层级、暂定参数、剩余问题和回退备份。若生成器或暂存稿参与交付，确保它们与编辑器中的最终修正一致；不要把过期候选当作可复用模板。
