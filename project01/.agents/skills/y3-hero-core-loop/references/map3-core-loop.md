# map3 核心循环实例

本页是 `ProjectMonster02/maps/map3` 的 2026-10 现场线索，不是跨地图标准。使用前通过 `get_map_info` 和当前文件重新核实路径、ID、字段及调用链。

## 管线定位

| 位置 | 当前作用与检查点 |
| --- | --- |
| `tables/单位技能配置表.json` | 英雄单位 ID 对应的主动/被动槽。空技能 ID 在本图为 `134255698`；2 星被动放 `技能5`。 |
| `tables/技能特有循环机制表.json` | `能力循环机制BUFF` 对应最多三个 `关联技能`。新增行放已有记录后的首个空行，不追加到空行尾部。 |
| `global_trigger/function/new/功能执行/根据拥有技能赋予能力循环机制.json` | 按单位拥有的技能查循环表、赋 Buff 并刷新公共 UI。检查调用时机和旧 Buff 清理。 |
| `global_trigger/function/new/功能执行/单位赋值和技能.json` | 从单位技能表赋技能，并按升星进度处理解锁。检查目标技能是否在正确阶段可用。 |
| `global_trigger/function/new/UI/刷新单位能量机制循环能量格子.json` | 循环能量格公共刷新；对象内嵌 ECA 的层数变化会调用它。 |
| `tables/技能作用描述表.json` | 以有效 `ability_type` 建唯一行，补默认和等级描述。 |

能力与 Buff 的物编分别在 `editor_table/abilityall/<id>.json`、`editor_table/modifierall/<id>.json`；对象内嵌 ECA 在 `ability/<id>.json`、`modifier/<id>.json`；本地图编辑器目录索引在 `editor/folderinfo/`，中文名等在 `zhlanguage.json`。空 ECA 文件可能被编辑器保存时清除，不把“文件消失”单独视作技能对象消失；要查物编和表。

## 选择实例时的陷阱

- 孙尚香循环 Buff `134248740` 的 `ET_UNIT_HURT_OTHER` + `GET_IS_NORMAL_HIT_FROM_EVENT` 可参考“普攻击中”，但其后续投射物动作不适合直接复制。
- 黄忠循环 Buff `134242511` 有受击减层和释放技能加层两个子触发器。复制 `ADD_BUFF_STACK` 前必须读取数值；许褚初稿误复制到 `-1`，经用户修为 `+1` 后才符合蓄势。
- 夏侯惇被动 `134259316` 提供“层数达阈值 -> 清层 -> 范围伤害”的参考，但目标中心、人数、特效和图标都需要按新英雄重做。
- 本图的部分循环 Buff 内部从 1 层起算，UI 显示 `GET_MOD_STACK - 1`。许褚可见 0–3 点对应 Buff `layer_max=4`、第三次命中后清回 1 层；新英雄先核实其自身堆叠约定。

## 许褚实装回看

许褚单位 `134242131`，2 星被动“踏地生威” `134283901`，虎势 Buff `134283902`。技能表 `技能5` 指向被动，循环表第 19 行把被动关联 Buff，描述表有一条对应行。Buff 内嵌 ECA 监听普攻击中，`ADD_BUFF_STACK +1`，满 3 点清层并对当前目标及附近最多 3 名敌人结算；260 半径是当次审核的暂定值，不作为其他英雄默认值。6 星联动未接入。

这次编辑器验证暴露两类问题：直接写磁盘时，编辑器首次保存曾把两张表恢复为旧内存值；确认无未保存改动后重新写表、无预保存地重载、再保存，配表才稳定。另一个是模板残留：初稿 Buff 图标/后缀属于黄忠；用户改为许褚。已确认用户把现场 Buff 叠层改为 `+1`；但 `outputs/y3-xuchu/build_xuchu.py` 和暂存 ECA 仍生成 `-1`，不能原样用于重建。当前被动物编还沿用夏侯惇“刚烈”图标，震地触发特效 ID `104756` 实为“粉色暗影攻击”；后续视觉验收应处理。不要把本例的结构检查或用户反馈表述成完整自动化战斗验收。

当前版本的 `export_object_editor` 定向导出在 `include_dependencies:false` 时曾报内部异常；改为 `true` 后可导出参考 ZIP。这是现场观察，不保证以后版本仍如此。导出成功不等于可以直接安全导入改 ID 的物编；导入格式和依赖仍需核实。

## 韩当六技能实装回看（2026-10-09）

韩当单位 `134256942`，手写备矢 Buff `134230485`；六技能依星级为 `134284010` 至 `134284015`，新增四个状态 Buff 为 `134284016` 至 `134284019`。技能槽与循环表、描述表均已接入。备矢原有受击叠层和自身冷却保持不变，仅在受击动作前新增两条 KV 写入，记录伤害来源与受击队长，供二星援射读取；改动前备份在 `outputs/y3-handang-six-before-20261009.zip`。

- 三个主动技能沿用孟获已验证的获得/等级变化/施法/失去阶段及自动搜索模板。施法时以 `目标单位` 为主目标；三星齐射另搜附近最多两名敌人，五星再遍历存活小兵加盾。六技能的可调系数、比例与时长已设技能 KV，并在获得和等级变化时赋值；当前物编等级上限仍为 1，不等于已测试升级流程。
- 二星被动在自己的 ECA 中监听满层、援射并给受击队长护盾；六星监听二星援射造成的伤害后施加降攻 Buff。六星比较 `DAMAGE_ABILITY` 前应先检查其存在，避免普通攻击等无技能伤害事件传入空值。
- 三星减速 Buff 初稿用 `move_speed` 属性名，编辑器重载保存后把获得触发器 `valid` 改成 `false`。本图已验证的移速属性是 `ori_speed`（可参照 `modifier/134219041.json`），修正后四个状态 Buff 和六技能各触发器的 `valid` 均为 `true`。因此生成 JSON 可解析、物编可查询仍不足以证明 ECA 有效。
- 一次性特效使用限时播放与自动销毁；持续附着特效在 Buff 获得时保存实体，失去时删除。资源 ID 可在编辑器查询，实际画面比例、挂点、持续时长尚未实机验证。
- 编辑器保存会重排 `editor/folderinfo/` 的 `f` 数组：逐项 JSON 差异很多，但 `d` 映射和 `f` 条目的无序集合一致。核对这两项后可识别为规范化排序，不应误报为丢失对象。
- 四星“远程来源伤害减免”的初稿曾用来源单位攻击距离不低于 8 近似判定；这不是精确分类。项目负责人后来改为 `远程普攻` 标签判定，见下方复核记录。不要把初稿当作现行写法。

此次完成了编辑器回读、重载、保存和 ECA `valid` 检查，未做战斗实机验收。后续复用前以当前地图重新核实对象 ID、源模板和特效，而不是照搬本例数值。

## 韩当人工复核补充（2026-10-10）

- 动作名需先查 `tables/角色类型对应动作模组表.json`。韩当当前行将 `技能01` 映射到 `attack5`，`技能02/03` 都映射到 `ability_3`。这些名字只能证明动作入口及资源映射，不能替代美术预览；项目负责人已预览并自行选定表现。自动实装可先填合法值，交由人工预览调整。
- 一星和二星援射已由项目负责人改为创建投射物、追踪目标、命中回调结算伤害，并在回调中删除投射物；部分特效的挂点、比例与持续时间也已人工调整。此处记录的是当前 ECA 结构，不推定所有弹道失败/目标消失分支均经过实测。
- 四星现用 `ABILITY_HAS_TAG` 检查 `DAMAGE_ABILITY` 的 `远程普攻` 标签。项目负责人确认该标签**只覆盖远程普攻**，不涵盖远程技能；后续设计应避免需要判定“是否为远程技能”的效果。旧版攻击距离阈值及其 KV 已从当前四星技能移除。
- 属性类型要先分清引擎内置属性和后期自定义属性。引擎内置属性选百分比类型时，项目负责人确认 `10` 表示 `10%`，而非 `0.1`；自定义属性名称中手写 `%` 只是名字，不能推定引擎会按百分比解释。韩当减攻速 Buff 当前改为基础类型 `-0.25`，但其是否实现设计的 `-25%` **未经实机属性读数确认**；原候选的比例类型 `-0.25` 也不可当正确范例。验收应记录加 Buff 前、持续中、失去后的实际攻速。
- 两个新增投射物的物编文件和文件夹索引均存在，项目负责人已确认它们在游戏内正常表现；当前编辑器 MCP 的投射物列表与定向查询却未返回这两个 ID，而同一接口可查询其他投射物。这是接口查询与现场不一致的观察，原因可能涉及缓存或过滤，不能据此断言投射物无效或确定官方接口存在何种缺陷。
