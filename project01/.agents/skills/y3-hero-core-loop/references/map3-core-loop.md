# map3 核心循环实例

本页是 `ProjectMonster02/maps/map3` 的 2026-10 现场线索，不是跨地图标准。使用前通过 `get_map_info` 和当前文件重新核实路径、ID、字段及调用链。

## 管线定位

| 位置 | 当前作用与检查点 |
| --- | --- |
| `tables/单位技能配置表.json` | 英雄单位 ID 对应的主动/被动槽。空技能 ID 在本图为 `134255698`；2 星被动放 `技能5`。 |
| `tables/技能特有循环机制表.json` | `能力循环机制BUFF` 对应最多三个 `关联技能`。新增行放已有记录后的首个空行，不追加到空行尾部。 |
| `global_trigger/function/new/功能执行/根据拥有技能赋予能力循环机制.json` | 按单位拥有的技能查循环表、赋 Buff 并刷新公共 UI。检查调用时机和旧 Buff 清理。 |
| `global_trigger/function/new/功能执行/单位赋值和技能.json` | 从单位技能表赋技能，并按升星进度处理解锁。检查目标技能是否在正确阶段可用。 |
| `global_trigger/function/new/UI/刷新单位能量机制循环能量格子.json` | 循环能量格公共刷新；对象内嵌 ECA 的层数变化会调用它。 |
| `tables/技能作用描述表.json` | 以有效 `ability_type` 建唯一行，补默认和等级描述。 |

能力与 Buff 的物编分别在 `editor_table/abilityall/<id>.json`、`editor_table/modifierall/<id>.json`；对象内嵌 ECA 在 `ability/<id>.json`、`modifier/<id>.json`；本地图编辑器目录索引在 `editor/folderinfo/`，中文名等在 `zhlanguage.json`。空 ECA 文件可能被编辑器保存时清除，不把“文件消失”单独视作技能对象消失；要查物编和表。

## 选择实例时的陷阱

- 孙尚香循环 Buff `134248740` 的 `ET_UNIT_HURT_OTHER` + `GET_IS_NORMAL_HIT_FROM_EVENT` 可参考“普攻击中”，但其后续投射物动作不适合直接复制。
- 黄忠循环 Buff `134242511` 有受击减层和释放技能加层两个子触发器。复制 `ADD_BUFF_STACK` 前必须读取数值；许褚初稿误复制到 `-1`，经用户修为 `+1` 后才符合蓄势。
- 夏侯惇被动 `134259316` 提供“层数达阈值 -> 清层 -> 范围伤害”的参考，但目标中心、人数、特效和图标都需要按新英雄重做。
- 本图的部分循环 Buff 内部从 1 层起算，UI 显示 `GET_MOD_STACK - 1`。许褚可见 0–3 点对应 Buff `layer_max=4`、第三次命中后清回 1 层；新英雄先核实其自身堆叠约定。

## 许褚实装回看

许褚单位 `134242131`，2 星被动“踏地生威” `134283901`，虎势 Buff `134283902`。技能表 `技能5` 指向被动，循环表第 19 行把被动关联 Buff，描述表有一条对应行。Buff 内嵌 ECA 监听普攻击中，`ADD_BUFF_STACK +1`，满 3 点清层并对当前目标及附近最多 3 名敌人结算；260 半径是当次审核的暂定值，不作为其他英雄默认值。6 星联动未接入。

这次编辑器验证暴露两类问题：直接写磁盘时，编辑器首次保存曾把两张表恢复为旧内存值；确认无未保存改动后重新写表、无预保存地重载、再保存，配表才稳定。另一个是模板残留：初稿 Buff 图标/后缀属于黄忠；用户改为许褚。已确认用户把现场 Buff 叠层改为 `+1`；但 `outputs/y3-xuchu/build_xuchu.py` 和暂存 ECA 仍生成 `-1`，不能原样用于重建。当前被动物编还沿用夏侯惇“刚烈”图标，震地触发特效 ID `104756` 实为“粉色暗影攻击”；后续视觉验收应处理。不要把本例的结构检查或用户反馈表述成完整自动化战斗验收。

当前版本的 `export_object_editor` 定向导出在 `include_dependencies:false` 时曾报内部异常；改为 `true` 后可导出参考 ZIP。这是现场观察，不保证以后版本仍如此。导出成功不等于可以直接安全导入改 ID 的物编；导入格式和依赖仍需核实。
