# 技能作用描述表填写指南 v1

> 状态：当前英雄技能描述配置与校验指南。本文服务于主策划、配置人员和程序顾问；英雄技能效果以已审核的英雄技能设计文档为准。军略技能请参阅 [军略技能作用描述表填写指南 v1](tactical-command-description-table-authoring-guide-v1.md)。

## 使用范围

本指南规定如何根据 `config_单位技能配置表.xlsx`，填写或增补 `config_技能作用描述表.xlsx`。它只处理玩家可见的技能描述，不决定技能效果、数值、冷却、目标筛选或技能 ID。

适用对象：

- 已确认英雄的主动与被动技能。
- 新增英雄进入技能配置后的描述补表。
- 既有技能效果调整后，对应描述的同步更新。

不适用对象：

- 空技能 ID、玩家默认空技能位。
- 英雄技能数值的首次设计或平衡调整。
- 军略技能的描述配置；适用 [军略技能作用描述表填写指南 v1](tactical-command-description-table-authoring-guide-v1.md)。
- 道具、怪物原生技能的描述配置；它们需建立各自的来源与填写规则。

## 使用前必读

按以下优先级确认信息：

1. 项目负责人最新明确口径。
2. 当前 `config_单位技能配置表.xlsx`：决定英雄、技能 ID、主动/被动分组和空技能位。
3. 已审核英雄技能主源：决定技能名称、正式效果与“游戏内简短描述”。当前首批来源包括：
   - `deliverables/三国斗阵_Y3_英雄技能实现说明_v0.2.docx`
   - `deliverables/三国斗阵_第一批新增预选英雄技能设计归档_v1.0.docx`
4. 本指南：决定描述表的字段填法与交付校验。

若配置表 ID、已审核技能文档与实现现状互相冲突，不得凭记忆补写；先记录冲突并请主策确认。

## 两张表的职责

| 文件 | 负责内容 | 不应承担的内容 |
| --- | --- | --- |
| `config_单位技能配置表.xlsx` | 英雄单位与 `ability_type` 的绑定关系；主动/被动槽位；空技能位。 | 技能的玩家可见文案、技能数值和实际效果逻辑。 |
| `config_技能作用描述表.xlsx` | 每个有效 `ability_type` 的类型标记、默认描述与等级描述。 | 反推技能 ID、擅自改写已确认效果、修改英雄技能槽位。 |

填表时必须先从单位技能表读取 ID；不得以技能名、历史表格行号或截图顺序反推 ID。

## 单位技能表读取规则

当前 `config_单位技能配置表.xlsx` 的字段含义如下：

| 字段 | 含义 | 描述表处理 |
| --- | --- | --- |
| `技能1` 至 `技能3` | 当前英雄的 3 个主动技能。 | 每个有效 ID 生成或更新 1 行，类型倾向标记为 `主动`。 |
| `技能4` | 主动空技能位。 | 必须为默认空技能 ID；不生成描述行。 |
| `技能5` 至 `技能7` | 当前英雄的 3 个被动技能。 | 每个有效 ID 生成或更新 1 行，类型倾向标记为 `被动`。 |
| `技能8` | 被动空技能位。 | 必须为默认空技能 ID；不生成描述行。 |

当前默认空技能 ID 为 `134255698`。它不是可显示技能，不能在技能作用描述表中创建一行描述。

### 重要映射提醒

英雄的设计解锁顺序通常是“1 星主动、2 星被动、3 星主动、4 星被动、5 星主动、6 星被动”；但单位技能表按“3 个主动，再 3 个被动”分列。

因此不得把已审核文档中的第 2、4、6 项技能按顺序填入 `技能2`、`技能3`、`技能4`。正确映射是：

```text
技能1 = 1 星主动
技能2 = 3 星主动
技能3 = 5 星主动
技能5 = 2 星被动
技能6 = 4 星被动
技能7 = 6 星被动
```

## 技能作用描述表字段

| 字段 | 填写规则 |
| --- | --- |
| `key` | 描述表内唯一键。既有记录不重排；新增记录从当前最大值继续递增。 |
| `技能类型` | 直接填写单位技能表读取到的有效 `ability_type`。以文本 ID 保持原表格式。 |
| `类型倾向标记` | 只能填 `主动` 或 `被动`，由技能槽位决定。 |
| `默认描述` | 当前技能的玩家可见简短描述。 |
| `技能描述等级1` 至 `技能描述等级10` | 按技能等级读取的描述字段。 |

当前 P0 的英雄技能固定 `skill_rank = 1`，没有技能升级渠道。因此当前填法为：

- `默认描述` 与 `技能描述等级1` 至 `技能描述等级10` 填写同一份已确认的简短描述。
- 这样可避免调用不同等级描述字段时出现空文案，同时不虚构不存在的等级差异。
- 若后续开放技能等级，必须先确认每一级的实际效果，再逐级改写对应描述；不得用同一文案掩盖不同数值或规则。

## 简短描述写法

描述优先采用已审核文档中的“游戏内简短描述”。若文档只有正式效果，可在不改变含义的前提下压缩为玩家可读版本。

一条描述应按需包含：

- 目标：当前目标、最低血队长、队长/精英、当前一路、当前区域、全体友方队长等。
- 行为：造成伤害、治疗、护盾、嘲讽、击退、眩晕、获得资源、消耗资源或施加状态。
- 可影响理解的数量：命中人数、伤害次数、百分比、资源层数、生命阈值、持续时间与冷却。
- 条件与消耗：前排/后排/侧翼、资源满层、目标低血、消耗全部资源等。

描述不应：

- 写入未确认的伤害、冷却、施法距离或内部实现值。
- 使用“多次”“短时间”“附近”等缺乏数量边界的模糊说法，除非该技能的已确认设计确实没有更精确口径。
- 把 `current_target`、`leader_or_elite` 等内部字段名直接暴露给玩家。
- 因配置方便而改写技能的目标范围、兵种对象、站前位置条件或资源消耗。

## 填表流程

1. 打开单位技能表，确认当前需要处理的英雄行与 6 个有效技能 ID。
2. 根据“3 主动 + 3 被动”列结构，将每个 ID 映射回已审核的 1 至 6 星技能。
3. 从当前英雄技能主源摘取“游戏内简短描述”；若存在多个历史版本，以最新审核版本为准。
4. 在技能作用描述表按 `key` 查找该 `技能类型`：存在则只更新类型标记与描述，不存在则在末尾新增记录。
5. 写入 `默认描述` 和等级描述字段；当前 P0 单级技能按同文案填入等级 1 至 10。
6. 保留表头、类型行、键行和无关字段结构；不因补描述改动单位技能表。
7. 导出后回读首行、中间行与末行，并进行 ID 覆盖、空技能与文本完整性校验。

## 提交前校验

### 结构校验

- 每名英雄恰有 3 条主动与 3 条被动描述记录。
- `技能4`、`技能8` 的空技能 ID 不生成描述记录。
- 描述表中每个有效 `技能类型` 仅出现一次；不存在重复 ID。
- 所有描述表 ID 都能在单位技能表的有效 6 个槽位中找到。
- `类型倾向标记` 与技能槽位一致，不得因技能设计的星级顺序而错置。
- `key` 唯一；增补时不重排既有记录。

### 文案校验

- 默认描述、等级描述不为空，且与当前已审核技能效果一致。
- 资源名称、层数上限、阈值、命中人数、持续时间和伤害百分比与主源一致。
- 目标是否仅限队长/精英、是否影响小兵、是否限制当前一路/当前区域等边界未被遗漏。
- 描述中没有旧版“战备”“手动英雄技能卡池”等已废弃表述。

### 技术与交付校验

- 不修改 `config_单位技能配置表.xlsx` 的 ID 与槽位，仅将其作为来源读取。
- 技能 ID 保持原表的文本格式，不转换成科学计数法或截断数值。
- 检查无 `#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?` 或 `#N/A`。
- 渲染确认描述列已换行、行高足以显示长文本，首行与末行均无裁切。
- 交付目录仅保留实际 `.xlsx` 配置文件；删除检查工具生成的临时输出。

## 当前基线记录

截至本指南创建时，当前单位技能表包含 18 名英雄，共 108 个有效技能 ID；描述表按每名英雄 3 主动加 3 被动完成覆盖。军略技能另有 36 条记录，因此 `config_技能作用描述表.xlsx` 当前共 144 条有效记录。该数量用于本轮回归核对，不应作为未来扩充英雄或军略时的固定上限。
