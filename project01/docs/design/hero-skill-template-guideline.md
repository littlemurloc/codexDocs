# Hero Skill Template Guideline

> 当前状态：英雄技能设计规范。本文用于后续新增英雄、复盘旧英雄和审查技能稿，不替代当前 10 英雄落表主源。

## 使用范围

本文适用于《三国斗阵》当前版本的英雄技能设计，尤其是以下工作：

- 新增英雄技能初稿。
- 检查英雄 6 个技能是否形成完整循环。
- 判断主动技能的自动释放规则是否清晰、可落表。
- 判断站位、小队、小兵和核心机制是否清晰可读。
- 为后续 Y3 落表和原型验证提供统一口径。

当前英雄技能落表主源以 [first-batch-10-heroes-skill-config-v1.md](first-batch-10-heroes-skill-config-v1.md) 为准；玩家主动参与规则见 [tactical-command-card-system-v1.md](tactical-command-card-system-v1.md)。

## 新英雄立项前检查

新增英雄进入 6 技能设计前，必须先完成以下检查，避免凭单个英雄灵感直接开写。

### 职业分布检查

当前新英雄挑选需要照顾已确认英雄的类型分布，至少先按“战 / 法 / 牧 / 贼”四类做粗分管理。

- 战：前排、防御、近战压制、正面输出、护卫等。
- 法：法术输出、范围压制、控制、战场规则变化等。
- 牧：治疗、护盾、净化、增益、救场等。
- 贼：侧翼、刺杀、干扰、破阵、卡牌节奏等。

新英雄优先补当前短板职业。若新增已经偏多的职业，必须先说明它和已有英雄的差异化理由。

当前首批 10 英雄的粗分可暂按以下方式观察，后续可再正式归类：

| 职业 | 已确认英雄 | 当前判断 |
| --- | --- | --- |
| 战 | 张飞、夏侯惇、吕布、赵云 | 偏多 |
| 法 | 诸葛亮、司马懿 | 已有基础 |
| 牧 | 刘备 | 偏少 |
| 贼 | 吕蒙、甘宁 | 已有基础 |
| 远程物理输出 | 黄忠 | 暂作独立观察，后续决定归入战、贼或单列射手 |

### 基础战斗类型确认

新英雄设计前，必须向项目负责人确认基础战斗类型和小兵类型。未确认前，不得在技能里擅自绑定武器、攻击距离或兵种。

至少需要确认：

- 英雄基础攻击类型：近战、远程、法术、辅助站桩、混合等。
- 英雄主要职责：输出、承伤、治疗、控制、干扰、增益、召唤等。
- 英雄小兵类型：近战、远程、混合、无特殊要求等。
- 是否允许技能绑定具体武器表现，例如射击、挥砍、法术、号令。

未确认时，技能描述只能使用中性表达，例如“普攻命中”“攻击当前目标”“造成伤害”，不得写“射击”“挥斩”“远程小兵”“近战伤害”等会提前锁死表现和配置的内容。

确认结果必须写入英雄设计稿的首行表格，至少包括：攻击类型、攻击距离、小兵类型。近战与远程未特别说明时，分别采用项目基准距离 `300` 与 `600`；任何偏离基准的距离都必须单独说明设计理由。

技能名称、动作和特效必须符合项目负责人已确认的武器设定。若现有立绘与已确认设定不一致，应以已确认设定为准，将立绘列为待修订资源；不得为了迁就错误立绘而改写技能表现。

## 英雄技能标准结构

每名英雄默认拥有 6 个技能：

- 3 个主动技能。
- 3 个被动技能。
- 技能通过外围英雄升星依次解锁。
- 英雄进入战斗时自动携带所有已经解锁的技能。
- 旧版“6 个技能战前携带 4 个”的装配规则已经废弃。

推荐设计顺序为：

| 阶段 | 技能类型 | 设计目标 |
| --- | --- | --- |
| 阶段1主动 | 主动 | 建立英雄最基础的战斗行为。 |
| 阶段1被动 | 被动 | 完整启动核心机制；可同时给出基础站位定位。 |
| 阶段2主动 | 主动 | 提供不同于主动1的战术用途。 |
| 阶段2被动 | 被动 | 强化定位、站位收益或小队关系。 |
| 阶段3主动 | 主动 | 提供英雄的高价值战术爆点。 |
| 阶段3被动 | 被动 | 完成核心循环，补足后期辨识度。 |

## 审核节奏

新增英雄按“单英雄、两阶段”审核，不一次性提交整批 6 技能供审核：

1. 先确认攻击类型、攻击距离、小兵类型、定位、核心职责和专属循环。
2. 上述内容通过后，再提交该英雄完整 6 技能及数值候选。
3. 已通过的英雄及时写入候选稿或正式配置；未审核英雄不得混入“已通过”结论。

## 人类阅读版英雄条目格式

对项目负责人、策划评审或落档文档展示单名英雄时，英雄介绍不使用属性表格，统一使用以下连续阅读格式：

```text
英雄名
定位：<战斗身份；攻击类型、攻击距离、带领小兵类型；推荐站位>
核心职责：<一句话说明该英雄在战斗中解决什么问题，以及主要战术对象。>
专属循环：<核心机制名称>
<用完整段落写明资源/状态的获得、初始值、间隔、上限、强化、消耗、失效与跨波规则。>
```

- “定位”必须包含攻击类型、攻击距离、带领小兵类型和推荐站位；近战与远程未特别说明时，分别使用项目基准距离 `300` 与 `600`。
- “核心职责”描述玩法结果，不复述技能表中的所有数值。
- “专属循环”单独成行；其后的完整说明必须让读者不依赖后续技能表，也能理解循环如何开始、如何推进和何时结束。
- 英雄介绍后再列出 1 至 6 星技能表、自动规则和玩家可读性提示。不得用“基础属性 / 推荐站位 / 核心职责”表格替代本格式。

## 核心机制规范

每名英雄原则上应有 1 个主要专属机制，贯穿其主动和被动。

核心机制需要明确：

- 如何获得。
- 初始层数、自动获取间隔与每次获取上限（若适用）。
- 统计对象的完整范围，例如“本队小兵”还是“全体我方正式部署小兵”。
- 明确不计入对象，例如临时召唤物、幻象或未确认单位类型。
- 若机制使用多个生命阈值，必须写明单次伤害跨越多个未触发阈值时的结果，以及被治疗后是否会重新触发。
- 最多几层或是否只有开关状态。
- 是否会被主动技能消耗。
- 什么时候失去。
- 是否跨波次保留。
- 玩家能否从 UI 或战斗表现中看懂当前状态。

若核心机制是“唯一目标标记”或“持续维持状态”，还必须明确：计时从何时开始、何时刷新、转移到新目标时如何处理、目标死亡后如何处理，以及同一目标每波最多能触发几次关联效果。

核心机制不应只写成纯数值标签。设计稿应能用一句简明的话说清“如何启动、如何推进、如何释放或重置”；玩家不应靠记忆多段隐藏条件才能理解循环。资源、目标状态或阶段切换必须有可见提示，关键动作也应能在战斗画面中辨认。数值和触发规则可以在制作说明中完整展开，但玩家阅读版应先讲清循环动作。例如：

- 黄忠：守后排积累蓄势，再用主动技能转化为压制、穿透或斩首。
- 刘备：通过友方队长低血获得仁德，再强化治疗和护盾。
- 赵云：通过闪避获得游龙，再转化为额外攻击或救援护盾。
- 张飞：通过承受近战伤害获得守势，提升生存并强化控制和护盾。

核心机制来源需要多样化，不应默认做成“每 X 秒获得 1 层”。定时资源可以使用，但必须有明确设计理由，并避免多个新英雄连续使用同一类循环。

资源来源不能只依赖一个可能永久消失的对象或事件。例如资源若依赖小兵状态，必须确认小兵全部阵亡后循环仍有合理的持续来源，或明确设计为一次性资源；不得在残局中形成无资源可用的死循环。

常见机制来源可包括：

- 战前站位型：根据布阵格决定资源、强化或触发条件。
- 受击承压型：通过承受特定压力获得资源。
- 命中/闪避型：通过攻击命中、闪避、格挡等战斗事件获得资源。
- 目标死亡型：通过明确标记目标死亡、敌方单位死亡等直接事件获得收益；不得依赖伤害归属或“参与击杀”判定。
- 友方状态型：通过友方低血、护盾破裂、治疗目标等触发。
- 敌方状态型：通过敌方低血、被控制、被破防等触发。
- 波次节奏型：通过波次开始、敌方增援、精英出现等事件触发。

## 主动技能规范

三个主动技能不能只是同类技能的数值升级。它们应至少在以下维度中形成差异：

- 目标类型不同：当前目标、一路敌人、低血队长、友方队长等。
- 战术职责不同：单点、穿透、控制、护盾、治疗、斩杀、救援。
- 资源消耗不同：消耗 1 层、消耗全部、不消耗但触发额外状态。
- 自动释放规则不同：目标筛选、释放阈值、冷却或资源消耗条件不同。

主动技能统一使用自动释放模式：

- 已解锁主动技能始终自动释放；英雄技能不进入卡牌池，也不提供按英雄关闭自动释放的开关。
- 主动技能的自动目标、释放阈值、冷却和无合法目标处理必须可落表，且不能因缺少玩家选点而失效。
- 玩家主动参与由局内军令卡承担。军令不与英雄技能共用冷却，也不改变英雄技能的自动释放规则，详见 `tactical-command-card-system-v1.md`。

### 自动施法与资源规则

- 不得把英雄资源写成“玩家决定现在消耗还是继续保留”；战斗中资源使用只能由技能自身的自动条件决定。
- 禁止用“技能 A 优先于技能 B”或隐藏 AI 优先级解决两个主动技能的资源冲突。
- 多个主动技能涉及同一资源时，必须满足以下至少一项：只有一个主动会消耗该资源；或各自的自动施放条件天然互斥且能被玩家读懂。
- 资源条件、目标条件和生命阈值应直接写在该技能内；不允许依赖只有实现人员可见的隐式调度规则。
- 当前阶段禁止以“参与击败”“造成过伤害”“最后一击归属”等伤害归属规则作为英雄技能触发条件。优先改用施放成功、层数达到阈值、目标持有状态、目标死亡或自身生命变化等可直接观察的事件。
- 多目标主动技能必须明确主目标、附带目标和状态施加范围。若核心标记只应作用于主目标，必须明确写出；范围附带命中默认不获得、刷新或转移核心标记。

## 被动技能规范

被动技能主要承担三类职责：

- 启动核心机制：例如获得层数、定义触发条件。
- 强化英雄定位：例如前排承伤、后排输出、侧翼刺杀。
- 补足小队或站位关系：例如小兵受益、后排防护、侧翼攻速。

被动技能不应堆砌过多独立规则。若一个被动同时包含多个条件，需要确认玩家是否能理解它们之间的关系。

### 6 星被动规则

6 星被动默认应直接完成或强化该英雄的核心循环，例如核心资源达到阈值、同一标记目标持续维持、核心状态转化或明确的独立战场事件。

不得将“5 星主动施放成功”作为 6 星被动的通用触发模板。只有在该英雄存在不可替代的专属机制理由、且 5 星与 6 星的因果关系对玩家清晰可读时，才可例外使用；例外必须在评审中单独说明。

若 5 星会消耗或清除核心状态，6 星的触发条件必须在实际战斗时间线上有独立且可行的触发窗口，不能依赖一个通常已被 5 星提前清除的状态。

### 资源阈值与全场状态

不得把会频繁增减的资源层数，直接映射为全场单位持续实时变化的 Buff 数值，例如资源在 3/5 层之间反复变化时，实时修改全体小兵减伤。

默认做法是：资源首次达到明确阈值时，施加一次独立、固定数值、固定持续时间的状态，并写明是否每波只能触发一次。只有在 UI 能持续显示状态来源、数值变化频率可控且经过专项审核时，才允许使用实时动态光环。

## 站位联动规范

当前站位术语统一如下：

- 前排 = `1/2/3`
- 中排 = `4/5/6`
- 后排 = `7/8/9`
- 侧翼 = `1/4/7` 或 `3/6/9`

站位效果使用“战前布阵锁定”规则：

- 站位只取自战前布阵阶段的 3x3 格子。
- 波次开始后，英雄的站位属性在本波次内固定。
- 战斗中移动、追击、后撤、被击退、绕行或贴近敌人，不会改变该英雄的站位属性。
- 技能中写“位于前排/后排/侧翼”时，设计含义是“本波次开战前布置在对应站位”。
- 下一次备战调整站位后，下一波次重新锁定站位属性。
- 禁止写“离开前排/后排/侧翼后失效”这类动态站位判断。

站位联动应满足：

- 布阵阶段能提示是否触发。
- 战斗中能看出收益是否存在。
- 不要求玩家靠记忆背隐藏规则。
- 不把同一个英雄的核心玩法绑定到过多格子条件。

如果技能因为站位触发，应在布阵 UI 中提供明显提示，例如高亮、标签、预览文本或触发特效。

## 小队与小兵规范

当前英雄小队规则如下：

- 队长 = 英雄。
- 每个英雄带领一支小兵队伍。
- 玩家队长死亡时，该队小兵溃败离场。
- NPC 队长死亡后，该队小兵继续战斗。
- 小兵和队长都是独立个体，都可以被技能选为目标。
- 当前小兵兵种只确认近战和远程。

技能设计需要遵守：

- 写“队长/英雄”时，目标筛选忽略小兵。
- 写“小兵”时，目标筛选忽略队长。
- 不依赖医疗兵等未确认兵种。
- 不设计让小兵频繁切换目标或脱离队长行为的机制。
- 小兵联动应尽量是稳定增益、减伤、伤害修正或兵种收益。

## 玩家阅读版规范

技能玩家阅读版要写正式效果，不写只有设计讨论上下文才能理解的句子。

必须明确：

- 数量：例如“2 次伤害”“最多 3 个敌人”。
- 时间：例如“持续 3 秒”“每 8 秒最多触发一次”。
- 阈值：例如“生命低于 40%”。
- 目标：例如“当前目标”“生命比例最低的友方队长”。
- 消耗：例如“消耗 1 层仁德”“消耗全部威势”。

避免使用：

- “多次伤害”
- “短时间”
- “生命较低”
- “范围内”但没有定义范围
- “该加成提高”但不说明玩家能感知什么

工程限制、目标筛选、内置冷却、系统锁定等内容可以写在落表注释中，不必塞进玩家阅读版。

## 禁用或慎用机制

当前阶段不建议设计以下机制：

- 依赖技能前摇/后摇缩短、延长、取消的机制。
- 让小兵频繁切换目标的机制。
- 判断“正在被某个单位攻击”的复杂条件。
- 依赖未确认兵种的机制，例如医疗兵。
- 过度随机的次级选敌规则。
- 需要玩家实时操作走位才能成立的机制。
- 一个属性反复自我放大的循环，例如“拥有某资源提高闪避，闪避又大量获得该资源”。

敌人读性中的动作前摇提示不属于本条禁用范围；本条主要限制英雄技能机制收益不要绑定前后摇调整。

## 审核清单

新英雄技能稿进入评审前，至少检查以下问题：

- [ ] 是否有清晰的 1 个核心机制。
- [ ] 2 星被动是否完整写明核心机制的来源、范围、上限、间隔、排除对象和跨波规则；是否同时给出必要的基础站位定位。
- [ ] 唯一目标标记或持续状态是否写明计时开始、刷新、转移、死亡清除和同一目标每波触发上限。
- [ ] 新英雄是否优先补当前短板职业，或已说明新增偏多职业的差异化理由。
- [ ] 英雄基础攻击类型、攻击距离、小兵类型和职业归属是否已由项目负责人确认并写入设计稿。
- [ ] 技能名称、动作和特效是否符合已确认的武器设定；错误立绘是否已列为待修订资源。
- [ ] 核心机制来源是否有差异化，未无理由套用“每 X 秒获得 1 层”。
- [ ] 玩家是否能用一句话理解核心循环，并从 UI 或战斗表现中看见其推进和重置。
- [ ] 是否是 3 主动 + 3 被动。
- [ ] 三个主动技能是否有不同战术用途。
- [ ] 主动技能的目标筛选、释放阈值、冷却和资源消耗是否可由自动规则完整处理。
- [ ] 是否未使用手动资源取舍、技能优先级覆盖或隐藏 AI 调度；共享资源的主动技能是否只有一个消耗者，或条件天然互斥。
- [ ] 是否未使用参与击败、最后一击或伤害归属判定；多目标技能是否明确主目标、附带目标与核心状态的作用范围。
- [ ] 被动技能是否服务定位、站位或核心机制。
- [ ] 6 星是否直接服务核心循环，而非模板化绑定 5 星施放；若 5 星会清除核心状态，6 星是否仍有独立、可实际发生的触发窗口。
- [ ] 全场状态是否使用固定数值与固定时长，而非随资源频繁实时涨跌。
- [ ] 站位收益是否能在布阵或战斗中被玩家看懂。
- [ ] 小队/小兵联动是否不破坏队长跟随规则。
- [ ] 是否没有使用废弃的 6 选 4、旧装备、旧战备、旧羁绊口径。
- [ ] 玩家阅读版是否明确了数量、时间、目标和阈值。
- [ ] 是否没有引入当前禁用或慎用机制。

## 批次完成后的横向自检与历史对比

单名英雄通过审核，不代表整批英雄可以直接归档。每一批新增英雄全部完成“单英雄、两阶段”审核后、写入正式落表主源前，必须进行一次本节定义的横向自检；结论应写入该批归档文档或候选稿末尾。

本流程的目的不是强制每名英雄都使用从未出现过的机制，而是防止多个英雄只更换资源名称或武器表现，实际沿用同一套主动骨架、队伍增益和爆发窗口。

### 第一步：本批查重

为本批每名英雄填写一行“差异矩阵”，至少记录以下字段：

| 字段 | 必填内容 |
| --- | --- |
| 战斗身份 | 攻击类型、攻击距离、站位、带领小兵类型、主要职责。 |
| 核心循环 | 资源或核心状态名称、来源、上限、消耗者、跨波规则。 |
| 主动骨架 | 1 / 3 / 5 星的目标类型、战术职责、资源关系和主要爆点。 |
| 后期完成方式 | 4 / 6 星的触发条件、是否固定状态、是否作用小兵或全队。 |
| 战场动词 | 伤害、护盾、治疗、控制、破防、减益、位移、反击、召唤、阵型规则等。 |
| 队伍收益 | 受益对象、增益属性、持续时间、触发条件和每波上限。 |

查重时，重点检查下列高风险组合：

- 两名或更多英雄同时采用“相同资源来源 + 相同 3 星用途 + 相同 5 星消耗爆发”时，至少有一人必须在核心来源、主动职责或高星完成方式上重新拉开差异。
- 若两个英雄都使用唯一队长/精英标记，必须在标记的战术目的、后续收益或目标处理上明确不同；不得都做成“标记 - 破甲 - 斩杀”的同一循环。
- 同一批中出现三名或更多英雄以短时“小兵攻速”或“对队长/精英增伤”作为主要队伍收益时，必须调整其中至少一项的受益对象、属性类型、持续方式或改为其他小队关系。
- 不得只把“每 X 秒攒层”“普攻攒层”“敌人死亡攒层”等资源名称换掉，就复用同一组单体伤害、范围伤害、低血斩杀和 6 星强化。
- 检查同批同星级主动技能的战术职责分布，尤其不得让整批 3 星主动都套用“范围攻击”骨架。若多个英雄在同星级使用同类效果，必须说明玩家可感知的用途与表现差异；整批同质时应调整，而非仅更换伤害数值或技能名称。

出现重叠不必自动推翻已通过英雄。评审结论必须明确写为以下之一：`保留，差异充分`、`调整后归档`、`保留并列入实测对照`。若保留相似设计，必须写明玩家可感知的差异及需要对照的战斗场景。

### 第二步：与已完成英雄对比

每批必须与当前已归档的全部英雄进行一次纵向对比，而不是只比较本批内部。比较至少覆盖：核心循环来源、1 / 3 / 5 星主动骨架、6 星完成方式、控制与生存方式、队伍收益、目标类别和站位关系。

- 新英雄不得只是已完成英雄的“换属性/换武器/换资源名”版本；若定位接近，至少要在核心循环、主动战术职责或队伍关系中有一项形成明显可读差异。
- 同时检查当前英雄库的能力覆盖：单点、范围、治疗/护盾、控制/干扰、破防/减益、生存回应、位移/反击/特殊战场关系等。某一批不需要全部覆盖，但连续批次若长期只增加伤害、护甲、攻击和攻速效果，必须在立项说明中解释，并优先补足缺少的战场动词。
- 已归档英雄中存在的旧规则、旧判定或经审核批准的例外，不自动成为新英雄模板。例外必须单独记录其原因、适用英雄和是否允许复用。

### 第三步：场景与实现自检

对每名英雄至少以以下四种场景进行纸面推演或原型实测，并记录首次触发时间、目标选择和未触发原因：

1. 单一 Boss 或队长/精英，几乎没有小兵。
2. 多名普通小兵的密集波次。
3. 队长/精英带小兵的标准战斗。
4. 我方至少两名队长低血的承压场景。

每个技能还必须核对：

- 目标搜索范围、同生命值时的取舍、无合法目标时的行为。
- 标记、护甲降低、伤害降低、攻速、对队长/精英增伤、护盾和全场效果的叠加、刷新与上限。
- 资源被 5 星消耗后，4 / 6 星是否仍有实际触发窗口；全场或小兵 Buff 是否为固定数值和固定时长。
- 技能在 Boss、只有小兵、只有队长/精英时不会永久失去核心循环，也不会无意义地高频空转。

### 批次归档门槛

归档文档至少应包含：本批英雄清单及最终 6 技能、差异矩阵结论、与历史英雄的对比结论、需要实测的对照组、批准的历史例外和未决落表字段。未完成本节自检的批次，不得标记为“技能设计归档完成”。

### 批次横向审核清单

- [ ] 已为本批所有英雄填写差异矩阵，并完成核心循环、主动骨架、6 星完成方式和队伍收益的查重。
- [ ] 已按星级检查主动技能的职责分布，未让整批同星级技能套用同一范围攻击骨架。
- [ ] 相同唯一标记、资源消耗斩杀或兵线短时增益已逐项确认差异；必要时已调整或列入实测对照。
- [ ] 已与全部已完成英雄比较，未把历史例外当作新模板。
- [ ] 已检查当前英雄库的战场动词覆盖，并说明本批补足或暂未补足的方向。
- [ ] 已完成 Boss、密集小兵、队长带兵、我方低血四类场景的纸面推演或实测记录。
- [ ] 已定义目标搜索、同值取舍、无目标行为，以及关键状态的叠加、刷新和上限。
- [ ] 已将“保留 / 调整 / 实测对照”的批次结论写入归档文档。
