# 局内装备设计指导规范 v0.1

> 状态：扩量方向及下列机制规则已获负责人确认；具体新装备与数值仍是策划候选。本文确认设计目标，不代表现有 ECA 已全部实现或经过验收。
>
> 范围：当前 `map3` 的装备补给、行囊与英雄双装备格。旧版随机属性装备、局外装备和旧战备方案不适用。

## 定位与边界

- 装备是单局内的**英雄个体构筑选择**：在每英雄两格的限制下，提供角色适配、局势应对与有代价的取舍。它不能替代英雄技能、站位、军令或补员。
- 购买后先扣徽章、进入玩家局内库存，再由行囊转移至指定英雄；单位不做跨局装备存档。英雄与小兵的效果对象须在文案中区分，默认不能把英雄加成扩展到其小兵。
- 现有八件是首轮比较锚点，不是已证明等价的强度单位。扩量先增加不同用途的选择，不堆叠纯数值升级品。
- 设计与实装分层：唯一装备池表管投放、价格、权重、解锁和限制；物编管固定属性及单件效果；玩家局内库存管已购未穿戴数量和必要的单件状态。公共 ECA 只处理抽取、交易、转移与展示，不枚举逐件效果。

## 已确认的扩量规则

- **同名可双持**：同一英雄可在两格中穿戴两件同名装备，除非该装备明示互斥。互斥须作为单件规则明确配置和提示，不能把“同名”本身作为默认拒绝理由。双持效果按下述叠加规则结算。
- **报价按当前队伍过滤**：每次生成或刷新三选一时，只保留当前队伍至少一名可成为穿戴目标的英雄能够使用的装备。主属性与指定英雄限制都参与判断；英雄两格已满仍可通过换装使用，不因此过滤。队伍变化后重新抽取须重新判断；已展示报价在购买时也应复核适用性。此为已确认设计要求，现有抽取 ECA 是否完整做到需单独审计，不在本文中冒称已实装。
- **普通属性相加**：两件装备的普通百分比属性各自以未计入这两件装备的同一基础属性为基准相加，不逐件复利。例如两把“攻击 +8%”的设计目标是合计攻击 +16%，不是 `1.08 × 1.08`。个别强效果可在该装备上明示“取最高”或“互斥”；装备与技能、军令间的跨系统结算顺序仍须按战斗数值口径核验。
- **消耗次数按单件保存**：每只药囊等有限次装备有独立剩余次数。卸下、交换、重新穿戴及英雄死亡均不恢复次数，也不因这些操作自动销毁；若英雄实例消失，须有保留该件状态的退库处理。新一场战斗只重置“每场可触发”资格，不补回总次数；同编号波次重打也算新战斗。次数耗尽时才销毁，单局结束统一清空。
- **同事件不重复消耗**：同一英雄双持两只救命药囊时，一次低血事件只触发一只，按装备格顺序选择仍可触发的药囊；每名英雄每场战斗最多获得一次药囊治疗。另一只保留自身次数，可在后续战斗触发。同类消耗品如需不同规则，必须在单件设计卡明确说明。

## 单件设计卡

每件候选进入物编前，必须写齐以下字段：

| 字段 | 设计要求 |
| --- | --- |
| 身份 | 名称、图标、一句话用途及主要适配英雄或阵容问题。 |
| 获得 | 徽章价格、报价权重、最低难度/波次、是否投放；说明为什么此时出现。 |
| 穿戴 | 通用、主属性限定或指定英雄三种现有约束之一；区分推荐与硬限制。 |
| 效果 | 触发时机、作用对象、数值基准、持续/结束条件、叠加规则及可观察反馈。 |
| 消耗 | 若有限次，写明每件次数、每场限制、卸下/交换/死亡/销毁时的状态。 |
| 验证 | 购买、双格、重复购买或双持、卸下回库、HUD、数值变化、战斗日志与复测方法。 |

新增一行表不等于实装完成。物编正数 ID、语言键、图标、配置表、物编总索引、效果 ECA 和 HUD 展示须逐项对应。

## 品类与池子

按**战术用途**而非品质颜色规划：基础属性、风险换收益、战术适配、机动/保命、专属与消耗。基础品提供可靠入口；风险品正负效果都写在卡面；专属品强化角色特色但不应成为其正常运作的必需件；消耗品必须有明确次数和失效反馈。

扩量先保证常见阵容有足够可用的通用候选，再加入少量主属性、专属及消耗装备。三报价须从投放条件与当前队伍适用性均成立的表行读出，且同组不重复；有效候选不足三件的降级规则须专门设计，不用无效装备凑数。避免某一英雄、主属性或效果类别长期垄断报价。具体类别比例待评审，不把建议写成现有系统承诺。

本轮 40 件候选按数量规划为普通 24、稀有 12、珍奇 4。**稀有度是策划分层，报价权重是每条有效表行参与抽选的相对数值**；二者相关但不是同一个字段。若所有 40 件都有效且权重相同，单次候选池的原始比例才接近 60%／30%／10%；队伍适用性过滤、解锁波次和同组三张去重都会改变实际出现率。首版不为稀有度再造一套抽选枚举，后续依据实测报价频率调权重。

## 数值与经济锚点

现有样本：精铁短刃 `3 徽章/攻击 +8%`，狂战短刃 `5/攻击 +16%、防御 -12%`，镇阵护甲 `4/力量英雄生命 +12%`，聚法玉简 `4/智力英雄法术攻击 +10%`，疾风扳指 `4/敏捷英雄攻速 +10%`，行军轻靴 `4/移速 +12%`，燕人铁环 `5/张飞承伤 -8%`，救命药囊 `5/低血治疗、单件两次`。这些只描述当前表，不代表已完成横向平衡。

- 暂沿用 `3/4/5` 徽章档位提出候选：3 是可靠但窄的基础选择；4 强调适配；5 应有强条件、次数约束或真实取舍。超出档位先核对徽章收入、刷新成本和同局平均购买量。
- 百分比效果同时计算英雄 1 级与 6 级的绝对改变量，并验证双装备、军令、护盾与技能叠加。防御、减伤、生命和治疗不是可以直接相加的同一收益；不能形成无限续航或让普通敌人无法造成可观察伤害。
- 同款双持及普通属性相加已确认；每件物编仍须核对原生属性是否达到目标值。特殊触发效果在单件设计卡明示取高或互斥，不能从普通属性的相加规则推导出“同一事件可重复触发”。
- 攻速、移速和“法术攻击”须做实际收益验证。现有英雄数值候选把 `spell` 作为设计标签、技能攻击暂映射物理攻击力；聚法玉简不能未经核验就当成后续法术装备的数值模板。

## 文案与反馈

- 卡面按“谁获得什么收益；何时触发；主要限制或代价”写短说明，百分比必须写基准，如“自身最大生命的 15%”。报价、行囊、HUD 提示保持同一口径，长说明在各自卡内换行。
- “每场”“每波”“每局”“每件”“每名英雄”不可混用。重打同编号波次时，以实际**战斗场次**而非编号处理每场触发限制。
- 限定无法穿戴、交换、卸下、次数耗尽应有可见反馈；不能让玩家仅凭库存数推断结果。

## 扩量与验收

1. 先填单件设计卡，与同价位现有装备比较用途、代价和组合风险；评审后再占正式物编 ID。
2. 分批实现不同类型样本：固定属性用物编字段，触发效果放该物品的 ECA；报价与行囊继续动态读表，不新增逐件购买/显示分支。
3. 静态检查物编 ID、语言键、表行、图标、ECA 引用与 `valid`；再检查编辑器能打开、无红字。JSON 结构通过不等于编辑器或运行时通过。
4. 同一轮集中试玩覆盖扣费、库存、双格、HUD、属性前后值、卸下回库、限定/专属、消耗次数及一场完整战斗。关键效果日志记录英雄、装备、战斗场次、剩余次数与关键数值前后变化。
5. 回归检查 PVE/PVP 开局无旧装备发放、不同英雄可分别穿两件、换装与同类效果叠加；代表试玩不冒充全物品验收。

## 待负责人确认

- 下一批数量和品类比例；哪些具体装备需要互斥。
- 各价位购买机会、刷新成本与解锁波次曲线；有效候选不足三件时的处理。
- 攻速、移速、法术攻击的原生属性结算，以及装备与技能/军令间的修正顺序；这些属于实现和数值验证，不改变已确认的普通双装备相加目标。
- 哪些新装备需要例外的取高、互斥或不同于药囊的消耗触发规则，应逐件设计并明确展示。
