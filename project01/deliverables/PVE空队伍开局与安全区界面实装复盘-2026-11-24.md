# PVE 空队伍开局与安全区界面实装复盘

日期：2026-11-24。正式工程：`ProjectMonster02`，共享 ECA、UI 与配置维护入口为 `map3`。本记录覆盖空队伍开局、首将后布阵、正式开局修复、营地和收藏页改版，以及没有合入正式工程的小兵接敌错位试验。

## 正式玩法与验收边界

- 正式工程的 PVE 关卡开局没有己方队伍。第 1 波备战免费选一次首将；成功入队前不能开战或使用装备补给。可关闭后重开同一报价，不能通过关窗、重试或刷新再领首将。首将成功创建并关闭招募后，再打开布阵。
- 后续花局内徽章招募，沿用原卡池等级、品质与价格配置；满员后强化已有武将。确认时按该玩家的当前报价、队伍和余额重新校验；创建失败退回实际扣费。局外武将养成、解锁及旧阵型存档保留，但 PVE 初始阵容不再读取旧上阵配置。
- 关卡范围读取现有「关卡介绍信息表」；发布时覆盖编号 1、2、4、5，安全区和无配置地图不启用新开局。镜像入口暂时关闭，旧镜像入场标记不允许直通，不删除原镜像代码或档案。未改关卡难度、奖励配置、物编或数据表；副本中的额外徽章不进入正式版。
- 正式版初次试玩复现了旧队伍泄漏，修复后负责人确认开局流程正常；武将收藏页放大立绘后另经负责人确认。招募结算、范围和部分 UI 行为有离线检查，不据此扩大为每个关卡、皮肤、分辨率及全部原生异常分支均已试玩。

## 经验与后续维护

1. **关卡进入规则、局外养成和本局阵容是三件事。** 复用已有查表结果，不复制地图 UUID 清单；既要停读旧队伍，也要撤下局外操作入口，不清空玩家历史。覆盖有旧阵型的档、新局、无配置地图和残留模式标记。原型试验奖励不得跟随脚本流入正式版。
2. **结构合法不等于 Y3 会执行。** 初版把全局布尔标量写成数组目标（`100028` 却没有索引），正式试玩仍走旧队伍。按项目原生实例改为标量目标 `100030`；离线模型加入错误编码负例，不能用宽松解释器替引擎补足参数。
3. **报价不是入队成功；UI 刷新不能早于真源。** 重开保留当前报价；确认校验来源实例、状态、余额和队伍上限；成功以队伍实际登记为准，而非仅调用了建队函数。首将落地、旧弹窗关闭、布阵刷新是三个验收点；付费补员只刷新已打开的阵位页，不强制弹窗。
4. **删 UI 要同步读写链；改尺寸要查运行时覆盖。** 删除五人栏时同时撤显隐、染色和摘要读取，避免隐藏功能继续访问存档。立绘从旧裁切移到新栏时，原选择刷新仍会指定旧尺寸，一并校准；UID、皮肤选择和原业务按钮保持。效果稿只是比例和阅读层级参考，试玩必须检查切人、长图裁切和原生点击。
5. **停止试验的结论也要保留。** 小兵试验确认少量样本能走到预留点，但恢复原生攻击后仍会偏位或回叠；没有验证出稳定的攻击分散办法。没有把试验的寻敌、短移、碰撞切换等逻辑并入正式工程；不以实际下令等同于到位或成功攻击。经验见[接敌错位规范](../docs/y3-eca-implementation-standards.md#接敌错位排位到位与交还攻击分别验证)。
