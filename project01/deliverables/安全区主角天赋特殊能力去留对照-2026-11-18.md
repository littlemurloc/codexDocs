# 安全区主角、天赋、特殊能力去留对照

审查日期为 2026-11-18。工程为 `D:/littl/testTempFile/ProjectMonster02`，主地图为 `map3`。本轮读取现有 UI、ECA、配表、技能及存档声明，未修改正式工程，未读取玩家账户存档，未新增游戏内验收。

建议优先撤下旧主角选择／兑换和旧特殊能力的玩家入口。负责人随后明确“天赋也先撇下，暂时用不到”，因此新版安全区暂不安排天赋入口，天赋改版与收益接入一并暂缓。三个模块的底层数据和逻辑均有引用，现有 ECA、存档和后台载体继续保留。本次决定记录不涉及停用既有存档效果。

## 旧主角的实际依赖

`主角清单.json` 的两个单位 ID 为 `134249360`、`134273269`。后者兑换配置为 120，前者默认拥有。当前选择在槽 6 `playerInfo` 的 `当前角色` 字段，拥有记录在槽 15 `playerHeroRecord`，与武将养成使用的槽 16 `playerPartnerRecord` 分开。

`玩家刷新.json` 仍按主角清单创建单位，当前启用的创建坐标为 `(-999999999, -999999999)`，随后赋给 `playerHeroList`。在刷新区域创建这两个旧角色的其他分支已禁用。故它在当前实现中至少承担后台角色载体职责，不能把“玩家不需要选旧角色”推导成“可以删除这个单位”。

`读取存档 → 主角单位更新附加属性` 汇总槽 15 的拥有记录和旧角色出战配置，通过 Buff `134272976` 施加到 `playerHeroList`。这是旧主角上的真实数据处理，不能用这条链证明现行武将已获同样加成。该函数的出战判断还存在读取槽 9 的旧表达式，与当前选择写槽 6 的路径不一致，后续若继续维护旧角色属性应单独核查，本轮未修复。

当前三国队伍在 `universe01 → 创建英雄队伍单位／根据升星属性给英雄队长赋值` 等路径中创建，使用保存的武将与阵型，加入 `玩家队伍`。它与旧主角选择入口承担不同任务。

## 天赋的实际收益边界

天赋表为 `天赋技能清单.json`，TID 为 `9f346c30-b6ab-406a-8ed4-4fb58740e89e`。42 是有有效 key 的配置条数，已排除空白占位行。代表配置如下。

| 类别 | 配置例子 | 需要明确的产品规则 |
| --- | --- | --- |
| 基础战斗属性 | 攻击 +8、生命 +80、暴击率 +0.4% | 哪些武将、小兵获得，如何叠加与展示 |
| 技能收益 | 自动技能冷却减少、手动技能冷却减少、技能伤害增加 | 现有哪类技能读取，是否与当前冷却体系一致 |
| 局内经济 | 初始金币／钻石／徽章、每秒货币 | 与当前关卡经济、装备补给、军略商店是否采用相同资源及结算时机 |
| 持续成长 | 每秒攻击、每秒生命、经验加成 | 是否仍符合当前波次节奏、备战和战斗阶段规则 |

`初始化天赋树` 有真实初始化和交互注册，确认调用 `执行存档-实时天赋树`，取消重新读档，重置有返还点数和刷新逻辑。槽 7 为 `playerTalentInfo / configPlayerTalentInfo`，天赋点另走既有货币存档链。

`执行读档-实时天赋树` 对 `playerHeroList` 移除旧天赋类技能，再按存档重新授予／升级。代表“攻击1”的技能 ECA 以自身拥有者增减攻击，故直接收益对象仍为该旧主角，不能直接写成“所有武将攻击增加”。切图函数仍调用这条天赋读档链。

另查到旧的 `玩家主单位属性更新 → 仆从伙伴属性锚定玩家更新` 广播桥。接收端仍注册，但它操作旧 `局内-对应玩家的仆从队伍` 组；当前查到的发送端位于禁用的属性同步块或禁用触发器，当前新武将则加入 `玩家队伍`。脚本、技能和 Buff 中未查到该广播名的其他发送来源。因此现有证据不足以确认天赋已完整同步到当前三国队伍，应安排有／无天赋的队长、小兵和经济对照后再决定正式保留范围。

不建议在这次 UI 精简中顺带重构天赋数值或打开旧同步桥。旧桥包含直接设置生命、攻击、防御等行为，重新启用可能覆盖当前升星或军略属性，需另行设计和验证。

## 特殊能力保留了哪些旧内容

四项来自 `仆从特殊能力表.json`，当前四组均要求对应三个伙伴达到 1 星。

| 旧能力 | 当前行号映射到的英雄 | 当前授予目标 |
| --- | --- | --- |
| 雷电弹射 | 夏侯惇、刘备、诸葛亮 | 旧主角 `playerHeroList` |
| 浮游炮 | 马超、荀彧、太史慈 | 同上 |
| 能量光束 | 大乔、张郃、祝融 | 同上 |
| 火炮覆盖 | 诸葛亮、太史慈、祝融 | 同上 |

这些组合是当前表中行号的真实映射，不能当作已确认的三国羁绊设计。资格检查读取伙伴与星级，激活监听遍历槽 18 并更新选中项和其他项的 `是否激活`，界面刷新显示已激活状态。

`读取存档 → 主角解锁特殊能力` 按槽 18 的激活项授予旧主角技能，四项技能还保留拥有者攻击／伤害事件及对应效果逻辑。旧主角目前在场景外，不能由此认定它们已成为当前武将战斗技能。激活按钮处理本身以写档和刷新界面为主，即时切换是否生效也没有本轮实测证据。

若以后重新设计组合成长，应明确它与武将六技能、军略和兵种养成的分工，并重新建立组合依据、受益对象及结算时机。当前玩家导航可优先精简这一块。

如果采用上述去留，下一步先画安全区导航和页面结构参考，确认后仅改入口与布局。后台载体、存档、属性和技能退役应另列依赖清单，不与这一轮界面精简混做。

## 证据与限制

本轮检查了入口、监听、根初始化与子触发器引用。子触发器元数据 `enabled=false` 不能单独用来判定功能停用，本图有大量通过根动作中的子触发器 ID 引用注册的原生写法。只有结合实际注册块及其 `enable` 才讨论启用状态。

[源文件审查记录](evidence/safezone-modules-20261118/source-review.json)记录 73 个重点源文件的哈希、42 项天赋、四组能力及 UI 处理器的注册引用。它不含玩家账户数据或完整工程副本。未重开编辑器／对局，界面是否显示、收益最终是否生效和所有模式边界仍需实际验收。

本轮只新增对照文档和静态审查证据，未修改 UI、ECA、物编、配表及存档。
