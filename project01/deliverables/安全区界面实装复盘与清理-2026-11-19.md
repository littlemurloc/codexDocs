| 多套皮肤容易复制数据及交互 | 装饰模板与实时内容分层，共用业务函数；稳定风格ID与配表负责选择，不复制八套玩法 |
| 能力列表被配成0行，星级只能露一颗 | 本图按行模式1须有正行数；按列模式2搭配`(0,1)`为一列，星级横排搭配`(0,5)`。模式、行列数、单元格和可视区共同核对 |
| 原生分页与图片适配会覆盖手工外观和大小 | 同步分页`btn_image`，固定尺寸图关闭`size_adaptive`；按钮常态、悬停、按下、禁用四态文字都更新 |
| 图片改布局、旧功能收进弹窗后容易丢写入对象或事件上下文 | 保留原UID和实际访问路径；仍被写图片的节点保持图片类型；新操作转发原控件事件，不复制扣费／存档链 |
| 悬停改点击后留下了已经不存在的关闭事件监听，原生保存标红 | 控件声明、监听、根注册和派发一起检查，废弃事件及旧调用同步退役 |
| 技能／Buff类型常量0在原生保存被判无效 | 使用工程已有`NONE_ABILITY_KEY`／`NONE_MODIFIER_KEY`；变量默认值0不等于资源字面量0合法 |
| 给旧STRING局部变量套通用`VARIABLE`引用，保存后变null | 精确复制该函数已有`sub_type=2`表达式，保留列表／元组标记，回读实际引用；通用构造器不能无条件覆盖旧编码 |
| 真正星级超过15后，详情仍拼不存在的高星字段并转换空字符串 | 显示与计算使用相同有效配置档，真实星级另保留；0星／空字段先保护，不补造数值或修改玩家存档 |
| 新UI检查把旧详情函数当边界，漏掉其高星级解析 | 共用调用链也要覆盖代表失败路径；本次执行原属性动作块复现旧18星失败，再验证修复与26×15组现有配置 |
