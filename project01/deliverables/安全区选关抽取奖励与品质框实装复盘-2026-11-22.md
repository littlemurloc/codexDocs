# 安全区选关、抽取、奖励与品质框实装复盘

本轮为 2026-11-21 至 2026-11-22 的 `ProjectMonster02 / map3` 改动。上一阶段的八皮肤、阵容与兵种内页仍见[前次复盘](安全区界面实装复盘与清理-2026-11-19.md)。本轮正式清单为 **23 个工程文件（3 新增、20 修改）**，另导入两张军需箱图标。预置表、物编与存档声明沿用原资源。

## 经验教训

| 实装问题 | 后续做法 |
| --- | --- |
| 初版难度格能切换，但最后一个可挑战的 N9 缺底板，章节标题被改成「N」 | 沿着初始默认选择、延迟回调、动态事件和手动点击逐条找写入方。旧 `关卡preSelectShow` 会把旧默认档底板隐藏并重写标题，删除了该回调、事件注册和监听。由新版难度选择处理器统一维护选中表现。 |
| 关卡图、时长、长奖励名与星级标题在实机挤成一块 | 按目标分辨率验证真实装载后的视口。时长单独排在标题旁，奖励分区；密集奖励保留图标，用现有悬停查看名称和数量。网格以完整行数、单元尺寸、间距和父容器裁切一起计算。 |
| 武将招募偶发卡顿，小兵动画观感偏短 | 武将揭晓与武将列表、详情和红点刷新曾在同一时段执行，将后者移到演出收尾。单抽、十抽与点击跳过共用收尾，按玩家与演出序号隔离旧计时器。现有日志无逐段耗时，武将数据量是否为根因及改善幅度均待实机验证。 |
| 通用奖励换皮容易误影响其他用途，单抽和十抽数量差异大 | 保留共用弹窗入口、标题、关闭和道具详情绑定，新建奖励条目元件，按结果数选择布局。地图库和经济数据不承担皮肤状态。 |
| 挂机原弹框短且不显眼，后来需同时表达本次到账和下次奖励 | 区分「下次」「本次」「累计」三种状态。预览找现有配置里最接近的未来发放档，倒计时读发放计时器，奖励图标按原道具表解析，末档结束显示已发完。本次弹窗挂到现有非空发放分支，5 秒计时按玩家与本次序号判定，手动关闭后不应被旧回调影响。 |
| 品质颜色和原先两枚小饰件在小头像上不容易辨认 | 用带有不同轮廓的前景边框，连续双层边缘接四角包边，局部雕纹沿框贴合。立绘底纹在裁切下方，边框和雕纹在裁切上方且不吞输入；外圈继续表达选择状态。品质从现有 `仆从列表` 读取，同一材料只映射一位武将。 |
| 文件能解析不代表布局、命中和性能合格 | 区分发布回读、ECA 验证、原生保存回读和试玩。实机先覆盖截图暴露过的 N8／N9 切换、奖励读性及 R／SR 小头像，再对照玩法进入、重复抽取、同一弹窗多次刷新和章节锁定边界。 |

上述要求已经写入 [Y3 ECA 实装规范](../docs/y3-eca-implementation-standards.md) 的安全区 UI 小节，并同步 [验收清单](../tests/y3-eca-delivery-checklist.md)。

## 验证与保留边界

- 阶段试玩反馈包括小兵开箱能正常播放但偏短、武将招募偶发卡住、N9 缺框和奖励叠字，以及小头像雕纹观感弱。它们对应各自的修复前版本。
- 最终相关 ECA 已通过结构和引用检查。清理前回读发现 Y3 已重存，14 个文件仅改序列化格式，6 个 ECA 差异限于已核对的编辑器标记、空子触发器容器和禁用的默认参数。3 张画板保留控件 UID、类型和图标引用，部分默认样式字段及位置百分比发生变化，仍以实机画面核对。发布候选和重存版本均入档。关卡初始化中既有的「全局视野」引用提示及其他原有警告未列为新缺陷。
- 挂机配置的 480 个发放档已离线核对，另核对了存在空档、最后一档和 5 秒弹窗序号的行为。离线结果与是否实际到账、首次加载、自动关闭和重新进图分别验收。
- 当前武将配置为 26 位，实际品质只覆盖 R／SR。七档资源分配与框角层级已离线检查。最新前景框、完整层级和各分辨率的实机观感仍待复测。
