# 装备补给与行囊更新实装复盘

本轮在 Y3 的 `ProjectMonster02/map3` 更新了装备补给和装备行囊。沿用玩家自定义 `new/kit` 资源及原报价、物品栏和穿戴规则。以 1920×1080 为基准，补给为 1080×640，行囊为 1400×790。 [两张确认稿](../assets/art/ui/preview/equipment-ui-20261115/)记录视觉方向，行囊尺寸及字体以后续实装为准。

## ECA 改动与维护入口

| Y3 现有入口 | 本轮变更 |
| --- | --- |
| 刷新装备三张报价 | 从原配置读价格、徽章余额与穿戴限制。余额不足或无报价时禁用对应购买按钮。 |
| 购买装备_按物编ID | 加入 `购买前库存`，回读同一装备及剩余次数的数量，确认增加一件后扣费。购买成功打开行囊并选中新装备。 |
| 刷新装备库存行 | 显示剩余使用次数，按装备 ID 与剩余次数高亮所选库存行。完整说明移至详情区。 |
| 刷新装备英雄行 | 已穿戴装备加载配置图标，空格显示「+」，其他系统占用显示「占用」。 |
| 装备行囊_动态交互 | 清理或更新选中状态，预览穿戴限制及新旧装备，按当前选择启用穿戴、替换和卸下。返回补给时刷新报价显示与余额。 |
| 装备行囊_确认穿戴或交换 | 操作成功后清理选中项；暂存旧装备 ID，按实际结果记录穿戴或替换。 |
| 装备行囊_卸下回库 | 重置行囊交互状态并记录卸下的英雄、装备和槽位。 |
| 装备补给_刷新报价 | 将余额不足提示移到状态区，保留原刷新价格与抽取。 |

共改动 4 个函数、4 个触发器、1 个画板和 2 个预制件。保留原 ID、函数签名和事件绑定。后续在 Y3 编辑器维护这些入口，报价和物品说明仍由 `局内装备池配置表` 提供。

## 经验教训

| 现象 | 后续做法 |
| --- | --- |
| 已扣徽章，行囊列表却为空 | 局内堆栈显示库存行创建进入 `WorldUITextLabel._refresh_label_by_alignment` 后，因 `alignment=(0, 8)` 抛出 `KeyError: 0`。分开验证库存写入、扣费、动态元件创建和用户可见结果。对齐值直接取本图原生样本。 |
| 参考图能读，实装后说明压住图标，列表截断 | 正文改为无描边微软雅黑，列表只留名称、数量和适用的剩余次数。完整说明独立换行，行囊按内容放大。右侧视口 414 px，可容纳 5 个 78 px 行与 4 个 6 px 间距。实际运行要查看满员和长说明。 |
| 有大量赵云日志，其他英雄看起来没记录 | 原样本的 142 条均为赵云前锋腰牌的伤害结算。通用操作记录放进穿戴、替换与卸下的共用入口，按实际英雄、装备与槽位写一次。物品效果日志继续按各自条件输出。 |
| 已写文件、MCP 能读到 UI，局内仍可能跑旧版本 | 分别确认磁盘写回、编辑器导出、触发器加载和新对局。外部写入后先核对编辑器内未保存的用户变更，防止旧会话保存覆盖磁盘。 |

已更新 [Y3 ECA 实装规范](../docs/y3-eca-implementation-standards.md) 第 08、09、12 节、[交付验收清单](../tests/y3-eca-delivery-checklist.md)与 [UI 设计原则](../docs/design/ui-ux/ui-guidelines.md)。
