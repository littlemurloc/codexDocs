# 安全区八皮肤动态切换落地方案

日期：2026-11-18。状态：技术方案，待视觉与交互确认；没有修改正式工程的 UI、ECA、配表或存档。

## 目标与范围

在设置旁增加“界面风格”，由玩家从现有八套风格中选择，确认后切换安全区最外层界面。选择属于玩家个人偏好，建议跨次进入保留；不改变其他玩家的选择。

八套候选及现有资源 ID 见[八套资源对照](../assets/art/ui/preview/safezone-existing-kits-all-20261118/README.md)。参考图是基于实际资源生成的视觉方案，不能直接视为八套已完成的引擎皮肤。实装仍需补齐控件状态、排版与实际显示验证。

| 纳入外观切换 | 本次保持原有行为与外观 |
| --- | --- |
| 安全区主要面板底板、边框、标题装饰、主要及次要入口按钮外观、摘要区头像装饰框、对应文字配色 | 战斗 HUD、局内背包／装备／补给弹窗、各功能页内部界面、人物立绘和头像内容、技能和装备图标 |
| 新增“界面风格”入口自身的外观 | 原公告聊天、未开放占位、测试工具的位置、内容、显隐与权限 |

保留模块的范围不因换肤扩大。成就、天赋撤下玩家入口及保留底层／存档的既定决定不变；其他导航建议也不因本方案自动实施。

## 实现选择

采用“一套业务骨架 + 八套外观模板 + 一张皮肤目录表 + 一项个人偏好”。不复制八套业务页面，也不按图片资源 ID 全工程替换。

| 层次 | 职责 |
| --- | --- |
| 共用业务骨架 | 真实章节／阵容数据、入口功能、可用状态、点击事件与条件判断。只维护一份。 |
| 外观模板 | 每套预设图片、九宫边距、独立叠加装饰、文字样式和各按钮状态；按共同锚点装配。模板不包含购买、奖励、进图等业务处理。 |
| 皮肤目录表 | 稳定的数值 ID、显示名称、模板引用、排序、是否开放、默认标记，可附小型预览图。目录表引用模板，不另抄一份模板内部所有图片 ID。 |
| 玩家偏好 | 保存已确认的皮肤 ID。运行时选择、界面实例和事件处理均按对应玩家管理，不能使用全体玩家共用的“当前皮肤”。 |

目录 ID 固定为：1 清瓷地图、2 朱印令牌、3 墨刷浮层、4 玄铁铜铆、5 军务档案、6 青玉璧环、7 基础金边、8 墨金战阵。显示名称可以改，已使用的 ID 不随菜单排序改变。默认皮肤由配置指定，不在本阶段代替负责人选定。

界面绑定使用明确的安全区控件 UID／实例和角色清单。更新其图片引用，不覆盖共享图片文件，也不全局替换所有引用同一图片的控件。

## 为什么采用预设模板

当前工程有 `SET_UI_COMP_IMAGE_NEW`、文字颜色设置、UI 预制件创建以及 `SET_UI_COMP_SCALE_9_ENABLE` 的实际用法。但本次样本核对未证明运行时能完整改写九宫四边距和按钮所有状态的图片配置，因此不把这些能力当成已经验证的前提。

前六套基础系列的清单中，同类窗口／标题／矩形按钮分别使用相同边距，但不同控件角色的边距并不相同；kit01、kit02 则须按各自素材确认。08 的开战印章是圆形，必须等比显示，不能九宫拉成矩形。模板中预先配置这些差异，比运行时盲目只替换一张图可靠。

各模板保留相同的主要内容区和功能位置。少量形状差异通过预设变体处理，例如圆形与矩形开战入口分别使用匹配的外观和命中区域，都转发至同一业务处理器。不得同时启用两个叠加按钮。

装饰层不截获业务点击；独立角饰、印章、挂件按锚点叠加，不随底板拉伸。常态、悬停、按下、禁用都需明确配置；素材缺失时列为补齐项，不以拉扯常态图冒充完整状态。切换外观不能把业务上已禁用的按钮重新启用。

浅色与深色皮肤使用成套文字配色，并检查普通、辅助、选中和禁用文字的对比。共用骨架不意味着强制八套使用相同字体颜色。

## 玩家交互

1. 点击设置旁的“界面风格”，展开八项菜单；当前项标记“使用中”。菜单在安全区画面内展开，显示名称及可选的小型素材预览。
2. 点击当前项不重复切换；点击其他项，收起菜单并弹出确认框。
3. 确认框示例：“切换界面风格？”、“青玉璧环 → 墨金战阵”、“仅调整安全区外层界面，可随时切换。”按钮为“取消”和“确认切换”。
4. 确认后才应用新外观；取消或关闭确认框不改界面、不写存档。点菜单外部关闭菜单，Esc 优先关闭当前菜单／确认框。

确认框使用固定、中性的外观，不在确认过程中切换自身。菜单预览不使用整张高分辨率氛围图，也不提前更换实际界面来冒充“已确认”。

## 运行顺序与保存

进入安全区：等待对应玩家档案可用 → 校验保存的 ID → 使用对应模板；未设置或 ID 不合法时使用配置中的默认项。初始化挂接档案就绪流程，不靠任意延时猜测完成时机。

确认切换：校验目标 ID 和模板 → 准备新外观 → 成功后切换显示并应用文字样式 → 更新该玩家偏好 → 请求保存。准备失败时保留旧外观，不留下半套新皮肤。保存失败与外观失败分别处理，不能把“本局已切换”宣称为“已成功跨局保存”。

优先为该偏好使用独立的整数存档项，拟名 `playerUiSkin`，实施前核对实际可用槽位／键及容量规则，不预占假定空闲的编号。不得复用或重命名旧兵种养成兼容键，也不改写旧的整包玩家数据。

事件在共用业务层注册一次。外观反复切换时不反复注册进图、领取等监听；销毁旧模板前解除其临时转发绑定。一次确认只产生一次切换请求，处理中避免重复点击并发切换。

从战斗返回安全区时重新应用当前偏好；运行时按玩家指定 UI 实例，保存遵循工程现有按玩家的存档链，不能直接假设本地客户端变量就能可靠写入持久存档。

## 实施顺序与验收

1. 先确认“风格菜单 + 切换确认框”的 2D 参考，并确定默认项。
2. 用一浅一深两套打通共用骨架、模板切换和文字配色；确认九宫、命中区域及业务状态。
3. 补齐其余六套，单独验证圆形开战印章；八套全部通过后开放完整菜单。
4. 接入独立偏好保存，并验收重进、旧档无该项和多人互不影响。

验收覆盖：八套完整外观、透明边缘、九宫缩放及装饰定位；所有按钮状态和文字可读性；圆／矩形命中区域；确认生效、取消不变；连续切换无重复事件；存档恢复；多人独立；战斗与功能页未被意外换肤；原公告聊天、占位与测试工具保持原状。

静态 JSON 检查、编辑器载入和真实对局测试分别记录。未完成真实运行与重进验证前，不标记“动态换肤与存档已完成”。
