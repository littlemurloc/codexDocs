## 1. 实现程度判断

**军略卡牌已形成较完整的市场、购买、持有、Set 合成和战斗释放原型，九个正式 Set 的技能与 Buff 也已有大量实现；但目前还不能认定为按 V1.1 规则完成、可直接进行平衡验收的版本。**

最明显的缺口是：六张独立军略未进入正式卡池，实际效果仍是共同模板；主动和被动混用三格背包；战斗仍沿用技能卡片抽取与冷却补发机制，未落实独立军令点与每波一次的完整约束；多张已入池卡的真实系数、减益属性、补员方式和设计描述不同。

当前应定位为：**流程原型已有骨架、九套卡牌已有战斗逻辑，暂按现有实装运行；设计差异留待讨论，覆盖缺口和运行验证仍待处理。** 不适合给一个总完成百分比，否则会把“对象存在”“脚本写好”“实战正确”混为一谈。

本次没有修改地图、配表、物编或脚本，没有保存/重启编辑器、启动游戏或操作玩家存档。结果属于只读工程审查，不是实机测试结论。

### 购买与融合的实际过程

点击购买先调用“判断是否符合购买军略卡牌条件”，第三参数 true 表示按该行价格检查并扣款，然后才判断背包上限：未满直接处理，满则进入替换。

“3选1军略卡牌处理”定位卡行，改变解锁/获得/显示状态，添加技能及池记录，再按升级机制执行分支。当前正式 36 行全部是“基础”，九个 Set 使用基础分支。

完成 Set 后添加自动结果、折叠组件显示。屏蔽组件函数并未一概删除原有被动实例，主动进阶另外把旧主动池记录上锁，因此已有“保留组件收益”的结构基础。仍要验证合成前后不丢收益、不重复叠加、旧主动不再显示，以及新结果原位替换。

## 5. 已确认差异与风险

### 5.1 市场与持有

**A. 六张独立卡未接入，也没有独立效果实现。** 它们没有进入正式卡牌表和技能描述表。六份 ECA 的 action/event/condition 内容完全相同：等级变化写“伤害减免% = 0.2”，释放结束对目标队长及小兵施加同一受伤减免 Buff 5 秒。没有分别实现鼓舞、护盾、生命、开局攻击、移动闪避和胜利奖励。四张被动物编虽标被动，仍沿用释放结束模板，获得事件未写各自设计效果。应归类为“资源/模板已建，待接入和实装”。

**B. 三格上限统计所有展示卡。** 判断函数仅统计是否格子展示=true，不过滤主动/被动。两张被动已经占两格，再拿一张卡就填满。设计要求被动不占 HUD，并有已拥有主动军令库；当前会直接影响构筑和 Set 完成。

**C. 满包先扣款，再确认替换。** 扣款动作在打开替换界面之前，此段未看到交易挂起或取消退款。退出、取消、重复点击、无可替换对象的结果需要实测，或明确它是不可取消的购买。

**D. 三报价策略与二阶保底未落实。** 已有合法候选和随机去重，未区分三个报价位，也没有维护“后续两次备战分别保证两条新路线组件”的队列/次数。当前初始正式候选是三根系的 9 张组件，设计还应有四张独立卡，共 13 张。

### 5.2 战斗使用与数值

**E. 军令点/每波一次未闭合。** 当前技能池在使用后将已抽取置 true，按剩余 CD 恢复 false，并能补发卡片。取牌上限 3 不能代替普通/精英 2 点、Boss 3 点的独立军令点发放与扣点。目标失效返还、每波一次和波末清空也需在同一套规则下实现。

**F. 一级主动系数直接偏离描述。** 下表列的是等级变化事件 CASE 1 的真实赋值，即进入公式的系数，不是实战伤害读数。多个技能 KV 默认是 0；添加一级技能是否执行初始化也需验证。

| 卡牌 | 当前设计的核心比例 | 一级 ECA 写入 |
| --- | --- | --- |
| 斩将令 | 每段 0.02，共三段 | 0.02，比例一致 |
| 破阵令 | 全体 0.04，队长/精英另加 0.02 | 基础 0.4；启用分支统一用基础+0.02，未按队长/小兵分开 |
| 奇袭令 | 0.05 | 0.4 |
| 奔袭令 | 0.08 | 0.4 |
| 焚营令 | 每秒 0.01 | 每秒系数 0.05 |
| 火攻令 | 每秒 0.015 | 每秒系数 0.1 |
| 连环令 | 直伤 0.04、灼烧 0.01、火媒 0.025 | 0.4 / 0.05 / 0.1 |
| 焚舟令 | 直伤 0.06、灼烧 0.015、火媒 0.04 | 0.4 / 0.05 / 0.1 |
| 伏兵令 | 直伤 0.02 | 0.4 |
| 十面埋伏令 | 直伤 0.04 | 0.4；一级减益也复用 35% 攻速、30% 移速、15% 降攻 |

**G. 减益属性存在错位。** 破阵描述为降防 15%，实际加的是 134256265“降攻” Buff，ECA 修改 attack_phy。图标和描述正确不能证明真实属性正确。

**H. 灼烧不符合当前验收口径。** 共用 Buff 134253664 的伤害类型是 1，对应法术而非真实。映射已用 [Y3 官方常量定义](https://github.com/y3-editor/y3-lualib/blob/main/game/const.lua#L167-L178) 核对：0 物理、1 法术、2 真实。

火油物编系数为 0.06，描述为每秒 0.006；当前添加时长 10 秒，描述是 4 秒。阶段 2 的条件是“前排且没有灼烧”，满足时添加，else 分支则在存在灼烧时移除。**这两个分支互斥，并非新加后同次立即删除。** 但前排若已有灼烧，也会进入移除分支，而非按设计的强弱与持续时间规则处理；这种已有状态的情况应专项验证。

Buff 每秒从关联技能读系数，但未看到统一的强弱比较与保留较长剩余时长逻辑。添加动作已启用关联技能参数，不应误报为全部缺少关联；重叠灼烧仍需专项验证。

**I. 补员实现与设计不同。** 募卒备战时遍历所有存活未满编队长，每人补 1 个；精兵强军每人补最多 2 个。已有星级上限、预设兵种、所属英雄、小队组登记，但没有对应军资扣除、全阶段 1/2 次名额或指定单队目标，会显著放大恢复量。

**J. 百工被简化为增伤。** 每四次普通攻击后直接把当前伤害乘 1.3。忽略目标 30% 防御与固定增伤 30% 不是同一公式，对零防御和高防御目标收益不同。

**K. 一次触发与跨波重置未统一。** 死守按技能实例共享的 30 秒内置 CD 放开，不能代替“每个前排队伍每波首次”。风助按队长/小队从消耗组移除，不等于每条战前路每波一次。各卡已有一些清理和重置动作，仍要验证换波、死亡、补兵和长战斗中的状态。

### 5.3 UI、表现与扩展分支

已有卡名、类型、Set、进度、价格、合成动画、插画、相机和视频播放入口，九个视频引用均能定位到真实文件。未运行游戏，无法判断挂点、比例、预警与伤害是否同步，或演出是否阻断输入。

扩展配置还保留基础temp 36 行、基础2temp 4 行、群雄temp 54 行、蜀国temp 28 行、魏国temp 36 行、吴国temp 31 行、武器锻造temp 17 行。总处理函数保留阵营、声望累计、图纸与材料累计等分支。

但当前初始化明确复制正式军令表，该表全为“基础”机制；这些扩展应标为原型/备用分支，不能一并算当前正式开放功能。计划启用时需要另核对入口、配置、效果和最新设计范围。

## 6. 原设计对齐与验收建议（冲突项暂缓）

以下保留 2026-10-14 按 V1.1 设计提出的建议和用例，供后续讨论对照。依据 2026-10-15 确认，涉及机制和数值冲突的建议暂不作为当前修改任务或强制验收条件；交易稳定性、初始化、跨波及新局清理等运行验证事项仍有效，但应以当前实装口径确定预期。

1. 分开军令库、被动图鉴和三主动 HUD；明确购买提交时机；补军令点、每波一次、无效目标返还和波末清空。
2. 对齐主动一级 KV 初始化、所有系数、火油已有灼烧处理、灼烧类型和覆盖、真实减甲、补员名额/费用、百工以及死守/风助次数。
3. 六张独立卡先完成真实效果，再补正式卡池、描述表和第 3 波开放条件，不能只把当前模板 ID 加入市场。
4. 补三报价位置策略和两次新路线保底，统一临时经济参数，检查合成结果始终不进入报价。
5. 连续两波、再重开一局验证购买、满包、合成、继承收益、使用次数、军令点、死亡/补兵与状态清理；之后再做平衡。

最少的可观察用例：买被动不占主动槽；任意顺序集齐组件能进阶且继承收益；普通波最多支出 2 点、Boss 3 点；目标失效按规则返还；同卡本波不能冷却再用；补员按费且不超上限；火油遇到已有灼烧时按规则处理；灼烧保留高档；二阶两次报价出现不同新路线；重开没有旧卡与旧收益。

主规则对照：项目 docs/design/tactical-command-card-system-v1.md、tactical-command-card-catalog-v1.md；描述配表参考 tactical-command-description-table-authoring-guide-v1.md。若已有更新的人为设计确认，应据此修订“设计差异”分类。
