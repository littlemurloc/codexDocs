## 当前链路与编辑器位置

1. 物编编辑器 `玩家自定义 → 自定义道具 → new → 装备道具` 维护物品类型、固定属性及单件触发效果。首轮物编 ID 为 `134283200`–`134283207`；名称和说明还须核对语言映射及物编登记。不要把旧随机属性装备物编当作新装备。
2. 表格编辑器 `new → 局内装备池配置表` 是报价投放的唯一配置来源，维护是否投放、价格、权重、最低难度/波次、穿戴限制和消耗次数。抽取时按实际有效行读表，三张报价去重；新增表行不能单独视为装备已实装，还需物编、效果、库存/UI及限制链路对应支持。
3. UI 编辑器 `装备三选一` 独立画板含报价页与行囊页。报价页三张卡各有 `equipment_card_1/2/3` 容器；行囊由 `装备库存行`、`装备英雄行` 元件重复展示。层级调整保留原控件 UID、事件和位置，不能以重建控件代替整理父子关系。
4. 触发器编辑器 `UI` 下负责 F 键入口、三张卡点击、行囊选择/确认/卸下；函数库 `new → UI` 下负责读表抽取、刷新报价与清单、购买按物编 ID、库存调整及英雄行展示。购买时先扣局内徽章并记入玩家局内库存，行囊再指定英雄和格位；不得把待穿戴物品实体塞进隐藏军略单位。
5. 穿戴后物品进入对应英雄的**物品栏 1**，HUD 绑定也读物品栏 1；背包栏 0 不是装备生效栏。每英雄只展示/使用两格，数量限制按英雄而非整队判断。旧 PVE/PVP 开局发放的镇魂甲、绷带已撤离新链路，不能只检查其中一个入口。
6. 固定属性由物编承担，穿戴/卸下后实测数值变化。救命药囊的低血量治疗、剩余次数及销毁由其物编内嵌 ECA 承担；公共函数仅负责交易、库存与转移，不把单件效果堆进公共枚举。

## 本轮教训

- 先从本图已能工作的原生 ECA 和物编读真实参数，再建候选。旧系统可用于理解引擎机制，不能整体复制其冗长的随机属性/枚举实现。函数应短而具名，列表用动态元件与读表，避免大量手写同形分支使编辑器页面难以打开。
- 物编、表行、语言映射、UI UID、事件名、函数 FID 与目录索引是不同登记面。存在 JSON 文件不等于编辑器已识别；负数名称键也不等于物编类型 ID 为负。校验要逐层对应，不凭单一显示猜根因。
- 先划清物品栏 `1` 与背包栏 `0`。曾为修 HUD 图标把装备放到栏 `0`，造成面板数值和药囊效果失效；最终只统一装备发放、读取、HUD 绑定和物品 ECA 的栏位引用，保留精简架构，代表试玩恢复。
- 函数库标红先检查 `valid`、声明、变量类型、资源/函数引用及编辑器回写差异。`购买装备_按物编ID` 这次与可用候选的唯一语义差异为 `valid:false`；改回 `true` 后负责人确认可打开。但这不证明所有标红都可通过翻标记修复，更不能把点击闪退直接归因为文件大小或旧物品 ID。
- UI 层级整理先保留旧控件 UID 与事件，把重复卡片归入各自容器，并换算相对坐标。静态树检查只能证明结构、身份和坐标计算；实际加载、布局、点击仍须在编辑器/试玩中确认。
- 日志可能延迟写盘。2026-11-06 的试玩刚结束时运行日志为 0 字节，稍后写入 13 条 Error；不能说“没有错误”。应按日志会话、时间、`trigger_id/element_id` 回溯 ECA，并与历史日志比较。本次 13 条都指向 `关卡初始化内容/universe01` 的布阵传送节点，同一节点 7 月已报错，不应误算为装备画板错误。
- 编辑器打开时不写磁盘地图；先保存关闭、生成工作区候选、备份目标、校验原哈希，再定向替换和回读。离线结构、编辑器可打开、实际购买/穿戴效果是不同层级的证据，集中试玩优于每个小改动反复重启。

## 后续维护入口

首轮扩量前，先集中复测 8 件装备的全部属性与穿戴限制、双格交换/卸下、消耗次数及跨波次保留。新增装备以表和物编为源逐项检查库存、限制、效果及动态 UI；不要重跑旧的一次性迁移/安装脚本。布阵传送节点的既有 Error 单独立项排查，不混入装备验收。

### 集中回归清单

1. 开新局检查三张报价不重复，刷新和购买按表中价格扣徽章，购入后行囊数量增加；只开面板或刷新不改变库存。
2. 分别给不同英雄穿戴、交换和卸下，核对各自两格、HUD 图标、库存回退及属性撤销；错误英雄或限制类型尝试后库存和装备格保持不变。
3. 对照无临时增益的面板值检查七件常驻装备：两把短刃、护甲、玉简、扳指、轻靴和铁环；不可读的减伤不要凭感觉判通过。
4. 药囊至少观察一次实际治疗、剩余次数及最终移除。跨场战斗、同编号波次重打和卸下后再穿戴的剩余次数仍需单独取证；被一击击杀不能算治疗触发。
5. 地图关闭/跳转后本局装备自然消失，不把这一行为写成已实现单位装备存档。日志等待刷盘后按会话和 ECA 节点核对，不能以 0 字节文件断言无错。
