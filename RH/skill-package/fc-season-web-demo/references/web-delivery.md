# 制作、配置与验收

## 环境选择

先确认本地执行、图片生成和浏览器工具是否存在，不假设其他人拥有本聊天相同的插件。附带构建器只需 Node.js 18+，无需 npm 安装或远程服务。

可以用其他前端方案满足用户要求；若要离线单文件，最终不能残留 CDN、远程字体、图片地址、模块导入或 `fetch(theme.json)`。不要为套模板改坏用户已有实现。

## 模板配置

`create-demo.mjs` 建立 `index.html`、`style.css`、`app.js`、`theme.json`。不要直接打开带配置占位符的源 HTML，先运行构建器。默认起步包含大厅、训练、搭档、征程和决战，允许改页数和玩法。

`theme.json` 中主要字段：

- `id`：本地存档命名，改成另一套活动时使用不同 ID。
- `stage`：`starter` 表示通用起步，完成主题制作后使用 `concept`。
- `theme`、`title`、`subtitle`、`heroCopy`、`corePlayer`、`rewardLabel`、`pointLabel`、`tokenLabel`：主题和显示文本。
- `accent`、`gold`：六位十六进制颜色，如 `#7ce1e9`。
- `heroImage`：项目目录内图片的相对路径。空字符串使用 CSS 背景。`visualNote` 记录AI生成、用户素材或CSS背景等实际来源。
- `durationDays`：原创周期假设。模板只展示周期，不模拟真实服务器日历。
- `initialPoints`、`initialTokens`：加速演示起点，规则必须说明。
- `coreThreshold`、`matchesRequired`、`partnerCost`：核心球员门槛、决战场数、搭档兑换消耗。
- `dailyReward`、`matchPoints`、`matchTokens`：本地模拟产出。
- `drills`：三个训练项目。每项包含 `id`、`name`、`description`、`targetStart`、`targetEnd`、`points`。目标区间以0–100计，影响实际射门判定窗口。
- `routes`：三条搭档路线。每项包含 `id`、`name`、`description`、`task`、`partner`，路线会改变决战显示的任务条件及兑换的搭档类型。模板决战仍为简化结算，不能宣称已经实现真实足球比赛。
- `milestones`：五个节点，包含 `at`、`name`。末节点门槛等于核心球员门槛；累计领奖不扣点。

结构检查只保障脚本兼容性。球星主题是否恰当、玩法是否有变化、数值是否合理，需要设计者判断。若主题不适合射门玩法（例如门将），应更换训练交互，不能只改文案。

## 资源与数值

通用模板的可达成条件：初始点数 + 一次每日补给 + 所有训练首次奖励 + 全部决战奖励，应不低于核心门槛；初始徽记 + 决战徽记应足够兑换搭档。构建器会检查这两条关系。它不代表真实赛季的经济验证。

编辑产出或增加消耗后重新核对关键目标的可达成性。核心领奖、路线兑换、阶段领奖要各自防止重复提交。首次训练奖励和重复练习的区别应可见。

## 单文件图片与脚本

大幅 Base64 图片直接塞入 CSS 自定义变量可能触及浏览器解析限制，导致背景消失。构建器将原图字节放在惰性数据脚本中，解码后建立 Blob URL，再给 `--hero-image` 设置短 URL。保持这个方式，或使用你验证过的等价方案。

源文件使用本地图片不等于单文件已嵌入。检查字体、图标、背景和音频的最终请求来源。加入第三方素材时保留必要许可，避免把账号、密钥、绝对本机路径或私人资料放进分享包。

## 交互验收

至少验证一条完整路径：

1. 大厅领取补给、导航到训练。
2. 完成三次射门，领取首次训练奖励，重复练习不重复发奖。
3. 选择另一条路线，确认任务说明和搭档类型改变。
4. 领取普通节点，连续点击不会重复发奖。
5. 完成决战，重复结算不会增加场数或奖励。
6. 满足点数与场数门槛后领取核心球员，兑换搭档时扣除正确徽记。
7. 重置、刷新恢复、存储被禁用或存档异常时行为合理。
8. 取消训练或关闭对话框后，旧计时器不应继续修改进度。

视口至少检查常见桌面窗口和小窗口，手机画布保持比例。检查背景、字体、文字溢出、弹窗、按钮点击范围和底部裁切。

`check-offline.mjs` 检查文件可解析、配置可达成、CSP、静态资源和网络调用等基础条件，不能代替浏览器渲染或实际断网测试。不要把通过脚本写成“全平台兼容”或“已在PowerPoint/浏览器实际检查”等无关结论。

模板将每日补给设计为每轮演示领取一次，训练与决战进度本地保存；不会按真实日期刷新。若需要演示多日或真实开放阶段，应新增明确的演示日控制并在规则中说明。不要用用户电脑日期秘密操纵进度。

## 分享与安装

分享完整 `fc-season-web-demo/` 文件夹的 ZIP，不能只分享入口文件。接收者把目录放入其工具支持的 Skill 目录，或使用该工具的导入功能。Codex 本地常用用户目录为 `~/.codex/skills/`；其他宿主的目录和刷新方式按其说明。

在支持显式调用的环境可以输入：

```text
使用 $fc-season-web-demo，主题为“德罗巴”，制作一版可体验的中文赛季活动网页，默认手机预览，并提供离线 HTML。
```

制作时的图片生成或研究可能需要网络与对应权限；生成后的离线 HTML 不要求用户安装 Node.js、登录 AI 账号或连接网络。
