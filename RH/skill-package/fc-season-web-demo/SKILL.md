# FC赛季活动网页工坊

把一个主题变成可体验的活动概念：先决定各模块怎样组合，再让玩家能实际完成主要操作并看见结果。默认中文、横屏手机画面、本地离线 HTML，除非用户另有要求。

## 设计依据

先读 [六模块框架](references/framework.md)。树状提纲是设计依据，不得用单一玩家流程代替：

1. 主题与入口。
2. 日常参与与产出。
3. 推进机制。
4. 奖励获取。
5. 成长与收藏。
6. 开放节奏。

各期按需选择、替换或组合做法，允许模块缺席、合并或并行。开放节奏贯穿其他模块。章节名称与界面数量不是模块数量，路径、拼图、里程碑也不要求全部采用。

## 从主题到网页

用户只给主题时，先用清楚的假设做一版，不为配色、页面数量等常规选择反复追问。不要自动继承哈兰德案例的六周周期、球员评级和奖励条件。

在项目目录保留 `season-plan.md`，简述主题体验、M1–M6 的选配、资源关系、开放安排及制作范围。它是制作依据，不必把整份说明塞进产品页面。

让主题至少影响两处实际体验，例如训练条件、比赛目标、路线选择、奖励推进或开放次序。只更换球星姓名、背景和颜色不算完成主题设计。明确哪些是官方事实、哪些是原创方案。

随后读 [制作与验证](references/web-delivery.md)，按当前环境的实际工具制作。现有网页需要修改时先检查并复用，不覆盖用户的其他项目。新项目可以使用附带的无依赖起步模板：

```bash
node "<skill-dir>/scripts/create-demo.mjs" --theme "孙兴慜" --out "<project-dir>"
```

`<skill-dir>` 指实际安装目录，不是固定机器路径。脚本只建立通用起步模板；继续编辑 `theme.json`、HTML、CSS、JS，使它符合主题和方案。模板不限制你只能制作五个页面。

### 视觉与交互

- 默认直接展示手机画面，整幅横屏画布等比缩放以适配窗口。不要先展示一大段网页功能说明。
- 活动页面应有一个明确重点，辅助页面围绕训练、路线、进度与奖励展开。控件必须产生状态变化、反馈或有用导航。
- 有图片生成工具时，根据主题生成合适构图的背景，预留标题和操作区域。检查成图后再用。工具名称按接收环境发现，不依赖本聊天的私有工具 ID。
- 没有图片生成工具时，可用用户素材、可合法使用的现有素材，或用模板的 CSS 氛围背景继续完成。交付时简述素材限制，不谎称已经生成图片。
- 字体、图标、组件优先使用本地或原生实现。模板使用系统字体和自带 CSS，不要求组件库或在线 CDN。
- 保持主题视觉、资源名称、玩家目标和奖励条件一致。球员评级、价格、数值与周期若为设计假设，要在规则或方案中注明。

### 交付与验证

把主题配置中的 `stage` 从 `starter` 改为 `concept`，并完成真实主题设计后生成单文件：

```bash
node "<skill-dir>/scripts/build-offline.mjs" --project "<project-dir>" --out "<project-dir>/开始演示.html" --ready
node "<skill-dir>/scripts/check-offline.mjs" "<project-dir>/开始演示.html" --ready
```

重建已有生成文件时可用 `--force`。`--ready` 只检查基础交付条件，不能证明主题设计质量或浏览器体验。

图片放在项目目录内，使用 `theme.json` 的 `heroImage` 相对路径。构建器将图片嵌入后转为本地 Blob URL，避免把大幅 Base64 图片放入 CSS 变量。当前助手脚本支持 PNG/JPEG/WebP/GIF 图片。

用浏览器实际检查主要操作和缩放；若目标环境不允许打开本地文件，尊重工具限制，不绕过访问控制。继续运行可用的静态与状态检查，并如实说明没有做浏览器视觉验收。至少覆盖：正常领奖、重复点击、取消训练、重置、刷新恢复、存储不可用，以及核心奖励可达成性。

默认交付：

- `开始演示.html`：嵌入所需资源，双击本地打开，不需要运行服务器。
- 项目源文件和 `season-plan.md`，需要整体分享时可再打包 ZIP。

不把起步模板、完整赛季内容和游戏客户端实现混为一谈。简化比赛必须在规则里说明。保存进度遇到浏览器限制时仍应能继续演示。

## 适用环境与分享

这份 Skill 不包含账号、密钥、私有服务或远程部署依赖。附带脚本需要 Node.js 18+，只使用内置模块；生成的网页运行不需要 Node.js，也不依赖网络。

接收者需要支持 Agent Skills 的工具，以及本地文件读写/代码执行能力。图片生成和浏览器控制按对方环境提供，缺少时使用上述替代方式并准确交代验证范围。仅聊天且不能写文件的 AI 可以据框架提供设计与代码，但不能声称已创建可下载文件。

分享时发送整个 `fc-season-web-demo/` 目录或其 ZIP，保留参考文档、脚本与模板的相对路径。普通 MD 参考文档可独立阅读，但不能替代完整工作流。
