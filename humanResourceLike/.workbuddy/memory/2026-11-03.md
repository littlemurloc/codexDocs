# 2026-11-03 · v24 移动竖屏（第一版）

## 做了什么

给桌面版加了一套**竖屏布局**，一套代码两套排布，运行时按屏幕宽高比自动切。
桌面那套一个字没改（回归 124/5/244@1280 全绿，244@390 也全绿）。

- 设计基准：横 1280×800 / **竖 390×844**（不是 540）。390 的意义：桌面那套
  44 行高、50 按钮、14 字号换算成物理尺寸正好是手指和眼睛要的，不用另设尺寸表。
- `content_scale_aspect = EXPAND`（不是 KEEP）：手机比例千奇百怪，KEEP 会留黑边，
  而 Playables / itch 都明确要求「不许有黑边」。
- 竖屏排布：抬头 52 → 舞台 244 → 编辑器(expanding) → 指令面板条 127 → 操作台 144。
  舞台搬到编辑器**上面**：竖屏是自上而下读的。
- 指令面板从右栏改成下方一条（列数按屏宽算 2~4 列）。
- 操作台拆三行：运行+单步 / 重置+清空+状态 / 三只读数表。
- 触屏：× 删除键常驻（桌面仍是悬停才浮出）；行卡改成**长按 0.32s 拿起**
  （否则「滚列表」和「挪行」抢同一个手势，列表永远滚不动）。

## 这一版踩到的坑（都记进 MEMORY.md 了）

1. `clampf(v, 560, 350)` 下界大于上界时返回**下界** → 任务牌 350 变 560，整块溢出屏幕。
2. 舞台横向分配（258 / size.x-258 / 右边 158）是按 1252 宽写的，374 宽时木牌带只剩 8px，
   多边形三角化直接报错（不崩，但会把真错误淹掉）。
3. 「整屏最小宽被一个孩子撑开」有三个隐形凶手：指令面板写死 3 列(447)、
   空程序占位行那句 13px 长文案(440)、SpinBox 内部 LineEdit(161)。
4. 滚动条**盖在**内容上画 → 行尾那枚 × 被遮一半。
5. 浮层写死宽（说明书 700 / 设置 392 / 结算 340）在 390 上左右各切一截，不报错。

## 移动版的启动入口（达叔问「启动文件是哪个」）

**没有单独的移动版启动文件** —— 同一份 main.tscn / main.gd，运行时按
`DisplayServer.window_get_size()` 的宽高比判：`< 0.95` 走竖屏（BASE_TALL 390×844），
否则走桌面（BASE_WIDE 1280×800）。所以"启动哪个版本"由窗口形状决定，不由文件决定。

三个入口：
1. `start_game.bat` / `dev_game.bat` —— 桌面窗口，**把窗口拖窄到高>宽**就自己切竖屏。
2. `play_h5.bat` —— 起本地服务 + 开浏览器，绑 `127.0.0.1`，只有本机能开。
3. `play_h5_phone.bat` —— 新增，绑 `0.0.0.0` 并打印局域网地址，**手机真机用这个**。

`tools/serve_web.py` 加了 `--lan` 参数（`lan_ip()` 用 UDP connect 问内核出口地址，
不发包、不依赖外网）。理由：移动版那三个手势只有真手机能验，
绑 127.0.0.1 时手机连不上，等于这一版的验收少一半。

⚠ `build/web/` 里的包是**手动重导**的：`--export-release "Web"` 之后必须再跑
`python tools/patch_web_html.py`，否则加载页退回 Godot 默认样式（index.html 5443 → 6915）。

## 达叔报的三个环境/脚本问题（13:15 前后）

**① Chrome 按 F12 没反应** —— 不是项目问题。查了 `chrome://policy`：这台机器由
`kwstemp.com` 云管（CloudReportingEnabled / EnterpriseRealTimeUrlCheckMode=1），
但**策略表里没有禁 DevTools 的条目**。最可能是笔记本 F 键被 Fn 锁成媒体键
（同一台机器上次 Ctrl+F5 也是这个原因）。做了 `_f12test.html` 供他自己区分
「键没到网页」和「Chrome 不吃这个键」。

**② `play_h5_phone.bat` 报 WinError 10048** —— 我的 bug：
`free_port()` 里设了 `SO_REUSEADDR`，Windows 上这个选项**允许两 socket 绑同端口**，
于是探 8123 说空闲、真绑时冲突。改成不探、直接 try bind（`make_server`）。

**③ 连点五次 = 五个服务进程** —— 加了 `find_running()`：探到已有一个在跑（端口在听
**且**返回内容含 `SHEEP COUNTER`）就打印地址退出，不再另起；要强制另起加 `--force`。

新增文件：`play_phone_window.bat` + `tools/phone_preview.py`（iPhone 13 / SE / 安卓三档，
`--device N` 切换）。不用 F12，直接开一个 390×844 带触摸的 Playwright 窗口。
`phone_preview.py` 会自动在 8123–8130 里找活着的服务，并能在三个 Python 之间
挑出装了 playwright 的那个重跑自己（**Windows 上不能用 `os.execv`**，它会把子进程输出
和退出码吞掉，表现是黑窗一闪；要用 `subprocess.call`）。

**④ 双击启动文件「没反应」** —— 我自己挖的坑：加 `find_running()` 短路分支时只复制了
「打印地址」，**漏掉了原来那支的副作用「打开浏览器」**，于是 double-click → 打印 → return
→ 窗口关掉，什么也没发生。
教训：**给一段流程加「提前退出」的分支时，要清点原分支的副作用清单**（打开/写文件/设状态），
而不只是复制它的输出文字。只复制 print 等于把功能删了还留着台词。
同时 `open_page()` 改成 os.startfile → cmd start → webbrowser 三层，
因为这台机器上 `webbrowser.open()` **返回 True 却什么也没打开**——它只代表请求发出去了。
验证方法：查 `%LOCALAPPDATA%\Google\Chrome\User Data\Profile *\History` 的 `urls` 表，
比看窗口标题可靠（标题只反映活动标签，而且他日常用的是 Profile 1 不是 Default）。
两个 play_h5*.bat 末尾都加了 `pause` 兜底：浏览器没开也能看见地址手动复制。




## 竖屏编辑器太小 → 专注编写模式

达叔反馈：竖屏程序区太小，看不到函数布局全景，影响逻辑判断。

量出来的账：844 高被抬头 52 + 舞台 244 + 指令面板 131 + 操作台 144 分完，
编辑器只剩 227，扣掉标题行+表头 66 → 行区 157 → **一屏 3.4 行**（最长关卡 36 行）。

做法：编辑器标题行加「专注」按钮，点了把舞台整块收起来，8.1 行（2.5 倍）。
- 只改 visible，不重建 —— 重建会丢滚动位置和选中行，而按下这个键时玩家正在看某一行
- 舞台一收，目标牌也跟着没了，标题行下补一行「目标：…」复述（读 `stage.goal_text`，不另存）
- 偏好进 `settings.cfg [view] focus`：一次设置永久生效；**只在竖屏生效**
- 专注态把跳转线车道从 24 放宽到 64（那时玩家要的正是看清结构）

顺手修掉两个真 bug：
1. **test_ui 每跑一次就把 40 关参考答案写回玩家存档** —— 因为它调 `_fill_programs("all")`，
   而这个函数非 demo 模式会 `_save_progress()`。加 `persist` 形参，测试传 false。
   这类污染不报错，只表现为「答案怎么又回来了」。
2. 空程序提示「把**右边**的指令牌」在竖屏方向说反了（牌子在下面），按 `_tall` 分支。

新坑：**改了 app.otf 必须 `--import`**。`.godot/imported/*.fontdata` 不刷新，
测试读旧字形报「缺字」而界面明明是好的 —— 我差点去改字体子集脚本。

回归：124 / 5 / 244×2（1280 与 390）/ 文案 162·116 全绿。Web 包重导 + 打 zip（10.2MB）。
