## UI 第二十一版：任务说明从抬头搬到牧场（一块牌子）

达叔一句：

> 这块的任务提示的位置太不明显了，用户估计不能第一时间聚焦到。改成在下面这个区域显示，
> 且把提示的说明字体做的更显眼些

（箭头：从抬头中间那块「目标 + 数据流」指向舞台的空白天空。）

### 判断：这不是字号问题，是位置问题

v18 把任务说明塞进抬头时我自己还挺满意 —— 密度高、没浪费。可抬头的屏占比只有 6%，
而且它在**视线中心之外**：玩家运行、看羊、看结果，眼睛全在舞台上。
最该第一时间读到的一句话，被压成 13px 放在最不看的角落，加粗也没用。

现在的排法：抬头只留「身份 / 关卡 / 星 / 提示按钮 / 翻页」，高度 56 → 48。

### 做法：画一个东西，不是挪一个 Label

`stage.gd::_draw_task_sign()`：

- 米色木牌（`TAG_FACE` + 2px `C_WOOD_D` + 9 圆角 + 3px 硬投影），两角各一枚钉子
- 目标 **17px 加粗**（`FontVariation.variation_embolden = 0.55`，项目无粗体字重）
- 第二行数据流：数字上色、标签压灰，整行居中
- **牌子宽度按内容量**：`clampf(最长行宽×1.09 + 40, 560, 舞台宽×0.775)`。
  写死宽度时短目标会变成「一大片奶油色中间嵌一行字」，空的地方比字还显眼
- 三级提示不再用 Label，改成牌子下沿挂出来的一张**纸条**（浅黄底 + 「提示」小黄签），
  `_draw` 画、**完全不进布局** —— 玩家自己叫出来的东西不该把任何东西顶走

### 四个坑

1. **`FontVariation` 的 embolden 不进 advance。** 用加粗字体 `get_string_size()` 量 660，
   `draw_string()` 画出来 682（差 8%），牌子按它算字就贴着边。
   → 折行和量宽一律用**基础字体**，宽度乘 `SIGN_BOLD_FUDGE = 1.09`，画的时候才用加粗版。
2. **牌高必须由折行结果唯一决定。** `_wrap_chars()` 抽成静态纯函数（按字符折、
   超 2 行补省略号），单测断言「短句 1 行 / 超长 2 行且末行带…」。
3. **搬走之后高度分配要重算。** 抬头 56→48，但牌子占掉舞台的 sky，
   `_draw_pen` 的「羊圈 INBOX」（`fy-90`）会被压住 → `body : stage` 从 1.8:1 改 **1.45:1**：
   舞台 228→264（28.5%→33%），编辑区 410→382（7.7 行→7.1 行）。
   这不是「给舞台加高」，是给牌子腾位置。
4. **太阳、云、栅栏挂牌全跟着让。** 牌子占 `x 12..0.775w, y 4..66`，
   原来 0.70w 的太阳正好在里头 → 挪到 0.80w / 0.20fy；两朵云压到牌子下、山脊上那道缝。

### 一个反复犯的读图错误

这次又是先看 1080 缩放图、以为「文字贴着牌子左边缘」，裁到真实分辨率放大才发现左右留白
是均匀的。**判断「画出来的东西」必须按真实分辨率裁剪，不能看缩放预览** —— 和 v19 那条
「CLI 参数要跟截图一字不差」是同一类错误：看到的和以为看到的不是一回事。

## v22 · 多语言（英文 + 繁体中文）

达叔三条要求：① 首次启动按 IP 归属定语言（非中文区英文，中文区繁体）；② 游戏内可切；
③ 交付时列出「哪些区域算中文区」。

### 地基：原文即 key

源码里的简中原文就是整张 i18n 表的键。漏翻**不崩**，只退回中文 —— 换来的是
「多语言」从「一份要同步维护的副本」变成「一张能自动体检的差值表」。
全量 300 条（144 界面 + 116 关卡 + 40 关名走 `name` 不翻）。

### 三条工程决定

1. **繁体不另写一份**：简→繁四趟（`hant_pre` 词 → `hant_char` 字 → `hant_post` 台湾用词 →
   `hant_twchar` 台湾字形），字典从 OpenCC 仓库取、`tools/gen_hant.py` 离线烘焙进
   `data/i18n.json`（126KB），运行时不联网。
   体检方式：同一批 300 条，`runtime()`（游戏四趟）vs `reference()`（完整 s2twp）逐条比 →
   **需要补词 20 个 · 仍不一致 0 条**。
   OpenCC 的 TWPhrases 只收 IT 词，不管游戏里会撞的七个（程序→程式、循环→迴圈、数据→資料、
   鼠标→滑鼠、设置→設定、运行→執行、重置→重設）→ 写进 `MANUAL`，且**两边流水线都先过一遍**，
   否则每次烘焙都把这七条当「差异」报。
2. **换语言 = 整屏重建**（`_relocalize()`，几十毫秒）。逐个控件回填要维护「控件↔文案」清单，
   漏一项永远错一项且不报错；重建天然全覆盖，代价只是搬状态（程序/当前关/选中行/提示级别）。
3. **区域表只有四个**：`ZH_REGIONS = ["CN","TW","HK","MO"]`，其余全英文 —— **含新加坡、马来西亚**
   （华人多但系统默认工作语言是英语）。判定链：`--lang=` → `--country=` → 存档手选 → 系统语言
   （`zh*`→繁中）→ IP 异步。**手选过就不再探 IP**；`--shot` 时整条探测跳过（截图必须确定）。

### 漏翻是静默失败：三道网

1. 两个汇聚点：`_label()`/`_button()` 统一 `I18n.t()`；VM 三个出口 + 21 处 `_fail()` 各包一层
2. `tools/scan_strings.py --check`：枚举源码中文串逐条查表（144/144 · 116/116）
3. 测试把语言切英文后**递归扫控件树**，出现汉字就失败（四个语言名放行）

Scanner 曾经骗过一版：正则 `[^"\\]*` 把带 `\n` 的长句整条跳过 → 「覆盖率 100%」是假的。
改成允许反斜杠 + `unescape()` 才真。**这类「体检工具本身出错」比被检查的东西出错更危险。**

### 英文排版四处硬伤

按词折行（否则 `accumulat / or.`）／卡面缩成 `Jump if <0 (compare)`／
挂牌缩成 `%d of %d`／纸条能横着长（见下）。

### 提示纸条：写死宽度 vs 会变的舞台高度（又一个同类坑）

第 6 关英文提示要 5 行、4 行会截掉「所以你得自己扔」。加到 5 行后：纸条高度由折行决定、
可用空间由**窗口高度**决定（`fy = size.y - 78`），两者没关系 —— 1280×800 上只剩 5px 缝。

修法不是往上挤（上面就是任务牌），而是**宽度按阶梯往上试**：
`[0.56w/700, 0.72w/880, limit_w]`，取第一个「竖着放得下」的。**「更宽」永远比「更高」便宜。**
几何抽成静态纯函数 `Stage.hint_layout()` + `note_top()`，测试因此能在**没有渲染帧**时量：
每条提示 × 三门语言 × 两种舞台高度，最小间距 ≥ 8px（实测 1280×800 = 17px，舞台 250 = 9px）。

| 文案 | 299 条硬编码 | 299 条 = 一张 126KB 表 |
| 漏翻检测 | 无 | 静态扫描 + 运行时扫控件树 |
| 回归 | 124 / 5 / 151 | **124 / 5 / 184** |

## v23 · 补完：声音、渐进加速、四条「不新增元素」的修法

达叔问「这游戏还缺哪些元素」，我报了八条分三档；他逐条回了：1 同意 / 2 改需求 / 3 同意 / 4 同意 /
5 同意 / 6 **否**（导入导出：「实际意义是为啥？」——我答不上来，砍掉）/ 7 同意 / 8 同意。

第 2 条被改成：**不要手动倍率，要「跑得越顺它自己越快」** + 每小步音效/画面叠加的 COMBO 感。
这一改定了整章方向：加速从「一个玩家要去按的东西」变成「一个玩家挣来的东西」。

### 声音：零素材，六种音现场合成（`scripts/sfx.gd`，163 行）

`AudioStreamWAV` 现场合成，和「舞台零位图」同一个取舍。真正逼出这个方案的是**音高必须跟 COMBO 走**
——素材包里翻不出「同一个音升半音」。

| 音 | 触发 | 参数 |
|---|---|---|
| `click` | 每一步 | 680Hz/36ms，很轻，随 combo 升调（**封顶 12 半音**） |
| `wood` | 动木牌 | 300 + 900Hz（1:3 泛音）＝敲木头的空腔感 |
| `out` | 推羊过栅栏 | 523Hz，**音高跟「今天第几只」**（0~12）＝数满一关是一段上行音阶 |
| `err` | 绊倒 | 370→196 扫频（`u*u`），一次连续下坠 |
| `win` | 过关 | 四音上行琶音 |
| `ding` | 刷了 SPEED | 1568Hz，叠在 win 后 0.34s |

三条硬约束：
1. **起音给 4ms 不给 0** —— 从满幅开始会「啪」一声，那是爆音。
2. **变调走 `pitch_scale = pow(2, semi/12)`，不重新合成** —— 高速每 75ms 一个音，现场合成会卡帧
   （六个流合成一次共 93ms，之后只改一个浮点）。
3. **8 路 player 池** —— 一个 player 播新流会掐掉上一条，池子不够就「漏拍」，
   那正好是 COMBO 该有的反效果。

### 渐进加速：`tick = 0.075 + (0.26-0.075) * pow(0.86, combo)`

- 指数收缩不是线性：**起速感全在头三下**（0.26→0.224→0.192），第 20 步已到 0.077。
- `combo` 只由**自动运行**累积；**手动单步不涨**（否则点 20 次再按运行就直接全速＝可预支的加速）。
  单步照样给声音，只是不给涨幅。出错/重置/切关归零。
- `_process` 里必须 `while + guard 8`，不能只 `if` 一次：75ms 间隔时一帧可能跑好几步，
  只 `if` 会让实际速度卡在「一帧一步」。
- `stage.pace = tick / STEP_SLOW`，舞台所有动画统一除这个值 —— 否则高速时羊跳会抽帧。

### 节拍可视化：试了两个方案全删了（重要教训）

1. **草地上撒光点/四角星** → 读成噪点或小白花。问题不在形状，在**位置**：草地是画面里最不该出现
   界面元素的地方。
2. **底部 12 格凹槽灯** → 位置偏（舞台最下沿）、对比弱、且和右下「周期÷件」仪表**语义重复**。

最后答案是**不新增元素**：程序列亮几行（`_trail`，最多 3 行，去重）。起步亮 1 行、全速 3 行一起亮＝
一道往下扫的亮痕。去重不只是省性能：死循环 `JUMP a → a` 会稳定亮一行，**看得出来它在原地打转**。

### 色盲第二通道：征用行号（不新增一栏）

红绿型色盲看「执行绿 / 出错红」都是黄褐，而这是运行时唯一要紧的信息。加一列图标要把表头、
缩进、跳转线车道全挪 → 不值。该问的是「运行时哪一列最不重要」——**行号**。
`01` 在运行时换成 `▶`（执行中）/ `✕`（出错），两者宽度相同，列宽不动。

### 提示回看：把「记录」和「显示」拆开

`hint_stage`（记录看第几级，决定星数，只增不减）与 `hint_view`（现在贴哪张）分离。
回看只改后者，星数判据只认前者。顺手修了空程序占位行「拖到**右下角**的指令」→ 指令面板在**右上**。

### 全三星：判据现算

`_all_stars()` 遍历 40 关的 `_stars_of_idx`，不用累加计数器（删档/改判据/存档写一半都会留假状态）。
`allstar_ack` 落盘只认一次，`demo_mode` 下不落盘也不弹。
**首版直接复用单关两行，打出 `速度 0.00 / 30.75 ✕`** —— 因为 target_speed 是第 40 关的。
「在一张『你全做完了』的卡上出现红叉」是最伤人的错。改成 `星数 120/120` + `关卡 40/40`，徽章留空。

### 新手引导：判据不需要存档字段

`li == 0 and program.is_empty() and saved_programs.is_empty()`。一关没写过程序 = 新手，
天然带着「删光程序时不会再烦他」。做法是第一块指令牌 0.62s 呼吸（`modulate` 提亮）＋一句提示。
**只点一块** —— 整片面板都点亮等于没点亮。

**只靠动效表达 = 验收时指不出来。** 第一版只有 modulate 呼吸，静止截图里两块牌长得一样，
我自己都说不出「在呼吸的是哪一块」。补一圈常驻琥珀描边（`_mark_guide()`：border 换 AMBER、1→2px，
非新手时收回），静态一眼可辨。**改描边不改形状**——守住「状态只换颜色」。测试钉住两头。

### 设置：和语言共用一个 cfg，分 section

`[i18n]` / `[audio]`。**写前必须 `load()` 一次**，只改自己那节再存 —— 直接 `save()` 会冲掉另一节。
滑条要长成滑块不能长成进度条：轨道用凹槽（`Kit.well("062c4b")`）、已走过一段金色填充。
浮层宽 392 是**按繁中量**的：繁中比简中长约 8%，按简中量的 300 会让繁体那句只剩「樂。」两字掉到第二行。

|---|---|---|
| 声音 | 0 | 六种音全合成，零音频文件（93ms 生成完） |

| 提示 | 看过就禁用 | 可回看，星数只认 `hint_stage` |
| 全三星 | 无 | 专属结算卡 |

| 回归 | 124/5/184 | **124/5/227** |
| 布局余量 | 574/776 | 574/776（浮层进 CanvasLayer，不进根 VBox） |

新增 CLI `--set` / `--allstar`。截图 `_shots/v23/`：`trail_sixth.png`、`settings.png`、`guide.png`。
`scan_strings` 156/156 · 116/116；`gen_hant` 312 条 · 0 不一致。

## v23.1 · 达叔实测报的三个问题

### 1. 切语言后音效全静音（真 BUG）

根因：`_relocalize()` 的 `for c in get_children(): remove_child(c); c.queue_free()` 把挂在 main 上的
**sfx 节点一起拆了**。`sfx` 变量还指着 freed 对象，之后 `play()` 全打在死节点上 —— 不报错、不出声。

修法：拆除循环跳过 sfx。**教训：整屏重建是对的，但「拆除范围」要有豁免名单** ——
界面要重建，音效池不要。测试钉住：切语言后 sfx 存活、8 路 player 全有效、音量不重置。

### 2. 有些关卡羊圈是空的（数据对、表达错）

排查：第 21/25/26/34/38/39 关 inbox 本来就只有 1 个数（题目是「给我 N 输出一串」）——一只羊是对的；
**第 3 关 inbox 是空的**（只从木牌 COPYFROM，根本没有羊）。

真正的错：空羊圈那行「空了」12px 无描边灰蓝色，压在深绿草地上几乎看不见 → 玩家以为坏了。

修法：两种空分开说 + 按标题同款深色描边：开局就空 →「这关不用数羊」（`pen_starts_empty` 在
configure 时记一次）；数完 →「羊都数完啦」。

顺手立规矩：**开发者日志（print）一律英文** —— i18n 只收玩家看得到的文案，
调试输出混进去会让 scan_strings 报假漏翻（157/158 就是这么来的）。

### 3. `--fill`：把参考解铺进存档验关

`--fill=20-40`（也支持 `21` / `all`）→ parse 成程序写进 saved_programs（「我的解」位置）→
打开就是现成答案。三个边界：铺完 `get_tree().quit()`（批处理动作不干等）；会覆盖玩家程序
（所以只在命令行里）；`--shot`/demo 下只填内存不写盘。

**已给达叔的真实存档铺了 20–40 关**（1–19 他自己写的没动）。核对过 20–40 全齐。

回归 **124 / 5 / 238**；scan_strings 157/157 · 116/116；gen_hant 313 条 0 不一致。

## v23.2 · 清预置答案 + 打包 H5

### 存档清理

`--fill` 铺的 20–40 关参考解从真实存档里删掉（1–19 是达叔自己写的，没动；40 关通关成绩保留）。
清前备份了一份 `progress.json.before_clear`，达叔确认没问题后可删。

### H5 导出（Godot 4.7.2 → Web）

预设 `variant/thread_support=false`：单线程构建不需要 COOP/COEP 响应头，任何静态托管都能放。

**两个真踩的坑：**

1. **Web 版没有系统字体 → 中文全是豆腐块。** `_apply_font()` 原来从 `C:/Windows/Fonts` 加载微软雅黑，
   浏览器沙箱里此路必死，回退的内置字体没有汉字。修法：
   - `tools/make_font_subset.py` 从思源黑体（SIL OFL，jsdelivr 拉 `noto-cjk/Sans/SubsetOTF/SC`）
     裁出子集：字符源 = `i18n.json` 全文（含简→繁四趟字典）+ `levels.json` + ASCII/符号 →
     8703 字 / 2.2MB（原始 8.3MB）。**改文案后要重跑**，不然新字在网页上是方框。
   - 运行时必须 `load("res://...")` 而不是 `FontFile.load_dynamic_font()`——
     导出包里只有**导入产物**，res:// 原始文件根本不在 pck 里，直读必失败。
   - OFL 分发要带许可：`assets/fonts/LICENSE-NotoSansSC.txt`。
2. **`boot_splash` 不是独立 section**，是 `[application]` 下的键（`boot_splash/image`）。
   写成 `[boot_splash]` 段静默失效，splash 还是 Godot 默认 logo。

**patch 脚本吞标签**：`patch_web_html.py` 替换 `<style>` 时把 `</style>` 吞了没补，
浏览器把整个 body 当 CSS 文本，页面全空（Console 无报错，纯 HTML 解析事故）。
验 HTML 结构用 `html.parser` 数未闭合标签，比截图快。加载页品牌小字要放遮罩**里面**——

## v23.2 补 · H5 本地试玩的坑

达叔在 **`C:/windows/system32` 目录**里跑 `python -m http.server 8080`，报 `WinError 10013`。
两个问题叠在一起：

1. **目录错了**：在 system32 起服务，网站根目录就是 system32，就算起来也访问不到游戏。
2. **端口冲突**：8080 在本机已被别的软件占着。10013 看着像权限，其实是端口不可用
   （`netsh interface ipv4 show excludedportrange` 里 8080 不在保留段，所以是占用而非保留）。

## v23.3 · H5 版乱码（字体子集漏字，两层原因）

达叔在网页版看到零星方框：抬头 `01 / 40 ▾` 的下拉三角、结算卡的星、设置按钮。

**根因有两层，第一版脚本一层都没覆盖：**

1. **字符源取错了。** 第一版只收 `data/i18n.json` 全文 + `levels.json`，
   于是 ① 源码里的符号（`▾ ⚙ ✔ ✕`）全漏，② 简繁字典那 3881 个罕用字反倒被裁进字体
   （1568 个"缺字"里大半是它们）。现在按「会被画出来的字符串」取：i18n 的原文键 +
   每个键跑四趟简→繁的结果 + 英文值 + 关卡数据 + **所有 .gd 源码的非 ASCII**（含注释，宁可多收）。
   字符数 8703 → 1478，字体 2.2MB → **318KB**，pck 也从 2.4MB 降到 677KB。

2. **思源黑体 SC 本身没有 `▾ ▴ ⚙ ✔ ✕ ✗`。** 这不是截子集能解决的。查了三个字体才凑齐：
   `NotoSansSymbols2` 有 ▾▴✔✕✗ 但**没有 ⚙**；`NotoSansSymbols`（一代）有 ⚙ 但那些都没有。
   所以是两个备用字体挂 fallback 链：`app.otf → sym2.otf → sym1.otf`。
   两个各只有 3KB / 6KB（就裁那 5+1 个字）。
   → **教训：换字体先查覆盖表，别信「思源什么都有」。**

### 让缺字无处可藏（这次才是真修）

- `make_font_subset.py` 最后一步是**校验不是打印**：三个字体的 cmap 合起来必须覆盖全部候选字符，
  缺一个就列出并 `exit 1`。
- `tests/test_ui.gd` 加了断言（241 项）：遍历 i18n 全部原文键 + 繁体转换结果 + 英文值 + levels，
  每个非 ASCII 字符都要 `Font.has_char()` —— 实测**会沿 fallbacks 链查**。
  这样「改了文案忘了重跑子集脚本」会在回归里立刻炸，而不是等达叔看见方框。

### 缓存

`serve_web.py` 补 `Cache-Control: no-store`。python http.server 默认只发 Last-Modified，
浏览器启发式缓存会让「改了 pck 还是老样子」，看起来像没修好。

### 顺带

达叔截图里任务条两端那个"方框"是 3px 图钉 `draw_circle`，不是字（放大 2 倍才看出来）——
**截图放大倍率不对会把圆看成方**，这类误判先量尺寸再下结论。

## v23.4 · 结算卡满屏方框（真相：CanvasLayer 断了 theme 继承链）

达叔截图：主界面 `/ 40 ▼` 正常、三颗星正常，**唯独过关结算卡里全是方框**。
我一开始判断成「他看的旧缓存」，判断错了 —— 那正是这个 bug 的典型表现。

### 根因

`win_layer` / `set_layer` 是 **CanvasLayer**，里面的根 `Control` 没有 `theme`。
**CanvasLayer 不是 Control，theme 的继承链到那儿就断了**，卡里所有控件退回
ThemeDB.fallback_font —— 那个字体只有拉丁字符，中文和 ★ ✓ → 全是方框。

而主界面在根 VBox 里，正常继承 main 的 theme，所以看起来「一半好一半坏」，
特别容易被当成缓存问题。

修法：给两个 CanvasLayer 的根 Control 显式 `root.theme = theme`。
（`doc_layer` / `map_pop` 是 Control 直挂 main，本来就好，不用动。）

### 顺带否掉了 fallback 方案

上一版试过 `FontFile.fallbacks = [sym2, sym1]` 补思源黑体没有的符号。探针证明**不 work**：
```
f.fallbacks.size() = 2                        ← 设置成功
Label 拿到的字体: FontFile  has ▾? false        ← 换了一个实例
Label 字体 fallbacks=0                         ← 丢了
```
`Theme.default_font` 取到的不是同一个实例，fallbacks 不透传；
只有 `add_theme_font_override` 能带过去，逐控件设置不现实。

所以改成**换字符**：空心小三角→实心、✔→✓、✕→×、⚙→⋯（都是主字体自带的）。
删掉 sym1/sym2 两个字体和 fallback 代码。视觉差别极小。

### 三道防线（这次才是真的收口）

1. `make_font_subset.py`：缺字 `exit 1`。跑的时候真报出了 6 个 —— 来源是**注释里还写着
   那些废弃符号**（`.gd` 全文进字符源）。改注释成文字描述后才通过。
2. `test_ui.gd`：i18n 全表字符 `has_char` 断言（1476 字全覆盖）。
3. `test_ui.gd`：**两个 CanvasLayer 浮层的根节点必须有 theme**。
   这条专门盯「主界面正常、浮层方框」这种最会骗人的故障。

回归 **124 / 5 / 244**。网页版实测：主界面、结算卡（★★★ / ✓ / ★ / →）、设置浮层全部零方框。
