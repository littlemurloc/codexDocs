## UI 美化第七版：「深夜牧场 · 木牌与牛皮纸」（达叔：太软件化，没游戏美感）

**诊断出软件感五源**（对《UI 设计军规》）：① 满屏同级深棕 + 1px 边（违规则 19）② 全屏无亮面、亮度挤在 10–25%（违规则 03）③ 主次操作同长相（违规则 14/15）④ 原生控件长相（违规则 06）⑤ 无位移/无抬升反馈（违规则 25）。

**基调卡（新增 `scripts/ui_kit.gd`）**：木牌=容器（暖褐底+2px 木边+8px 下投影）／纸条=内容（浅牛皮纸 `#c4b394` + 左 3px 色带 + 薄影）／墨=纸上字（`INK_1/2/3` 三档深棕，不用纯黑）／暖黄=可拿起或选中、绿=执行中、赭红=出错／唯一动效=执行行呼吸 + 舞台萤火虫。

**本轮核心改动：明暗反转。** 程序行从深棕 `#3b2f22` 改为浅牛皮纸 `#c4b394`，理由是把全场唯一亮面给玩家「真正动手」的地方，焦点自然成立（正文对比度 4.8:1 → 6.4:1）。

**舞台补光**（`stage.gd`）：月亮光晕从单个半透明圆改 9 圈递减同心圆（单个像贴光盘）；新增 `_draw_light_pool()` —— 月光冷斑固定 + 牧羊人脚下暖光跟人走；草地分 7 段压暗造纵深 + 踩出来的土路；羊圈羊 1.55→1.72 倍。

## UI 第十版：换向「明亮卡通牧场」（达叔给了 Township 风格参考图，**这一条最重要**）

**达叔定调**：参考图是 Township / Coin Master 一类明亮卡通休闲游戏。这不是配色微调，是把问题从"怎么不像软件"换成"怎么像一款手机休闲游戏"，**推翻了第七版的深夜基调**。

**新基调卡（五条可复述规则）**：① 粗描边 2–3px 深色实边（卡通感第一来源，不是圆角）② 大圆角 9–10px ③ 三层明度阶梯 `#05223f` 页底 → `#0e5a96` 面板 → `#1470b4` 卡片（撑层级不靠描线）④ 硬投影 offset 4 / blur 2（blur>4 立刻变网页卡片）⑤ 白字+深蓝描边（任何底都读得清）。

**关键做法**：`ui_kit.gd` **常量名一个没改、只换值**，`main.gd` 近百处引用一次性生效 —— 这是第七版抽那一层的回报。新增 `Kit.card()`（整圈描边）与旧 `strip()`（只左色带）分工：**新版状态靠整圈描边，不靠左色带**。

**程序行四态改成"只换描边颜色"**：普通=深边 / 选中=白边 / 执行中=绿边（呼吸）/ 出错=红边。形状不变只变色，整列扫下来才有节奏。关卡列表选中同步改成整圈白框（一个界面只能有一种"被选中"表示法）。

**`_label()` 自动加描边**：亮度 >0.62 的字自动配深蓝描边 3–4px，省掉上百处调用点。

**舞台改白天**：星空→太阳（9 圈递减光晕保留）、云→白边厚云、月光斑→日光斑+接地影、草地调亮、新增树/灌木/小花/蝴蝶（`_draw_deco()`，全用圆和矩形）。

**真 bug（一直在调却调不动的那条）**：SpinBox 的主题项名写错了 —— 引擎里没有 `up_button`/`up_icon`，正确是 `up_background`/`down_background` + `up`/`down`。**名字写错不报错、只静默失效**，所以那对箭头从第一版起就是引擎自带灰三角。用 `ThemeDB.get_default_theme().get_stylebox_list("SpinBox")` 一查即明。修好后换自绘刻痕三角（4×4 超采样算覆盖率当 alpha，不引外部图）。**教训：主题项这类字符串常量写错是静默失败，改不动先写探针列真名，别猜。**

### 达叔拍板「就用免费的」—— 下载受阻 + 一处必须纠正的说法

**下载抓不下来**：itch 的免费包也要走 purchase 流程（`POST /crisp-kit-free/purchase`），价格 0 仍要求 `payment_method` 合法；`none/free/paypal/stripe/空` 全返 `{"errors":["Please select a valid payment method"]}`。`data.json` 只给 `title/price/id/tags/cover_image`，**不含 uploads**，拿不到 upload_id 也就拼不出 `/file/<id>`。结论：**必须在浏览器里点一次 Download**，脚本绕不过去。

**必须纠正的授权口径**：`data.json` 的官方 tags 含 `ai-generated`、`ai-generated-code`、`ai-generated-graphics`。上一轮我说「未使用 AI 图像生成器」是按作者正文表述（Claude 写代码程序化绘制）转述的，但 itch 的官方分类把图形标成了 AI generated。**对外/商用要按后者说**（Steam 等平台的 AI 披露口径）。项目自用原型无所谓。

**顺手确认**：作者另有 `crisp-cozy-free`（cozy 向，可能比 crisp-kit 更贴牧场），以及站内指南 `anipixels.github.io/guides/godot-4-cozy-ui-theme/`，文中明确引用 `Crisp Kit Free` 采样包的 `sheets.json (1x)` 作为 9-slice 数据源。

## UI 第十一版：接入 Crisp Kit 贴图皮肤（达叔：就用免费那套）

**素材落地位置**：`_assets_src/`（原始解包，含 zip）+ `hrm_godot/assets/ui/crisp/`（重切后的图 + `crisp_slices.json`）。切图脚本 `tools/import_crisp_skin.py`，盘点脚本 `tools/inspect_skin_pack.py`。

**关键动作：先重切，别直接导入。** 原包 `input_normal` 是 160×48、9-slice 上下边距合计 32px，而程序行只有 30px 高，原样用会顶开整行。脚本按目标高度等比缩图，**并把 slice 边距同比例缩放** —— 只缩图不缩边距，边距会大于图，九宫格退化成整张拉伸，圆角糊掉。

**接入层 `scripts/skin_crisp.gd`**：`ok()` 一票决定走贴图还是回退手搓，**没素材时游戏照跑**，不报错也不少一块。

**两个必须记住的坑**：
1. **SpinBox 自身没有 `normal` 主题项**，可见的是里面那个 `LineEdit`。给 SpinBox 设 normal 不报错、也不生效，必须先 `get_line_edit()`。
2. **SpinBox 步进键宽度跟着图标宽度走，不跟样式块 content_margin 走**。改边距无效，只能把三角画进更宽的透明图里（`_tri()` 就是这么干的）。

**步进键没用素材**：`button_flat_normal` 自带薄荷绿描边，染蓝后绿边仍在，挤在白输入框右边很刺眼。改为自绘白片 + 浅灰描边，与贴图输入框描边同灰度。

**白按钮＝整套配色**：`button_flat_normal` 是纯白，`白 × 色 = 色`，所以一块白按钮能染出任意配色 —— 次操作染蓝，主操作直接用原色绿 `button_medium_*`。`_button()` 因此加了 `kind` 参数（primary / secondary / 空=手搓）。

**已接**：数字框、步进键、下拉框（含深墨 V 形箭头）、滚动条、主次按钮。**回归全绿**：64 / 5 / 92，布局余量仍 744/776（贴图边距没吃预算）。

**未做（下一轮最大的杠杆）**：面板仍是纯色平涂。参考图那挂是**白卡压深蓝底**，但那要把全界面文字从白翻深色，是伤筋动骨的手术，等达叔确认方向再动。

## UI 第十三版：HUD 去软件化（2026-10-30 下午）

达叔："控件皮肤有游戏味了，但 HUD 布局还是像软件。"

诊断：不是材质问题，是**布局语法**问题。五处在发"我是软件"的信号：
标题栏式顶栏、IDE 状态栏式底栏、文件树式左栏、文档小节式标题、舞台只占 23%。

### 总纲：游戏给每个信息一个「东西」

软件用**位置**组织信息（第 3 列第 2 行），游戏用**物体**组织（徽章/仪表/星）。
所以每处改动都是同一个动作：把一行文字换成有体积的东西。

- 关号 → 木牌（17 大号 + /20 小号）
- 新增三星（★ 亮=拿到，暗=没拿；同一字形只换色，缺一颗时形状不变，能数出来）
- 上一关/下一关 → 圆形 ‹ ›（**圆=方向，圆角块=命令**，全屏只允许翻页用圆）
- SIZE/SPEED → 凹槽表「指令 20/20」「速度 0.00/11.33」「周期÷件 34÷17」
- 「就绪」→「● 就绪」（圆点是灯，文字是日志）
- 关卡行 → 24px 正圆徽章 + 名字 + 成绩尾巴
- 「16/20 完成」→ 进度条（条子让人想填满，句子不能）
- 标题 → 深底铭牌

去重：抬头有 17 了，工作台顶就只留关卡名，不再写 #17。
程序区表头保留但压到 10px/55% —— 删了没人知道那列是木牌编号。

### 纵向比例才是主因（23% → 28%）

硬约束：根 VBox 最小高 ≤ 776。所以先腾高度：
- scroll_pal min 144 → 118（**144 是按一排 40 高估的，实测 34+6，白占 26px**）
- lbl_op_help 40 → 26；pv/right separation 各降 2
- p_stage 180 → 186 + `stretch_ratio = 1.8`（原来两栏都是 1:1）
- 净效果：余量 32 → 48，舞台 185 → 225

地平线 `size.y - 62` → `- 78`（原来天空占 2/3，草地薄得像栏杆）。

### 改地平线连累的两处坐标（新坑）

1. **栅栏挂牌飞出舞台**：挂牌在 fy 之上 148px，舞台一矮 y 就变负，画到编辑区上。
   修法：栅栏 84→66，挂牌吊在栅栏顶内侧（top-36），吊线朝下。
2. **「羊圈 INBOX」压羊脸**：写死在 fy-54，羊头顶在 fy-76。
   修法：抬到 fy-90。

> **通用规矩：凡是写死 `fy - N` 的坐标，都要检查 N 有没有超过上方可用空间。**
> 舞台高度会随窗口变，这些常量不会。

### 顺手修的真 bug：左栏不跟人走

`_refresh_level_buttons()` 重建后滚动回顶部 → 抬头写 17、左栏显示 01~12，两边对不上。
修法：`await process_frame`（刚 add_child 的按钮还没算尺寸，这时候滚会滚错位置）再 `ensure_control_visible`。

### 背景远景：做了但基本没用

`_draw_scenery()` 加月亮+9 颗星+三层正弦山脊（alpha 0.06~0.22）。
面板占屏 96%，缝太窄，几乎看不见。**留着，但这一版的主力是纵向重分配。**

### 测试打中一次

断言 `周期标签应摊开成 周期 ÷ 件数`。我一度把「÷ 件数」挪进 tooltip 想让胶囊干净，测试红。
**测试是对的**：「34」没有好坏，「34÷17」才知道往哪优化。改回表头「周期÷件」+ 值「34÷17」。

### 回归

64 / 5 / 92 全绿，布局余量 **728 / 776**。截图 `hrm_godot/_shots/v13/`（`compare_hud.png` 是前后对比）。

## UI 第十四版：通关反馈 + 两个真 bug（2026-10-30 傍晚）

达叔四条反馈，前两条是代码，后两条是设计分析。

### 一、通关特效 + 结算卡（分两层，刻意错开 0.85 秒）

**世界层（stage.gd）**：两处炮口喷彩纸（栅栏顶 + 羊圈顶）、栅栏顶炸一枚星爆、
栅栏里的羊错相位蹦跳、牧羊人早就在冒 zzz。
**系统层（main.gd）**：CanvasLayer 上的结算卡 —— 三颗金星逐颗弹出、指令/速度各一行、
一枚徽章（首次通关 / 破纪录）、下一关 / 再玩一次。

- **彩纸不用 Particle 节点**，全部 _draw 现算：粒子有时要等一帧才吐第一帧，截图会拍到空画面。
- **随机数必须确定性**（`_hash01(i)`）。`_draw` 每帧跑，用 randf() 每帧换数 → 彩纸原地乱抖，
  像信号干扰。同一片纸必须永远走同一条抛物线。
- **彩纸落地不消失**，趴草地上。玩家盯着结算卡发呆好几秒，画面得是「庆祝正在进行」。
- **炮口只有两个**，不是全屏乱喷。全屏是「放烟花」，两个炮口是「两个环节都完成了」——
  庆祝要绑在场景物件上，别绑在屏幕上。
- **结算卡不进根 VBox**，挂 CanvasLayer。根布局有 776 硬预算，结算是「事件」不是「模块」。
- **星级逐颗弹，没拿到的不弹也不亮**。一次全亮就成装饰了；缺的那几颗必须安静。
- 徽章只挂一枚：同时刷两项就只写「新纪录」，三行字挤一张卡没人读。
- 顺手：最后一关通关后「下一关」什么都不做 → 文案改「回到第 1 关」，行为跟着改。
- demo_mode 下 `_record_win` 仍然更新内存成绩（否则截图永远 0 星，看不出效果），但**绝不落盘**。

### 二、× 按钮被自己吓跑（真 bug，教训很值钱）

现象：鼠标移到行尾 × 上，× 当场消失，但还能点。

**第一版修法是错的**：加「延迟一帧再问鼠标还在不在行矩形里」。探针打出来的实测数据：
```
① 行中央   entered=1 exited=0
② × 上     entered=1 exited=1   ← 就在这发了一次 exit
③ 行外     entered=1 exited=1   ← 移出行外，不再发 exit
```
**Godot 在鼠标落进行内子控件时会给父控件发一次 mouse_exited（子控件接管鼠标）；
之后从子控件直接移出父控件外，不会发第二次。**
→ 旧版：② 时归零，③ 时没事件，永远不回来 =「想点它它跑了」。
→ 延迟判定版：② 拦住了，③ 也没事件，永远亮着。

最终：**鼠标位置是唯一真相**。`_input` 里每次 MouseMotion 扫一遍行矩形，
算出压着哪一行，命中行亮 ×、其余全收（`_update_row_hover`）。行用 `set_meta` 挂 del/op。

> **能用纯状态判断的，别用事件。** 信号适合表达「发生了什么」，不适合表达「现在怎样」。

探针 `tools/probe_hover.gd`，三态断言（行内 1 / × 上 1 / 行外 0），必须带窗口跑。

### 三、删掉舞台底部那条 HUD 条

16px 常驻横条，两条信息：「已数 1/1」（栅栏挂牌已有）＋「当前指令 X」（程序行绿边呼吸已有）。
一条两个人干同一件事的横条。删掉，计数搬进栅栏挂牌并改成「已数 N / M」（多了总数），
舞台净多 16px 草皮。

### 四、两条设计分析的结论（已写进 docs 第 22、23 章）

**HUD 分层**：判据是「玩家 90% 的操作步骤里都不看它，就不该占常驻面积」。
L0 常驻 / L1 状态驱动 / L2 学了才需要 / L3 低频查询。
最该动的三处：左栏 20 行关卡列表（→ 格子地图抽屉）、指令说明条（和 tooltip 重复，直接删）、
任务描述正文（→ 摘要一行 + 展开）。
不该动的：指令面板（核心输入）、指令数 20/20（是约束不是参考）。

**IAA 触发点**：红线是「任何广告都不能成为通关必要条件」。
这个游戏能放广告的地方只有两个 ——
① 提示阶梯第 2 档（「具体指令提示」看激励视频；第 1 档思路和第 3 档参考解保持免费）；
② 通关后**主动点下一关**时的插屏（前 3 关零广告、间隔 ≥300 秒、单会话 ≤3 次）。
不能放：主界面 Banner（毁构图）、「写→跑」之间（断心流）、撤销/重跑（基础能力）、买星（毁评价）、
体力（没有资源系统）、启动即插屏。

### 回归

64 / 5 / 92 全绿，布局余量 728 / 776。探针 probe_hover 三态全 PASS。
截图 `hrm_godot/_shots/v14/`（`compare_win.png` 是两层对比）。
新增 CLI：`--win`（跑到通关后立即弹结算卡）。


## UI 第十五版：左栏从「20 行清单」换成「20 块地」（2026-10-30）

达叔一句 ok，就动了上一版建议的那一刀：左栏是整个界面里最后一块「一看就是软件」的地方。

### 做了什么

新建 `hrm_godot/scripts/level_map.gd`（自绘 Control），左栏 238 宽 → 256，
原来的 `ScrollContainer + 20 个 Button` 全部删掉（`_level_row` / `box_levels` / `scroll_levels`
/ `_scroll_levels_to_current` 一并删除），换成一屏铺满的 4 列 × 5 行地砖：

- 已通关 = AMBER 底 + EDGE 2px 描边 + 砖底三颗五角星
- 当前关 = 亮蓝底 + **白 3px 描边** + 琥珀呼吸光环（`sin(_t*2.6)`）
- 未通关 = `#083a63`（比面板深一档，读作「凹下去」）
- 砖底部加了「三星收集」`★ 15 / 60`，攒钱罐比报表更能让人多打一遍
- 地图空白处撒 14 撮草（`_hash01` 确定性，否则每帧乱跳 —— 和通关彩纸同一个坑）

截 `_shots/v15/`：`map_fresh.png`（全新）/ `map_lv09.png`（中途）/ `map_last.png`（末关）
/ `map_allclear.png`（全通关）/ `zoom_tiles.png`（地砖放大 4 倍核对星形）。

### 三个决定（都有代价，记下来免得以后再吵）

1. **不用 `GridContainer + Button`。** 试过：按钮框是方的、间距均匀，换了排法还是列表；
   硬投影会被容器 `separation` 裁掉下半截；塞 60 个子控件装星纯浪费。自绘以后三套
   `StyleBoxFlat` 按尺寸键缓存在 `_boxes`，hover 只 `duplicate()` 改底色。
2. **星点从圆点改成真五角星。** 圆点在 52px 砖上读出来是「三个弹孔」，只有星形能跟抬头那三颗 ★ 对上话。
3. **4 列不是 5 列。** 5 列在 232 可用宽里每块只剩 40px，数字和星点会挤到一起；宁可多一行。
   代价：`custom_minimum_size.y = 288` 是按 5 行算死的，**40 关时这数不够**（10 行每块只剩 22px），
   到时候要么改 5 列 × 8 行、要么塞回 ScrollContainer。

### 顺手修掉的真 bug：「几颗星」原来是错的

`_stars(id)` 用成员变量 `target_size` / `target_speed`（= **当前关**的目标）去判任意一关的成绩。
列表时代只显示当前关的尾巴，所以永远是对的；地图 20 块砖同时显示星数，它会满屏错。

修成单源：
- `_target_of(idx)` —— 每关参考解的成绩，首次现算、之后缓存
- `_stars_of_idx(idx)` —— 按**关卡下标**算（不再按 id）
- `_stars(id)` —— 老接口保留，内部找下标转调上者
- `_refresh_targets()` 也改成从 `_target_of(li)` 取
- 热重载 `levels.json` 时 `level_targets.clear()`

### 新增 CLI

`--cleared=N`：`-1` 不动真实进度 / `0` 清空（看全新开局）/ `N` 假装前 N 关通关，
星数按 3、2、1 循环发，一屏能同时看到三种砖。

## UI 第十六版：程序列表「不跳了」+ 按住下滑（2026-10-30）

达叔反馈：「list 的长度变化界面一直处于跳动的状态，且整个区域没有按住下滑的功能也难受」。
两条都是体感，没有机理 —— 所以先写探针 `hrm_godot/tools/probe_scroll.gd` 逐帧量，别猜。

### 探针把「跳」拆成三种可能，两条坐实

| 猜的机理 | 结论 |
|---|---|
| A. 重建时容器塌陷，scroll_vertical 被夹回 0 | **不成立**（滚到 200，追加后仍 200，五帧稳定） |
| B. 行高不一致，重建后总高变化 | **成立**：带参数行 44px、不带 34px |
| C. 列表外的控件变高把列表顶动 | **成立**：解释条 26px ↔ 57px（autowrap 换行） |

### 修了什么

1. **`ROW_H` 30 → 44，每行 `custom_minimum_size.y = ROW_H`**。不画参数的行不画占位，但格子照样占满 ——
   空的是格子里的空白，不是格子本身。`DragGap` 里的同名常量一起改（插入空隙 / 边缘滚步长都引用它）。
2. **解释条关进固定高盒子**：`Control(58, clip_contents)` + `max_lines_visible = 3` +
   `TRIM_ELLIPSIS`。`custom_minimum_size` 是下限不是上限 —— 这是这次最值钱的一条教训。
   代价：布局余量 48 → **27**（最小高 728 → 749）。
3. **按住下滑**：按位置分工，不按手势分工。
   - 行卡内容上拖 = 挪这一行（原有）
   - **行尾空档上拖 = 滚列表**（新，`CURSOR_DRAG` 光标 + tooltip）
   - 列表下方空白处拖 = 滚列表（新）
   实现：`_press_kind` 加第三个值 `"scroll"`；`_start_drag` 里立刻按本帧位移滚一次（不然慢半拍）。
   **护栏必加**：行卡和容器都收到同一次按下（事件往上冒），`_begin_press` 里
   `if kind == "scroll" and _press_on and _press_kind != "scroll": return`，否则点每一行都变拖空白。
4. **追加一行只动一行**：点指令牌是最频繁的操作，原来每次 `_rebuild()` 把 20 行全销毁新建 →
   屏幕闪一下。改成末尾追加时只 append 一个节点。中间插入/删行/换标签仍全量重建（闭包捕获下标，重建最省心）。
5. 重建后置 `_hover_dirty`，下一帧重判 × 的显隐（否则改一次参数，× 先消失再冒出来）。
6. `String(ins.get("arg"))` → `str(...)`：存档里 JUMP 类参数是数字时 `String(0)` 直接抛异常，整行建不出来。

### 回归

64 / 5 / **102**（test_ui 新增 2 条：追加只动一行、旧行节点原地保留）。
布局余量 749 / 776（**只有 27 了，以后加东西先看这个数**）。
探针全 ✓：解释条恒 58、拖 60 滚 60（1:1 跟手）、松手状态复位、行上按下仍是 row。
截图 `hrm_godot/_shots/v16/`：`compare_rows.png`（前后对比）+ `zoom_help.png`（省略号）+ `final_lv17.png`。

## UI 第十七版：跳转线（2026-10-30）

达叔要「JUMP 牌放进命令区后能看出跳转关系，箭头横跨多行，有包裹感」。
这是这个原型第一次做「结构可视化」—— 前二十几章在解决「像不像游戏」，这条解决「像不像代码」。

### 结构（`scripts/jump_arcs.gd`，自绘 Control）

```
row_wrap (Control, clip_contents)      ← 必须这一层
├── scroll_rows (ScrollContainer)
│   └── row_gutter (MarginContainer, margin_left = 14)
│       └── box_rows (VBox)            ← 行卡
└── jump_arcs (Control, IGNORE, 每帧 redraw)
```

**三层位置都试错了一遍**，记下来免得再走：
- 塞进 `ScrollContainer`：会被当成第二个内容块，和 row_gutter 平分高度
- 塞进 `box_rows`：`VBoxContainer` 会把它当一行，吃掉整行高
- 画在 `main._draw()`：根节点绘制在子控件**之前**，线全被行卡盖住

### 三条设计决定

1. **必须给行列表左边留 14px 空白栏**（`row_gutter`）。第一版画在行卡内部 padding 里
   （左+4），正好压在行号上 —— 行卡 padding 只有 11px，行号从 13px 就开始。
   留栏以后线从「卡片上的划痕」变成「代码块外面的括号」，这才叫包裹感。
   副作用：行列表右移 14px，表头要补 13px spacer（= border 2 + padding 11）才对得齐。
2. **线一律走左侧，不按方向分左右。** 分左右会让同一段代码两头各挂一串线，重心散掉。
   都走左边，上下方向自己说明语义：在行**下面**收口 = 往回跳 = 循环，在上面收口 = 分支。
3. **贪心分列，不按出现顺序编号。** 17 关 6 条跳转，编号分列会占 6 列而栏只有 14px（3 列）。
   按 `[y_min,y_max]` 区间找第一条不冲突的列 —— 相隔很远的两个循环共用一列才干净。

### 端点越界

跳转另一端在视口外时，把线夹在边界 + 画一道 5px 短横杠（断口），
否则线冲出裁剪区，玩家看到的是「线没了」。

### 可测的那一半

`static func links(program) -> Array` 抽成纯函数（返回 `[[from,to],...]`），`_draw` 和测试都调它。
4 条断言：正常跳转两条、标签不存在不画线、**重复标签取最后一次（和 VM 寻址一致）**。
最后这条最要紧 —— 渲染层和解释器对同一程序的读法必须一样，否则表现是「线指着 A、程序跳到 B」。

### 回归

64 / 5 / **108**（test_ui +6）。布局余量 749 / 776 不变（gutter 是水平的）。
截图 `_shots/v17/`：`jump_lv06.png`（完整循环）、`jump_lv17.png`（多层 + 断口）、`zoom_jumps.png`。

## UI 第十八版：抬头重排（2026-10-30）

| 区域 | 内容 | 频率 | 结论 |
|---|---|---|---|
| 左栏 20 块地砖 | 关卡选择 | 换关时（一天几次） | 收起来 |
| 右栏任务卡 | 本关目标 | 读一次（一关一次） | 搬到抬头 |
| 中栏程序 / 右栏指令牌 | 自己写的、能拖的 | 一直在看 | 留下 |

抬头本来就是「宽度富余、高度紧张」——唯一适合住「短、一次性、但要能随时瞟一眼」的信息的地方。

### 做法

- 关号从一行字变成 `Button`（62×42，`Kit.button_boxes(Kit.WOOD_2, 9)`），内含大号 `17` + 10px `/ 20 ▾`。
  点它 → 牧场地图**以浮层铺开**（挂在本节点，不进根 VBox —— 根布局有 776 硬预算，浮层是「事件」不是「模块」）。
  点空白 / 点「收起 ×」/ 点一块砖之后都自动收。
- `LevelMap.tile_max` 从 `const` 变 `var`：左栏时代 52，浮层里 84（357×448 + 标题，1280×800 居中留白正好）。
- 任务条住进抬头：目标（最多 2 行、省略号）+ 数据流（压成**一行**）+ 「卡住了？看提示」。
- 抬头 `custom_minimum_size.y = 56` 钉死，**20 关高度必须一模一样**（回归里加断言，实测恒 56）。

### 三个坑（都是这版才暴露的）

1. **`VBoxContainer` 分配 EXPAND 孩子的规则不是「按 ratio 分富余」**，
   是「按 ratio 分扣掉固定项之后的**全部**高度，但谁也不许低于自己的最小高度」。
   探针实测：body/stage 都 EXPAND_FILL、ratio 1:1 时两块**各 319**（638/2），不是 358/280。
   → `tools/probe_layout.gd` 一行打出四块的矩形/最小高/ratio，**带窗口跑**。
2. **最小高度变小 ≠ 界面变高。** 左栏（288）和任务卡搬走后 root 最小从 749 掉到 582，
   但程序区从 350 缩到 196 —— 因为旧 ratio（stage 1.8 : body 1）是给「最小高度已被左栏撑满」调的，
   富余一来就全给舞台了。按屏占比反推：638 里舞台要 228（800 的 28.5%）→ `body 1.8 : stage 1.0`。
   实测 body 410 / stage 228 ✓
3. **两个 EXPAND 平分富余。** 右栏 `pad`（本意「把解释条顶到底」）和 `scroll_pal` 抢，
   面板长到 410 时多出的 150 有一半喂给空气，牌子只多一排。删 pad，`scroll_pal` 独占 → 132→270。

### 顺带删掉的死代码

`bar_levels` / `bar_levels_rest`（左栏那条通关进度条）—— 浮层里用「通关 12 / 20」这行字代替了。

### 两个小文案改动

- 抬头星位：`lbl_hud_total` 从 9px + `INK_3`（给白底配的深灰）→ 10px + `Color(TEXT, 0.82)`，
  原来压在亮蓝上等于没写。
- 地图标题栏：`12 / 20` + `24 / 60` 两个没标签的分数 → `通关 12 / 20` 和 `★ 24 / 60`。

## UI 第十九版：跳转线车道缩进 + 标签四色（2026-10-30）

达叔两条，其实是同一个病：**一眼分不出哪条线是谁的**。

> 1. 这块的箭头指示线路都叠在一起了，函数命令行可否根据箭头的数量做整体适当向右缩进
> 2. 不同的标签可不可以做颜色区分，同时箭头的跳转指示也会根据其目标的标签色变成一样的颜色

### 缩进：让位跟「这段代码有几个块」走

`row_gutter.margin_left` 从固定 14 改成 **动态 = 6*2 + (lanes-1)*12**：

| 车道 | 让位 | |
|---|---|---|
| 0 | **0** | 一条跳转都没有的程序，不该为不存在的线留白 |
| 2 | 24 | 一个分支 + 一个循环 |
| 5 | 60 | 多层嵌套 |

「要几列」只能由 `jump_arcs` 算（列分配要看每行 y），所以它发 `signal lanes_changed(n)`，main 照做。
**表头必须跟着让**：`head_pad.x = g + 13 - 8`（13 = 行卡 border2+padding11，8 = 表头 separation）。
不扣那个 8 就一直偏右一个格距 —— 眼睛看得出，但很难指出是哪儿。实测对齐 85 = 85。

### 分列顺序：跨度大的走外圈

原来按「程序里出现的先后」分列，改按**跨度降序**。括号是层层套的：
贯穿全程序的大循环该在最外圈，只包三行的分支该贴内容。
按出现顺序分，会让第 3 行那个短跳转占掉最外一列，**看起来像它包住了整个函数** ——
这种「看起来很有道理」的错觉比不画线更坏。

### 上色：`Kit.label_tint` 是唯一真源

a 黄 `#ffdc30` / b 青绿 `#4fd9a4` / c 珊瑚 `#ff8f6b` / d 紫 `#b49bff`。
两条约束：色相拉开（四个单字母在余光里长得一样）；**亮度够当 2.5px 细线**
（深色做贴纸底好看，做线就没了 —— 线的可辨识度优先于色板和谐）。
标签贴纸和跳转线共用这份 → `JUMP b` 的线和 `b:` 的牌子同色。
`links()` 多返回一个目标标签：`[[from, to, label], ...]`。

### 一个花了我半小时的假 bug

截图后扫像素，三条线全是琥珀，以为 `label_tint` 没生效。打了两轮 debug 才看明白：

**第一次 debug 漏了 `--shot`，跑的是存档里的程序（8 行 / 2 条线 / 都是 a）；
带 `--shot` 才是参考解（19 行 / 5 条线 / 3×a + b + c）。那三条黄线本来就都是 a。**

→ 铁律：**核对「画出来的东西」时，CLI 参数必须和截图一字不差。**
`--shot` 会切 `demo_mode`、把存档程序换成参考解，少一个参数看的就是另一个程序。
这类偏差不报错，只让人怀疑自己的代码。
为此留了 `tools/probe_arcs.gd`：程序行数 / 跳转条数 / 每条线的标签+颜色 / lanes / gutter / 表头误差。

### 结果

列间距 5→**12**；车道上限 3 列→**6 列**；无跳转程序 14→**0**；线色 单色→**四色**；
表头误差 14→**0**。回归 **64 / 5 / 128**（test_ui +12）。
截图 `_shots/v19/`：`lv06.png`（双色循环，最直观）、`lv17.png`（五车道）、
`zoom_lv06.png` / `zoom_arrows.png`（放大：绿线连着绿牌子）、`lv01.png`（无跳转 = 不缩进）。

## 第二十版：40 关 + 预选确认 + 难度曲线（2026-10-30）

达叔三条：

> 1. 地图点一下就直接进关了，能不能改成高亮预选、再加个确认按钮
> 2. 我已经全通关了，能不能再追加 20 关到 40 关
> 3. 关卡之间的难易度为什么感觉不是线性由低到高

### 第 3 问先回答：曲线是真的有三处塌陷，而且能算出来

难度分 = 参考解步数 + 可选指令数×1.5 + 木牌格数×2 + **跳转嵌套层数×4** + 新概念×6。
「跳转嵌套层数」比「用了几个 JUMP」准：三条并列分支和三层嵌套行数差不多，脑子负担差很多。

前 20 关实测：**第 14 关 19.5（比第 3 关还低）、第 19 关 28.5、第 12/13 关 24.5 一对镜像**，
峰值是第 17 关 54.0。三处塌陷成因不同且都不是乱摆的：
12/13 是镜像教学对、14 是复习关、19 是喘气关。**「不线性」不是 bug，是排序依据（按指令）
和难度依据（按结构）本来就不是一回事。** 那 20 关存档按 id 存、已经有人打过，不能重排。

### 21–40：换组织方式才谈得上单调

按**任务形态**组织（倒着数 / 每三只一车 / 破纪录 / 哨兵 / 两把尺子 / 斐波那契 / 欧几里得 / 阶乘），
参考解 14–36 行。写完先跑分，**再按分排序**：排序前是锯齿，排序后 38→77 单调。
排序安全（新关没人打过），只需照顾「下一关是上一关变体」的依赖（一车里最大 × 每三只一车），
以及把提示里「和上一关一样」改成点名 —— 排序会把它们拆开。

### 写 20 关踩的两个坑

1. **`JUMPZ`/`JUMPN` 不消耗手上的值** —— 跳过去的标签第一条几乎永远是 `MOVETO <废纸篓>`。
   二十来处，人眼一定漏 → 写了自动修复器（`design_levels.py::_repair`）：让失败信息指路，
   在失败那句前插清手，直到跑通。**多入口标签它修不了**（一条路手满一条手空，插一行只救一边）
   → 两条分支都 JUMP 到同一汇合点。
2. **废纸篓和计数器抢格** —— 清手要写进一格没人读的木牌；随手挑 3 号格而 3 号格正好是层数计数器，
   每清一次就写坏一次。表现「循环少跑两圈」，不报错。现在每关废纸篓显式指定（`scratch=`）。

### 预选：不可撤销的动作不该由一次误触决定

点砖 → 预选（墨绿底 + 亮绿框呼吸），底部绿按钮「进入第 N 关 ›」→ 真换关。
点空白 / 收起 × / 点当前关 → 取消，按钮说「第 N 关就是这儿 · 收起」。

**预选砖要换底色，不只是加绿框**：2px 绿线压在 84px 深蓝面上，眼睛先看到的是面。
预选是瞬间状态，这一秒玩家不需要知道「通没通关」，星点还留着，信息没丢。

### 分页的顺序陷阱

40 块砖塞一屏是能塞的（8 列 5 行），但砖会瘦成 94 宽的「表格单元格」，地砖的「一块地」感就没了。
4×5 一页 20 关、两页翻，翻页只用圆钮，打开时自动翻到当前关那页。

**`show_page_of(li)` 必须在 `set_tiles` 之后调**：反过来时 tiles 还空着，`page_count()` 算出来是 1，
「翻到当前关那页」被夹回第 0 页 —— 不报错，只是永远停第一页。（test_ui 抓到）

### 新增工具

- `tools/vm_py.py`：VM 的 Python 复刻（free 模式不校验 outbox，只跑到程序末尾）+ 难度分（`--json`）
- `tools/design_levels.py`：关卡设计器（写程序 → 真实输出 → 自动清手 → 按分排序 → 写回）
- `tools/curve_plot.py`：难度曲线折线图（Pillow）
- CLI 新增 `--pick=N`：开地图并预选某关，方便截图核对预选态
