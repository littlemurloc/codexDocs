## 「游戏感」判据

**游戏用物体组织信息，软件用位置组织信息。** 先问：这个元素是一行字，还是一个东西？
`SIZE 20/20 SPEED 0.00 就绪` 是 IDE 状态栏；关号木牌、凹槽仪表、★、进度条才是游戏。
- 圆=方向/切换，圆角块=执行/命令。凸起=能按，凹下去=只读（按钮凸、读数是凹槽）。
- 状态要带圆点（`● 就绪`）；进度用条不用句；星级同字形只换色。
- **屏占比 <30% 一定读成「带预览窗的软件」**。

## 工程约定（每条都踩过，且都不报错）

**布局**
- `VBoxContainer` 分 EXPAND 孩子＝按 ratio 分「扣掉固定项后的全部高度」，谁也不许低于最小高。
  给常驻块定高要**按屏占比反推 ratio**，探针 `tools/probe_layout.gd`。
- **最小高度变小 ≠ 界面变高**：搬走撑高度的东西后必须重算 ratio，**看探针不看截图**
  （截图只说「矮了」，不说「被谁拿走了」）。两个 EXPAND 平分富余，spacer 不能用 EXPAND。
- **一个孩子就能撑开整屏最小宽**（写死 3 列、长文案、SpinBox 内的 LineEdit）：
  `get_combined_minimum_size()` 一行一行量，`custom_minimum_size` 拦不住内部最小宽。
- `clampf(v,min,max)` 在 **min>max 时返回 min**（写死的下限永远要跟算出来的上限比一次）。
- `custom_minimum_size` 也是**下限不是上限**：autowrap 一长就撑高 → 变长文字要
  「固定高 + `clip_contents` 外壳 + `max_lines_visible` + 省略号」。
- 行高必须一致；滚动条是盖在内容上画的，列表右边要让出它的宽度；列表重建后要
  `await process_frame` 再 `ensure_control_visible`。
- 浮层不进根 VBox（根布局有 776 硬预算，浮层是「事件」不是「模块」），固定宽一律夹屏宽。
- **浮层超宽要找「最长的那个子控件」**让子控件 autowrap/clip_text，Control 没有 max_width。

**输入与手势**
- **能用纯状态判断的，别用事件**：鼠标落进行内子控件时父控件只收到一次 `mouse_exited`，
  表达不了「现在在不在矩形里」→ 在 `_input` 的 MouseMotion 里按坐标算。
- **子控件和容器会收到同一次按下**：容器抢手势前先看子控件有没有认领（`_press_kind`）。
- **一个手势只给一件事**：拖行卡=挪动、行尾空档=滚列表、牌条横滑=滚牌条；判据只能是**方向/位移**。
- **悬停才出现的控件，在触屏上等于不存在**（行尾 × 桌面 hover、竖屏常驻）。
- 自绘控件要手动设 `mouse_default_cursor_shape`。提示类元素单独一趟排最后。

**渲染**
- `_draw` 里不能用 `randf()`（每帧换数=原地乱抖），用确定性哈希。
- `FontVariation.variation_embolden` **不进 advance**（量出来窄约 8%）→ 折行/量宽用基础字体，
  画的时候才换加粗。牌子的块高只能由折行结果决定，折行抽成静态纯函数单测。
- **渲染层和解释器对同一份程序的读法必须一致**（跳转线取重复标签的最后一次 = VM 寻址），
  否则「线指 A、程序跳 B」比不画更难查 → 判据抽静态纯函数单测。
- 「写死的高度」与「会变的舞台高度」要显式协商：**换维度要空间**（宽度阶梯 `0.56w/0.72w/limit`）。
  **「更宽」永远比「更高」便宜。**
- 颜色板：色相拉开、亮度够当细线，**可辨识度优先于色板和谐**；同一语义用同一份色板。

**流程与工具**
- 三套回归必须全绿：`test_levels`(124) / `test_ideas`(5) / `test_ui`(258，**必须带窗口**），
  **竖屏另跑一遍 390×844**；外加 `scan_strings.py --check`。硬约束：根 VBox 最小高 ≤776。
- 截图 `-- --level=N --shot=<绝对路径>`；**核对画出来的东西时参数必须和截图一字不差**
  （`--shot` 会切 demo、换参考解）。**判断排版按真实分辨率裁剪，别看缩放预览。**
- **截图要等 `RenderingServer.frame_post_draw`**；**测试/探针不许改被测程序的真实状态**
  （`_fill_programs("all")` 会落盘，已加 `persist` 形参）。
- 改 `assets/fonts/app.otf` 后必须 `--headless --import`；主题项名写错是**静默失效**。
- **开发者日志（print）一律英文**：i18n「原文即 key」只收玩家看得到的文案，混进去会报假漏翻。

## 多语言（v22）

- **原文即 key**：源码里的简中原文就是键，漏翻只退回中文，且能被 `scan_strings.py --check` 抓出来。
- **繁体不另写一份**：四趟（词→字→台湾用词→台湾字形）OpenCC 离线烘焙进 `data/i18n.json`；
  人工偏离只留 `MANUAL` 七条（程序→程式/循环→迴圈/数据→資料/鼠标→滑鼠/设置→設定/运行→執行/重置→重設）。
  英文表 `en` 是手写的：**新增文案要同时补 `en` 再跑 `gen_hant.py --write`**，否则 --check 报缺。
- **换语言 = 整屏重建**（`_relocalize()`）；逐个回填要维护清单，漏一项永不报错。
- 区域表只有 `CN/TW/HK/MO`，其余全英文。判定链 `--lang=`→`--country=`→存档手选→系统语言→IP；
  **选过语言就不再探 IP**；`--shot` 时整条探测跳过。语言名用它自己的语言写，不进翻译表。
- 漏翻三道网：文案出口汇聚点 → 静态扫描 → 切英文后递归扫控件树不许出现汉字。
- **体检工具自己出错更危险**：凡「报 100%」的自检，先证明它能报出 0%。

## 手感与反馈（v23）

- **加速要「挣」不能「按」**：`combo` 只由自动运行累积，出错/重置/切关归零；
  `tick = 0.075 + (0.26-0.075)*pow(0.86, combo)`（指数收缩，起速感全在头三下）。
  一条新机制要**三条通道同时表达**（时间/耳朵/眼睛）。
- **音效零素材全部合成**（`scripts/sfx.gd`）：音高必须能变（`pitch_scale=pow(2,semi/12)`）；
  `out` 的音高跟「今天第几只」而非 combo；起音 4ms 不给 0；player 池要够。
- **进度可视化先问「现有布局哪个维度还没用到」**。**状态不能只有一个通道**，
  第二通道优先征用最不重要的现有元素（行号→▶/✕），不要加一列。
- **「记录」和「显示」要分开**（`hint_stage` 星数只增不减 / `hint_view` 现在贴哪张）；
  成就判据现算不累加。
- **只靠动效表达 = 没交付**：凡「让人注意到」都要补静止截图上也成立的通道。
- 配置文件分 section 时**写前必须 `load()`**；量宽按最长的那门语言量。
- `_process` 里「一帧可能多步」的定时器必须 `while + guard`。
- 通关庆祝分两层：世界层 `stage.gd`（彩纸/羊跳）、系统层浮层（结算卡），错开 0.85 秒。
  全三星卡用「星数 120/120 + 关卡 40/40」，不能复用单关的「速度 vs 本关目标」。

## 关卡设计（v20 起）

- **不可撤销的动作不该由一次误触决定**：「点砖=预选，按确认=真走」，预选态要换底色不只是描边。
- `JUMPZ`/`JUMPN` 不消耗手上的值；被跳转到的标签第一条几乎永远要 `MOVETO <废纸篓>`。
- **废纸篓格不能和计数器共用**（清手会写坏它，表现为「循环少跑两圈」），每关显式指定 `scratch`。
- 多入口的标签插一行修不了：两条分支都 `JUMP` 到同一汇合点，让所有入口的手都是空的。
- **难度分是诊断工具不是难度本身**（第 12/13 是镜像教学对、第 19 是喘气关，塌陷是有意的）；
  该修的是排序依据：按指令排必然起伏，按任务排才单调。
- 左栏=牧场地图（`level_map.gd`，纯渲染器）。关数超 20 前先解决 `custom_minimum_size.y=288`。

## 移动竖屏（v24）

- **基准尺寸挑「物理 1:1」的 390×844**：桌面的 44 行高/50 按钮/14 字号在 390 基准上正好是
  手指眼睛要的尺寸，两套布局共用一张尺寸表。按宽高比切（`_tall`，阈值 0.95）。
- **竖屏不是「窄一点的横屏」**：三栏并排要变换行，舞台搬到编辑器**上面**。
- **读的和按的分家**：`Instr / Speed / Cyc` 放抬头下方 30 高薄条，操作台只留能按的（省 58）。
  操作台三列（左 Reset/Clear · 中 Run 跨两行 74 · 右 Step），「下一关」补右列下方 ——
  **运行按钮不因多一个按钮改高度**。指令条单排横向滑（94→56，省 35）。
- **专注编写模式**（`_focus`/`_apply_focus`）：只改可见性、不重建（重建丢滚动位置和选中行）。
  目标牌跟着消失，所以标题行下补一行「目标：…」复述（读 `stage.goal_text`）。偏好存
  `settings.cfg [view] focus`，只在竖屏生效。
- **别把「省空间」做成常驻布局的默认值**：叠层方案被达叔否掉（「给一个开关，让他自己切」）。
  叠层要 `Control + anchors`（舞台 `TOP_WIDE`+写死高、工作区 `FULL_RECT`+`offset_top`），
  Control 不取子节点最小尺寸，压上去要 `shadow_offset=(0,-3)`。
- **开关必须和「只是查一下」的按钮长得不一样**：达叔两次没看见「专注」（与「说明书」同款），
  改成琥珀字 + 宽 60 才认出来。能改界面的入口 ≠ 查询类入口。
- 舞台横向按 1252 宽写死 → 374 宽时木牌带只剩 8px，多边形退化成线，每帧报 triangulation failed
  （不崩，但把真错误淹掉）→ 窄屏要重算三条带子。
- 空程序提示的方向词要分支（桌面「右边」/竖屏「下面」）；测试断言别认「第几个按钮」。

### 竖屏手势（行卡 / 指令条）：结论速查

细节与踩坑过程见 `docs/ui-gestures.md`。必须记住的六条：

- **按位置/方向分工，不用等时间**：行卡左侧 58px 是握把（拖=挪行）、右侧是滚动区；
  牌条上 `|dx|>=|dy|` 滚条子、纵向拿起牌、位移 < `PAL_SWIPE_PX`(14) 松手算点选。
- **一个手势只做一件事，判成什么就把这次按下作废**（`_press_on=false`），否则松手会被
  release 分支当成点击 —— 滑一下条子就白放一张牌。
- **起拖阈值必须分方向**（`_drag_threshold()`）：牌条横向为主抬到 14px，否则 5px 就进「拖牌」，
  14px 的横滑永远等不到 → 条子彻底滑不动。
- **触摸、鼠标是两条通道**：鼠标没有 ScreenDrag，横滑要另开 MouseMotion 那条；tap 由触摸
  release 自己裁决，不等模拟鼠标事件。
- **幽灵卡残留**：`_start_drag` 建卡前先 `_clear_drag_nodes()`；松手收尾要两道兜底
  （`_pal_gesture` + `_input` 各查一次「触摸抬起且 `_drag_on`」）；`_begin_press` 在拖牌中直接 return。
- **`_index_at` 先排除牌条矩形**：`panel_prog.grow(40)` 会盖到牌条上沿，在牌条里松手会被算成
  「插到最后一行」。

## 浮层 / 方向 / 试玩服务

- **`CanvasLayer` 上的浮层在 Web 导出里收不到鼠标触摸**（本地正常）→ 一律改普通 `Control`
  （`PRESET_FULL_RECT` + `MOUSE_FILTER_STOP` + 最后 add_child）。判据：本地 `push_input` 能点中，
  浏览器只有 `touchscreen.tap` 能点 → **测移动版一律用真触摸**。
- ⚠ `project.godot` 的 `handheld/orientation` 默认横屏会把应用钉死（`4`→`userLandscape`），
  改 `6`(SENSOR)。**这个值在 project.godot，不在导出预设里。**
- **浏览器里布局只认窗口尺寸**，偏好只用来「请求转屏」，锁不上就在提示行直说。偏好存
  `settings.cfg [view] orient`，`_ready` 里要在 `_apply_base_size()` 之前读。按钮选中态要改
  **四个**颜色项（font / hover / pressed / focus），只改一个＝手指还压着时看着没反应。
- Windows 的 `SO_REUSEADDR` 允许两个 socket 绑同一端口 → 只能直接 try bind（探测必出 10048）。
