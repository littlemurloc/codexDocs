## 「游戏感」判据（第十三版确立）

**游戏用物体组织信息，软件用位置组织信息。** 看到一个元素先问：它是一行字，还是一个东西？
`SIZE 20/20 SPEED 0.00 就绪` 是 IDE 状态栏；关号木牌、凹槽仪表、★、进度条才是游戏。

- 圆=方向/切换，圆角块=执行/命令；全屏只给「翻页」用圆
- 凸起=能按，凹下去=只读（按钮凸、读数是凹槽）
- 状态要带圆点（`● 就绪`）：圆点是灯，纯文字是日志
- 进度用条不用句；星级同字形只换色（缺一颗时形状不变才数得出来）
- **屏占比 <30% 一定读成「带预览窗的软件」**

## 工程约定（每条都踩过，且都不报错）

**布局**
- `VBoxContainer` 分 EXPAND 孩子＝按 ratio 分「扣掉固定项后的全部高度」，谁也不许低于最小高。
  实测两块 1:1 → 各 319，不是 358/280。给常驻块定高要**按屏占比反推 ratio**。探针 `tools/probe_layout.gd`。
- **最小高度变小 ≠ 界面变高**：搬走撑高度的东西后必须重算 ratio，且**看探针不看截图**
  （截图只说「矮了」，不说「被谁拿走了」）。两个 EXPAND 会平分富余，spacer 不能用 EXPAND。
- **一个孩子就能撑开整屏最小宽**：写死 3 列（447）、一句长文案（440）、SpinBox 内 LineEdit（161）
  都能把整屏撑开、右边全被挤出屏幕。`get_combined_minimum_size()` 一行一行量。
- `clampf(v, min, max)` 在 **min > max 时返回 min**：任务牌下限 560、窄屏上限 350 → 牌子比舞台宽。
  写死的下限永远要跟算出来的上限比一次。
- `custom_minimum_size` 拦不住内部最小宽（SpinBox = LineEdit + 两枚箭头，要钻进 `get_line_edit()`）。
- **`custom_minimum_size` 是下限不是上限**：autowrap 文字一长就把 Label 撑高、把上面整片顶走。
  变长文字要「固定高 + `clip_contents` 的外壳 + `max_lines_visible` + 省略号」。
- 行高必须一致（带参数行与不带差 10px 就参差）；不画插件的格子里留白，不是把格子做矮。
- 滚动条是**盖在内容上**画的：列表右边必须让出它的宽度，否则行尾按钮被遮一半。
- 滚动列表重建后要 `await process_frame` 再 `ensure_control_visible`（新节点还没算尺寸）。
- 浮层（结算卡/说明书/设置）挂 `CanvasLayer`、不进根 VBox：根布局有 776 硬预算，浮层是「事件」不是「模块」。
  浮层固定宽（700/392/340）一律夹屏宽，否则左右各切一截且不报错。

**输入与手势**
- **能用纯状态判断的，别用事件**：鼠标落进行内子控件时父控件会收到一次 `mouse_exited`，之后不再发；
  `entered/exited` 表达不了「现在在不在矩形里」。要在 `_input` 的 MouseMotion 里按坐标算。
- **子控件和容器会收到同一次按下**：容器抢手势前先看子控件有没有认领（`_press_kind`）。
- **一个手势只给一件事**：拖行卡=挪动，拖行尾空档=滚列表；触屏只能靠时间/位移分开。
- **悬停才出现的控件，在触屏上等于不存在**（行尾 × 桌面 hover、竖屏常驻）。
- 自绘控件要手动设 `mouse_default_cursor_shape`，否则玩家以为那是一张图。
- 提示类元素不要跟被提示的物体同层绘制（对照牌被牧羊人盖过），单独一趟排最后。

**渲染**
- `_draw` 里不能用 `randf()`（每帧换数=原地乱抖），用确定性哈希。
- `FontVariation.variation_embolden` **不进 advance**：加粗版量出来比画出来窄约 8% →
  折行/量宽用基础字体，画的时候才换加粗。
- 一块牌子的块高只能由折行结果决定，折行抽成静态纯函数单测，否则牌子一抖下面整片场景跟着抖。
- **渲染层和解释器对同一份程序的读法必须一致**（跳转线取重复标签的最后一次 = VM 寻址）；
  不一致的表现是「线指 A、程序跳 B」，比不画更难查。判据抽静态纯函数单测。
- 「写死的高度」与「会变的舞台高度」必须显式协商；做法是**换维度要空间**——宽度按阶梯往上试
  `[0.56w/700, 0.72w/880, limit_w]`。**「更宽」永远比「更高」便宜。**
- 写死 `fy - N` 的舞台坐标要检查 N 有没有超过上方可用空间（舞台高度随窗口变，常量不会）。
- 颜色板：色相要拉开、亮度要够当细线，**可辨识度优先于色板和谐**；同一语义在别处必须同一份色板。

**流程与工具**
- 三套回归必须全绿：`test_levels`(124) / `test_ideas`(5) / `test_ui`(244，**必须带窗口**，headless 测不了 GUI)，
  **竖屏另跑一遍 390×844**；外加 `scan_strings.py --check`。布局硬约束：根 VBox 最小高 ≤776。
- 截图命令 `-- --level=N --shot=<绝对路径>`；`--` 之后的参数在 `OS.get_cmdline_user_args()`，两个 args 都要扫。
- **核对「画出来的东西」时命令行参数必须和截图一字不差**：`--shot` 会切 demo、把程序换成参考解。
  已有探针：`probe_layout` / `probe_arcs` / `probe_scroll` / `probe_reflow` / `probe_focus`。
- **判断排版要按真实分辨率裁剪，别看缩放预览**（1280 预览成 1080，「贴边」和「留白均匀」看起来一样）。
- **截图要 `await RenderingServer.frame_post_draw`**，只 `await process_frame` 会截到上一帧：
  数字变了图没变，最容易被误判成「代码没生效」。
- **测试/探针不许改被测程序的真实状态**：`test_ui` 里曾调 `_fill_programs("all")`，而这个函数会落盘 ——
  每跑一次回归就把 40 关参考答案写回玩家存档（表现为「答案怎么又回来了」）。
  现已加 `persist` 形参，探针的 `I18n.settings_path` 也指到临时文件。
- **改了 `assets/fonts/app.otf` 之后必须 `godot --headless --path . --import`**：
  `.godot/imported/*.fontdata` 不刷新，测试和游戏读的都是旧字形（断言报缺字、界面却是好的）。
- 主题项名写错是**静默失效**；改不动先写探针 `ThemeDB.get_default_theme().get_stylebox_list("X")`。
- `boot_splash` 不是独立 section，是 `[application]` 下的键。替换 `<style>` 别吞 `</style>`（丢了整页变 CSS 全白）。
- **开发者日志（print）一律英文**：i18n「原文即 key」只收玩家看得到的文案，混进去会让扫描器报假漏翻。

## 多语言（v22）

- **原文即 key**：源码里的简中原文就是翻译表的键，漏翻只退回中文，且能被 `scan_strings.py` 抓出来。
- **繁体不另写一份**：四趟（词→字→台湾用词→台湾字形），OpenCC 离线烘焙进 `data/i18n.json`。
  人工偏离只留 `MANUAL` 七条（程序→程式/循环→迴圈/数据→資料/鼠标→滑鼠/设置→設定/运行→執行/重置→重設）。
- **换语言 = 整屏重建**（`_relocalize()`）；逐个控件回填要维护清单，漏一项永不报错。
- 区域表只有 `CN/TW/HK/MO`，其余全英文（含 SG/MY）。判定链 `--lang=`→`--country=`→存档手选→系统语言→IP。
  **选过语言就不再探 IP**；`--shot` 时整条探测跳过。
- 语言名永远用它自己的语言写（繁體中文/English/EN），不进翻译表。
- 漏翻有三道网：三个文案出口的汇聚点 → 静态扫描 → 切英文后递归扫控件树不许出现汉字。
- **体检工具自己出错更危险**：scanner 曾跳过带 `\n` 的长句却报「100%」。凡「报 100%」的自检，先证明它能报出 0%。

## 手感与反馈（v23）

- **加速要「挣」不能「按」**：`combo` 只由自动运行累积（手动单步不涨），出错/重置/切关归零。
  `tick = 0.075 + (0.26-0.075)*pow(0.86, combo)`，指数收缩——起速感全在头三下。
- **一条新机制要三条通道同时表达**（时间/耳朵/眼睛），只有一条就只是「变快了」。
- **音效零素材全部合成**（`scripts/sfx.gd`），理由是**音高必须能变**：`pitch_scale=pow(2,semi/12)`。
  `out` 的音高跟「今天第几只」而非 combo——进度变成旋律。起音 4ms 不给 0；player 池要够。
- **进度可视化先问「现有布局哪个维度还没用到」**，别造新元素（草地光点=噪点、底部灯带=语义重复）。
- **状态不能只有一个通道**：第二通道优先征用**最不重要的现有元素**（行号→▶/✕），不要去加一列。
- **「记录」和「显示」要分开**（`hint_stage` 决定星数只增不减 / `hint_view` 现在贴哪张），
  合成一个变量必出现「看过一眼就永久禁用」。成就判据现算不累加（遍历 40 关比计数器可靠）。
- **只靠动效表达 = 没交付**：呼吸/闪烁在静止截图上看不出来，凡「让人注意到」都要补静态也在的通道。
- 配置文件分 section 时**写前必须 `load()`**（否则语言↔音量互相覆盖）。
- 量宽按**最长的那门语言**量（繁中比简中长约 8%）。
- `_process` 里「一帧可能多步」的定时器必须 `while + guard`，只 `if` 一次会把速度卡在一帧一步。
- 通关庆祝分两层：世界层归 `stage.gd`（彩纸/羊跳），系统层归 `CanvasLayer`（结算卡），错开 0.85 秒。
- 全三星卡不能复用单关的「速度 vs 本关目标」（那是第 40 关的目标，必得一个 ✕），改成「星数 120/120 + 关卡 40/40」。

## 关卡设计（v20 起）

- **不可撤销的动作不该由一次误触决定**：换关会存盘，所以「点砖=预选，按确认=真走」。
- 预选态要换底色不只是描边（2px 线压在 84px 面上，眼睛先看到面）。
- `JUMPZ`/`JUMPN` 不消耗手上的值；被跳转到的标签第一条几乎永远要 `MOVETO <废纸篓>`
  （例外：该标签本来以要求手空的指令开头）。
- **废纸篓格不能和计数器共用**（清手会写坏它，表现是「循环少跑两圈」，不报错），每关显式指定 `scratch`。
- 多入口的标签插一行修不了：两条分支都 `JUMP` 到同一汇合点，让所有入口的手都是空的。
- **难度分是诊断工具不是难度本身**：第 12/13 是镜像教学对、第 19 是喘气关，这类「塌陷」是有意的。
  真正该修的是排序依据（按指令排必然起伏，按任务排才单调）。
- 左栏=牧场地图（`level_map.gd`，纯渲染器）。关卡数超 20 前先解决 `custom_minimum_size.y=288` 这个按 5 行写死的数。

## 移动竖屏（v24，2026-11-03）

- **基准尺寸挑「物理 1:1」的那个**：390×844 而不是 540×960 —— 桌面的 44 行高/50 按钮/14 字号
  在 390 基准上正好是手指眼睛要的尺寸，两套布局共用一张尺寸表。
- 两套布局一套代码，按宽高比切（`_tall`，阈值 0.95）。**竖屏不是「窄一点的横屏」**：三栏并排要变成换行。
  舞台搬到编辑器**上面**（竖屏自上而下读：先看羊，再低头看代码）。
- **专注编写模式**（`_focus` / `_apply_focus`）：收起舞台，编辑器从 3.4 行变 8.1 行。
  只改可见性、不重建（重建会丢滚动位置和选中行）。目标牌跟着消失，所以在标题行下补一行「目标：…」复述
  （读 `stage.goal_text`，不另存一份，两处各存必有一处忘更新）。偏好存 `settings.cfg` 的 `[view] focus`，
  **只在竖屏生效**（横屏没有这个按钮，藏了等于永久黑掉半边屏）。
- 舞台横向分配是按 1252 宽写的（羊圈 26~180、木牌带 258~(w-258)、栅栏贴右），374 宽时木牌带只剩 8px，
  多边形退化成线，Godot 每帧报 triangulation failed（不崩，但把真错误淹掉）。窄屏要重算三条带子。
- 竖屏行卡上「短按=选中 / 划开=滚列表 / 长按 0.32s=拿起」；空程序提示的方向词要分支（桌面「右边」/竖屏「下面」）。
  **长按方案 2026-11-04 已废弃**，改成左右分区（见下）。

### 竖屏行卡：左右分区（2026-11-04 定稿，取代长按）

达叔的主意，比我的长按好：**用手按在哪里决定做什么，不用等时间**。

- 左侧 `ROW_HANDLE_W = 58` 是握把（按下去拖 → 重排这一行），右侧是滚动区（拖 → 滚列表）。
- 判定用**全局坐标**自己算：`gpos.x - row.get_global_rect().position.x`。
  **不要信 `_gui_input` 里传进来的 `e.position`** —— 事件可能是子控件转上来的，
  那时它是相对子控件的，比出来的结果完全错（实测右半边被判成握把）。
- 握把必须**画出来**：一条淡色竖槽（alpha 0.085）+ 居中三道 7×2 横线。
  只画三道线试过，2px 压在深蓝上像一粒灰，缩略图里根本看不见 ——
  「有边界」这件事得靠**面**说，不能只靠线。行卡左边距要留到 18，
  11 的时候三道线紧贴行号「01」，看起来像数字前面的横杠（放大截图才发现）。
- 行内能点的控件（参数框、× 按钮）照旧吃掉手势 —— 手按在能点的东西上就点它，
  只有「弹性空白」才是滚动区。别为了统一而把参数框也变成滚动区。
- ⚠ **`ScrollContainer` 松手时会把它自己记的位置写回来**，把手动滚的值抹成 0
  （实测拖动中 55，松手瞬间 0，手感就是「一拖跟着走、一松弹回顶部」）。
  解法：motion 里记 `_scroll_keep`，松手后 `_restore_scroll()` **连写三帧**
  （它要等自己重排完、内容高度算出来才认这个值，只写一次会落在内容高度还是 0 的那帧）。
  试过 `mouse_filter = IGNORE` 想让它完全闭嘴 —— **连行卡都收不到事件了**，别试。
- 探针要干净：两次拖动之间必须**重建 main 实例**。第一次拖动改了程序顺序，
  第二次 load_level 读到的行内容就变了，落点撞在别的控件上，会得出「有时行有时不行」的假象。

### 竖屏第二次重排（2026-11-04）：读的和按的分家

- **读数表搬进抬头底部**：`Instr / Speed / Cyc` + 状态从操作台第三行挪到抬头下方一条 30 高的薄条。
  判据是「读的东西和按的东西不该抢同一块地盘」——操作台只留能按的。省 58。
- **操作台改三列**（左 Reset/Clear 上下 · 中 Run 跨满两行 74 高 · 右 Step）。「下一关」藏在右列下方，
  通关出现时正好补齐 74 —— **运行按钮不会因为多一个按钮改高度**，否则整片布局被推一遍。
- **指令条改单排横向滑动**：两排 94 → 一排 56，省 35。合计编辑器行区 157 → 213（3.4 → 4.5 行），
  专注模式 8.1 → 9.3 行。
- ⚠ **Godot 的 ScrollContainer 触摸滚动在 Web 导出里不响应**（`is_touchscreen_available()` 拿不到真值），
  鼠标拖也不响应。表现是「手指划过去，条子一动不动」，不报错，也不崩。
  接 `scroll_pal.gui_input` 同样收不到：牌子是 `MOUSE_FILTER_STOP`，ScreenDrag 冒不上来。
  → 正确做法：在 `main._input` 里**按坐标**判断手指是否落在滚动区矩形内，自己加减 `scroll_horizontal`。
  只留触摸通道，别接鼠标 —— 接了会抢行卡拖拽（回归立刻报「移动超过阈值应开始拖拽」失败）。
- **ScrollContainer 里的 HBox 必须 `SHRINK_BEGIN`**：设 FILL/EXPAND 时它的宽被拉成视口宽，
  内容永远「正好装得下」，滚动条再也不出现，牌子多也只是挤窄。判据看 `get_h_scroll_bar().max_value > page`。
- **浮层超宽要找「最长的那个子控件」，不是改容器**：地图浮层 410 宽（屏只有 390）的元凶是图例那句英译
  382px；把它 `autowrap`、把关数那行 `clip_text`，浮层自己就回到 386。Control 没有 max_width，只能让子控件肯缩。
- 测试断言别认「第几个按钮」。竖屏操作台改了顺序，`_check(first_btn.text.contains("运行"))` 立刻失败；
  顺序是设计决定、会变，要断言的是「有没有一个可见的运行按钮」。

### 竖屏第三次重排（2026-11-04 下午）：叠层试过，**被否**

达叔先说「把编辑器叠在舞台上」，做完之后他自己改了主意：**「有专注按钮的话就不用压空间了，
回到上一版，但新增个专注按钮」**。所以常驻布局回到「舞台 244 在上 / 编辑器在下」，
一屏 4.5 行；9.3 行那条路交给「专注」开关。

- **教训：别把「省空间」做成常驻布局的默认值。** 玩家要的是「能看更多」，不是「一直更挤」。
  常驻布局替所有人做了决定，而正确答案应该是「给一个开关，让他自己切」。
- **开关必须和「只是查一下」的按钮长得不一样。** 达叔连着两次没看见标题行那颗「专注」，
  宁可让我去压布局。它原来和右边「说明书」完全同款 —— 改成琥珀色字 + 宽 60 之后才被认出来。
  判据：**能改变界面的入口 ≠ 查询类入口**，只换颜色不换形状（不破坏按钮语言）。
- 叠层的技术留存（将来要重做时直接用）：VBox 排不出重叠，要 `Control + anchors`
  （舞台 `PRESET_TOP_WIDE` + 写死高，工作区 `FULL_RECT` + `offset_top`）；
  Control 不从子节点取最小尺寸，`custom_minimum_size` 得自己给；
  压上去的东西要有 `shadow_offset=(0,-3)`，否则读成「画歪了」；专注态记得把 `offset_top` 归零。

## 浮层与 CanvasLayer（2026-11-04，重要）

- **`CanvasLayer` 上的浮层在 Web 导出里收不到鼠标/触摸输入，本地窗口却一切正常。**
  设置浮层和结算卡都挂 CanvasLayer，两个都中招：按钮按下去毫无反应，连底下的
  「点空白关闭」都不触发。同一份代码的地图浮层 / 说明书浮层是普通 `Control`，点得动。
  → 全部改成 `Control`（`PRESET_FULL_RECT` + `MOUSE_FILTER_STOP` + 最后 add_child）。
  顺带好处：Control 自动继承 theme，不用再手工 `root.theme = theme`（方框坑自然消失）。
- **判据**：本地 `probe_click.gd` 用 `get_root().push_input(InputEventMouseButton)` 能点中；
  浏览器里 Playwright 的 `mouse.click` 和 CDP `Input.dispatchMouseEvent` **都点不动**，
  只有 `touchscreen.tap`（真触摸）能点。所以「浏览器里点不动」不等于「真机上点不动」，
  但 CanvasLayer 那一层是真的坏 —— 换 Control 后两种都正常。
- **测移动版一律用 `touchscreen.tap`，不要用 `mouse.click`**。用鼠标测出来的「点不动」
  会把你引向错误的结论（我为此绕了半小时）。

## 画面方向开关（设置里的「自动 / 竖版 / 横版」）

- ⚠ **`project.godot` 的 `display/window/handheld/orientation` 默认是「横屏」，会把应用钉死。**
  原来写的是 `4`（SCREEN_SENSOR_LANDSCAPE），导出的 APK manifest 里就是 `userLandscape`（值 11）——
  手机上竖着拿，系统把画面转 90° 贴在屏幕上，玩家看到的就是「一直都是横屏」。
  改成 `6`（SCREEN_SENSOR）后 manifest 是 `fullUser`（13）：四个方向都行，并且尊重系统的方向锁。
  **这个值在 project.godot 里，不在导出预设里，改代码是改不到的。**
- **浏览器里布局只认窗口尺寸，不认偏好。** 偏好只用来「请求转屏」，不用来「假装转了」。
- 三端三条路：
  - 手机（`_is_mobile()`）：`DisplayServer.screen_set_orientation(PORTRAIT/LANDSCAPE/SENSOR)`，系统真转；
    布局**永远跟随窗口**（`_want_tall` 直接返回 `_is_tall_screen()`），不强制。
  - 浏览器：`requestFullscreen()` + `screen.orientation.lock()`，全部 try 包住；锁不上就在提示行直说。
  - 桌面（短边 ≥ 480 且非移动端）：按钮就是「换个布局看看」，直接重建（`_can_force_layout()`）。
- 锁不上时**用提示行直说**，比给一张变形界面诚实。
- 偏好存 `settings.cfg [view] orient`；`_ready` 里**必须在 `_apply_base_size()` 之前读**，
  否则开机先建错一次再重建，会闪一下。
- 按钮选中态要改**四个**颜色项（`font_color` / `font_hover_color` / `font_pressed_color` /
  `font_focus_color`）。只改第一个的话，手指还停在按钮上时用的是 hover 色，看起来「没反应」。

## 本地试玩服务（tools/serve_web.py）

- Windows 的 `SO_REUSEADDR` **允许两个 socket 绑同一端口**（与 Linux 语义相反），
  所以「先探端口空不空再交给服务器绑」必然出「探测说空闲 → 真绑 10048」。端口判断只能**直接 try bind**。
- 脚本要能认出「自己已经在跑」：报出地址后退出，别另起（用户会连点五次）。
  判据不能只看端口在听，要验返回内容里的品牌字。抛错要给下一步动作，只报 WinError 编号等于没报。
- 双击 bat 要能打开浏览器：`webbrowser.open` 会「返回 True 却没打开」，要退到 `os.startfile` / `cmd start`；
  bat 末尾留 `pause`，至少让地址停在屏幕上。
