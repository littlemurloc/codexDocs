# 竖屏手势细节（行卡分区 / 指令条两步确认）

> 从 `.workbuddy/memory/MEMORY.md` 拆出：结论留在记忆里，这里放完整判据与踩坑过程。

### 竖屏行卡手势：左右分区（2026-11-04 定稿，长按方案已废）

达叔的想法：**用手按在哪里决定做什么，不用等时间**。左侧 `ROW_HANDLE_W = 58` 是握把
（按下拖 → 重排这一行），右侧是滚动区（拖 → 滚列表）。

- 判定用**全局坐标**：`gpos.x - row.get_global_rect().position.x`。**不要信 `_gui_input` 里的
  `e.position`** —— 事件可能是子控件转上来的，比出来完全错（实测右半边被判成握把）。
- 握把必须**画出来**：淡色竖槽 + 居中三道横线；行卡左边距留 18（11 时三道线贴「01」像横杠）。
  「有边界」得靠**面**说，只画线在 2px 深蓝上像一粒灰。
- 行内能点的控件（参数框、× 按钮）照旧吃掉手势，只有弹性空白才是滚动区。
- ⚠ **`ScrollContainer` 松手时会把它自己记的位置写回来**（拖到 55、松手弹回 0）→
  motion 里记 `_scroll_keep`，松手后 `_restore_scroll()` **连写三帧**才认。别用
  `mouse_filter = IGNORE` 让它闭嘴（连行卡都收不到事件）。
- 探针要干净：两次拖动之间**重建 main 实例**（上一次改了程序顺序，落点会撞别的控件）。
- ⚠ **Godot 的 ScrollContainer 触摸滚动在 Web 导出里不响应**（`is_touchscreen_available()`
  拿不到真值），接 `gui_input` 也收不到（牌子是 `MOUSE_FILTER_STOP`）→ 在 `main._input`
  里按坐标自己加减 `scroll_horizontal`。
- **ScrollContainer 里的 HBox 必须 `SHRINK_BEGIN`**：FILL/EXPAND 时宽被拉成视口宽，滚动条永不出现。
  判据 `get_h_scroll_bar().max_value > page`。

### 竖屏指令条（底部牌条）：方向分流 + 两步确认（2026-11-09）

达叔原话：「左右滑动 + 点选卡片老是会同时触发，滑一下条子就白放一张牌」。
根因不是「点得太灵」：**按下那一刻横滑和点选长得一模一样**，只有位移能分开。

- 一个手势三个出口，判据是**方向**：`|dx| >= |dy|` → 滚条子；否则 → 把牌拿起来拖；
  位移不到 `PAL_SWIPE_PX = 14` → 松手算点选。**14 而不是行卡的 5**：手指点按本来会晃，
  5px 会把每次正常点按判成滑动，玩家只觉得「点了没反应」。
- **判成滑动必须把这次按下作废**（`_press_on = false`）：卡片早已在 GUI 里 `_begin_press("new")`，
  不作废的话松手会被 release 分支当成点击 → 白追加一行。这才是那个 bug 的修复点。
- **鼠标没有 ScreenDrag**：横滑要另开一条 MouseMotion 通道（`_pal_mouse_scroll`），
  否则桌面/调试窗里左右拖牌条 = 幽灵卡跟着走。判「横向为主」还要 `|dx| > |dy|*1.5`。
- ⚠ **起拖阈值必须分方向**（`_drag_threshold()`）：牌条上横向为主时抬到 `PAL_SWIPE_PX`，
  否则 5px 就进「拖牌」，14px 的横滑永远等不到 → 表现是**条子彻底滑不动**（真人拖动是每帧 2~4px）。
- ⚠ **探针的步长要按真人手速**：一次 20px 的大跳会绕过上面那个坑，把 bug 藏住。至少要有一档
  2~4px/帧，并且**先证明它在 bug 存在时会 FAIL**（把阈值临时改回固定 5 跑一次，应报「滑不动」）。
- **tap 由触摸 release 自己裁决**，不等模拟鼠标事件（Web/Android 上时有时无），处理完置
  `_press_on = false` 防同一下算两次。
- ⚠ **幽灵卡（拖拽预览）残留有三道保险**（2026-11-09 手机上出现）：①`_start_drag` 建卡前先
  `_clear_drag_nodes()`（`_ghost` 只有一个引用，重复建就把上一张丢在屏幕上）；②松手收尾不能只挂在
  「这一下经过牌条判定」上 —— `_pal_gesture` 与 `_input` 各留一道「触摸抬起且 `_drag_on` 就收」的兜底；
  ③`_begin_press` 在 `_drag_on` 时直接 return，多指/另一只手不许插队改状态。只认 `index == 0`。
- ⚠ **`_index_at` 必须先排除牌条矩形**：`panel_prog` 的 `grow(40)` 会盖到牌条上沿，
  手指停在牌条里松手会被算成「插到最后一行」—— 玩家没往列表里放，程序却多了一行。
- **两步确认只在竖屏**：第一下只选中，第二下同一张才追加；从牌上纵向拖出去＝拖拽本身即确认。
  横屏单击仍直接追加（鼠标精准，没有横滑要抢）。手落在别处（点行/点空白）= 收回选中；
  `_rebuild_palette` 也要清空。
- **选中 / 引导 / 普通三态只能有一个绘制出口**（`_paint_palette_card`），分三处改必出现
  「选中了还在呼吸」「取消选中把引导点亮」。选中优先于引导；`_guide_on` 存字段，不能现算。
- 选中牌必须**换底色 + 字反深色**（静止截图上也成立），白描边只是第三条通道。
- `_end_drag` 的**成功分支也要 `_update_insert_hint()`**，否则放下后屏幕上一直挂「松手 → 插到第 N 行」。
- 探针 `tools/probe_palette.gd`（412 竖屏，13 项）。**`get_image()` 在 `--script` 下拿到的是
  「最后一次 present 的帧」**，截图只能放流程末尾（带 `--shot` 时探针跑到选中态就 quit）。
