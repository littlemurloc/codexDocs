# SHEEP COUNTER（数羊）· Godot 原型

机制参考《Human Resource Machine》，**美术、文案、关卡数值全部自研**，不含原版任何素材。

一句话：你不是在搬箱子，你是在失眠的夜里数羊——每只羊身上有一个编号，数完一只就把它推过栅栏。数错了，羊会被栅栏绊倒。

## 主题映射（技术概念 ↔ 画面）

| 程序里的概念 | 画面上的东西 |
|---|---|
| `INBOX`（读一个数） | 从左边**羊圈**里牵一只羊 |
| `OUTBOX`（输出一个数） | 把羊**推过右边的栅栏**，它跳过去就算数过了 |
| 手 / `hand` | **怀里抱着的那只羊**，编号浮在头顶 |
| `mem_size` 地板格 / 内存 | 草地里插着的**木牌**，牌子上写数字 |
| `COPYTO 2` / `COPYFROM 2` | 把值记到 2 号木牌 / 从 2 号木牌捡回来 |
| `BUMPUP` / `BUMPDN` | 木牌上的数字 +1 / −1 |
| 程序出错 | 羊**被栅栏绊倒**，四脚朝天，头顶冒星星 |
| 全部输出正确 | 羊全部跳过去，头顶飘起 `z z z`，月亮变亮 |

**为什么"数羊"里会有加减乘除？** 因为设定是"半梦半醒时数糊涂了"——羊的编号开始自己翻倍、自己比较。这不是硬凑：它刚好给抽象算术关卡一个叙事理由，也让"信号比较器"这种怪关卡有了归宿。

## 跑起来

### 开发时：不要用 exe

Godot 是**引擎直接读工程目录**跑的，`.gd` / `.tscn` / `.json` 就是源码，没有"编译"这一步。改完保存 → 重开一次（2 秒）就能看到效果。`build/HRMClone.exe` 只是**分发用的快照**，只有要把游戏发给别人时才需要重新导出。

| 方式 | 命令 / 操作 | 适合 |
|---|---|---|
| 双击 `../dev_game.bat` | 用 console 版引擎跑工程，黑窗里能看到 `push_error` / `print` / 脚本解析错误 | **改代码时首选** |
| 双击 `../start_game.bat` | 用 GUI 版跑工程，无黑窗 | 只想玩，不想看日志 |
| Godot 编辑器 | 导入 → 选 `project.godot` → F5 | 调界面布局、看节点树 |
| 命令行 | `"D:/XT/godot/Godot_v4.7.2-stable_win64.exe" --path .` | 脚本化、批处理 |

> 改 `data/levels.json` **连重启都不用**：游戏里按 `L` 重新读取关卡数据，当前关卡和已存进度都保留。

### 分发时：导出 exe

```bash
"<godot_console.exe>" --headless --path . --export-release "Windows Desktop" "<绝对路径>/build/SheepCounter.exe"
```

导出产物是单文件（pck 内嵌），拷走即玩。**注意 `export_path` 在 headless 下必须给绝对路径**，否则会落在工程目录里。

### 分发时：导出 H5（网页版）

```bash
"<godot_console.exe>" --headless --path . --import                # 新资源先导入一遍
"<godot_console.exe>" --headless --path . --export-release "Web" build/web/index.html
python tools/patch_web_html.py                                    # 加载页换成牧场风
```

产物在 `build/web/`（wasm + pck + html），**扔到任意静态空间就能跑**——
预设关了线程支持，不需要 COOP/COEP 响应头，GitHub Pages 都能放。
本地试玩：**双击项目根目录的 `play_h5.bat`**（自己挑空闲端口 + 自动开浏览器）。
手动起也行：`cd build/web && python -m http.server 8123`，然后开 `http://127.0.0.1:8123`。
两个坑：双击 `index.html`（file://）一定白屏，wasm 加载被浏览器拦；
8080 这类常见端口在本机可能已经被别的软件占着，bind 会抛 `WinError 10013`，
看起来像权限问题其实是端口冲突，换个端口就好。

三件事是网页版特有的，动 Web 相关代码前先知道：

- **字体必须内嵌**。浏览器沙箱拿不到 `C:/Windows/Fonts`，中文全是豆腐块。
  只有一个字体文件 `assets/fonts/app.otf`（`tools/make_font_subset.py` 从思源黑体裁的子集，
  1476 字 / 318KB）：i18n 原文 + 每个键的繁体转换结果 + 英文 + 关卡数据 + 源码里的非 ASCII。
  改了文案要**重跑这个脚本**：它会校验「每个字符都有字形」，缺一个就 `exit 1` 并列出缺字。
  `tests/test_ui.gd` 里有对应断言，漏跑会在回归里炸。

- **符号只用思源黑体自带的**。`FontFile.fallbacks` 那条路走不通：`Theme.default_font`
  取到的是另一个字体实例，控件那边 `get_theme_font("font").fallbacks.size()` 恒为 0
  （只有 `add_theme_font_override` 能带过去，逐控件设置不现实）。
  所以：空心小三角 → 实心小三角、`✔` → `✓`、`✕` → `×`、齿轮 → `⋯`。视觉差别极小。
  要加新符号，先确认主字体有 —— 加错了子集脚本会当场报错。

- **CanvasLayer 浮层必须显式挂 `theme`**。CanvasLayer 不是 Control，theme 继承链到它那儿
  就断了：结算卡和设置浮层里的字会退回引擎默认字体（无中文、无符号）。
  网页版上的表现特别有欺骗性——**主界面全正常，一过关结算卡满屏方框**。
  `tests/test_ui.gd` 盯着这两个浮层的根节点。

- 加载字体走 `load()` 而不是 `load_dynamic_font()`：导出包里只有导入产物，
  res:// 原始字体文件不进 pck。

- **单线程构建**（`variant/thread_support=false`）：共享托管能跑比快 5% 重要。
- 图标/加载图在 `assets/icon_512.png`（`tools/make_icon.py` 画的）， splash 底色随 `boot_splash/bg_color`。

## 开局与提示

**关卡不会预填答案。** 进关是空白编辑器，你写的东西会被自动保存，下次进来还是你自己的解。

卡住 60 秒后，右侧的「卡住了？看提示」才真正生效，并且分三级：

1. **思路** —— 一句话点出这关的关键洞察（不是代码）
2. **关键做法** —— 具体用哪几条指令、按什么顺序
3. **参考解** —— 直接把标准答案填进编辑器

用过第 3 级的关卡，成绩标记从 `★` 变成 `☆`（保留最优 SIZE/SPEED，只是不算"自己想出来的"）。

**看过还能再看。** 回看不改 `hint_stage`（决定星数的那一条），只改 `hint_view`（现在贴在舞台上的那张），
所以翻来覆去看十次和看一次的结果完全一样。

**第一次进游戏的 90 秒**：指令面板的第一块牌会做一次呼吸（亮 0.62s 再暗回去），
配一句「点一下右边任意一块指令牌，它就会变成一行代码」。判据是「一关都没写过程序」，
所以不需要额外的存档字段，也不会在玩家删光程序时又跳出来烦他。

## 执行反馈（HUD）

- **程序行配色**：绿色边框 = 刚执行的那一行，红色 = 出错那一行，蓝色 = 当前选中行
- **视野跟随**：程序长到超出可视区时，列表会自动滚到正在执行的行
- **底部指标**：`SIZE 15 / 15`、`SPEED 4.67 / 10.67`、`14 周期 ÷ 3 件`（把 SPEED 的算式摊开，方便判断该优化哪里）
- **羊的走位**：`INBOX` 走向羊圈，`COPYTO 2` 走向 2 号木牌并高亮，`OUTBOX` 走到栅栏左端把羊推过去

### 渐进加速（COMBO）

**没有倍速按钮。** 跑得越顺，它自己越快：

```gdscript
const STEP_SLOW := 0.26      # 第一步
const STEP_FAST := 0.075     # 封顶
const STEP_DECAY := 0.86
tick = STEP_FAST + (STEP_SLOW - STEP_FAST) * pow(STEP_DECAY, combo)
```

- `combo` = **本次运行连续成功的步数**。手动单步**不涨**（否则可以预支加速），出错 / 重置 / 切关归零
- 加速由三条通道同时表达：间隔（3.5 倍）/ 音高（每步升半音，封顶一个八度）/ 执行行拖尾（起步亮 1 行，全速 3 行一起亮）
- 行号在运行时变成 `▶`（正在执行）/ `✕`（出错）—— 形状第二通道，红绿不分的人也能读
- `stage.pace = tick / STEP_SLOW`，舞台上所有动画跟着变速；不这么做高速时羊的跳跃会抽帧

### 声音

**项目里没有一张音频文件**，六种音全部 `AudioStreamWAV` 现场合成（`scripts/sfx.gd`）：

| 音 | 什么时候 | 特点 |
|---|---|---|
| `click` | 每一步 | 很轻、像节拍器，随 combo 升调（封顶 12 半音） |
| `wood` | 动木牌 | 300 + 900Hz 的 1:3 叠加＝空腔感 |
| `out` | 推一只羊过栅栏 | **音高跟「今天第几只」走**，数满一关就是一段上行音阶 |
| `err` | 绊倒 | 370→196 扫频，一次连续下坠 |
| `win` | 过关 | 上行四音 |
| `ding` | 刷了自己的 SPEED | 叠在 win 后 0.34s，只在新纪录时响 |

变调走 `pitch_scale = pow(2, semitone/12)`，不重新合成（高速时每 75ms 一个音，现场合成会卡帧）。
8 路 player 池：一个 player 播新流会掐掉上一条，池子不够就会「漏拍」。

### 收尾：四十关全三星

第 40 关打完和第三关打完本来长得一样——四十关这个故事没有结尾。所以第一次凑满 120 颗星时，
结算卡换成另一张：标题 `四十关 · 全三星`，两行数字改成 `星数 120 / 120` + `关卡 40 / 40`，徽章留空。

- 判据**现算**（遍历 40 关的 `_stars_of_idx`），不靠累加计数器 —— 删档、改判据、存档写一半都不会留假状态
- `allstar_ack` 落盘只认一次（这张卡只该看一次）；`demo_mode` 下不落盘也不弹
- **不能照搬单关那两行**：`target_speed` 是第 40 关的目标，会打出一个红叉 —— 在一张「你全做完了」的卡上出现叉是最伤人的错

## 存档

`%APPDATA%\Godot\app_userdata\Sheep Counter\progress.json`

结构是 `{ver, levels:{成绩}, programs:{你写的程序}, allstar:bool}`。旧工程名（HRM Clone Prototype）的存档会在首次启动时**自动迁移**过来。

编辑器跑工程和独立 exe 读的是同一个文件，进度互通。想从头玩就删掉它。

`settings.cfg` 在同一个目录，分两节：

```ini
[i18n]
lang=zh_Hant
manual=true     # 玩家自己点过切换才写；没写过 = 每次重新按 IP 探

[audio]
volume=0.8
```

**写之前必须先 `load()` 一次**，只改自己那一节再存 —— 直接 `save()` 一个新配置会把另一节冲掉
（测试钉住了：改音量不影响语言，改语言不把音量打回 80%）。

## 多语言（简中原文 / 繁体 / 英文）

**源码里写的简中原文就是整张翻译表的键。** 漏翻不会崩，只会退回中文；而且能被
`tools/scan_strings.py --check` 一条条抓出来 —— 这是整套方案的地基。

| 语言 | 怎么来的 |
|---|---|
| `zh_Hans` 简中 | 源码原文，恒等。**只作原文语，不给玩家选**（测试也钉在这一门上） |
| `zh_Hant` 繁中 | 运行时四趟转换：`hant_pre`（词）→ `hant_char`（字）→ `hant_post`（台湾用词）→ `hant_twchar`（台湾字形） |
| `en` 英文 | 查表（156 条界面 + 116 条关卡） |

繁体不手写第二份：字典从 OpenCC 仓库取（`tools/opencc/`），用 `tools/gen_hant.py` **离线烘焙**进
`data/i18n.json`。运行时只带这张 126KB 的表，不联网、不依赖 OpenCC。
那七条 OpenCC 不管的游戏用词（程序→程式、循环→迴圈、数据→資料、鼠标→滑鼠、设置→設定、
运行→執行、重置→重設）写死在 `MANUAL` 表里，且**流水线两边都先过一遍**，
否则每次烘焙都会把它们当成「差异」报出来。

### 首次启动判定：先看人，再看 IP

| 顺序 | 依据 | 结果 |
|---|---|---|
| 1 | `--lang=` / `--country=` | 命令行钉死，测试与截图用 |
| 2 | `settings.cfg` 里的手选 | 玩家选过就不再探 IP |
| 3 | 系统语言 | `zh*` → 繁中，其余 → 英文（IP 全不通时的兜底） |
| 4 | IP 归属 | 异步探测，通了再切；四条源依次兜底、超时 3 秒 |

**默认中文（繁体）的地区：中国大陆 `CN`、中国台湾 `TW`、中国香港 `HK`、中国澳门 `MO`。**
其余一律英文 —— 包括新加坡、马来西亚（华人多，但系统默认工作语言是英语）。
判据就是 `scripts/i18n.gd` 里的 `const ZH_REGIONS := ["CN", "TW", "HK", "MO"]`。

### 切换入口

抬头右上角一枚按钮，按钮上写的是**按了会变成的那门语言**（`繁中` / `EN`），而且永远用它自己的
语言写 —— 英文界面里出现「繁中」不是漏翻，是必须长这样。

切换 = **整屏重建**（`_relocalize()`，几十毫秒）。逐个控件回填要维护一份「控件 ↔ 文案」清单，
漏一项就永远错一项且不报错；重建天然覆盖全部文案，代价只是把程序、当前关、选中行、提示级别搬过去。

### 加文案 / 改文案

1. 直接在源码里写中文
2. `python tools/gen_hant.py` —— 体检：跟 OpenCC 完整 `s2twp` 逐条比，有差异会打出来
3. `python tools/scan_strings.py --dump` —— 找出还没进 `data/i18n.json` 的句子
4. 补 `en` 那条，再 `--check` 到 100%

## 界面

- **抬头**：产品名 · 关号徽章（点它展开牧场地图）· 三颗星 · 「卡住了？看提示」· 手动翻页 · 语言切换 · 设置
- **舞台顶上**：一块米色木牌，写着本关目标（17px 加粗）+ `INBOX … → OUTBOX …`；
  点了提示以后，牌子下面再挂一张浅黄纸条
- **左**：程序编辑器（编号 / 标签 / 指令 / 参数）。跳转线走左边的车道，**车道数由这个程序需要几条决定**——
  没有跳转就不缩进，有五条就整体右移 60px；线按「目标标签」上色（a 黄 / b 青 / c 珊瑚 / d 紫）
- **右**：本关开放的指令牌（拖进左边就是一行代码）
- **下**：明亮的牧场——羊圈（待数）、木牌（内存）、栅栏（输出）、牧羊人、云与树
- **底**：运行 / 单步 / 重置 / 清空，加 SIZE·SPEED·周期 三块凹槽仪表

牧场地图不常驻：它只在「想去别关」时才需要，收在抬头的关号徽章里。点开是一张 4×5 的大地砖
（84px 一块），**40 关分两页**，打开时自动翻到当前关那页。四种地砖：琥珀=已通关、白框=当前关、
墨绿底+绿框=**已经选中、等你确认**、深蓝=还没到。

点一块地只是**预选**，按底下那颗绿按钮「进入第 N 关 ›」才真的换关 ——
换关会存盘、会换掉编辑区，这种擦不掉的动作不该由一次误触决定。

## 加一关

两条路，选一条：

**A. 手写 json** —— 往 `data/levels.json` 追加一项：

```json
{
  "id": 41, "name": "New Night", "cn": "新的一夜",
  "goal": "一句话说明",
  "hint": "第一级：点出关键洞察",
  "hint2": "第二级：用哪几条指令",
  "inbox": [1, 2, 3], "outbox": [2, 4, 6],
  "allowed": ["INBOX", "OUTBOX", "MOVETO", "COPYFROM", "ADD", "JUMP"],
  "mem_size": 2, "mem_init": [],
  "ref": ["a:INBOX", "MOVETO 0", "COPYFROM 0", "ADD 0", "OUTBOX", "JUMP a"]
}
```

**B. 用设计器** —— 21–40 关是这么来的，比自己算 outbox 快得多：

1. 在 `tools/design_levels.py` 里加一个 `lv(...)`，**只写 `inbox`、不写 `outbox`**
2. `python tools/design_levels.py --dump` —— 它用 Python 复刻的 VM 跑一遍参考解，
   把真实输出打出来，顺手把「`JUMP` 之后忘了清手」这类错误自动补掉
3. 人工看一眼输出对不对（这一步不能自动化：对不对是题目的事，不是语法的事）
4. `--sort --write` 写回 json，它按难度分重排 21 关往后并重编 id
5. 跑 `tests/test_levels.gd`，这次用的是**真的 Godot VM**

注意事项：

- SIZE / SPEED 目标值由参考解自动算出，不用手填
- `ref` 里 `a:` 前缀表示该行是跳转标签
- `mem_init` 可以预置木牌常量（如第 40 关预置了 99 和 −99 当「初始最低/最高」）
- `hint` 只写思路，别写代码；`hint2` 才给指令组合
- **`JUMPZ` / `JUMPN` 不消耗手上的值**：跳过去的标签第一条几乎都得先 `MOVETO` 到一格废纸篓
- **废纸篓别和计数器共用一格**：清手会把它写坏，表现是「循环少跑两圈」，不报错
- 改完跑一遍回归测试，确认不是死关；再跑 `tools/curve_plot.py` 看曲线有没有塌
- **新关的 `goal` / `hint` / `hint2` 是翻译表的 key**：`name` 走英文原名（不翻），`cn` 走繁体。
  加完关务必 `python tools/scan_strings.py --check` —— 它会把没进 `data/i18n.json` 的新句子
  一条条列出来，`--dump` 则是整理好的待翻清单

## 已知取舍

- 舞台全是 `_draw` 现画的几何色块，**没有一张位图**。好处是改配色/比例不用动资源，坏处是到不了手绘的精致度
- 音效全是代码合成的正弦波，**没有一张音频文件、也没有背景音乐**。好处是音高能跟着 COMBO 和「数到第几只」实时变，坏处是音色比不上采样
- 繁体是「转换」来的，不是人写的：跟 OpenCC 逐条对齐过（0 差异），但文案风格仍是简中那句的直译腔
- 英文界面下有些字缩了（卡面 `Jump if <0`、挂牌 `3 of 8`）—— 都是为了不裁字，中文那边不受影响
- 羊只有一套朝向 + 一条抛物线跳跃，没有逐帧行走动画
