# 项目执行规范：先学习，再制作

适用范围：本目录及其所有子目录。用户当前要求与运行环境约束优先。本文是项目工作约定，不代表模型内部训练规范。

## 每次开工的必读顺序

新建场景、重建流程或首次接手本项目时，必须先完成以下学习，再执行建模与批量修改：

1. 阅读 [README.md](README.md)，确认文件结构、两个案例的主工程及实时版本。
2. 完整阅读 [PIPELINE.md](docs/PIPELINE.md) 和 [CASE_LESSONS.md](docs/CASE_LESSONS.md)。
3. 阅读 [场景制作与视觉验收指南](learning/materials/Blender_Agent_场景制作与视觉验收指南.md)，包括文末资料来源及证据边界。
4. 阅读两套学习案例的 README、`01_analysis.md`、`scene_spec.json`、`cameras.json`、`validation.json`；室内还要读 `scene_as_built.json`。
5. 实际查看两套案例的 `reference.png`、`renders/05_final.png`、白模和至少一个反向或俯视结果。通过各自 `index.html` 可浏览完整过程。只读文字不能代替看图。
6. 阅读与本次工作相关的 `source/build_scene.py` 或 `source/build_lane.py`，理解清空场景、阶段输入输出、材质保留、相机、保存与验证逻辑。学习包已经展开在 `scenes/`；ZIP 用于移交与复核，无需重复解压到工作目录。
7. 在本次场景的 `work_state.md` 记录已读资料、至少三条将落实到本任务的经验、交付范围、当前检查点和下一步。

同一任务的后续接续：先读本规范、该场景的 `work_state.md`、最新评审记录及涉及的规范章节，保留已完成阶段；不要为满足学习要求重新搭建。资料缺失时先查找并记录缺口，不能声称已读。

## 必须遵守的制作规则

- 单图只支持一种可能的空间解释。将可见事实、推断和设计补全分开；米制尺寸与高差没有测量依据时必须标为假设。
- 先约定单镜头、多视角浏览或游戏引擎交付范围。八张诊断图不等于完整可探索关卡。
- 执行“需求与分析 → 统一布局/高差 → 相机与白模 → 样板资产 → 场景扩展 → 材质 → 灯光 → 多视角修复 → 重开验证 → 打包”流程。每阶段提供实际预览、指出差异并记录修改。
- 白模构图未达到本次约定标准，不进入大规模细节制作。完成每阶段后默认自行评审并继续，不要求用户逐步批准。
- 所有交付的场景预览必须来自对应 Blender 工程实际渲染。生成参考图、纹理和设计图必须另行标注；不得冒充三维成果。
- 多视角从同一工程中的相机产生。隐藏顶棚、关雾、增加诊断灯等操作须记录，并在渲染后恢复。
- 使用独立后台进程执行会清空场景的模式。修改已有成果前保存新检查点；非幂等阶段从前一检查点恢复，不能在成品上反复追加。
- 脚本以自身位置推导项目路径；依赖使用相对路径或打包。创建自有资产，保留来源与生成提示词，不擅自上传用户图片或引入付费服务。
- 分开保存 Cycles 成片版和 EEVEE 浏览版；关闭浏览版叠加与 Gizmos，检查雾与透明材质。明确两种渲染器的视觉差异。
- 技术校验和美术评审分别记录。对象数、文件存在、脚本退出成功都不能证明参考图还原程度；没有测量不得报告相似度百分比或帧率。
- 交付前在独立进程重开最终文件、检查依赖并实际渲染。更新说明和学习包，验证包内工程与目录中的工程一致。
- 不覆盖这两套学习案例来试验新任务。新场景建在 `scenes/<SceneName>/`；改进案例时使用版本/检查点，明确变更与验证。

## 工具与边界

实际案例通过本地 Blender 4.2.3 LTS + Python 脚本完成，不依赖 MCP。MCP、CLI 和 GUI 是操作通道，必须保留观察和修正闭环。当前机器路径与复现注意事项见 README；不要假定其他机器具有相同软件、字体和 GPU。

新任务模板位于 [templates/](templates/)。迁移清单与校验报告位于 `docs/`。旧日志和历史 ZIP 是学习证据，不能把其失败运行当作当前可执行流程。

## 可见内容保留门槛（2026-11-10 增补）

开工还须阅读 [VISIBLE_CONTENT_GATE.md](docs/VISIBLE_CONTENT_GATE.md)。按物件记录原图可见轮廓、数量、图案和排列；分别检查对象存在、外观保留和成片可见。可见部分按证据保留，隐藏部分才设计补全。主资产占位不得自动通过最终外观验收。
