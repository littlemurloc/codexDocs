# 两套场景的实际经验与限制

记录日期：2026-11-10。本页总结项目内已有工程、阶段图、代码和验证文件；并非模型能力基准。公开案例与资料另见 `learning/materials/` 的指南。本次本地案例是对方法的实际试做，不能据此声称已经复现指南中引用的其他项目。

## 案例一：玩偶房间

输入：一张暗调室内图。主要约束是中心圆桌与玩偶、前景角色、左右柜体、墙上涂鸦、顶灯与侧向光。所有场景预览来自 Blender，未用图像生成替代成片。

| 实际发现 | 采取的修正 | 可复用经验 | 证据位置（相对案例目录） |
|---|---|---|---|
| 第一版柜体挤向中央、吊灯偏低 | 柜体向外移、提高吊灯和空间上部 | 白模先校对占画面比例与负空间 | `renders/03_blockout_v1.png` 与 `03_blockout.png`、`source/build_scene.py` |
| 第一轮侧光过亮，下一轮整体偏暗 | 调整中心光池、光束与局部斜光，再做暗角 | 光照需要候选对照；先看主体与背景亮度关系 | `05_lighting_v1.png`、`05_lighting_v2.png` 与 `05_final.png` |
| 简单程序玩偶能表达位置，难以达到原图轮廓和气质 | 作为学习占位保留，明确差异 | 主视觉资产需专项精修；几何数量无法代替造型质量 | `renders/view_table_detail.png`、`reference.png` |
| 初始设计与构图修正后的数值不同 | 保存实际对象边界与最终脚本 | 方案和实现必须区分；未来应同步配置 | `scene_spec.json` 与 `scene_as_built.json` |
| 反向暴露开放拍摄面；俯视被顶棚、雾和吊灯遮挡 | 说明拍摄面限制，俯视使用切面和诊断灯 | 多视角要揭示真实建成范围，诊断修改须声明 | `cameras.json`、`README.md`、反向/俯视图 |
| Cycles 浏览转动后先出现噪点 | 另存 EEVEE、关闭叠加与 Gizmos，隐藏视口雾 | 浏览版与成片版分别保存和检查 | `scene.blend` 与 `scene_realtime.blend` |

设计尺度示例：桌面顶约 0.94 m、地毯顶约 0.025 m；这些是建模假设，不是测量结果。光源对应的右侧窗洞也是设计解释。

原技术记录：390 个对象、243 个网格、8 个相机，无缺失外部图像；曾在独立进程重开并输出 720×480 图。迁移后的再检查另见 `docs/relocation_checks/`。这些检查证明工程可用，不证明与参考高度相似。

仍需改进：玩偶和角色造型、家具形变与结构、表面磨损、涂鸦风格及主镜头精确对照。房间未建设为完整可玩关卡。

## 案例二：雨后樱花街

输入：一张湿润古街氛围图。难点来自街道纵深、多组重复但应有差异的建筑、檐口与桥、湿地面反射、招牌、树冠遮挡和远处空气层次；难度不适合用“室外固定是室内多少倍”描述。

| 实际发现 | 采取的修正 | 可复用经验 | 证据位置（相对案例目录） |
|---|---|---|---|
| 白模保存再开后，未使用材质被清理，后续出现 `KeyError: Old door planks` | 保存时标记必要材质 `use_fake_user=True` | 每阶段必须能在新进程继续，不能依赖内存残留 | `source/build_lane.py` 的 `save()`；历史日志在 `archive/run_logs/` |
| 石板缝过宽、起伏偏大，像玩具地砖 | 减小缝隙与高度随机量 | 先做近景样板，按真实视觉尺度控制微细节 | `renders/04_ground_detail.png`、源码石板参数 |
| 初版积水像银色薄片 | 金属度降到 0、调整透射/粗糙度，并加入连续湿润变化 | 水层、湿材质和石板高程应分别处理 | `04_dressed_v1.png` 与 `04_dressed.png`、材质代码 |
| 树冠被屋顶遮挡，花瓣形状生硬 | 调整树的位置/高度/冠幅，修改花瓣形状 | 树本身存在不等于在主镜头中可见；近景和遮挡都要看 | 最终主镜头、`view_right_detail.png`、源码树参数 |
| 多视角发现远端建筑下缺地面、模块之间漏天 | 延伸地基/地面、封接缝、补完整坡屋顶，重新渲染 | 主镜头遮住的问题会在斜看和俯视暴露；先修结构再继续 | `05_before_multiview_fixes.png` 与 `05_final.png`；`integration()` |
| 多处用重复模块，整体仍偏规整 | 当前原型保留并明确限制 | 模块扩展之后仍需轮廓、尺度、材质和布景的设计变体 | `renders/view_high.png`、`view_mid_street.png` |
| 需要可迁移纹理和中文招牌 | 项目保留图集与提示词，工程打包图像/字体 | 打开工程与从零重建的依赖要分别说明 | `assets/`、`source/build_lane.py`、`validation.json` |

设计尺度示例：主街宽约 5.2 m，路缘顶约 0.27 m，建筑约 5–7 m，桥面约 3.95 m；街道总体平缓，局部起伏是设计值。浅水面与石板独立。

纹理来源：内置 image_gen 生成四分区底色图集，详见 `assets/generation_prompt.md`；其余几何、灯具、招牌、树枝与花瓣由脚本构建。该图集不是扫描 PBR 材料。最终图由 Blender 渲染。

原技术记录：672 个对象、614 个网格、8 个相机，`Material Atlas` 已打包，无缺失外部图像，独立进程重开并实际渲染。字体也随工程打包；从零重建仍需可用的中文字体路径。

仍需改进：与参考相比色调更冷、建筑变化不足、植被自然度和屋面细节有限，水面与磨损仍较简化。室内、背面和远端没有按全面探索要求交付。

## 两次实践提炼出的执行规则

1. **规模先收敛。** 先匹配主镜头体块和关键轮廓，再增加细节；室外先做一段近景立面/地面样板，避免把错误复制到整条街。
2. **支撑与连续性必须跨镜头检查。** 主视角漂亮不能证明地面延伸、房屋背面、屋顶和模块接缝完整。
3. **阶段检查点必须可独立续跑。** 先重开前一阶段，再执行下一阶段；保存必需材质和外部依赖，保留非幂等阶段的输入文件。
4. **修改后同步所有成果。** 主工程修复后重新输出受影响视图、验证记录与实时版本，最后刷新 ZIP，避免不同版本分叉。
5. **不同用途分开验收。** 成片检查光影与构图，实时版检查交互视觉；游戏交付另需引擎验证。这两例尚未完成游戏引擎验收。
6. **诚实记录成因与范围。** 单图设计补全、生成纹理、诊断切面、未完成区域及失败尝试均写清；不得凭经验编一个相似度百分比。
7. **GUI 操作必须看结果。** 曾出现组合快捷键执行结果与预期不同，另存为未按预期发生；用文件菜单、窗口标题、实际文件与重开检查确认，不推断按键一定成功。启动接口超时也要检查窗口是否已经出现。

## 旧案例复现注意事项

- 两套主脚本按自身位置推导资源目录，可随案例文件夹移动。
- 室外 `facade`、`dress` 等是顺序追加，重复在成品运行会产生重复资产；应加载前一检查点。
- 室内 `blockout` 会清空场景，且一开始已创建部分细节；其白模是粘土检查，不是连续录像。其他模式也应遵循 README 指定的输入。
- 室内配置函数可能重置曝光等设置；新增改动时应验证配置不会覆盖艺术参数。不得只看函数调用成功。
- 使用已验证的 Blender 4.2.3；此前其他安装路径中的 5.2.3 启动未成功，未对其建立兼容性结论。
- 原始日志里包含旧绝对路径与失败运行。它们是历史证据，不是让新 agent 照抄执行的命令清单。
- 历史室内 ZIP 不含后存的实时版本。当前学习包由 `tools/build_learning_packages.ps1` 生成，以当前案例目录为内容来源。

这些原型没有使用专门的三维扫描、摄影测量或已知真实尺寸进行反演。后续若引入多张真实照片、深度数据或实测尺度，应重新设计对应的重建与误差验证方法；由单图脑补出的多视角不能当作新增观测证据。
