# M4 · 可玩循环

M1–M3 都在证明「规则对不对、数值成不成立」。
这一层要回答的是另一个问题：**有没有人愿意再打一趟。**

那件事测不出来，只能让人真的玩一次。所以 M4 把规则层接成了一个能点的循环：
出发 → 地图 → 战斗 → 结算。

## 交付了什么

```
src/view/expedition_scene.tscn   主场景（也是 project.godot 的入口）
src/view/expedition_scene.gd     四个界面 + 输入 + 自检
src/view/dd_theme.gd             共用色板与文本工具
src/view/main.tscn               M1 战斗切片，保留可单独跑
```

四个界面，全程自绘、零外部素材：

| 界面 | 内容 | 操作 |
|---|---|---|
| 出发 | 三种规格（短/中/长 × 1/3/5 级队），标出预期强度 | 点一行出发 |
| 地图 | 光照条、口粮/火把/休整、路线节点、队伍卡、行程记录 | 继续前进 / 点火把 / 休整 / 撤退 |
| 战斗 | 敌我站位、血量压力条、事件流水、技能面板 | 点技能 → 点目标 |
| 结算 | 推进、遭遇、阵亡、崩溃、终局血量压力、剩余补给 | 再来一趟 |

快捷键：`F` 点火把、`C` 休整、`Esc` 撤退、`空格` 自动代打一回合。

## 让规则层「可以停下来」

界面不能一次跑完整场战斗，但规则层原本只有一个 `run_round()`（同步跑完一轮）。
硬把 `await` 塞进规则层是错的：规则层是 `RefCounted`，没有信号，
也不该为了界面去引一套异步机制。

所以把它拆成两套驱动，共用同一段结算逻辑：

```gdscript
# 同步（bench / 测试 / 自动模式）
battle.run_round()

# 逐步（界面）
battle.begin_round()
while battle.step_turn():
    if battle.awaiting_input != null:
        battle.submit_choice(action, targets)
```

`step_turn()` 处理一个单位后返回；碰到英雄行动就把 `awaiting_input` 置上并停下，
等界面调 `submit_choice()`。`run_round()` 现在只是上面那段的同步包装。

**关键约束：两套必须走出完全相同的战斗。**
`tests/test_expedition.gd` 里有一条专门的断言：同一颗种子，
逐步驱动（用 AI 兜底决策）与同步驱动的轮数、胜方、每个英雄的血量/压力/生死
必须完全一致。这条断言是给表现层兜底的——哪天界面上的战斗和 bench 里的不一样，
说明规则层被界面需求带歪了。

## 端到端自检：界面接线断了，规则测试不会红

规则层的 182 项断言全绿，也不能说明「点了技能有反应」。
这类断裂最典型的形态是：按钮矩形算错、`player_options` 返回空、
提交后 `awaiting_input` 没清掉——全都不报错，只是玩家点了没反应。

所以场景自带一个自检模式，走的是界面自己的那条路：

```bash
godot --headless --path . -- --selftest --size=medium --level=3
# SELFTEST 状态=3 推进=10/10 玩家出手=139 结束原因=complete
# SELFTEST PASS
```

它做的事就是：出发 → 推进地图 → 遇到战斗 → 反复「选第 1 个技能 → 选第 1 个合法目标」
→ 打完 → 结算。三种规格都跑通，`acted > 0` 且到达结算屏才算 PASS。

同一套代码还给了三个截图/冒烟开关：

| 参数 | 作用 |
|---|---|
| `--start` | 直接进地图（跳过出发屏），截图用 |
| `--to-result` | 用 AI 跑完一整趟再展示结算屏 |
| `--auto` / `--auto-map` | 自动推进（前者连战斗一起代打） |
| `--fast` | 把战斗步进压到 0.02 秒 |

## 真的玩一遍之后发现的四件事

这些不是指标能吐出来的，是坐下点鼠标才浮出来的。

**1. 长图 5 级队是断崖，不是斜坡。**
自检用「永远选第 1 个技能」的贪心策略打 long/Lv5：第 4 步就团灭（4/18 步）。
短图 1 级队则 6/6 走完、终局血量 96%。
和 M3 的量化结论一致，但手感上更明确：**它不是「难」，是「没准备好就必死」**。
真正需要补的是「玩家能不能提前判断这趟不该来」——现在只能靠出发屏上那句提示。

**2. 撤退按钮没有存在感。**
它在界面上，逻辑也对（全员 +20 压力、远征判负），但没有任何东西推动玩家去点它。
撤退的收益是「保住剩下的人」，可这一版**没有跨远征的持久化**，
人死了就是死了，下一趟还是满编四人。于是撤退 = 纯亏。
这正是「资源层做完了、元层没做」的典型症状。

**3. 战斗里的信息量刚好不够。**
技能面板给出了「伤害区间 / 修正 / 命中修正 / 效果数」，
但没有给出「打这个目标大概掉多少血」——因为护甲、闪避、buff 都要算进去。
玩家第一次点技能时无法判断这一下是否值得，只能靠事后看伤害数字。
DD1 的解法是面板直接显示预期伤害区间（含修正），这一点值得抄。

**4. 节奏偏慢，但慢在正确的地方。**
一场战斗 4–6 轮、每轮 7 个单位，全部点完约 20 次点击。
这不是「点击太多」，而是「每次点击都需要判断」——这是想要的。
问题只在于**动画反馈太少**：伤害数字飘一下就没了，看不出谁打谁。
自绘版能补的只有颜色和飘字，真正的解法要等美术。

## 怎么跑

```bash
GODOT="D:/XT/godot/Godot_v4.7.2-stable_win64_console.exe"

# 正常玩
"$GODOT" --path .

# M1 的战斗切片（自动跑）
"$GODOT" --path . --script res://tests/dump_battle.gd

# 端到端自检
"$GODOT" --headless --path . -- --selftest --size=medium --level=3

# 截图
"$GODOT" --path . -- --start     --shot=shots/exp_map.png    --shot-at=1.2
"$GODOT" --path . -- --auto-map  --shot=shots/exp_battle.png --shot-at=3.6
"$GODOT" --path . -- --to-result --shot=shots/exp_result.png --shot-at=1.0
```

现有截图在 `shots/`：`exp_map.png`、`exp_battle.png`、`exp_result.png`。

## 界面上刻意没做的

- **不做地图生成**：路线是线性节点条，来自 `RouteGen` 从地图参数抽的遭遇序列。
  真正的网格地图（分支、回头、奇物）是下一层的事，套进来会把这一版的可测性打散。
- **不做战利品与城镇**：结算只报「走了几步、死了几个人」。
  没有金币/传家宝/装备，因为那需要一整套元层循环，不是一屏能装下的。
- **不做美术与音效**：全部色块 + 文字。理由和 M1 一样——
  一旦像了，人就会被「像不像」骗过去。

## 已知局限

- **AI 与玩家共用同一套动作规则，但 AI 不会撤退、不会用道具**。
  自动模式（`--auto`）只用于冒烟和截图，它的胜负不代表玩家水平。
- **一场战斗内不能撤退**。DD1 允许战斗中逃跑（`combat_retreat_chance` 已在数据里），
  这里只在战斗外提供撤退。
- **崩溃/美德的「失控动作」只有摆烂一种**。数据里只有面板减益，行为在 exe 里。
- **装备阶写死在路线里**：一趟远征内不会换装备，也没有战利品升级。
- **没有存档**：关掉窗口，这趟远征就没了。
