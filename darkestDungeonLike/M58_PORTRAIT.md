## 3. P1：战斗屏

### 3.1 站位

横屏是「我方占左半、敌方占右半，前锋在中间相接」，8 格并排需要 1360px。
竖屏放不下，改成**两队共用同一组 4 列**：

```gdscript
var x0: float = (size.x - slot * 4.0) * 0.5
if is_enemy: return x0 + rk * slot + slot * 0.5
return x0 + (3 - rk) * slot + slot * 0.5
```

- `slot` 从 `(size.x - 80)/7` 改成 `(size.x - 48)/4` → 750 下 175.5，4 列 = 702
- 敌方 rank1 在左、我方 rank1 在右，两队前锋隔着中缝相对

常量：

| 常量 | 横屏 | 竖屏 |
|---|---|---|
| GROUND_ENEMY | 250 | **348** |
| GROUND_PARTY | 470 | **652** |
| SPRITE_H | 180 | **240** |
| SLOT_W | 170 | 175（实际由 `_battle_slot_w()` 算） |

人物从 180 放到 240：竖屏纵向空间多，210 时人物偏小、屏幕空。

### 3.2 底部三段（顺序照 M1 定稿）

```
日志摘要条 44 高 → 次级操作 92 高 → 技能区 246 高（贴底）
```

- 三段从底部往上叠：`scl.y = size.y - 44 - 246`
- **技能压在最底**：它是全场最高频动作，占一级拇指落点
- 「调整站位 / 跳过」上移一层（一回合一次，低频）
- 技能区固定两行（`66 + 90*2`）：所有职业最多 7 技能，两行一定放得下；
  不按实际数量收缩，否则切人时面板高度跳、敌方回合缩成一条

### 3.3 日志

- 常驻只剩一行最近记录 + 「▾ 全部」
- 点整条展开半透明浮层（`_draw_log_float`），浮层里是原来的 `_draw_log_panel`
- 信息没删，只是从「一直看得见」变「点开看得见」

### 3.4 技能卡

横屏 3 列 × 3 行、卡高 34（被 206 高的面板逼的）。
竖屏 4 列 × 2 行、卡高 **80**，「狂热点名」这类四字名不用截断。

## 7. 横向滚动区（后补）

名册 15 人、建筑 8 个，竖屏一行放不下；多行网格又会让**高度跟着人数变**——
5 个人两行、10 个人三行，下面的建筑区和出发区全跟着往下跳。

统一改成「单行 + 横向滑动」，高度定死：

| 区 | 卡片 | 可见 | 定高 |
|---|---|---|---|
| 名册 `roster` | 150 × 124 | 4.4 张 | **140** |
| 建筑 `blds` | 190 × 162 | 3.7 张 | **178** |

实现（`_hscroll_*`，共用一套）：

1. **裁剪**：Godot 的自绘 `_draw()` 没有 scissor API
   （`canvas_item_set_clip_rect` 不存在，`clip_contents` 只管子节点），
   所以用「背景色回涂」—— 卡片溢出的部分用 `DdTheme.BG` 盖回去，最后补面板边框。
   滚动区左右是页边距，回涂不会伤到别的元素。
2. **点击 vs 拖动**：按下先不触发点击，抬手时看位移是否超过 **8px**。
   不设死区的话，手指按下抖 2px 就会把「点卡片」吃成「拖动」。
3. **吸附**：抬手吸附到整卡边界，不停在半张卡上。
4. **命中裁剪**：`_add_hit` 在滚动区内会把矩形裁到面板范围，
   否则滚出去一半的卡片在面板外也能点到。
5. **滑条**：底部一条 3px 的灰条，长度按可见比例，位置跟着偏移走 ——
   没有它，玩家会以为只有 4 张。

验收参数：`--scroll=roster:150` / `--scroll=blds:200`，把某个区钉在指定偏移，
用来验证「偏移之后的绘制是否正确」（拖动本身没法用命令行模拟）。

截图：`shots/m58_roster_scroll.png`、`shots/m58_build_scroll.png`。

## 8. 城镇屏：把屏底那块空白吃掉（A+B）

改之前量了一下：**内容只画到 y=678，下面 656px 是空的，占整屏 49%**。

原因是两条：
1. 所有区块都是「上一个的底 + 间距」正向堆叠，没有一处按 `size.y` 反算；
2. 尺寸全是 1280×760 时代的绝对值，竖屏多出来的 574px 没有人认领。

（战斗屏没这个问题，因为它的底部三段是 `size.y - 44 - scl_h` 反算的。）

| 区块 | 改前 | 改后 |

| 建筑 | 178 | **340** |

任务卡从 4 张并排改成 2×2，是因为 161 宽的卡装不下「会遇到什么怪」这一行 ——
而那是点进出发前唯一能看的信息。改成 339 宽之后，情报和「够格几人」都能展开。

## 12. 战斗背景：横图对半切

原来整张 1280×422 cover 到 750×604：等比例没错，但**横向裁掉 60%**，
只看得到画面正中间一条，两侧的房间结构全丢。

改成从中间竖切，左右两半各贴一段：

| 半张 | 来源 | 贴到 |
|---|---|---|
| 右半 | 横版里**敌人**所在的那侧 | 上方敌方区（48 .. 330） |
| 左半 | 横版里**我方**所在的那侧 | 下方我方区（330 .. 620） |

不用改素材 —— `draw_texture_rect_region` 直接取源图的一半：

```gdscript
var hw: float = ts.x * 0.5
var k: float = maxf(dst.size.x / hw, dst.size.y / ts.y)
var sx: float = float(half) * hw + (hw - dst.size.x / k) * 0.5
draw_texture_rect_region(tex, dst, Rect2(sx, (ts.y - dst.size.y / k) * 0.5, ...), tint)
```

两段在 `GROUND_ENEMY` 处相接，接缝压一条 40 高、中间浓两头化开的暗带
（等浓度的矩形会在上下各留一道硬边，比接缝本身还显眼）。

效果：两段各自的宽高比接近 1.5（原图半张就是 640×422），
比整张铺满竖屏的 3 倍变形自然得多，而且上下两段分别是「敌方侧」和「我方侧」，
和站位对得上。

## 13. 顶部安全区（刘海）

真机上刘海/状态栏会压住顶部状态条。做法不是逐屏改坐标，而是**把根 Control 整体下移**：

```gdscript
offset_top = _safe_top      # 内容整体下移
offset_bottom = 0.0         # 底边不动 → size.y 自动少一截
```

这样所有「贴底」的布局（战斗底部三段、地图按钮、各屏返回键、任务卡）
都按缩短后的 `size.y` 重算，**一行代码让出安全区，不用逐屏动**。

刘海那块用一块纯黑 `ColorRect` 盖住（比窗口清屏色更深，和手机边框连成一片）。

安全区高度来源：

| 环境 | 来源 |
|---|---|
| 真机（Android） | `DisplayServer.get_display_safe_area().position.y` 按视口比例换算 |
| 桌面验收 | `--safe-top=90` 手动指定 |

上限 160 —— 超过这个值说明取到的不是刘海而是别的（比如软键盘弹出时的可用区）。

验收：`godot --path . -- --start --battle --safe-top=90 --shot=shots/m58_safetop_battle.png --shot-at=1.2`

截图里顶部 90 行是纯黑（像素校验 `<8` 全真），内容从 90 开始，底部仍然贴边。

> **M63 补了底部，并且发现「只让出空间还不够」**，见第 18 节。

## 14. 建筑立绘出框 + B 区改成「左关卡 / 右难度」

### A 区：立绘画到邻卡上

`_draw_building_card` 原来**只按高度**贴合：

```gdscript
var k: float = ih / float(tex.get_height())   # ih = 卡片图区高
var w: float = tex.get_width() * k            # 宽度不设上限
```

八张建筑图里七张算出来比卡片宽（卡片 190）：

| 图 | 尺寸 | 算出的绘制宽 |
|---|---|---|
| `wagon` | 285×220 | **381** |
| `smith` | 221×220 | **295** |
| `guild` | 197×220 | 263 |
| `tavern` | 193×220 | 258 |

于是立绘直接画到相邻卡片上。从单张卡片看不出异常，整排铺开才像「几个按钮互相盖住」。

改成 **contain + 底对齐**：

```gdscript
var k: float = minf((rb.size.x - 8.0) / tw, ih / th)   # 宽高都不得越界
var iy: float = rb.position.y + 2.0 + (ih - h)          # 底边对齐文字条
```

底对齐而不是居中：这几张都是「站在建筑里的人」，脚踩同一条线才不像浮空。
代价是宽图（`wagon` 比例 1.30）会被缩到 182×141，上方留白多；换来的是**谁都不越界**。

| 建筑卡 | 340 高 | 300 高（给 B 区腾 40） |
| 名册 | 220 高 | 210 高 |

## 15. 点击反馈全盘梳理

### 扫出来的三个问题

| # | 问题 | 范围 |
|---|---|---|
| 1 | **没有「按下」态**：`_press_begin` 直接调 `_on_click`，手指落下、界面已经切走 | 全部 |
| 2 | **只有一部分控件有 hover**：19 处自定义热区里 8 处完全没有 | 卡片类 |
| 3 | **触摸设备上 `_mouse` 不更新**：`InputEventScreenTouch` 没同步指针，手机上 hover 恒假 | 全部 |

第 1 条最要紧：它不只是「缺一层视觉」，而是**按错了没法反悔**——
按下即触发，手指还没抬起来就已经切屏了。

### 改法：按下只记录，抬手才触发

```
press  → _press_begin(): 记录 _press_id，不执行
       ↓（这段时间控件画成按下态）
release → _press_end(): 抬手位置还在同一控件上 → 才 _activate_id()
```

配套把命中判定收敛成一个 `_hit_id_at(pos)`（地图房间 > 战斗目标 > 普通按钮，
和原来的 `_on_click` 优先级一致）。按下和抬手各查一次，两次答案相同才触发 ——
判定逻辑只能有一份，否则迟早会分叉。

> 这回顺带修掉一个潜在的误触点：按住一张卡、手指滑到隔壁再抬起，
> 以前会按「抬起位置」触发（点到隔壁），现在直接作废。

### 按下态长什么样

| 控件类型 | 常态 | 悬停 | 按下 |
|---|---|---|---|
| 普通按钮（`_draw_buttons`） | `BTN` | `BTN_HOVER` + `DIM` 1px | `BTN_ACTIVE` + 内凹 `PANEL_DEEP` 2px，**文字下沉 1px** |
| 卡片（`_hit_overlay`） | 原底色 | 白色 4.5% + `DIM` 1px | 白色 10% + `DIM` 2px |
| 战斗技能格 | `BTN` | `BTN_HOVER` | 白 10% + `DIM` 2px（压过「已选中」的金框） |
| 战斗单位 | 无 | `DIM` 1px 地环 | `LIGHT` 3px 地环 |
| 地图房间 | 无 | 白 4.5% | 白 10% |

按下态用 `BTN_ACTIVE`(#3a4453) 而不是「`BTN_HOVER` 再亮一档」：
后者和 hover 只差三个色阶，手指盖着根本分不出来。

### 覆盖情况

| 类别 | 数量 | 反馈来源 |
|---|---|---|
| `_add_button` | 43 | `_draw_buttons()` 统一三态 |
| `_add_hit` 自定义热区 | 19 | `_hit_state()` / `_hit_overlay()` |
| 战斗单位 | — | `_press_id` 驱动的地环 |
| 地图房间 | — | `_hit_overlay()` |

补上的 8 处：建筑卡、存档槽、日志摘要条、补给 ∓、准备屏行程卡、
准备屏出战卡、建筑屏名册、饰品空槽。

其中补给 `＋/－` 原来是两个悬空的字符，这次补了 40×40 的底 ——
它一直是个「能点但没有形状」的控件。

### 副作用（需要知道）

**按钮从「按下即响应」变成「抬手响应」**。这是触屏的标准行为，
但桌面上手快的人会觉得慢了半拍。换来的是按下反馈 + 可反悔。

**禁用按钮没有按下态**，这是有意的：点不动的东西不该给出「收到了」的信号。
`--press=idle_week` 第一次没验出来就是这个原因 —— 那个档金币是 0，按钮本来就禁用。

### 验收参数

```bash
--press=<id>      # 把某个控件钉在按下态（真机没法模拟「按住」这一帧）
--mouse=x,y       # 把指针钉在某个坐标，验悬停态
```

```bash
godot --path . -- --save=user://probe2.json --press=dungeon:crypts --shot=shots/m58_fb_region.png --shot-at=1.6
godot --path . -- --save=user://fb_new.json --start --battle --press=skill:0 --shot=shots/m58_fb_skill.png --shot-at=0.9
```

### 一个没动的地方

**城镇名册卡看起来像卡片，但不可点**（`_draw_hero_tile` 没有 `_add_hit`）。
它只是展示，所以没有反馈是对的；但视觉上它和后面的建筑卡是同一套外观，
玩家会去点。要么给它加反馈（点了没反应更糟），要么把它画得明显不像按钮。
这一轮没动。

## 16. 名册卡点开详情抽屉

名册卡原来**只展示、不可点**（`_draw_hero_tile` 没有任何 `_add_hit`），
但它的外观和建筑卡是同一套（`_panel` + 顶部 3px 色条 + 悬停变亮），
玩家一定会去点。上一轮扫点击反馈时，它是唯一一个「看起来能点、点了没反应」的控件。

### 做法：底部抽屉，不新开屏

```
点卡片 → 遮罩 + 底部抽屉（高度按技能行数算）
        点遮罩任意处 / 关闭 / ESC → 收起
```

不开新屏是因为：竖屏上「点一个人看细节」是**临时查询**，不是一段流程。
开新屏要「进入 → 看 → 返回」三次跳转，而这三次跳转里玩家想看的还是同一屏。

| 区块 | 内容 |
|---|---|
| 身份 | 头像 92×122、名字、`职业 · Lv · 装备阶`、压力条（200 上限）、出征/阵亡次数 |
| 技能 | 已装备列表（名字 + 描述），标注 `4 / 4` 或「全开」 |
| 饰品 | 两个槽位，空格写「空槽」 |
| 状态 | 正常（绿）/ 病·负·忙（黄）/ 已阵亡（红） |

抽屉高度 `464 + 技能行数 × 34`（技能行数至少按 3 算）：
只带 4 个技能时 600，7 技能的变身职业是 702。
一开始写死 720，4 技能的人在技能和饰品之间空出一大段 —— 那段是给 7 技能预留的，对多数人纯浪费。

### 模态的正确做法

抽屉在 `_draw_town()` 里画，但按钮统一在 `_draw()` 末尾的 `_draw_buttons()` 里画。
第一版就是这样翻车的：**「休整一周」浮在抽屉上面，压在关闭按钮底下露出来。**

两个地方要配合：

```gdscript
# 1) 抽屉打开时，统一按钮层整体跳过
func _draw_buttons() -> void:
    if _state == S_TOWN and not _roster_open.is_empty():
        return

# 2) 命中判定最前面拦截：抽屉内 → 执行，抽屉外 → 关闭
func _hit_id_at(pos):
    if _state == S_TOWN and not _roster_open.is_empty():
        for b in _sheet_hits:
            if (b["rect"] as Rect2).has_point(pos):
                return str(b["id"])
        return "sheet_close"
```

只做第 1 条不够：抽屉盖住了按钮，但 `_buttons` 里的矩形还在，
点击会穿透到「休整一周」「建筑卡」。必须连命中一起拦。

抽屉自己的按钮不进 `_buttons`，进 `_sheet_hits` —— 后者每帧清空、
由 `_draw_hero_sheet()` 重新填，和 `_buttons` 同一条生命周期。

### 顺带的

- **名册卡补了 `_hit_overlay()`**：悬停变亮 + 灰边，按下变亮 + 粗边。
  现在它和建筑卡一样「看起来能点、点了有反应」。
- **ESC 先关抽屉再管撤退**：抽屉是最上一层。
- 「（在公会调整）」「（在仓库调整）」写成括号说明而不是「去公会改」——
  后者读起来像按钮，而这里点不动。

截图：`shots/m58_hero_sheet.png`、`shots/m58_roster_hover.png`（左常态 / 右悬停）。

```bash
godot --path . -- --save=user://probe2.json --click=hero_info:crusader --shot=shots/m58_hero_sheet.png --shot-at=1.6
```

## 18. 底部安全区 + 竖向预算（M63）

### 18.1 底部安全区

顶部（第 13 节）只让出了刘海。手机屏幕底部还有**手势条 / 圆角下巴**，
它压在最下面那排按钮上：按钮照画、照显示，只是**点不到**——
截图验收永远发现不了。

```gdscript
offset_bottom = -_safe_bottom   # 底边收回来，size.y 同步变短
```

| 环境 | 来源 |
|---|---|
| 真机 | `窗口高 -（安全区顶 + 安全区高）`，按视口比例换算 |
| 桌面验收 | `--safe-bottom=52` |

两块黑底板都改成**锚点定位**（`anchor_top/bottom` + offset），
窗口尺寸变了它自己跟着走，不再写死矩形。

### 18.2 只让出空间不够：六屏都是「定高块刚好顶满」

`size.y` 一少 132，原来「刚好贴着按钮」的排版就叠上了。
症状各不相同，而且**都不报错**，只能靠截图抓：

| 屏 | 症状 | 让的地方 |
|---|---|---|
| 城镇 | 难度栏最后一张卡压到页脚说明字上 | 名册 200→150（内容只用到 y+112），建筑 300→235 |
| 地图 | 动作区是贴底的、日志条按队伍条往下排固定 60 → **两者重合**，只在按钮缝隙里露出几个字 | 网格 340→280、房间面板 300→260、日志 60→36 |
| 出发准备 | 出战英雄卡下半排被「出发」按钮切掉 | 补给行 72→58、出战卡 100→84、合计块 228→170 |
| 公会 | 最后一张技能卡底边落到「每人只能带 4 个技能…」下面 | 技能卡 7×142 按剩余空间除、名册步长同理 |
| 建筑内页 | 面板下半截空 400~700px | 底部贴一块「当前技能 + 压力」 |
| 胜利屏 | 内容写死在 56~538，下面空 800px（60%） | 整块竖向居中 |

统一写法：先算 `over = 需要的总高 - 可用高`，再按「先压内容余量大的、后压装饰」
的顺序依次吃。**不要**用固定比例缩放——那会让 1334 下的正常排版也跟着变。

- **中段待办条**：背景图正中是街道阴影（340px 黑），放「这周该处理 2 件事」
  正好把黑填了，并且解释了右上角红点为什么亮。

### 城镇屏已改成场景（M64 第六轮，代码已落地）

`_draw_town()` 现在是：**场景 → header/资源条 → 名牌 → 名册条 → dock**，
最后才是英雄抽屉。顺序错一次就会被场景盖掉（踩过：资源条整条消失）。

**新的「出征」页（S_GATE）**：区域列表 + 难度卡从城镇屏整块搬过去，
行高按剩余高度算（固定 150 会让 1202 高的屏下面空 400px）。
「休整一周」也跟过去，返回走 `gate_back`。

**dock**：城镇 / 出征 / 商店，出征居中放大 + 金环。

**名牌自动避让**：候选顺序 下方 → 上方 → 建筑内底 → 右侧 → 左侧，
取第一个不越界、不压别的建筑、不压 UI 条的。两个必备细节：
1. 中心点先夹回画面内 —— 否则右半出框的建筑（酒馆）所有候选都越界，
   牌子被甩到屏幕中间，看着像别人的；
2. 最后一道保险 `pick.y = min(pick.y, size.y - 194)` —— 商队这种底边沉在
   dock 里的建筑，回退位置正好在 dock 后面，等于没有名牌。

**可交互描边**：用 alpha 膨胀减原图得到 `rim_<id>.png`（不是画方框 ——
方框是「卡片」，不是「这栋楼可点」）。常态 42% 亮度，悬停/按下提到 95%，
同时建筑本体提亮到 1.18。素材在 `assets/art/ui/town/rim/`。

游戏里 size.y 已经扣掉安全区，所以画的时候统一 `y - TOWN_Y0(80)`。

### dock 比例重排（M64 第十二轮）

用户反馈：三颗按钮「比例小、夹子气，跟整条栏比起来留白太多」。

量了一下，问题在**圆占栏高的比例**：

| | 最初 | 第一轮 | 第二轮（定稿） |
|---|---|---|---|
| 栏高 | 160 | 168 | **188** |
| 侧边圆直径 | 60（占 37%） | 76（占 45%） | **92（占 49%）** |
| 中间圆直径 | 82（占 51%） | 98（占 58%） | **118（占 63%）** |
| 图标 | 44 / 62 | 59 / 75 | **71 / 89** |
| 文字 | 12 | 13 | 14 |
| 横向中心 | 0.185 / 0.815 | 0.20 / 0.80 | 0.20 / 0.80 |

**调法要记住：圆先定，栏高跟着圆走**，不是反过来。
第一轮我先加栏高（172）再放大圆，结果上下各空出一圈 ——
栏高只是「圆够不够放」的结果，不能当自变量。

### 坐标系对齐：为什么「编辑器摆得对、实机对不上」（M64 第八轮）

现象：布局编辑器里摆好的八栋楼，进游戏后**位置和缩放比例都对不上**，
而且不同启动方式差得还不一样。根因有两层，都是「两个坐标系混用」：

| 情况 | 底图 | 建筑 | 结果 |
|---|---|---|---|
| 带 `--safe-top=80`（视口 1202） | `Rect2(0,0,size.x,size.y)` → 1334 压进 1202，**缩放 0.90** | 高度按画布像素直接给，**不缩放** | 建筑大 11%，越靠上偏得越多 |
| 不带安全区（视口 1334） | 不缩放，正确 | 位置减了写死的 `TOWN_Y0=80` | 整体上移 80，房子陷进地里 |

偏差量：底边 1064 处偏下 26px、638 处偏上 17px —— 这正是「看着哪儿都不对、
但每栋单看又都像那么回事」的原因。

**修法**：底图和建筑共用**同一个 1334 画布坐标系**，只按**实际** `_safe_top` 整体平移。

```gdscript
func _town_canvas_rect() -> Rect2:
    var h: float = size.x * TOWN_CANVAS_H / 750.0
    return Rect2(0.0, -_safe_top, size.x, h)   # 往上溢出，底部由安全区裁掉

# 建筑同理：slot[2]（画布底边） - _safe_top
```

平移量必须是**实际** `_safe_top`（桌面 0、真机 47/59），不能写死 80：
写死的话换一台设备建筑整体偏掉同样的量，而底图不动。

验收方法（比肉眼看可靠）：同一份存档分别带 / 不带安全区各截一张，
裁同一块场景区域逐像素比较 —— 现在 **y 200~900 全段差异 0.00**，
只有顶部 header 区（位置本来就不同）有差异。

### 品红残留：单看很淡，连成线就是粉边（M64 第八轮）

上一轮抠图用 `mag / 80` 算 alpha，`mag=20` 时还有 75% 不透明。
留下来的弱品红（`mag` 18~30）单看几乎看不出，但**连成线**就是一条粉紫轮廓
（酒馆底部那条）。实测 `bg_near` 有 13603 个、每张建筑 1.4k~6.9k 个。

`import_town_art.py` 处理完自动调它。

> 判据还是 `mag = min(r,b) - g`。这张是墨线稿，画面里没有真正的紫色内容，
> 所以可以放心清；换别的图要先确认没有紫色物件。

用高频纹理（`|图 − 高斯模糊| > 4`）找出每列的地形顶（实测 y 614–677），
把上面切成透明并羽化 4px，远景的天空/城堡才露出来。
**这也是以后收分层素材要检查的第一件事：中景的天空区是否透明。**

脚本：`tools/build_town_layers.py`（入库）、`tools/gen_town_scene_v2.py`（出预览）。

**每个建筑可选前后**：编辑器里选中建筑 →「在前景层前面 / 后面」，
JSON 里是 `front: true/false`。合成顺序变成
`远景 → 中景 → [front=false 的建筑] → 近景 → [front=true 的建筑]`。
