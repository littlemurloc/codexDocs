# M44 · 光照的可见范围

> 规则层早就有光照，画面上却一点表现都没有。这一期只做「让光照被看见」。

## 1. 问题：数据齐全，观感为零

`exp.light` 是 0–100，四档，改一堆东西：

| 光照 | 档位 | 怪物伤害 | 我方受压 | 侦察 | 被偷袭 |
|---|---|---|---|---|---|
| >75 | 明亮 | +0% | +0% | +15% | +0% |
| 50–75 | 微光 | +5% | +10% | +7.5% | +5% |
| 25–50 | 昏暗 | +10% | +20% | 0 | +10% |
| 0–25 | 漆黑 | +15% | +30% | 0 | +20% |

但画面上唯一的体现是顶栏那行字：`战斗 · 第 1 轮 · 光照 100（明亮）`。

**光照是这个游戏唯一「省一点资源换一点风险」的机制**（省火把 = 更疼、更容易被偷袭，但火把是补给，
带多了占背包）。一个纯数值的风险不该只靠一行小字传达——玩家不会看那行字，只会看画面。

## 2. 技术选择：为什么是渐变纹理，不是 shader

CanvasItem 的 `_draw` **没有擦除能力**：只能往上盖东西，不能挖洞。

而「光圈」的本质就是「中间不盖、四周盖」。所以做法是把「洞」做成纹理：

```
vignette 纹理：中心 alpha 0 → 边缘 alpha 0.94 的径向渐变
绘制时铺成比屏幕大一圈的矩形，中心对准光源
→ 屏幕中心透出画面，四周被逐渐压黑
```

两张纹理，代码生成，不入库、无版权：

| 纹理 | 尺寸 | 作用 |
|---|---|---|
| `vignette` | 256×256 | 暗角：中心透明 → 边缘近黑 |
| `warm` | 192×192 | 暖光：中心一层很淡的光色，**纯白纹理 + modulate 上色** |

`warm` 写成纯白是有原因的：颜色要在绘制时按光照值插值（暖橙 → 冷青），
如果纹理里写死橙色，乘一层冷色只会把橙色变浊，得不到「冷」。

## 3. 参数

```gdscript
static func params(light: float) -> Dictionary:
    t = clamp(light / 100, 0, 1)
    radius_k = 1.02 + 0.40 * t     # 光圈半径 / 屏幕宽
    vignette = 0.30 + 0.56 * (1-t) # 暗角强度
    warm     = 0.20 + 0.80 * t     # 暖光强度
    warm_tint = lerp(冷青, 暖橙, t)
    dim      = 0.22 * (1-t)        # 全屏压暗
```

| 光照 | 光圈半径 | 暗角 | 暖光 | 全屏压暗 | 色温 |
|---|---|---|---|---|---|
| 100 | 1.42×屏宽 | 0.30 | 1.00 | 0 | 暖橙 |
| 55 | 1.24 | 0.55 | 0.64 | 0.10 | 中性 |
| 30 | 1.14 | 0.69 | 0.44 | 0.15 | 偏冷 |
| 0 | 1.02 | 0.86 | 0.20 | 0.22 | 冷青 |

光源位置 = 我方四人水平中心，`GROUND_PARTY - 90`（地面线上方 90px）。

## 4. 三个坑

### 4.1 暖光的**范围**比强度更影响观感

第一版暖光画在 `0.74r` 的矩形上，r = 1.42×1280 ≈ 1817，于是暖光铺满整屏 ——
观感是「加了一层橙色滤镜」，而不是「中间有盏灯」。缩到 `0.46r` 才成立。

### 4.2 暗部压不下去，所以要整屏压

界面基色已经是 `(20, 22, 26)`。靠暗角「再压暗」压不了多少：实测 100 与 15 两档，
敌方区域的像素只差 10 个色阶，肉眼几乎分不出。

所以加了 `dim`：光照低时整屏盖一层 0.22 以内的黑。**这是「火把快烧完了」最直接的表达**，
比调暗角有效得多。

### 4.3 光源按「屏幕中心」算是错的

第一版把光源放在 `size.x * 0.5 - 60`。但队伍只占左侧 40%（四人 x 约 111–540，1080 宽下），
屏幕中心落在十字军身上——瘟疫医生在暗处，十字军最亮。

改成从站位函数取：`40 + slot * 2`，同时把 `_battle_slot_w()` 抽成函数
（原先站位和名字宽度各自写了一遍同一个公式，这是 M42 已经交过学费的事）。

## 5. 平滑跟随（不然点火把像 UI 刷新）

```gdscript
_light_vis = lerpf(_light_vis, exp.light, 1.0 - pow(0.02, delta))
```

约 1.2 秒收敛。直接读 `exp.light` 的话，点火把是「29 → 89」瞬间跳变，
玩家读到的是一次数值刷新，不是「火把烧起来了」。

验证方式（`--dev` 打印，每 0.25 秒一行）：

```
[light] vis=41.7  target=10.0
[light] vis=21.9  target=10.0
[light] vis=14.4  target=10.0
[light] vis=10.6  target=10.0
[light] vis=10.0  target=10.0
```

**静态截图完全无法区分「瞬变」和「渐变」**，这条打印是唯一能复现的证明。

## 6. 两个调试参数

| 参数 | 作用 |
|---|---|
| `--light=N` | 强行固定光照值。没有它，想截一张「昏暗」只能靠点火把/走路碰运气——四档里只有 100 能稳定复现 |
| `--no-light` | 整个光照层不画。用来判断某个「看不清」是光造成的还是布局造成的（和 `--no-skin` 同一用途） |

## 8. 已知限制

1. **顶栏会被暗角轻微压暗**（100→15 差约 6 个色阶）。要彻底隔离得把 `_header` 挪到光照之后重画，
   代价是每帧多一次顶栏绘制。目前读数不受影响，先留着。
2. **漆黑档敌方名字几乎不可读**。血条和轮廓还在，所以仍可点选。这是「漆黑」该有的代价，
   但如果将来加了「黑暗中的敌人需要侦察才显示」，这一条要重新算。
3. **只有战斗屏有光影**。城镇和地图不加，理由不同：城镇是白天的室内/广场，地图本身就是 UI 平面图
   （DD1 的地图也是全亮的）。**不要**因为「统一风格」就往那两屏加暗角，那会直接损害可读性。
