# M23 · 周次循环

> 一句话：M22 盖了八座建筑，但它们全是「点了立刻生效」——那不是城镇，是八个功能面板。
> 建筑之所以像建筑，靠的是**时间**：把人派出去，这一周他就不能出征。

## 1. 起点：有「趟」，没有「周」

`settle` 里其实早就写着：

```gdscript
# 一趟回来换一批货。DD1 的商店是按周刷新的，这里按趟——
# 趟是最自然的时间单位，玩家不需要再记一个「周」的概念。
shop_seed = randi()
refresh_shop()
```

注释把问题说得很诚实：**「趟」被当成了时间单位**。这在只有「打完一趟回城」的循环里够用，
但一旦有了建筑，就不够了——因为建筑的核心语义是「占用人」。

一个人去疗养院，代价不该只是 600 金，还应该包括「这周他不能出任务」。
没有时间轴，这个代价无法表达。

## 2. 一趟 = 一周

新增 `Campaign.week`，`settle` 末尾调一次 `advance_week()`：

```gdscript
func advance_week() -> void:
    week += 1
    for hid in roster.keys():          # 忙的人少忙一周
        var b := int(roster[hid].get("busy", 0))
        if b > 0:
            roster[hid]["busy"] = b - 1
    # 压力自然衰减（默认关，见 §5）
```

`expeditions`（打了多少趟）和 `week`（过了多久）并存。现在它们同步增长，
但语义不同：一个是成绩，一个是时间。以后加「不出发也能过一周」时，
两者才会分开。

## 3. 建筑占周（这一期的核心）

疗养院、修道院、酒馆三个动作，成功后写 `busy = 1`：

| 动作 | 效果 | 代价 |
|---|---|---|
| 治病 | 立刻去掉一条疾病 | 600 金 + 这一周不能出征 |
| 清怪癖 | 立刻去掉一条负面怪癖 | 350 金 + 这一周不能出征 |
| 减压 | 立刻减 40/70 压力 | 200/450 金 + 这一周不能出征 |

**效果立即生效，代价是时间**——这是对原版的简化。
原版是「派出去 → 下周回来 → 那时才生效」，需要 pending 队列。
我们选「立即生效」，因为玩家能马上看到结果；时间代价照收。

这个组合自然产生了原版的那个限制：**一周只能干一件事**。
之前（M22）可以一口气花钱治完所有病、再减压、再清怪癖——现在不行了，
因为第二次点的时候人已经「忙」了。

`selectable_ids()` 从「活着的人」收窄成「活着且不忙的人」，
所以出发准备屏根本列不出忙人——不是列出来点了才报错。

## 4. 存档兼容

| 字段 | 旧档 | 处理 |
|---|---|---|
| `week` | 没有 | 按 `expeditions + 1` 补，不从 1 重来 |
| `roster[h].busy` | 没有 | 缺省 0 = 谁都不忙，行为和 M22 一致 |

周次那条特意没「从 1 开始」：一个已经打了 10 趟的档，
显示「第 1 周」比不显示更糟——它会是**错的**，而不只是缺的。

## 5. 压力衰减：旋钮留着，默认关

`advance_week` 里有一段：

```gdscript
var relief: float = float(cfg.get("weekly_stress_relief", 0.0))
if relief > 0.0:
    ...
```

**默认 0，也就是不衰减。**

理由不是偷懒：M16 量过「无口粮死亡 0.72→1.35」，整条续航基线是靠
「回城那 40 点」撑着的。如果每周再自然掉 5 点，所有续航数字都要重跑——
而这一期的目标是「建立时间轴」，不是「改续航」。

所以旋钮留着、默认关，等真的要做「时间本身就是资源」时再拧。

同理，`settle` 里那个 `town_stress_relief = 40` 一点没动。

## 6. 界面

- 城镇标题：`城镇 · 第 7 周`，副标题写「远征 10 趟」
- 英雄卡状态行加了「忙 N 周」，和「怪癖 / 疾病」并列
- 建筑面板右上角：「这周还有事（剩 1 周）」
- 建筑里的动作按钮在忙时**变灰**，同时右上角写明原因——
  光灰着不解释等于「点了没反应」，这是 M18 那次的教训
- 派遣成功的提示分两种：「办好了」/「办好了 · 这一周他不能出征」
  （招募和升级不占时间，不该套同一句话）

## 7. 踩的坑

**新机制一上线，测试立刻红——这是好事。**

加完 `busy = 1` 之后，M22 的测试直接失败三条：

```
FAIL  清负面怪癖成功  期望= 实际=这周还有事（剩 1 周）
FAIL  清怪癖扣钱      期望=4050 实际=4400
FAIL  怪癖真的没了    期望=true 实际=false
```

不是测试写错了，是**行为真的变了**：治完病之后不能再清怪癖。
把测试改成「推进一周再清」，顺手把新机制本身也钉成了断言
（忙的人不在 `selectable_ids` 里、`busy` 递减、周次随存档走）。

「测试红了先想是不是设计变了」——M18 写「开局 4 人」那条断言时也是这么处理的。

## 9. 没做的

- **「不出发也能过一周」**：现在只有打完一趟才推进时间。原版可以什么都不做直接过周
  （让压力自然衰减、让建筑队列前进）。这条要先拧开 `weekly_stress_relief`，
  否则「跳过一周」等于纯亏。
- **建筑队列的**「下周生效」**：见 §3，现在效果是立即的。
- **周次驱动的其他东西**：原版的马车每周来新英雄、饰品车每周换货、事件按周触发。
  商店换货已经有了（`refresh_shop` 现在挂在 `advance_week` 上），
  新英雄和事件还没有。
- **周次对难度的意义**：原版「拖得越久，任务越难」是核心压力。我们还没有这个层。
