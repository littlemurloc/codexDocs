# M3 · 资源层与远征

M2 收尾时留了一个明确的未决问题：

> 满编四只高难怪、怪物伤害再 ×1.6，实测仍是**零死亡、零死门、终局血量 94%+**。
> 原因不是指标坏了，而是治疗把累积伤害完全抵消了。
> **压迫感不可能靠调伤害数值做出来，必须在资源层设计。**

M3 做的就是这一层，并且用同一套测量器去验证那句话对不对。

## 结论先放这里

同一套战斗数值、同一批路线，**只换资源策略**：

| 资源预设 | 完成率 | 团灭率 | 英雄死亡率 | 终局血量 | 压迫指数 |
|---|---:|---:|---:|---:|---:|
| lenient（宽松） | 0.867 | 0.133 | 0.200 | 0.520 | 0.787 |
| standard（标准） | 0.783 | 0.217 | 0.312 | 0.323 | 1.303 |
| tight（紧张） | 0.283 | 0.717 | 0.858 | 0.051 | 2.810 |
| brutal（残酷） | 0.000 | 1.000 | 1.000 | 0.000 | 3.340 |

（weald / medium / Lv3 / 60 趟一档）

> **M9 之后重跑。** 上表在 M3 完成时是 0.867/0.733/0.233/0.017、压迫
> 0.773/1.385/2.767/3.297。M9 让 AI 会主动换位（详情见 [M9_MOVEMENT.md](M9_MOVEMENT.md)），
> 战斗结果随之改变，四个预设的数字全部平移。**单调性完好**，结论不变。

而 M2 里那个「测不出危险度」的规格，在这里终于有反应了：

| 同一预设 standard | M2 单场战斗 | M3 整段远征 |
|---|---:|---:|
| 基线终局血量 | 0.941 | 0.323 |
| lethal_probe（怪物伤害 ×1.6）终局血量 | 0.934 | 0.035 |
| 基线英雄死亡率 | 0.000 | 0.312 |
| lethal_probe 英雄死亡率 | 0.000 | 0.850 |

**伤害维度不是钝，是之前没有放大器。** 资源层就是那个放大器。

## 资源层做了什么

四个机制，每一个都直接对着 M2 发现的漏洞。

### 1. 光照与火把

火把有限，每走一步掉光，用一根 +25。光照不是装饰，它按 DD1 自己的
`rules.darkness` 表改一整套数字：怪物伤害、命中、暴击、英雄闪避、
受压倍率、被惊袭概率。

这张表是从数据里原样搬来的，五档区间左开右闭（75 属于微光而不是明亮）：

| 光照 | 受压 | 怪物伤害 | 怪物暴击 | 被惊袭 |
|---|---:|---:|---:|---:|
| > 75 明亮 | +0% | +0% | +0% | +0% |
| 50–75 微光 | +10% | +0% | +1% | +0% |
| 25–50 昏暗 | +20% | +10% | +2% | +15% |
| 0–25 漆黑 | +30% | +15% | +3% | +25% |
| 无光 | +40% | +25% | +5% | +40% |

还有一条容易被忽略的：**走廊本身会加压**（`hallway_stress`，每格 30% 概率、2 点压力）。
没有它，省火把只等于「多挨一点打」，玩家一眼就能算出该省；
有了它，省火把 = 持续加压 = 崩溃风险，光照才成为一个真正的选择。

### 2. 口粮与饥饿

路线里的饥饿检定次数来自地图参数（短图 1–3 次、中图 2–5 次、长图 2–6 次）。
吃到口粮回 5% 血（`hallway_hunger_HPrestore`），断粮则全员加压并按比例掉血
（`hallway_hunger_starve_HPdmg` = 20%）。

**按比例掉血**是刻意的：固定伤害对高血量英雄是挠痒，对低血量英雄是处决。

### 3. 休整

短图一次、中图一次、残酷档零次。休整消耗口粮、回血、减压、点满火把，
并且能把**死门上的英雄救回来**——这是休整最重要的用途。

但它不是稳赚：`ambush_camping_base_chance = 0.33`，营地会被偷袭，
被偷袭的一方第一轮整轮不行动。

### 4. 压力兑现：崩溃 / 美德 / 心脏骤停

这是 M1 记在「已知未实现」里的一条，也是整套资源层的支点。

在此之前，压力只是一个会涨的数字：涨到 200 什么都不会发生。
现在：

- **100 压力** → 崩溃检定（数据给的是 75% 崩溃 / 25% 美德）
- **崩溃**：一组 5 条减益（`afflictionFearfulBuff1..5` 全上）+ 15% 概率当回合摆烂
  + 每轮给随机队友加压
- **美德**：一组 2 条增益（`virtueStalwartBuff1..2`）+ 每轮给队友减压 + 立刻减压 45
- **200 压力** → 心脏骤停，当场倒地进死门；已在死门上则直接死亡

崩溃种类和减益内容**不是编的**，是从 `buffs.json` 里按前缀反推的：
`afflictionFearfulBuff1` 存在，就说明有 "fearful" 这一种。
换数值包时它们跟着包一起换，代码一行不动。

真正让压力有分量的是「摆烂」：**队伍在关键时刻少一个行动**。
面板上 -10% 命中不会让人紧张，少一次行动会。

## 顺带修掉的三个 M1 遗留缺陷

做资源层时才发现，跨战斗的三个前提原来都是坏的。

**1. 死门被当成死亡。** `is_alive()` 原先写的是 `hp > 0`，
于是英雄一进死门就从 `living()`、行动序、目标选择里全部消失——
等于进了死门就直接退出战场，后面所有「死门上再挨一下才真死」的规则都是死代码。

**2. 治疗对死门无效。** `heal()` 在死门上直接 `return 0`。
DD1 里治疗可以把人拉回来，代价是留下「恢复期」减益（`recovery_buffs`）。
原实现把死门做成了单向陷阱，和原作手感正好相反。

**3. 持续伤害在死门上必定致死。** `tick_dots` 调 `take_damage` 时没传掷骰，
用了默认的 1.0（必死）。等于「死门上挂一个流血就死」，随机性被写死成最坏情况。

这三条都不报错、不影响单场战斗的指标，只在跨战斗时才显形。
这也是为什么 M3 必须先补它们——否则资源层只是在错误的基座上堆参数。

## 测量器：15 项指标，一个综合指数

`tests/bench_expedition.gd` 跑整段远征，指标分四类：

| 类别 | 指标 |
|---|---|
| 结果 | 完成率、撤退率、团灭率、推进进度 |
| 伤亡 | 英雄死亡率、崩溃率、美德率、心脏骤停率、死门率 |
| 状态 | 终局血量、最低血量水位、终局压力 |
| 资源 | 终局光照/口粮/火把、断粮次数、休整次数、营地被偷袭 |

外加一个 `pressure_index` 综合指数（团灭 ×1.0 + 撤退 ×0.7 + 死亡 ×2.0 +
崩溃 ×0.8 + 心脏骤停 ×1.2）。权重是设计判断不是物理量，
所以原始指标全部保留，只看这个数会漏掉细节。

三条口径上的教训，都写进代码注释了：

- 人均死亡率的分母是**队伍人数**而不是「趟数 × 人数」——
  sums 里存的是每趟平均，这里写错过一次，0.975 的团灭率算出来死亡率只有 0.02
- 怪物死亡事件也叫 `death`，不分阵营会得到「每趟死 14 个人」
- 路线必须先全部生成再喂给各预设，否则差异里混进了「这次遇到的怪不一样」

## 三个实验

### 实验一：只换资源，危险度必须单调上升

见开头那张表。四个包（data / faithful / signature / lethal_probe）
全部满足 `lenient < standard < tight < brutal`，
`compare_expedition.py` 把这条做成了自动判定。

顺带得到一个校准结果：**faithful 包与 data 包的远征指标完全相同**
（压迫指数都是 1.303，逐项一致）。这和 M2 的「faithful 单场指标与 DD1 基线逐项相同」
是同一件事在两个尺度上的重复验证。

### 实验二：伤害维度终于可测

见开头第二张表。M2 里 `lethal_probe` 只让终局血量掉了 2.2 个百分点；
M3 里同样这个包让死亡率从 0.392 涨到 0.850。

原因是资源层把「一次伤害」变成了「一次伤害 + 一次没法治的损失 + 一段没走完的路」。

### 实验三：图长本身是难度旋钮

同样是 Lv3、同样 standard 预设，只改地图规模：

| 场景 | 路线步数 | 完成率 | 终局血量 | 终局压力 | 压迫指数 |
|---|---:|---:|---:|---:|---:|
| 短图 | 7.3 | 0.933 | 0.686 | 64.7 | 0.442 |
| 中图 | 10.5 | 0.783 | 0.323 | 114.0 | 1.303 |

短图 Lv1 则是 100% 完成、终局血量 0.750、压力 40.9。
**新手区、考验、致命**三段，靠地图规模就能拉开，不必改战斗数值。

### 实验四（副产品）：发现 signature 的真实缺陷

M2 给 `signature` 评的是「四条目标全部达成」。放进远征就露馅了：

| 数值包 | 单场轮数 | 远征完成率 | 团灭率 | 压迫指数 |
|---|---:|---:|---:|---:|
| data / faithful | 4.10 | 0.783 | 0.217 | 1.303 |
| signature | 5.30 | **0.333** | 0.667 | 2.457 |
| signature_v2 | 5.26 | 0.567 | 0.433 | 1.845 |

诊断：**战斗长 30%，英雄就多挨 30% 的打，而治疗输出没有变**。
「每轮承受 > 每轮治疗」意味着净掉血，7 场下来必然见底。
M2 看不到这一点，因为三场连打之后血量反而在涨。

修法不是把数字调软，而是把「时长」与「强度」解耦：
`signature_v2` 保留 1.45 倍怪物生命，同时把怪物伤害压到 0.85。
完成率从 0.333 拉回 0.500，压迫指数从 2.457 降到 2.020，长战斗的设计意图原样保留。

> 这条比前面三条都重要：它说明**单场指标全绿不等于这套数值能用**。
> 一个资源层如果只产出「更有压迫感」的结论而从不否定上游设计，那它就没有在工作。

## 数据从哪来 / 哪里是自己设计的

这条线必须划清楚，否则以后分不清「哪些是 DD1 的、哪些是我们的」。

**来自 DD1 数据（原样使用）**

| 内容 | 出处 |
|---|---|
| 光照五档修正表 | `rules.darkness` |
| 每格光耗、走廊压力 | `rules.tile_light_loss` / `rules.hallway_stress` |
| 饥饿回血 / 断粮掉血比例 | `rules.hallway_hunger_*` |
| 营地被偷袭概率、营地点数 | `rules.ambush_camping_base_chance` 等 |
| 撤退加压 | `rules.combat_retreat_stress` |
| 崩溃触发率、美德比例、顶住后减压 | `rules.affliction_*` |
| 崩溃 / 美德 / 死门 / 恢复期减益 | `buffs.json` 全部按前缀取 |
| 遭遇组合、地图规模、战斗数与饥饿数 | `dungeons.json` 的 maps 与 encounters |

**自己设计的（`data/expedition.json` 的四个预设）**

补给品带多少、自动点火的阈值、休整策略、治疗配额、断粮加压值、
崩溃者摆烂概率与氛围加压值。这些 DD1 的数据里没有（道具是玩家在城镇买的，
不写进配置文件），必须由我们定。

预设之间的差异**只在**这些自研参数上，所以「只换资源」的对照实验是干净的。

## 怎么跑

```bash
GODOT="D:/XT/godot/Godot_v4.7.2-stable_win64_console.exe"
B="D:/XT/codex/projectTestCodexDocs/darkestDungeonLike"

# 单趟战报（看机制怎么咬合）
"$GODOT" --headless --path . --script res://tests/dump_expedition.gd -- \
  --preset=standard --seed=3 --size=medium

# 四档资源 × 60 趟
"$GODOT" --headless --path . --script res://tests/bench_expedition.gd -- \
  --runs=60 --size=medium --level=3 --out="$B/bench/exp_data_medium.json"

# 换数值包再跑一次（资源策略相同，所以差异只来自战斗数值）
"$GODOT" --headless --path . --script res://tests/bench_expedition.gd -- \
  --runs=60 --size=medium --level=3 --data="$B/balance/signature_v2" \
  --out="$B/bench/exp_signature_v2_medium.json"

# 对比 + 目标判定 + 生成 markdown
python tools/compare_expedition.py
```

## 已知局限

- **AI 不打撤退**。真人打不过会撤，这里一律打到团灭，所以团灭率是上界。
  撤退的机制已经实现（+20 压力、远征判负），只是没接进自动策略。
- **AI 不会集火、不会保护治疗、不用道具**。所有对比在同一 AI 下做，
  相对差异有效，绝对值不代表 DD1 真实难度。
- **崩溃只有 6 种、行为只做了「摆烂」**。DD1 每种崩溃有各自的失控动作
  （攻击队友、拒绝治疗、乱跑位），数据里只有面板减益，行为在 exe 里。
- **治疗配额是自研机制**。DD1 没有「次数上限」，它的约束是行动机会与休整次数。
  这里加配额是为了直接对冲 M2 发现的「治疗抵消一切」，属于设计选择而非还原。
- **饰品 / 怪癖 / 疾病 / 光照掉落加成未接入**。光照表里的 `loot_increase_*`
  已经解析出来了，但还没有掉落系统接。
- **地图是线性路线**，不是真实的网格地图：没有回头、没有分支、没有奇物。
