# M28 · 解雇

> 一句话：M27 让名册能扩到 15 人，但**只能加不能减**。满了就没法换人，
> 练废的人也只能一直占着位置。这一期补的是那条出口。

---

## 1. 起点：单向的扩张

M27 做完之后，名册是这样一个东西：

```
hire(cls)   → roster[cls] 建起来，_order.append
dismiss()   → 不存在
```

于是名册满了（15 人）之后：

- 马车里的新面孔永远招不进来
- 一个练到 5 级但技能组配错的人，只能一直带着上路
- 团灭过几轮、`_order` 里躺着一排死人的档，永远清不干净

原版的解雇是**免费**的，代价是「你在那个人身上投入的等级和装备全部归零」。
这正好是 M25「招募=新人」的同一条逻辑：这个 ID 代表的不是一个具体的英雄，
而是**名册上的一个位置**。

---

## 2. 规则

```gdscript
can_dismiss(hid):
    · 名册里有这个人
    · 不忙（这周还在疗养院/酒馆里）
    · 活人的话，解雇后至少还要剩 1 个活人

dismiss(hid):
    roster.erase(hid)
    _order.erase(hid)
    recruit_candidates.erase(hid)   # 防御
```

### 三条限制，各有理由

**「至少留 1 个活人」** 不是数值平衡，是防锁死：名册空了之后如果金币也不够招人，
这个档就再也走不动了，而存档不会自己回退。原版没这条限制是因为马车永远有货、
而且便宜；我们的招新要 1000 金币。

**「忙人不能解雇」**：他这周还在疗养院里，人走了那笔钱算什么。
与其编一套退款规则，不如直接拒绝——这种情况只会在玩家手滑时出现。
检查放在 `can_dismiss` 而不是 `dismiss` 里，是为了让按钮直接灰掉：
**可点但点了报错，玩家会以为是 bug**。

**「死人可以解雇」**：那不是解雇，是从墓园里删掉这条记录。
死人不占出征名额（见下），但会一直占着名册列表的位置。

### 顺带修的一个名额 bug

`roster_full()` 原来是 `_order.size() >= 15`，而 `_order` 里包含死人。
一个团灭过两轮的档会出现「名册上写着 15、实际能出征的只有 3 个、而且再也招不进人」。
改成按**活人数**算之后，死人不占名额，只有活人才算。

## 3. 界面：一个按钮点两次

自绘 UI 没有弹窗，而解雇是**不可逆且清空投入**的操作——点错一下就把练了十趟的人删了。

做法是「点两次」：

| 第一次点 | 第二次点 |
|---|---|
| 按钮变成 `再点一次 —— 十字军 会消失，等级不保留` | 真的执行 |
| 边框和文字转成警示色 | —— |

第一次点不执行任何逻辑，只是把 `_fire_pending` 置成这个人的 id。
换选别人会清空它（否则会误删下一个选中的人）。

**只改文字不改样式是不够的**：玩家连点两下时不会读字。所以给 `_add_button`
加了一个 `danger` 参数，危险态用警示色描 2px 边 + 警示色文字。

### 马车现在分上下两半

```
马车                      名册 5 / 15 人（存活 4）
────────────────────────────────
本周新面孔（每周换一批）      ← 往名册里加
  [憎恶（1000 金币）]
  [古董商（1000 金币）]
────────────────────────────────
名册管理                    ← 处理名册里的人
  十字军 · Lv3 · 装备 2 阶 · 出征 1 次
  解雇会把他的等级和装备一起抹掉，招回来还是 Lv1。
  [解雇 十字军]
```

左栏也改了：**马车里会列出死人**（灰字 + 「已阵亡」），因为「复活」和
「从墓园移除」都作用在他们身上。其他建筑仍然只列活人——铁匠铺对着一个死人
没有可做的事。

原来的 `_draw_buildings` 用 `campaign.alive_ids()` 画左栏，所以死人在任何建筑里
都点不到。M28 之前这不是问题（马车只处理选中的人），现在必须能选中。

## 4. 现在的完整回路

```
马车 ──hire(1000金)──→ 名册 +1（Lv1）
  │                      │
  │                      ├─ 出征 → 升级/装备 → 变强
  │                      │
  └──dismiss(免费)───────┘ 等级和装备一起归零
```

这是 M27 缺的那一半。名册从「一个只能往里塞的桶」变成了一个真正的池子。

## 5. 新增的调试参数

| 参数 | 用途 |
|---|---|
| `--pending-fire` | 进马车时把解雇按钮置成「待确认」，给截图用 |
| `--bld-hero=<hid>` | 指定建筑屏选中的人（默认选第一个活人，所以死人的那半屏截不到） |

第二个是必要的：`_boot_building` 分支固定选 `alive_ids()[0]`，
「复活/移除记录」这部分界面在静态截图里永远看不到。

## 6. 踩的坑

**（1）左栏只列活人，死人根本选不到**

`--bld-hero=man_at_arms` 传进去了，但 `_draw_buildings` 里有一句
`if not who.has(_building_hero): _building_hero = str(alive[0])` 把它重置掉了。
截图截出来是活人的面板，我一开始以为是参数没生效。

**（2）危险态按钮和普通按钮长得一模一样**

第一版只改了文字（「再点一次确认」），截图一看还是普通按钮的样式——
玩家连点两下时根本不会读字。加 `danger` 参数之后才有警示色边框。

## 7. 已知限制

1. **解雇没有二次收益**。原版解雇不退还任何东西，我们也一样。但原版有
   「解雇的人会出现在墓园/城镇事件里」这种叙事反馈，我们没有。
2. **不能解雇正在远征的人**。我们没有「远征中」这个状态——远征是同步跑完的，
   所以这条天然满足。
3. **解雇后马车候选不补**。招走一个就少一个候选，要等下周。
   解雇腾出的名额也一样要等下周才用得上（因为候选是每周刷的）。
4. **装备没退还**。解雇一个装备 3 阶的人，那 3 阶的投入直接消失。
   原版也是这样（装备绑在人身上），但我们的升级价格是按真表标定的
   （M13：招募 1000、升满 10000），所以一次误删的代价比原版更疼。

## 9. 下一步

名册这条线（M27 扩容 + M28 解雇）现在是完整的了。剩下的缺口按「离原版多远」排：

1. **受压 +25%/级**（M25 起就记着的另一半）。现在只有「进本 +20 压力」，
   缺了「在高级本里每次受压也更多」。要做就得动 `Combatant.add_stress`
   的倍率链，会影响到 M9 以来所有压力基线，值得单独一期带对照。
2. **马车候选按阵容短板加权**（缺治疗时更容易来修女）。这是原版「马车有感觉」
   的来源，现在是纯随机。
3. **同职业多人**。key 是职业 id，所以不会有「两个修女」。要做得把 key 改成
   `id#序号`，牵动存档、装备、技能组、UI 四处。

我倾向 **1**：它是目前唯一还躺着的「原版核心机制缺口」，
其余的都属于丰富度而不是机制。
