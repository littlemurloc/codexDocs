# M8 · 走廊内容：陷阱与障碍

M7 做完之后，走廊里只有「战斗」和「饥饿」两种内容。两条走廊在玩家眼里长得一模一样，
所谓「选路」实际只能靠房间类型来分。这一层补的是那个缺口。

## 一、机制

### 陷阱

```
踩中判定 = 队伍最高陷阱抵抗 + 0.03 × 平均装备阶 − 地牢等级难度 (+0.40 如果已侦察)
         夹在 [0.05, 0.85]
```

- **队伍陷阱抵抗取全队最高**。玩家没法调整谁走前面，取平均等于四个人一起被绊；
  取最高等于「让最警觉的那个探路」，这是唯一合理的默认。
  实测四个初始英雄是 `crusader 0.10 / highwayman 0.40 / vestal 0.10 / plague_doctor 0.20`
  ——**队里有强盗，陷阱就更好躲**。这是队伍构成第一次影响走廊风险。
  （M10 把开局的前排从十字军换成了战争老兵，所以现在最高值改由 `man_at_arms` 提供；
  强盗仍在队里，这条结论本身不受影响。）
- **难度来自 `rules.difficulty_trap_base`**（DD1 自己的表，按等级索引）：
  `[0, 0, 0, 0.2, 0.2, 0.4, 0.5]`。它减的是躲避几率，不是伤害。
  这个字段从 M0 就抽出来了，一直没人用。
- **侦察加成来自 `rules.trap_scout_disarm_bonus = 0.40`**。同样是一直闲置的数据。
  它证明原版的设计就是「看见陷阱就能更好地处理」——不是我们发明的规则。

踩中：全队掉 18% 最大血 + 11.9 压力（standard 预设；四档分别为
`0.144/0.18/0.234/0.288` 血、`8.5/11.9/15.3/20.4` 压力）。

### 障碍

有铁锹就凿开（消耗 1 把，全队无损）；没有就用手挖（全队掉 9% 血 + 5 压力）。

这条是**补给预算的第三个去处**。在此之前只有火把和口粮，而这两个都只影响「挨打多少」；
铁锹影响的是「能不能不挨打」。`inventory.json` 里 shovel 的购买价是 250，
是口粮/绷带的 1.7 倍——原版也认为它贵。

### 走廊可见性

这是让上面两条成立的**前提**，也是这一层最重要的改动：

| 信息 | 什么时候知道 |
|---|---|
| 走廊存在（能通往哪） | 站在房间里就知道，不需要侦察 |
| 走廊里有什么 | **只有侦察过才知道**；走过一次之后也会记住 |

未侦察的走廊在界面上**不画任何标记**——不画圆点、不给颜色暗示。
泄露了就等于免费侦察，机制的一半就没了。

侦察成功时，候选池里同时包含「两步内的未知房间」和「相邻走廊的未知内容」，
随机挑一个揭示。所以侦察买到的可能是地图，也可能是路况。

## 二、三策略对照

`tests/bench_hazards.gd` 用同一张图、同一个种子跑三种选路策略：

- `straight` —— 只走最短路
- `avoid` —— 看见陷阱/障碍就绕（绕路权重 2 步）
- `smart` —— 距离 ×10 主导，同距离时才比较走廊内容与房间类型，且绝不回头

weald · medium · Lv3 · standard · 120 趟：

| 指标 | straight | avoid | smart |
|---|---:|---:|---:|
| 完成率 | 0.908 | 0.817 | **0.950** |
| 团灭率 | 0.092 | 0.100 | **0.050** |
| 阵亡人数 | 0.675 | 0.633 | **0.442** |
| 终局血量 | 0.556 | 0.577 | **0.642** |
| 终局压力 | 63.8 | 73.7 | **52.9** |
| 终局光照 | 65.3 | 59.5 | 66.8 |

**两条结论，方向相反：**

1. **信息确实值钱**：综合使用已知信息，完成率高 4.2 个百分点，
   阵亡少 34%，终局血量高 8.6 个点。
2. **单目标优化反而有害**：只盯着陷阱躲，完成率掉 9.1 个点。
   因为它为了避开一条已知有陷阱的走廊，会走进更多未知的战斗房——
   **它优化的是自己看得见的那一项，代价付在看不见的地方。**

这条比「陷阱好不好玩」重要得多：它说明这层的价值不在陷阱本身，
而在「玩家能不能把有限的信息用对」。

### 绕路本身是负期望

`avoid` 输掉的原因不是它判断错了，而是**绕路在当前地图上就是不划算**：

- 网格图上没有「绕 1 步」的选项，绕路门槛至少 2 步
  （权重扫过 1.0 / 2.0 / 4.0，1.0 与 0 完全一致，2.0 与 4.0 完全一致）
- 多走 0.8 间房 = 多耗约 14 光照 → 更容易掉进昏暗 → 压力加成翻倍
- 一趟踩中的陷阱期望只有 0.5 次，绕路省的还不够付光照

所以这一层真正的决策不是「绕不绕」，而是：
**要不要为侦察多点火把**。M6 的光照链到这里才闭合：

```
火把 → 光照 → 侦察率 → 走廊可见 → 陷阱解除率 +40%
```

## 三、顺带修掉的 M7 结构缺陷

做对照实验时发现 `smart` 和 `straight` 的每一列数字**完全相同**，这不可能是巧合。
查下去发现：中图 14 间房只有 15 条边——**树加 1 条环**，最短路基本唯一，
玩家根本没有第二个选项。M7 说的「玩家开始选路」是不成立的。

修的过程试了三种：

| 做法 | 结果 |
|---|---|
| 不加环（M7 原状） | 深度 100%，但最短路唯一，选路是假的 |
| 无脑加满环 | 中图 7.5→6.9 跳、长图 10.8→8.4 跳，长图深度达标率掉到 **5%** |
| 加环但绝不缩短最短路 | 深度 100%，但加的全是旁支，玩家走最短路时碰不到 |
| **加环，只允许缩到深度下限为止** | 深度 100%，环数 4/6/8，跳数 5.6/8.9/12.1 |

最后一种才是对的。关键在于「禁止缩短最短路」和「允许无限缩短」都走极端：
**前者禁止了分岔，后者毁掉了深度**。数据给的 `min_final_distance` 本来就是
「入口到目标至少多远」，而不是「必须正好等于最远对」。

配套还改了两处：

- 加环后**重算**最短路（否则界面上「出口 X 步之外」一直偏大）
- 重试 16 次取「达标里最深」的那张，而不是一达标就 break
  （break 会停在刚好等于下限的图上，短图 3 步就走到出口）

### 现在有多少分叉

| 规格 | 平均分叉点/趟 | 有分叉的图 | 平均步数 |
|---|---:|---:|---:|
| short | 1.25 | 36/40 | 5.7 |
| medium | 1.70 | 39/40 | 8.9 |
| long | 2.10 | 39/40 | 11.8 |

（分叉点 = 该房间有两个以上「距离目标更近一格」的邻居）

## 四、踩到的坑

**1. 界面漏了两种内容。** `_drain_queue` 的 `match` 只处理 `hunger` / `curio` / `walk`，
新增的 `trap` / `obstacle` 会掉进 `_:` 分支被当成战斗启动。
规则层的 320 项断言一条都抓不到——它们不走界面路径。
**两端都加了内容类型而没有对应的分派分支，是这类 bug 的固定形态。**

**2. 对照实验的 `smart` 分支静默没写进去。** 用脚本做字符串替换时源串写错，
替换失败但脚本没有断言，于是 `elif policy == "smart"` 根本不存在。
表现是三组数字一模一样。**这正是这一层要防范的「不报错的失效」，
结果先在我自己的测量工具上发生了一次。**

**3. 配额按顺序分配会让后面的类别饿死。** 第一版 `battle → hunger → trap → obstacle`
依次消耗槽位，陷阱一上，饥饿从 3.5 直接掉到 0.2——而饥饿是 M3 资源压力的主循环。
改成按比例分配、每类保底 1 个。

**4. `--reveal` 只点亮房间不点亮走廊。** 截图里永远看不到徽标，调试开关失去意义。

**5. `--to-result` 用线性驱动器跑图模式。** `exp.run_auto()` 不认识待结算队列，
于是「推进 1/9 步」就被判定完成，截图上完全看不出来。

## 五、数据落点

`data/expedition.json` 的四档预设各有一节：

```json
"supply":   { "shovel_start": 1 },
"trap":     { "damage_ratio": 0.18, "stress": 11.9, "min_avoid": 0.05, "max_avoid": 0.85 },
"obstacle": { "damage_ratio": 0.09, "stress": 5.0, "shovel_uses": 1 }
```

| 预设 | 铁锹 | 陷阱伤害 | 陷阱压力 |
|---|---:|---:|---:|
| lenient | 2 | 0.144 | 8.5 |
| standard | 1 | 0.180 | 11.9 |
| tight | 1 | 0.234 | 15.3 |
| brutal | 0 | 0.288 | 20.4 |

## 六、怎么跑

```bash
# 生成质量与走廊内容构成
"$GODOT" --headless --path . --script res://tests/dump_map.gd -- --stats --runs=40

# 三策略对照（straight / avoid / smart）
"$GODOT" --headless --path . --script res://tests/bench_hazards.gd -- \
  --runs=120 --size=medium --level=3 --weight=2.0

# 看整张图（含走廊徽标）
"$GODOT" --path . -- --start --reveal --size=medium --level=1
```

## 七、已知局限

- **陷阱不能主动解除**。DD1 里发现陷阱后可以尝试拆，失败才触发；
  这里只有「发现 → 躲开几率 +40%」，少了玩家主动操作那一步。
- **一条走廊只有一个内容**。原版走廊是 4 格（`spacing`），可以同时有陷阱和战斗；
  我们仍然没接 `spacing`，所以种类之间互斥。
- **绕路是负期望**，所以「看见陷阱就绕」并不值得。这一层兑现的是
  「为侦察付火把」和「综合用信息」，而不是「绕路躲陷阱」。
- 陷阱/障碍的伤害是我们定的策略值（`expedition.json`），DD1 数据里没有对应常量；
  只有难度和侦察加成是原数据。
- 走廊走第二次不重复触发，也不额外耗光——这一条没做次数上限。
