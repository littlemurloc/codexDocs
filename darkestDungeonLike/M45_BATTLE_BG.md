# M45 · 战斗背景

> 战斗屏从「深色底 + 两排人」变成「站在地窖/荒野里打架」。

## 1. 素材在哪

DD1 的战斗背景不在 `loading_screen/`（那是过场大图），而在：

```
dungeons/<region>/<region>.room_wall.<name>.png     1920×720，每区域 7–8 张
```

文件名带语义：`crypts.room_wall.empty / altar / arch / barrels / drain / library / torture`、
`weald.room_wall.clearing / gate / handtree / poisonriver / shroomland`……

一共 **31 张**（weald 7 + crypts 8 + warrens 8 + cove 8），全部是「一面墙 + 一片地面」的构图。
`dungeons/darkestdungeon/` 下也有，但那是终局专属，本作没开放，先不收。

## 2. 最关键的一条：地面线在哪

原图地面线在 **y ≈ 632 / 720（87.8%）**，不是凭感觉的 82%。
这是量出来的：逐行算平均亮度，第一次跳变出现在 632（墙面 → 石板地面）。

提取时按**目标区域比例**裁到地面线为止：

```
目标绘制区 = 1280 × 422（48 → 470，即顶栏下沿到我方地面线）
比例        = 1280 / 422 = 3.033
原图裁切高  = 1920 / 3.033 = 633  ← 正好卡在地面线
```

于是得到一条性质：**「图的底边」= 「原图的地面线」**。

绘制端只做「铺满宽度 + 底边压在我方地面线上」，地面就自动接上，
不需要逐张调偏移，换任何一张背景角色都不会"换身高"。

> 反过来如果按常规做垂直居中，地面线会随每张图的比例浮动，
> 31 张里必然有几张对不齐，而这类错只在换到那一张时才露。

## 3. 敌人为什么需要一条「台面」

DD1 的背景是给**同一条地面线**的构图用的（敌我左右对峙）。我们的战斗屏是**上下两排**
（M37 为了 rank 可读性改的），敌方站在 y=250、我方站在 y=470。

有背景之后，敌方剪影会读成「浮在墙前」——原来的细线撑不住「他们站在这儿」。

改成 10px 的暗色台面带 + 上沿高光，像一段比战场更高、更靠后的石台：

```gdscript
draw_rect(Rect2(0.0, GROUND_ENEMY, size.x, 10.0), Color(0.030, 0.028, 0.026, 0.62))
draw_line(Vector2(0.0, GROUND_ENEMY), Vector2(size.x, GROUND_ENEMY), Color(0.30, 0.27, 0.23, 0.55), 1.0)
```

## 4. 三个坑

### 4.1 亮度差 3.6 倍，必须归一

31 张的平均亮度：

| | 均值 |
|---|---|
| 最暗（`crypts_6`） | 9.1 |
| 中位 | 18.1 |
| 最亮（`weald_6`，有月光） | **32.8** |

差距 3.6 倍。只压一个固定系数的话，暗的那几张会糊成一片黑，亮的那几张仍然抢戏。

导出时做**逐张亮度归一**到 18：

```python
gain = clamp((18.0 / mean), 0.60, 1.30)    # 限制增益，避免把噪点放大
if 均值 > 20: gamma 1.22                    # 再压一次高光（月光/水面反光）
```

归一后落在 13.8–19.4，肉眼一致。

### 4.2 只压暗不够，还要加雾

压暗只降**亮度**，不降**对比度**——骷髅堆、木桶、砖缝仍然清清楚楚，和前景立绘抢视线。

叠一层 36% 的底色当"雾"，对比度也压下来，背景才真的退到后面。

> 为什么不直接在导出时高斯模糊：模糊不可逆，而雾的浓度可以随时调。
> 将来觉得太淡就改一个数字，不用重跑 31 张。

### 4.3 地面线以下的衔接，别做渐变

背景在 470 处截断，到日志面板（530）之间空 60px。第一版用 6 段矩形做渐隐，
结果衔接处画出一条**比背景更亮**的横带，像地面被切了一刀。

改成一条近黑纯色（`#0B0B0B`）直接接上——它读起来就是"近处地面在阴影里"。

## 5. 选哪一张：按房间号，不按随机

```gdscript
idx = room_index % count_of(region)
```

- **确定性**：同一趟远征回到同一个房间，背景还是那一张
- **不消耗 `rng`**：这是 M15 那条铁律——新增的"解析成具体东西"的随机一律不能用主序列，
  否则之前量到的所有 bench 数字同时作废。这里是纯视觉，连派生 rng 都不需要，用房间号就够
- `room_index < 0`（不在房间里）时用第 0 张

`--dev` 下打印切换记录：

```
[bg] region=weald room=0 张数=7 -> 0
[bg] region=weald room=6 张数=7 -> 6
[bg] region=weald room=8 张数=7 -> 1     ← 回绕
```

这条打印是唯一能确认"index 真的在变"的方式——静态截图看不出背景有没有换。

## 6. 文件与体积

```
assets/art/battle/bg/<region>_<n>.png     960×316，31 张，9.6 MB
```

不建 manifest：`<region>_<n>` 从 0 连续，探测到第一个缺号就是末尾（`BattleBg.count_of`）。
"有几个文件"是唯一需要的信息，写一张表只会多一个会失同步的地方。

已加进 `.gitignore`（DD1 版权图不入库）。顺带补上了 **M40/M42 漏掉的两处**：
`assets/art/ui/**/*.png` 和 `assets/art/battle/**/*.png`——之前只有 `units/*.png` 被忽略，
`git add .` 会把建筑立绘和区域横幅一起带进仓库。

## 8. 已知限制

1. **背景按宽度铺，1080 下左右各裁掉一点**。素材是 3.03:1，1080 视口要 2.56:1，
   等于横向裁掉 15%。裁掉的是最边缘，构图中心不受影响。
2. **cove 有几张右下角偏亮**（水面/礁石反光）。归一化压过一轮，但单张内的局部高光压不平，
   1080 下偶尔会注意到。要彻底解决得做局部色调映射，收益不值。
3. **背景不区分"战斗类型"**。DD1 里 boss 房、走廊遭遇各有专属背景，我们只有房间背景，
   而且走廊遭遇（`current_room = -1`）会用第 0 张。
4. **只在战斗屏**。城镇和地图不加，理由同 M44。
