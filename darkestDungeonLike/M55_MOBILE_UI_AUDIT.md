# M55 手机版 UI 触屏审计

> 起因：APK 上「不少 UI 被遮挡、点不到」。
> 桌面端看不出来，所以先做了一个**热区体检工具**，再用手机实际会拿到的逻辑宽度复核。

---

## 0. 审计工具：`--dump-hits`

```bash
godot --path . -- --w=1690 --dump-hits --start --battle --shot=x.png --shot-at=2.6
```

打印当前界面的全部可点元素，按三类问题分类：

| 类别 | 判据 | 为什么在手机上会出问题 |
|---|---|---|
| **贴底** | `y2 > size.y - 26` | 手势条、圆角会盖住；点击变成「返回桌面」 |
| **过小** | 高 < 34 或宽 < 44 | 手指落点约 9mm，逻辑像素还要除以缩放 |
| **重叠** | 两个热区相交 | 轻则点了没反应，重则点到隔壁那个 |

同一屏只打一次（`state + 尺寸 + 按钮数` 变化才算新屏），不会刷屏。

> 踩过的坑：第一版没有 2 秒延迟，进屏第一帧就打印——战斗屏报了 `total=0`，
> 因为那时 `_battle` 还没建好。**测界面要等它稳定，不是第一帧。**

## 1. 已修：战斗技能面板重叠（严重）

### 症状

截图里第二排技能的下半截被「调整站位」压住，副标题完全看不见。

### 实测

```
[hits] 重叠 1 对：
    skill:2            x movemode           重叠 449x14
```

### 原因

面板高 206，标题占 52，剩 154；技能卡 40 高、行距 46，两列三行要 138 ——
但底部两个动作**各占一行**（32+32，分别在 `-44` 和 `-82`），各自压在第二、第三行上。

### 改法

- 技能卡 40 → **34**，行距 46 → **38**（三行只占 110）
- 底部两个动作并成**一行**（各半宽：「调整站位（N 号位）」「跳过（+5 压力）」）

改后 1280 / 1080 两档实测 `重叠 0 对`。

## 2. 已修：第 7 个技能被静默丢弃

### 症状

固定两列 × 三行 = 6 格，第 7 个之后被 `break` 掉——**界面上根本不存在**。

### 实测

```
15 个职业 × 4 个站位的最大可选技能数 = 7（abomination @ 2 号位）
```

其它职业最多 6，所以只有憎恶在 2 号位会撞上。但这是「看不到也点不到」里最难查的一种：
没有报错、没有日志，只是少了一个按钮。

### 改法

`cols = 3 if options > 6 else 2`，容量变 9。窄屏下名字会截断，但至少能点。

## 3. 未修清单（按严重度）

### A. 屏幕最底部 6 处文字落在手势条区

| 行号 | 内容 | 基线 y |
|---|---|---|
| 2926 | 城镇底部说明 | 732 |
| 3435 | 战斗「光照影响：怪物伤害 …」 | **752** |
| 4394 / 4400 / 4409 / 4454 | 各建筑的操作提示 | 726 |
| 4941 | 公会提示 | 726 |

手机手势条约占底部 30–35 逻辑像素，这一带会被盖住。
**修法**：这些位置改成 `size.y - 34` 之类的相对量，并整体上移到面板内侧；
或者 `OS.has_feature("android")` 时不画（都是新手提示）。

### B. 触摸目标过小（实测数量）

| 界面 | 数量 | 尺寸 |
|---|---|---|
| 准备屏 补给 +/− 步进器 | **18 个** | 32×30 |
| 城镇 区域标签（荒野/墓穴/巢穴/海湾） | 4 个 | 110×28 |
| 战斗 底部两个动作 | 2 个 | 910×32 |

Android 建议触摸目标 ≥ 48dp。**修法**：视觉尺寸可以先不动，把**热区**向外扩 4–6px
（`_add_button` 里统一处理，且要先做重叠检测，扩完不能互相压）。

### C. 键盘独占的操作：空格 = 自动一回合

`_unhandled_input` 里四个快捷键，其中三个地图操作（ESC 撤退 / F 火把 / C 扎营）都有屏幕按钮，
**只有战斗的「自动一回合」没有按钮**——手机上进战斗就没有这个功能，而它恰好是打得久时最常用的。

**修法**：战斗面板底部加一个「自动」按钮（桌面也留着，等于给键盘操作一个可视入口）。

### D. 安全区（刘海 / 挖孔 / 圆角）完全没处理

全项目 `get_display_safe_area` 零引用。横屏时挖孔在左侧，而城镇屏左边距只有 28px，
标题和卡片左边缘会落在挖孔下面。

**修法不是加个 offset 就完事**：布局里大量绝对 y（`y=752`、面板 `530..736`），
一旦 safe area 让可用高度小于 760，这些坐标会整体跑到屏幕外。
要改成「所有纵向坐标相对 `size.y`」，是一次布局整理，约 1 小时。

### E. 没有 hover，手机上「哪些能点」不可见

桌面用 `_mouse` 做悬停高亮（`TILE_HOVER`、`_hover_uid`、按钮 hover 色）。
触摸只会产生一次按下，没有悬停态——玩家点之前无法判断哪里可点。
**修法**：给主要按钮加常驻描边/底色区分（不依赖 hover），或按下时给 120ms 的按下反馈。

### F. 列表没有滚动，长列表可能被截断（未验证）

`grep scroll` 零结果。墓园（每个阵亡者两行 × 46px）、名册（最多 15 人）、
商店（10 种补给）在人多时会不会画出面板外，我**没有造数据验证过**。
需要的话我可以构造 8 个阵亡记录 / 12 人名册截图确认。

## 5. 已知的验证边界

我没有真机也没有模拟器。上面所有数字来自：
1. `--dump-hits` 读出的真实热区坐标；
2. 用 `--w=1690` 模拟 20:9 手机的逻辑宽度（`content_scale` 下 2400×1080 屏 = 1689×760）。

**无法验证**：刘海实际高度、手势条实际高度、触摸坐标是否与鼠标坐标一致。
这三项需要你在手机上点一次并告诉我「哪个屏、哪个位置」——或者跑一次
`adb logcat | grep -i godot` 把崩溃/警告发我。
