# M7 · 房间图

M6 结束时我给玩家的信息是「4 敌 · 65 血」，可他们能做的只有「继续前进 / 点火把 / 休整 / 撤退」。
**信息涨上去了，决策空间没跟上。**

而更根本的问题是：路线是 `Array`——遭遇随机，但「往哪走」不存在。
`dungeons.json` 里 25 个地图生成参数，只用了 4 个（战斗数、走廊战斗数、饥饿数、走廊长度）。

这一层把那 21 个字段用起来。

## 生成算法

```
1. 撒房间   在 gridsize 网格上放 base_room_number 个房间
            按 nudge_neighbour_bias 决定「贴着已有房间长」还是「随便撒」
2. 连走廊   只在相邻房间之间连（曼哈顿 <= 2），带抖动的 Kruskal 保证连通
            再按 connectivity 加少量环，让岔路和回头有意义
3. 选端点   全对 BFS，取距离最远的一对作为入口 / 目标房间
4. 投内容   战斗 / 奇物 / 饥饿，按 maps 里的区间分配到房间与走廊
```

**第 3 步必须是「先连再选」，不能反过来。**
`min_final_distance` 要的是**图上的跳数**（短图 3、中图 7、长图 10），
不是网格曼哈顿距离——5×5 的网格曼哈顿最多 8，长图要 10 跳，
只有先建好树再挑最远对，这个数才有意义。

## 用到的字段

| 字段 | 用途 |
|---|---|
| `gridsize` | 网格尺寸（weald 中图 5×5） |
| `base_room_number` | 房间数量（9 / 14 / 19） |
| `nudge_neighbour_bias` `nudge_span` | 房间聚集还是分散（weald 成簇、crypts 更散） |
| `connectivity` | 额外环的数量 |
| `min_final_distance` | 入口到目标的最少跳数 |
| `total_room_battles` `room_curio` `room_guarded_curio` | 房间内容 |
| `hallway_battle` `hallway_hunger` | 走廊内容 |

没用上的还有 `hallway_trap` / `hallway_obstacle` / `hallway_curio` / `room_treasure` / `secret_rooms` /
`nudge_map_centre_bias`——它们需要陷阱、障碍、宝箱、密室这些**内容**支撑，
留到内容层再做。

## 图怎么接进远征

线性模式没有被删掉，两者共用同一套结算：

```gdscript
# 线性（bench 走这条，口径一字不变）
route[step_index]

# 图（界面走这条）
travel(room) → pending 队列 → take_step()
```

一次移动会产生**两步**：走廊上的事件（战斗/饥饿/无事）+ 到达房间后的内容（战斗/奇物）。
队列让 `take_step()` 不需要知道自己身处哪种模式，资源、战斗、结算全部复用。

**光照只在对走廊那一步扣除。** 如果「走一条走廊」和「进一个房间」各扣一次，
一次移动的光耗会翻倍，短图的补给根本撑不到出口。

## 三个翻车点

### 1. 走廊一开始连了跨半张图的房间

第一版没有限制连接距离，生成的图里有「0 号房 ↔ 5 号房」这种边。
图上它们是邻居，空间上隔着三个房间——**玩家看到的就是「地图在骗我」**。

走廊必须连相邻房间（曼哈顿 ≤ 2）。长边只作为连通性兜底：
房间撒得太散、近邻不够连成一整块时，才用最近的一对补上。

### 2. 按宽度铺满会让格子变成扁的

第一版 `cw = 宽/列数`、`ch = 高/行数`，中图 676×336 五列五行得到 135×67 的格子，
房间横向稀、纵向挤，看起来像表格而不是地图。

改成取两边较小的那个做正方形格子，再整体居中。

### 3. 固定按整张网格画，开局像空页面

只有两间房探明时，却按 5×5 铺满整屏，剩下的全是点阵。
改成**按已探明房间的包围盒向外扩一格**来取景——视野跟着探索走。

## 验证

```
全部通过：285 项断言
```

生成器的硬指标（每档 12–60 张图）：

| 指标 | short | medium | long |
|---|---:|---:|---:|
| 生成成功率 | 100% | 100% | 100% |
| 全图连通 | 100% | 100% | 100% |
| 深度达标（≥ min_final_distance） | 100% (≥3) | 100% (≥7) | 100% (≥10) |
| 走廊都是相邻房间 | 100% | 100% | 100% |
| 房间数 | 9.0 | 14.0 | 19.0 |
| 走廊数 | 12.0 | 19.0 | 26.0 |
| 平均跳数 | 5.7 | 8.9 | 12.1 |
| 环数（边 − 房 + 1） | 4.0 | 6.0 | 8.0 |

> 上表是 M8 修订后的数字。M7 当时的环数是 1/2/3 —— 图接近一棵树，最短路几乎唯一，
> 「选路」实际不成立。M8 把加环逻辑改成「允许缩短最短路，但只缩到深度下限为止」，
> 环数涨到 4/6/8，深度仍然 100%。详见 [M8_HAZARDS.md](M8_HAZARDS.md)。

「深度达标 100%」不是运气：生成器最多重试 16 次，取「达标里跳数最大」的那张，
所以即使某次撒得不好，也不会退回一张 2 跳就到的图。

**最关键的一条：线性模式的 bench 数字一个都没变。**
同一批次重跑 `bench_expedition --runs=40 --size=medium --level=3`，
压迫指数仍是 `0.835 / 1.448 / 2.725 / 3.278`，完成率仍是 `0.850 / 0.700 / 0.250 / 0.025`。
地图是新增的一条路，不是替换——M3 的全部结论继续有效。

## 现在玩家能做的决策

| 之前 | 现在 |
|---|---|
| 走不走 | **往哪走**：岔路左还是右 |
| 点火把吗 | **绕不绕**：奇物房要多吃一段光，换一笔钱 |
| 休整吗 | **到了出口走不走**：出口旁边还有一间没探索的战斗房 |
| 撤退吗 | 全部保留 |

最后一条是这一层最重要的副产品：**到达目标不等于完成**。
要不要继续挖，第一次成为一个真正的贪心决策。

## 已知局限

- **奇物只有「搜刮」一种交互**，掷骰给钱或加压，没有第二次选择。
- **走廊长度恒为 1 格**。`spacing`（4 格）还没接进来，所以长走廊的「耗光更多」还没有体现。
- **陷阱 / 障碍 / 秘密房间 / 宝箱没有做**，对应的地图参数仍然闲置。
- **回头没有额外成本**：走过的走廊照样扣光，但不会再有事件，所以「原路返回」很便宜。
- **没有迷雾动画**：探索是瞬间展开的，看不到"一步步点亮"的过程。
