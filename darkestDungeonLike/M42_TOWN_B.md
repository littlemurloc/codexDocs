# M42 · 城镇屏收尾（b 档）

> 一句话：建筑卡按宽度自适应两套排法，出发区加了地貌横幅。
> **原计划的"面板九宫格"放弃了**——素材不可用，理由在 §1。

---

## 1. 面板九宫格：`panels/` 里的素材不能用

原计划用 `panels/` 做面板边框。逐个看过之后放弃：

| 文件 | 实际是什么 |
|---|---|
| `panel_hero.png` 720×224 | 带心形血条槽、剑/盾/王冠图标的**专用 HUD 布局** |
| `panel_banner.png` 754×136 | 横幅没错，但右下角**印着 1 2 3 4 5 的编号** |
| `panel_inventory / panel_map / panel_monster` | 同样是带内建槽位的专用版式 |
| `blg_name_background.png` | 一坨墨迹飞溅，不是名字底板 |

DD1 的 UI 是**每个面板单独出图**，不是一套可九宫格拉伸的皮肤。
硬拿来当通用边框，会把心形血条和编号一起贴到我们界面上。

**换成**：出发区的地貌横幅（§2）。这一项比边框更值——它回答的是"我要去哪"。

## 2. 地域横幅：把"要去哪"先画出来

素材是 DD1 的 loading 图（1920×1080，44 张按区域分）。取中上部横带
（10%–62%，避开最下面的地面和人物脚），压成 1280×260 存
`assets/art/ui/regions/<id>.png`，共 4 张 / 984 KB。

四张的构图都是"入口"——荒野是橙色拱门、墓穴是哥特尖拱、巢穴是木门、
海湾是紫色岩洞加青水。所以它们天然适合当"出发"的背景。

绘制用 **cover**（按短边放大盖满再居中裁切），不拉伸变形；
上面压一层 52% 暗色，保证标签和四个区域按钮读得清。

## 3. 建筑卡：两套排法，按宽度切

| 视口 | 列 × 行 | 卡尺寸 | 卡内布局 |
|---|---|---|---|
| ≥1200 | 8 × 1 | 146×132 | 图在上、字在下（文字底条） |
| <1200 | 4 × 2 | 244×96 | **图在左、字在右** |

为什么窄的时候必须换行：1080 下 8 列每张只有 119 宽，而英雄卡同样在挤——
名字加头像之后已经没有余量。换成 4 列之后每张 244 宽，字能回到 13px。

窄版用横排而不是"竖排但更小"：244×96 的卡里再竖排，图只有 50 高，
半身像会糊成一团；横排能给到 82 高，反而比 8 列版（90 高）只小一点。

## 4. 布局坐标收口

上一版这些 y 全是硬编码（`452` / `436` / `480` / `650`），
M40 排一次算一遍、M41 调一次再算一遍。这次改成：

```gdscript
var b_end: float = _draw_town_buildings(286.0)   # 返回建筑区底部
var dep_y: float = b_end + 36.0                  # 出发行由它推
# 任务卡 dep_y + 26，说明文字 dep_y + 180 / 202
```

建筑区高度在两种模式下是 132 与 206，差 74——靠返回值传下去，
下面的区块自动跟上，不用再手算。

## 5. 踩的坑

**横幅顶边由 `dep_y` 反推，和建筑底不对齐。**
`dep_y = b_end + 30`、横幅 `Rect2(20, dep_y - 34, ...)` → 顶边落在 `b_end - 4`，
比建筑卡底部还高 4px，1080 那版横幅被上面一排卡压住一条。

改成 `dep_y = b_end + 36`（36 > 34），顶边正好贴住建筑底。

这类"两个量各自算、差一点点"的错误在布局里最费时间——它不会报错，
只在特定宽度下露出 4 个像素。

## 6. 已知限制

1. **1080 下建筑卡右侧留白多**。244 宽的横排卡里，图占 72、文字从 90 起，
   右半边空着。这是"列表式卡片"的固有形态，加内容才好填（比如"这周谁在里面"）。
2. **1280 底部空约 100px**。内容排到 670，视口 760。
   可以靠拉大建筑卡高度（132→150）填一部分，但这轮没做——先保证 1080 不溢出。
3. **横幅只有 58px 高**，只能露出地貌的一条。想更像"目的地"得给整个出发区
   （含四张任务卡）当背景，但那会让任务卡的可读性下降。
