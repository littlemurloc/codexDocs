## 追加：M71 桌面窗口等比缩放（「界面遮挡严重」的真因）

用户报三屏遮挡（准备屏按钮压出征卡、地图屏按钮压队伍卡、战斗屏技能区被裁），
怀疑是窗口分辨率。**是**，而且不是布局 bug：

- 项目逻辑分辨率是竖屏 750×1334，但**没有设 stretch**，桌面 1:1 开窗 = 750×1334 px。
- 屏幕可用高度只有 1032（1920×1080 减任务栏）→ 窗口底部被截，
  而三屏的「贴底按钮」全在那一块，看起来就像互相压住。
- 布局本身没问题：同一批界面在 750×1334 截图里完整、不重叠（`shots/m71_prep.png`、
  `shots/m71_map.png` 可证）。

修法（`_fit_desktop_window()`，在 `--w` 分支的 else 里调用）：
- `content_scale_mode = CANVAS_ITEMS` + `aspect = KEEP` + `content_scale_size = 750×1334`
  → **逻辑尺寸永远是 750×1334**，布局不随窗口变。
- 窗口按屏幕可用区等比缩到 96%（给标题栏留 4%），居中。
  本机 1920×1032 → 557×990。

三种情况**故意不缩放**：
1. `--w=` 排版验收：依赖「窗口多宽、布局就多宽」（M41 踩过，开 canvas_items 会让 1080 被缩回 750，测了个假的）。
2. `--shot=` 截图：要输出 750×1334 原尺寸，否则所有验收图都变成缩略图。
3. headless / Android：各自已有处理。

**教训**：`size` 是布局的唯一真源。只要窗口尺寸能小于逻辑尺寸，
所有「贴底/贴右」的 UI 都会跑出可视区，而它看起来像「元素重叠」而不是「被裁」——
因为上层元素正好盖住了下面的内容。竖屏项目上桌面必须锁逻辑尺寸。

## 追加：M72 挪位文案 + 字号整体 +2

### 挪位（用户问「怎么感觉是定死的」）
逻辑本来就是动态的：`move_options()` 按 `move_action.move=[min,max]` × 前后两个方向
现算落点（`crusader [1,1]` 只给相邻，`highwayman [2,2]` 可跨两格）。
问题在呈现——按钮只写「移到 3 号位」，看起来像两个写死的选项。

- 文案改成 `前移 1 格 → 2 号位（与强盗换位）`，方向/格数/交换对象都算出来。
- 战场上加高亮：挪位模式下，可落点的队友脚下套一圈金色地环（`is_move_spot`），
  不用读「3 号位」再回头数人。

### 字号整体 +2（`dd_theme.gd`）
`FONT_TAG 9→11 / SM 10→12 / MD 11→13 / BD 13→15 / LG 15→17 / H1 16→18 / HERO 20→22`。

原因：750 宽是按手机 2x 密度设计的，9~13 在手机上等于 4.5~6.5 逻辑点；
桌面窗口按 1334 高等比缩到 0.74 之后，9px 只剩 6.7 物理像素。

**连带修的四处**（都是「字变大就溢出」）：
1. 地图屏队伍卡：`压力 0` 单独一行会压到卡片底边 → 去掉文字，只留条形 + 中点刻度。
2. 地图格子「你在这里」：阈值 78 → 88 高，图标中心 0.46 → 0.42。
3. 城镇名册条：`存活 5 · 上限 4` 顶到「全部 ›」→ 缩成 `活 5/4`。
4. 技能卡摘要：去掉「命中 +X%」「暴击 +X%」——卡片第二行只放得下 10 个字，
   而真实命中率在瞄准态直接标在目标头上。

**物理上限**：1080p 屏可用高 1032，750×1334 最多缩到 0.77。字号 +2 相当于把这行字
的等效密度提了约 20%，再大就得重排各屏行距，不是改常量能解决的。

## 追加：M73 地图房间编号 + 残骸可摧毁

### 地图编号

### 残骸（尸体）可摧毁

规则层（`combatant.gd` / `battle.gd` / `effect_resolver.gd`）：
- `corpse_hp: int = -1`，死亡时设为 `ceil(base_hp / 12)`（小怪 1~2 下）。

- `_legal_targets` 把敌方残骸加进池子。判据是**「不是友方技能」**而不是「有伤害」：
  英雄技能的 `dmg` 是百分比修正，十字军惩击的 `dmg_mod` 就是 0，
  按伤害字段判断会漏掉一半攻击技。
- `_strike_corpse()`：不判命中、不走伤害公式，每下扣 1 点耐久；
  归零则 `remove_at` + `_relayout()`，后面的人整体前移一格。
- `_pick_target`（AI）：优先活人，只在没有活人可打时才清残骸。
- 事件 `corpse_hit` / `corpse_destroyed`；界面写日志 + 飘字，
  并把该 uid 从 `_order_ids` 里摘掉。

界面：残骸头顶写「残骸 N」（紫色）—— 不写的话玩家不知道打一下还在、打两下才清。
`marks` 基线从 `hp.end + 14` 调到 `+9`（敌方那行原来掉到块外，压在立绘头顶上）。

**验收坑**：`--start --battle` 会 start 两次战斗（队列里一场 + `_boot_into_battle` 一场）。
`--corpse-demo` 第一版只在「第一次进玩家回合」时杀敌，杀到的是被顶掉的那一场，

## 追加：M74 房间叙事卡

用户反馈「点进房间就结束了，没有任何画面叙事」。原来 `_drain_queue` 是**瞬间批量结算**的：
点房间 → `resolve_curio()` → 日志多一行 → 人还站在原地。

做法：新状态 `S_ROOM` + 两页卡。
- **抵达页**：房间图标 + 「N 号房 · 奇物」+ 一句环境描写 + 「你看见了：<奇物名>」，
  按钮「走进去」。
- **结果页**：把结算结果摆出来，按钮「继续赶路」。

实现要点：
- 新增 `Expedition.peek_step()`：**只读**地看一眼下一步。`take_step()` 里带着
  光照消耗和走廊压力，取走再放回很脆。
- `_room_should_pause(step)`：**只拦房间里的奇物**。
  走廊步骤带 `corridor: true`，一路走一路停会把节奏拖死；
  战斗房由遭遇横幅负责。`_selftest` / `_auto` / `_skip_battles` 一律返回 false
  —— 自动化不会点按钮，停下来就是卡死。
- 结果文案**直接复用刚写进日志的那几行**（记 `_log.size()` 前后差），
  不另维护一套：日志说掉血、卡片说没事这种不一致迟早会出现。
  显示时用 `_strip_log_tag()` 去掉「【奇物】」前缀。
- 卡片底下先 `_draw_map()` 再盖 0.66 遮罩，然后 `_buttons.clear()` ——
  模态卡片只该有自己那颗按钮（不清的话地图片区的热区还活着）。
- 卡片高度按内容算（结果可能只有一行，也可能五六行）。

**没做的**：空房间（`K_EMPTY` 没有 step，压根不进 `_pending`）、
走廊陷阱/路障（不打断节奏，目前只有一行日志）。
这两块要补的话，方向是「不打断的横幅」而不是再弹一张要点的卡。

验证：`shots/m74_room.png`（抵达）、`m74_room_res.png`（结果）。
验收参数 `--room-demo` / `--room-demo=1`。规则层 1365 项全过。

## 追加：M84 战斗状态块挪到光照之后（「紫字像半透明」的真因）

用户问「为什么有些字体半透明，紫色的尤其」。查下来**跟 alpha 无关**：
`DdTheme.STAT = #9d7bd8`，alpha 一直是 1。

真因是**绘制顺序**：`_draw_unit`（含头顶状态块）画在 `_draw_lighting` **之前**，
而光照会铺一层全屏 `Color(0.012,0.011,0.013, dim)` + vignette。
敌方离我方火把远 → 那一带 dim 高 → 紫字被压掉一半亮度，看着就是半透明。

修法：把状态块从 `_draw_unit` 拆出来成 `_draw_unit_status()`，
在 `_draw_lighting()` **之后**遍历 `_slots` 再画一遍。
`_slots` 里补了 `cx/gy/top` 三个几何字段，绘制时不用重算立绘尺寸。
`_draw_unit` 里只保留「算 blk_top + 存 slot」，立绘/阴影/地环照旧。

**教训**：这类「看着像透明」的问题，先看是不是被上层画的东西压住了。
`_dci()`/光照层/遮罩都是同一类陷阱，查 alpha 只会白跑一遍。

验证：`shots/m84_battle.png`（敌方 DOT×1 紫字不再发灰）。规则层 1365 项全过。

## 追加：M90 公会技能卡描述行（可读性）

用户反馈「眼睛要瞎」。查下来是两件事叠在一起：
- **12px**（`FONT_SM`）+ **最暗的 `DIM`(#8b8a84)** 压在深灰卡上，对比度约 2.8:1；

改：
- 字号 → `FONT_MD`(13)。
- 颜色 → 新常量 `DESC_COL = #aaa79e`（比 `DIM` 亮一档，对比度约 5.4:1），

## 追加：M92 属性文案补齐（16 种未映射）

`_buff_line()` 是饰品/怪癖共用的「一条属性 → 中文」翻译函数，末尾有兜底
`return "%s %+.0f"`。数据里 `stat_type` 共 **27 种**，只映射了 **11 种**，
剩下 16 种全落进兜底 —— 界面上直接露出英文键。

而且兜底**不乘 100**：`stun_chance` 的 amount 是 0.1，`%.0f` 写成「+0」，
看着像「零效果」，比露出英文更误导。

补齐 16 种（眩晕/流血/中毒/减益/位移/被暴击/受伤/受疗/施加压力/施加减压/
饥饿伤害/怪物奇袭/我方奇袭/决心经验/消除负面怪癖/无视潜行），
`ignore_stealth` 不带数字（它是开关）。

**教训**：这类「翻译表 + 兜底」的函数，兜底本身要为「未知键」设计得保守
（至少别把 0.1 写成 +0）。补映射时先用脚本比对「数据里出现过的键」和
「代码里 match 过的键」，比翻截图快。

验证：`shots/m92_shop.png`（六件饰品摘要全是中文且百分比正确）。规则层 1365 项全过。
