## M192 · 「互动」标签加缩放呼吸

**需求**（用户给横屏截图，红框圈住地图房间底部的「互动」标签）：
现有的呼吸只有颜色/透明度脉动，"能不能更明显些，例如比例呼吸似的缩小放大"。

**改法**（`src/view/expedition_scene.gd`，`_draw_grid_map_on` 内）：
- 原有 M190 颜色呼吸保留，`pulse` 改用 `0.5 - 0.5*cos(ph)`（从原尺寸起跳，不会一进屏就是大的）。
- 新增 `draw_set_transform(标签中心, 0, Vector2(scale,scale))` 做等比缩放，**只放大不缩小**
  （标签底边贴着房间框，缩到 1.0 以下会离线看不清），峰值 **1.26**。
- 描边线宽跟着 pulse 走：`1.5 + 1.0*pulse`，亮的那一帧整块标签"顶"出来。
- 缩放结束**立刻 `draw_set_transform(ZERO, 0, ONE)` 复位**——这是全局状态，漏掉会把后面
  所有格子一起缩放（症状是"越往下画越小"，而且不报错）。

**新增调试参数 `--show-interact`**：强制当前房间显示「互动」。
理由：呼吸是逐帧的，静态截图看不出来；靠真实走位几乎截不到——地图每次出发都重新生成，
房间号随机，`--click=room:N` 会直接 `enter_room()` 跳过门口状态。

**截图命令（验证用，可复现）**：
```
cp m190.json m192_t.json   # user:// 目录
godot --path . -- --save=user://m192_t.json --click=dock:prep,prep_go \
      --show-interact --shot=shots/m192_peak.png --shot-at=1.44
```
相位峰值 t：`2.2t = π` → **1.43s**；相位谷底 t：**2.86s**。
截图：`shots/m192_peak.png`（峰值，标签宽度溢出房间框两侧）、`m192_f2.png`（谷底，原始大小）。

**验证**：headless 启动无报错；`tests/run_tests.gd` **1150 项断言全绿**。

### 6. 状态栏「▼攻0」出现三次（M196）
用户截图问「攻0 写了 3 次是什么意思」。拆开看：
- `▼` = 减益，`攻` = 类别缩写（attack_rating / damage_low / damage_high **全部映射成「攻」**），
  `0` = **剩余回合数**。而 `remaining == 0` 在 `combatant.tick_round()` 里表示**永久**
  （只减 >0 的条目，0 的保留到战斗结束）。所以三个「▼攻0」= 一次减益压了三条属性 + 永久。
- 用户的困惑是「0 看起来像 0 回合 / 0 效果」，完全合理。

已改（`_draw_party_status`）：
1. `remaining == 0` 显示 **「永」**，不再印 0。
2. 先按「类别 + 增减 + 是否永久」归并再画：一次技能的三条属性合并成一条
   「▼攻 永」，不再重复三遍。

**未验证**：截图那两场（菌人 / 邪教徒）都没出永久减益，视觉样本没复现。
另注意：状态栏只画 `u.buffs`，不画 `statuses`（崩溃/中毒），所以会出现
「头顶写着崩溃、下面写无状态」的矛盾——这是既有的分工，不是本次改出来的。

## M202 · 日志浮层点击穿透

**问题**：战斗里的「行程记录」浮层打开后，底下的「挪位 / 跳过 / 撤退」照常显示、照常可点。
撤退是**丢掉整趟**的动作，误触代价极大。

**根因**：`_draw_log_float()` 在 `_draw_battle()` 末尾调用，而 `_draw_buttons()` 在 `_draw()` **更后面**，
所以按钮画在浮层之上；`_hit_id_at()` 也没有浮层的模态判断。

**改法**（两边必须同时改，只改一边就是「看着盖住了、其实能点」）：
1. `_draw_buttons()` 循环里：`if _log_open and _state == S_BATTLE and id != "log_toggle": continue`
2. `_hit_id_at()` 开头：`_log_open` 时只放行 `log_toggle`，其余返回空（空 → `_on_click` 当"点空白"→ 关浮层）

**这是同一类错的第三次**（M140 名册抽屉、M154 补给面板、M202 日志浮层）。
判据：**任何"浮层/抽屉/弹窗"，都要同时问三件事** —— 画在谁之上、命中拦不拦、底层按钮要不要跳过绘制。

**现象**：走到首领房，没有战斗，直接可以「离开地牢」。

**根因**（界面层，不是规则层）：`_draw_map_actions` 中间那颗按钮的优先级写成了
`at_goal > has_pending_room`。而首领房**两条同时成立**：它是终点（at_goal），
也有一场待触发的首领战（`travel` 会把 `rooms[goal].step` 放进 `room_pending_step`）。
结果中间那颗直接变成「离开地牢」，「互动探索」被顶掉 —— **玩家没有任何入口触发战斗**。

规则层是对的：`QuestGoal` 对 kill_boss 用 `KIND_BOSS`，判 `boss_killed`，
而 `boss_killed` 只在打赢 `active_is_boss` 那场时置真；`finish()` 里未达成会改判 `incomplete`。
所以那趟的结算确实是「未完成」——但玩家看到的是「离开地牢」，先入为主以为结束了。

**修**：
1. 优先级改成 **`has_pending_room` > `at_goal`**（有待互动的东西永远优先，它就是「往前走」）。
2. 「离开地牢」文案按任务是否达成区分：达成写「▣ 离开地牢」，未达成写「▣ 离开（未完成）」。

**教训**：终点房间不是特例，它和其他房间一样有「内容待触发」。
凡是「优先显示 X」的分支，都要问一句：**X 和别的条件会不会同时成立，同时成立时谁该赢**。

## M204 · 任务进度看不见

用户说「地牢里完全没有任何任务进度提示」。实际上**一直有**，在房间面板第三行，
但三个原因叠起来等于没有：
1. 字号 `FONT_TAG`(16)，和「位置 0 · 已走 0 步」一样大 —— 扫一眼根本不会注意；
2. 探索类任务只写「走到出口」四个字，**没有进度数字**（清剿/收集有「0/4」）；
3. 颜色是 WARN（橙），读起来像警告而不是「当前目标」。

改：
- `_quest_line()` 对 `KIND_REACH` 补上「（还差 N 步）」/「（已到达）」，用 `_dist_to_goal()`
  （和底部「出口在 N 步之外」同一个最短路，不会两处对不上）。
- 任务行字号提到 `FONT_MD`(20)；有分母的任务在右边加一条 **96×9 进度条**。
- 进度条轨道用 `PANEL_EDGE` 不用 `PANEL_DEEP`：0/4 时只画轨道，深色轨道和面板底同色，
  看起来像「没画」——第一版就是这样，截图才发现。
- 任务行原文案「清剿任务：图上的战斗全打完，走到出口才算完成」23 字，34 号折两行、
  第二行压住面板标题，压到 16 字「全图战斗打完才算完成」。
- `_room_panel_h()` 起点 88/98 → 98/108（任务行变高占的 10px 要从预算里出）。
