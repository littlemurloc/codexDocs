## M192 · 「互动」标签加缩放呼吸

**需求**（用户给横屏截图，红框圈住地图房间底部的「互动」标签）：
现有的呼吸只有颜色/透明度脉动，"能不能更明显些，例如比例呼吸似的缩小放大"。

**改法**（`src/view/expedition_scene.gd`，`_draw_grid_map_on` 内）：
- 原有 M190 颜色呼吸保留，`pulse` 改用 `0.5 - 0.5*cos(ph)`（从原尺寸起跳，不会一进屏就是大的）。
- 新增 `draw_set_transform(标签中心, 0, Vector2(scale,scale))` 做等比缩放，**只放大不缩小**
  （标签底边贴着房间框，缩到 1.0 以下会离线看不清），峰值 **1.26**。
- 描边线宽跟着 pulse 走：`1.5 + 1.0*pulse`，亮的那一帧整块标签"顶"出来。
- 缩放结束**立刻 `draw_set_transform(ZERO, 0, ONE)` 复位**——这是全局状态，漏掉会把后面
  所有格子一起缩放（症状是"越往下画越小"，而且不报错）。

**新增调试参数 `--show-interact`**：强制当前房间显示「互动」。
理由：呼吸是逐帧的，静态截图看不出来；靠真实走位几乎截不到——地图每次出发都重新生成，
房间号随机，`--click=room:N` 会直接 `enter_room()` 跳过门口状态。

**截图命令（验证用，可复现）**：
```
cp m190.json m192_t.json   # user:// 目录
godot --path . -- --save=user://m192_t.json --click=dock:prep,prep_go \
      --show-interact --shot=shots/m192_peak.png --shot-at=1.44
```
相位峰值 t：`2.2t = π` → **1.43s**；相位谷底 t：**2.86s**。
截图：`shots/m192_peak.png`（峰值，标签宽度溢出房间框两侧）、`m192_f2.png`（谷底，原始大小）。

**验证**：headless 启动无报错；`tests/run_tests.gd` **1150 项断言全绿**。

### 6. 状态栏「▼攻0」出现三次（M196）
用户截图问「攻0 写了 3 次是什么意思」。拆开看：
- `▼` = 减益，`攻` = 类别缩写（attack_rating / damage_low / damage_high **全部映射成「攻」**），
  `0` = **剩余回合数**。而 `remaining == 0` 在 `combatant.tick_round()` 里表示**永久**
  （只减 >0 的条目，0 的保留到战斗结束）。所以三个「▼攻0」= 一次减益压了三条属性 + 永久。
- 用户的困惑是「0 看起来像 0 回合 / 0 效果」，完全合理。

已改（`_draw_party_status`）：
1. `remaining == 0` 显示 **「永」**，不再印 0。
2. 先按「类别 + 增减 + 是否永久」归并再画：一次技能的三条属性合并成一条
   「▼攻 永」，不再重复三遍。

**未验证**：截图那两场（菌人 / 邪教徒）都没出永久减益，视觉样本没复现。
另注意：状态栏只画 `u.buffs`，不画 `statuses`（崩溃/中毒），所以会出现
「头顶写着崩溃、下面写无状态」的矛盾——这是既有的分工，不是本次改出来的。

## M202 · 日志浮层点击穿透

**问题**：战斗里的「行程记录」浮层打开后，底下的「挪位 / 跳过 / 撤退」照常显示、照常可点。
撤退是**丢掉整趟**的动作，误触代价极大。

**根因**：`_draw_log_float()` 在 `_draw_battle()` 末尾调用，而 `_draw_buttons()` 在 `_draw()` **更后面**，
所以按钮画在浮层之上；`_hit_id_at()` 也没有浮层的模态判断。

**改法**（两边必须同时改，只改一边就是「看着盖住了、其实能点」）：
1. `_draw_buttons()` 循环里：`if _log_open and _state == S_BATTLE and id != "log_toggle": continue`
2. `_hit_id_at()` 开头：`_log_open` 时只放行 `log_toggle`，其余返回空（空 → `_on_click` 当"点空白"→ 关浮层）

**这是同一类错的第三次**（M140 名册抽屉、M154 补给面板、M202 日志浮层）。
判据：**任何"浮层/抽屉/弹窗"，都要同时问三件事** —— 画在谁之上、命中拦不拦、底层按钮要不要跳过绘制。

**现象**：走到首领房，没有战斗，直接可以「离开地牢」。

**根因**（界面层，不是规则层）：`_draw_map_actions` 中间那颗按钮的优先级写成了
`at_goal > has_pending_room`。而首领房**两条同时成立**：它是终点（at_goal），
也有一场待触发的首领战（`travel` 会把 `rooms[goal].step` 放进 `room_pending_step`）。
结果中间那颗直接变成「离开地牢」，「互动探索」被顶掉 —— **玩家没有任何入口触发战斗**。

规则层是对的：`QuestGoal` 对 kill_boss 用 `KIND_BOSS`，判 `boss_killed`，
而 `boss_killed` 只在打赢 `active_is_boss` 那场时置真；`finish()` 里未达成会改判 `incomplete`。
所以那趟的结算确实是「未完成」——但玩家看到的是「离开地牢」，先入为主以为结束了。

**修**：
1. 优先级改成 **`has_pending_room` > `at_goal`**（有待互动的东西永远优先，它就是「往前走」）。
2. 「离开地牢」文案按任务是否达成区分：达成写「▣ 离开地牢」，未达成写「▣ 离开（未完成）」。

**教训**：终点房间不是特例，它和其他房间一样有「内容待触发」。
凡是「优先显示 X」的分支，都要问一句：**X 和别的条件会不会同时成立，同时成立时谁该赢**。

## M204 · 任务进度看不见

用户说「地牢里完全没有任何任务进度提示」。实际上**一直有**，在房间面板第三行，
但三个原因叠起来等于没有：
1. 字号 `FONT_TAG`(16)，和「位置 0 · 已走 0 步」一样大 —— 扫一眼根本不会注意；
2. 探索类任务只写「走到出口」四个字，**没有进度数字**（清剿/收集有「0/4」）；
3. 颜色是 WARN（橙），读起来像警告而不是「当前目标」。

- 任务行字号提到 `FONT_MD`(20)；有分母的任务在右边加一条 **96×9 进度条**。
- 进度条轨道用 `PANEL_EDGE` 不用 `PANEL_DEEP`：0/4 时只画轨道，深色轨道和面板底同色，
  看起来像「没画」——第一版就是这样，截图才发现。
- 任务行原文案「清剿任务：图上的战斗全打完，走到出口才算完成」23 字，34 号折两行、
  第二行压住面板标题，压到 16 字「全图战斗打完才算完成」。
- `_room_panel_h()` 起点 88/98 → 98/108（任务行变高占的 10px 要从预算里出）。

## M205 · 怪物美术：AI 出图 + 抠图管线

**结论**：`UnitArt` 对英雄/怪物完全通用（按 id 找 `<id>_combat.png`），**代码不用改**，
只要往 `assets/art/units/` 放图。这是用户自己提出的判断，实测成立。

**AI 出图的两个坑（重要）**：
1. **`background: transparent` 是假的** —— 生成器直接在画布上**画了一层棋盘格纹理**，
   全图 alpha 全是 255。`--inspect` 一测就露馅（非透明区域铺满整张）。
   所以必须自己抠：`tools/gen_monster_art.py` 用**四角+四边中点泛洪**（thresh 60），
   把「与边缘连通的亮灰」判成背景。不用按 alpha、也不用"全图清亮灰"——
   后者会把人物身上的浅色绷带打出麻点。
2. **右下角水印**（「AI生成 WORKBUDDY」）固定在那儿，直接 alpha 清零一块 320×120。

**规格归一**：裁到内容 bbox → 等比缩放到**高 400**（和英雄同一套，README §2）→ 存
`<id>_combat.png`。脚底贴画布底、左右居中，和英雄的脚线一致。

**新增验收参数**：`--foe-demo=<id>` 把战场上的敌人立绘换成指定 id（只改绘制、不改 `def_id`），
配合 `--no-light` 看原始画风。补一张图就能立刻验比例，不用等随机抽到它。

**已出 3 只样张**：`cultist_brawler`（169×400）、`skeleton_militia`（262×400）、
`swine_wretch`（318×400）。画风与英雄协调（粗墨线 / 低饱和平涂 / 右上侧光）。

**待解决**：敌方区域在光照系统里被压得很暗，带光照时细节几乎看不出来
（`--no-light` 才看得清）。批量补图前要么给敌人立绘加边缘光，要么提高敌方基础亮度，
否则 101 张做完在游戏里还是一团黑。

## M206 · 怪物立绘：抠图定版 + 头身比

用户反馈两件事：① 部分图没抠干净留白底；② 画风偏写实（头身比不对）。

### 抠图（重写了三次才对）

| 版本 | 判据 | 结果 |
|---|---|---|
| 1 | 四角泛洪（thresh 60） | 残留 ~1.2%，人物边缘的阴影渐变处泛洪停下 |
| 2 | 连通域 + "亮低饱和" | 残留降到 0.02%，但**同一 prompt 第二次生成背景变成深灰**，判据失效 |
| 3 | **四角取色 + 纯色幕分支** | 定版 |

**根因**：生成器每次给的底**不一样**（暖灰渐变 200 / 深灰 70 / 棋盘格），
而人物暗部和深灰底颜色接近，靠"猜背景色"必然翻车 ——
放宽会吃掉帽子（邪教徒兜帽顶部就是这么没的），收紧会留下白块。

**定版做法**：prompt 里**明确要求纯品红幕**（`solid magenta #FF00FF, no gradient, no texture`），
生成后用 `四角颜色标准差 < 12` 判定"这是纯色幕"，直接按颜色距离全清，不做连通/面积兜底。
纯色幕和人物颜色天然拉得开，不存在误吃。**批量出图必须走这条路。**

### 头身比

英雄是 5 头身（头大、手大、腿短）。AI 默认给 7-8 头身（写实），所以"看着不像一套"。
prompt 要写**双向**约束才管用：
```
PROPORTIONS: oversized head, big hands, short thick legs, about 5 heads tall,
NOT realistic anatomy, NOT slender, NOT 7 or 8 heads tall
```
只写正面词（"stylized"）不够，模型会往写实靠。

### 结果

`cultist_brawler` 202×400 / `skeleton_militia` 288×400 / `swine_wretch` 241×400，
三张都干净、5 头身、和英雄同一画风。验收看 `shots/m206_alpha_check.png`（品红底检查图）。

**仍然待办**：敌方区域在光照下偏暗，细节被吃掉（和 M205 同一个问题）。

## M207 · 敌方镜像 + 品红去溢色

**需求**：敌人要面朝左（面向我方），素材统一朝右。

**实现**：`_draw_unit` 里 `is_enemy` 时把坐标原点挪到矩形**右边缘**、沿 x 缩放 -1，
画完立刻 `draw_set_transform(0, 1)` 归位。地环 / 血条 / 名字都用 `cx` 算坐标，
变换没复位会让它们整屏镜像。

**`draw_texture_rect_region` 传负宽度不行**：Godot 4 里那样画不出来，
表现是**整排敌人变空白**（第一版就是这样，截图才发现）。

**顺带查出的真问题**：镜像后立绘周围出现**品红块**。
根因是抠图只把「接近底色」的 alpha 置 0，而轮廓外一圈抗锯齿像素是
「品红 + 人物色」的混合，颜色距离已经拉开、被当成内容留下。
修法加 `despill()`：按 `mag = min(R,B) - G`，mag>55 判背景、mag>8 压 R/B 到 G 附近。

**验证方法的漏洞（重要）**：用**品红底**做检查图看残留 —— 品红压在品红上，看不见。
必须用**对比色底**（绿/暗红）才暴露。以后所有抠图验收都用绿底。

结果：`skeleton_militia` / `swine_wretch` 残余品红 **0 px**，`cultist_brawler` 剩 24px（可忽略）。

## M208 · 敌方边缘光

**问题**：光照的暗角以我方为中心，敌人站在远处 → 立绘被压成一团黑，
新补的怪物美术（M205-207）在游戏里等于白做。

**做法**：`_draw_unit` 里对敌人**先画一圈偏移的亮色副本、再盖原图**。
8 个方向各偏移 2.2px、modulate `(0.98,0.90,0.70, 0.55)` 暖白；
只有超出轮廓的部分留下来，形成外发光。不用 shader、不用额外美术资源，
换任何一版立绘自动生效。

**三个必须注意的点**：
1. **必须在镜像变换之内画** —— 人物在画布里不对称（剑在一侧），
   按未镜像的位置偏移，光会跑到没有武器的那一侧。
2. **只在 `not u.dead` 时画**：尸体该是塌的，加光会读成"还活着"。
3. alpha 0.42/偏移 1.8 太弱（第一版在暗角里几乎看不出）；
   0.55/2.2 合适；再高会变成「发光怪物」，和火把照明打架。

**成本**：每只敌人多 8 次 draw，4-7 只 = 32-56 次/帧。2D 下无压力。

**没动光照本身**：暗角是氛围的一部分（光源在我方），
调 `dim` 会让整屏发白、把「火把」这件事抹掉。补光只该补在单位上。

## M209 · 站立浮空 = 影子太小

用户报「怪物站着像浮空」。查图本身：三张立绘底部**有效像素到第 399 行**（画布 400），
没有透明边距 —— 不是裁图的问题。

真因是**脚下阴影写死半径 34**：那是给 60px 宽的旧剪影准备的。
新立绘显示宽 120~180px，一块 68×20 的小椭圆压在脚底托不住，
而"站得实不实"几乎完全由这块影子决定，不是由立绘本身。

改：
- 半径按立绘显示宽度算 `clampf(tex.width * sx * 0.42, 30, 96)`；
- 叠两层（外层 0.5、内层 0.45、半径 55%），单层椭圆中间发虚；
- 因为要读 `tex`，把阴影代码**挪到取图之后**（原来在取图之前，拿不到宽度）。

顺带：英雄阴影也跟着变大了（同一个公式），截图看自然，不需要单独处理。

## M210 · 怪物动作帧（骷髅兵一套）

**两张图**：`skeleton_militia_attack_melee.png`（270×400）、`skeleton_militia_dead.png`（276×170）。
用 **image-to-image**（原 combat 图作参考 + `input_fidelity: high`）保证是同一个角色 ——
纯文生图会换成另一个骷髅，装束对不上。

**内容审核坑**：dead 帧的 prompt 写 `destroyed corpse` / `caved in` 被拒，
改成 `fallen pile` / `lying down` 才过。

## M212 · 命中帧 = 攻击者命中瞬间的轮廓

用户否掉了上一版 `attack_melee`：「看不出来是攻击动作」，并指出关键是
**命中那一瞬间攻击者自己的表现**（不是受击者）。

**为什么上一版不像攻击**：手臂是**收着的**、剑贴着身体、躯干直立。
轮廓和站姿几乎一样，只是剑尖换个角度 —— 阅读不出"力"。

**这版的做法（prompt 三条）**：
1. **用轮廓描述，不用姿势名**：`SILHOUETTE MUST READ AS A WIDE DIAGONAL`，
   力从后脚经腰到剑尖连成一条对角线；
2. **写清各部位的状态**：肘几乎伸直、剑远离身体、前膝深弯承重、后腿绷直脚跟离地、
   盾牌甩到身后做配重、破布朝反方向甩；
3. **否定词必不可少**：`arm not bent / sword not close to the torso / body not upright /
   legs not standing square`。只写"命中瞬间"模型会给一个握剑站姿。

**尺寸要单独补**：前倾姿势的 bbox 高比站姿小，按 400 归一会把人物放大 ~17%，
切帧时会"跳"。`--target-h=340` 才和站立帧一致（516×400 → 438×340）。

**注**：这版动作是**刺**（thrust）不是劈。要劈的话 prompt 得改成横扫过身体。

## M214 · 团灭后名册条还在显示"4 个正常人"

**根因**：`_draw_roster_strip` 的 `show_ids` 本来已经过滤死人和忙人（M191），
但过滤后为空时会走两条 fallback，其中 `campaign.party_ids` **没有过滤** ——
存档里的名单是「上次出征的 4 个人」，他们死了名单也不会被清。
于是团灭回城，这条还是 4 个正常头像 + 上阵 4/4。

**改法（两层）**：
1. `party_ids` 的 fallback 也过滤 `alive` / `busy`；
2. **绘制用「不过滤」的名单** `draw_ids`，计数才用过滤后的 `show_ids`。
   这是关键取舍：过滤掉死人 → 4 个格子变空槽，玩家读成「没人编队」，
   反而把「他们都死了」这个最重要的信息抹掉了。所以格子留着，人标成阵亡。

**阵亡标记**：头像 `tint` 压到 0.45（0.30 会压成纯黑块、连是谁都看不出）、
暗红 2px 边框、中间一条半透明黑 + 红色「亡」字。

**颜色坑**：一开始用 `DdTheme.CRIT`（#f0c040 金黄）—— 那是暴击/奖励色，
读起来像"高亮"而不是"死亡"。改用 `DdTheme.HP`（#a8322d 暗红）提亮。

**验证存档**：`m214_dead.json`（把 m190 的 4 个英雄全标 alive=false + 写进 party_ids）。

## M215 · 怪物动作的三个观感问题

用户跑了游戏，提三条：
1. 死亡时像被缩放了，和活着的角色比例不对；
2. 攻击看着像"两个动作"（抬手 + 命中）；
3. 命中帧一闪就过，看到的几乎都是抬手。

**1. 死亡比例**：英雄 `combat 544 / dead 350 = 64%`，而骷髅兵的骸骨堆只有 `170/400 = 42%`
—— 塌得太狠，读成"被缩小了"。改成 `--target-h=255`（64%），和英雄同一比例。
副作用：骸骨堆横向 413px，4 只并排会重叠（真实战斗里尸体不会一字排开，可接受）。

**2 & 3. 两段式的时长**：原来 1:1、总 0.34 秒 → 每帧 0.17 秒，命中帧等于闪一下。
现在改成 **1:2、总 0.6 秒**（起手 0.2s / 命中 0.4s）。
- 权重用**重复项**表达：`seq = ["attack_windup", anim, anim]`，`_unit_anim` 按进度取索引，
  重复的帧自然分到更多时间，不需要额外的权重字段。
- `dur` 同时传给 `_pose`（位移补间也按这个时长走，前冲跟着变慢，节奏一致）。

**注意**：英雄仍是单帧 0.34 秒 —— 整段都停在命中姿势上，所以观感更"重"。
怪物因为多一个起手，总时长反而更长，这是对的（不是 bug）。

**踩坑**：编辑时 `_pose[uid] = ...` 出现了两行（旧行没删干净），后一行用 `POSE_TIME` 把
`dur` 覆盖回去，等于时长改动完全没生效。改完这类赋值语句要 `grep` 一下有没有重复。

## M217 · 我方攻击时有一瞬间变成骷髅

用户报：队友攻击时角色图标会短暂变成敌人的样子。

**不是英雄缺帧**（15 个英雄、所有技能的 `art.anim` 对应的图全都在）。
真因在**两段式攻击的判据**：

```gdscript
if _art.frame(u.def_id, "attack_windup") != null:   # ← 这里
    seq = ["attack_windup", anim, anim]
```

`frame()` 有「找不到 → 退到怪物占位（骷髅）」的兜底，而骷髅**有** `attack_windup`。
于是英雄也被判定成"支持两段式"，前半段的 `attack_windup` 就去占位里取 ——
我方出手的前 0.2 秒显示骷髅。

**修了两处**：
1. `frame(id, anim, allow_placeholder := true)`：英雄传 `false`；
   同时加一步「缺这个动作 → 退到**自己的站姿**」。英雄素材包动作不全时
   （比如某职业没有 `attack_xx`），表现应该是"站着不动"，不是"变成别人"。
2. 新增 `has_frame(id, anim)`：**只查文件在不在，不走任何 fallback**。
   两段式判据必须用它 —— 用 `frame() != null` 的话，因为第 1 条新加的兜底，
   任何有立绘的单位都会返回非 null，判据永远为真，英雄会先站 0.2 秒再出手。

**教训**：给"查图"的函数加兜底，所有**拿它当判据**的地方都会跟着变成恒真。
查询函数和判定函数要分开（`frame` vs `has_frame`）。

验证：英雄 `has_frame(windup)=false` → 两段式关；骷髅 `=true` → 开。
