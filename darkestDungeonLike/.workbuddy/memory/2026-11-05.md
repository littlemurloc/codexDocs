## M32 分区任务板与任务目标层（同日继续）

**起点**：`dd_db.gd` 里根本没有 `quests` 字段——6 种任务类型、48 个目标定义
从 M0 抽出来一次没读过；任务在代码里只是 `explore` / `kill_boss` 两个字符串；
`campaign.board` 一块，四区共用。

**先做数据核查，推翻 M26 的一个结论**：M26 记的是「cleanse/gather 只有布局、
缺目标数量」——**错**。数量在 `data.amount`（gather item.amount=3）、
比例在 `data.percentage`（battle_all_rooms=1、explore_all_rooms=0.9）。
没读那两行就下了结论。

**清剿 = 探索 + 一场仗**：四个区域 × 三个尺寸，`total_room_battles` 全部差 +1
（short 1-3→2-4、medium 3-4→4-5、long 7→8），hallway_battle 完全一样。
所以清剿不是「更凶的图」，是同图多一场不能跳过的仗。

**做了什么**
1. 新增 `src/core/quest_goal.gd`（~200 行）：`parse(quests, quest_type, region)` /
   `met(goal, state)` / `progress` / `describe`。不认识 Expedition 也不认识界面，
   状态由调用方拼扁平字典（`at_goal`/`boss_killed`/`battles_total`/`battles_cleared`/...）。
2. `DdDb.quests` 接上（`_read_dict_fallback`，不走 balance 包）。
3. `Campaign`：`boards`（region→4 格）+ `BOARD_SLOTS_BY_REGION` 四区槽位不同；
   `board` 保留为 `boards[board_region]` 的**同名引用**（不是复制）；
   `select_board_region()` / `board_for()` / `_sanitize_board()`。
   保底档是**区域级**的（每块板子都有一格）。
4. `Expedition`：`quest_goal` / `quest_state()` / `quest_met()` / `quest_line()`；
   `enter_map` 固定分母（`quest_battles_total`）；`finish_battle` 只数 room/boss 且非僵持；
   `_end("complete")` 过通用判据（路线模式不参与，保 M3 基线）。
5. 界面：区域按钮同时切板子；卡头 `清剿 · 短途 · 1 级怪`；地图右面板加任务行；
   打过战斗房变暗；出口房未达成时警告。
6. 自检 AI 学会绕路：`_pick_step` / `_nearest_uncleared_battle` / `_step_toward_room`
   （以当前房间为源 BFS，能往回走）。

**数值**：清剿短图 Lv1 ×10 —— AI 只会朝出口走时 **0/10**；学会绕路后 **9/10**，
推进 5/7→6/7 房间，出手次数 20-65 → 40-97（翻倍，这就是清剿收的税）。
探索仍 10/10。

**最大的发现（数据缺口）**：10 个任务奇物里 **9 个在 `_raw` 出现 0 次**
（reliquary / chirurgeons_satchel / foodstuff_crate / shipment_crates /
corrupted_altar / infected_corpse / animalistic_shrine / protective_ward / beacon），
只有 `iron_maiden` 真的存在。所以 gather/activate 不是「没时间」，是**目标不存在**。
下一步应做「奇物标签化」的目标表，而不是硬映射。

**验证**：1172 项断言全绿（+68，新增 `tests/test_m32.gd`）；
自检 explore PASS / cleanse 9/10；截图 `shots/m32_{town_weald,town_cove,town_click,map_cleanse}.png`；
文档 `M32_TASK_BOARD.md` 十节；README 同步（断言数、结构、限制、重跑命令）。
未 commit、未 push。

**踩的四个坑**： board 必须是同一个数组（复制会出现「换区域再换回来选择没了」）；

## M33 任务奇物标签化 + 收集 / 激活

**起点**：M32 查出 10 个任务奇物里 9 个在 `_raw` 出现 0 次。硬编 id 冒充＝假造数据，
所以把目标**降到标签层**：`CURIO_TAG_MAP`（10 条，每条带 why）
+ `resolve_curio(name, region, curios)`：
1) 名字本身是真的且区域对得上 → 直接用（只有 `iron_maiden`）；
2) 否则查标签，在该区域带该标签的奇物里取，**本区域优先于 ALL**，同层按 id 排序。
确定性：同 (名字, 区域) 永远同一 id，否则同一张卡每次指的东西不一样。

**地图投放**：gather/activate 的图自然只有 1–2 个随机奇物，不管的话收集必做不完
（而「做不完」不报错，只像运气差）。`MapGen._place_quest_curios` 在常规内容之后
按 `amount` 额外投：空房间优先 → 空走廊兜底，避开入口/终点，用**派生 rng**
（`need*101+7`），step 打 `quest:true` 标记。房间数不变。

**计数**：`Expedition._note_quest_curio` —— 只算目标奇物、**不看交互结果**、
去重键是**位置**（`room:N` / `edge:N`）。`travel()` 里给房间步补 `room` 键。

**任务板**：四区槽位改成 探索/清剿/收集/激活/首领 的混编。
硬约束：收集/激活在 dungeons.json 里**只有 medium 一档**，且 activate 目标
铁处女只在墓穴 → 这两种只能放对应位置。

**数值**：收集（荒野 medium Lv1）×5 → 4 次完成、收集=3；
激活（墓穴 medium Lv1）×5 → 5 次完成。探索/清剿回归 PASS。

**踩的三个坑**
1. 去重键写成奇物 id → 任务要 3 件、图上 3 个同类奇物，碰完第一个后
   另外两个全被挡掉，**收集数永远停在 1**。按位置改才到 3。
2. 测试用「图里有没有这个 id」判投放 → 探索图也会自然刷同一个奇物，随机红。
   改成数 `step.quest` 标记。
3. 奇物房只写「奇物房」→ 玩家找「老树」得一间间进。加 `_room_label()`，
   奇物房直接报名（原版靠精灵图认，我们没美术，名字是等价物）。

**验证**：1210 项断言全绿（+38，新增 `tests/test_m33.gd`）；
截图 `shots/m33_{town_weald,map_gather,map_gather_progress}.png`；
文档 `M33_QUEST_CURIOS.md` 九节；README 同步。未 commit、未 push。

**下一步建议**：同职业多人（roster 的 key 从职业 id 改 uid）——它是加法之外
的**改地基**，名册/存档/任务板/招募/解雇全要动，越晚越贵。

## M35 任务物品与带道具激活（六种任务类型全开）

**关键发现**：`inventory_activate_*` 的 goal `type` 写的就是 `activate`，
唯一多出来的是 `starting_items`。所以需要的不是"道具系统"，
而是**一个每趟重置的计数器 + 一条消耗规则**。M33 把它标为"要道具系统"是估大了。

**设计**：`Expedition.quest_items: id -> 剩余件数`，独立于 `supplies`。三条理由：
pickaxe/eldritch_lantern/beacon_light 根本不在 supply 表里；补给可买可卖可被
奇物顺手用掉，任务物品不行；原版任务物品本来就独立于补给栏。
`set_location` 按 `starting_items` 自动带上。
`DdNames.quest_item_name` 先查任务物品表、查不到退回补给表（圣水/解毒剂两边重合）。

**消耗顺序（踩点）**：必须**先记 `has_qitem` 再调 `_note_quest_curio`**（它会扣一件），
扣完再问就把最后一件漏掉——症状是"带 3 件只能激活 2 次"，只在正好用光时出现。
另一个坑：`out["item"] != ""` 分支原本无条件 `take_supply`，任务物品不在 supplies 里，
不分 branch 就是"圣水扣了但计数没扣"。

**数据发现**：四个区域里只有**一个**目标奇物真的接受那件任务物品
（墓穴：圣水 × 光照祭坛）。其余三个（荒野古棺/巢穴涂鸦/海湾浮雕）不接受，
所以任务物品只当计数凭证。根因还是 M33 那句：真目标奇物不存在，等价奇物的
`items` 表是它们自己的。不硬编。

**改动**：QuestGoal（`items` 解析 + `required_item` + `inventory_activate` 进 CURIO_TYPES
+ describe 区分"用任务物品"）、Expedition（容器 + 消耗 + 优先用 + stats/事件）、
Campaign（warrens 的 medium 槽换成 inventory_activate）、DdNames（QUEST_ITEM_NAMES）、
场景（`_quest_items_line` + 卡片"仪式" + flash）。

**验证**：1310 项断言全绿（+45，新增 `tests/test_m35.gd`）；
巢穴 medium Lv1 ×5 → **5/5 任务完成**（激活=3 物品用=3 缺=0）；
截图 `shots/m35_{town_warrens,map_ritual}.png`；文档 `M35_QUEST_ITEMS.md`。
未 commit、未 push。

**下一步建议**：任务这条线（数据→判据→地图→道具）已经闭环，
再往规则里加东西边际收益明显下降。建议转**美术**；或者接 `quest_rewards`
（任务本身额外报酬，是 next 一块没读过的表）。

## M37 战斗布局：rank 轴对齐

**用户指出的问题（对）**：上下两排卡片让「前进/后退」读不出来，
因为位移在规则层是横向的 rank±1，画面上却没有这条轴。

**更严重的一层（用户没提，我查出来的）**：位置是按**数组下标**算的
（`for i in en.size(): x = ex + i*(w+gap)`），不是按 `rank`。
所以就算把布局转横向，rank 变了卡片也只是**瞬移重排**，没有滑行过程。

**改法**：
- `_battle_slot(u, is_enemy)`：rank 换算成 x，阵营决定 y。
  敌方右上 rank1 在最左、我方左下 rank1 在最右，两军前锋在中间相接
  （`enemy_x0 = party_x0 + slot_w*3 - BATTLE_W` 是算出来的，不是试的）。
  **空位保留**——3 人队不挤在一起，否则"最前排"位置随人数变，位移仍读不准。
- `_slot_anim`（uid→Vector2）每帧朝目标 lerp（`1-pow(0.0015,delta)` ≈ 0.25s），
  位移变成"滑过去"。换战斗时用 `_slot_anim_battle != _battle` 清空，
  否则上一场坐标漏过来会从旧位置飞入。
- 受击抖动从"只有头像抖"改成"整卡抖"——和滑行同一个坐标系，否则互相打架。
- 卡片必须收窄：横排 4 张 + 两军错开，200×104 放不下（需 1200 > 1080），
  改 160×84 长条；头像 44 在左、文字列 96。
- 连带：「位 N」那行删掉（位置已经是 rank，且长条卡没高度）；

## M38 战斗屏站桩（素材包推翻 M36 结论）

**用户带来** `DD sprites-…zip`（921 张 PNG / 197MB），是**别人用 Spine 导出好的成品帧**，
不是安装目录里的 atlas 零件页。M36 的「DD1 没有立绘」结论只对**安装目录**成立，
两种来源不矛盾。

**包里结构**：18 职业（本作 15 全齐 + 3 个 DLC）× 4 配色 × 65 种动作。
RGBA 真透明，画布紧贴人物。**坑**：`afflicted` / `heroic` 是 2000×2000 全屏插图，不能当战斗姿势。

**关键发现**：`heroes.json` 每技能带 `art.anim`（`smite → attack_sword`），
素材文件名正好对应 → **出招换帧零成本、不用改规则层**。
战斗事件 `attack` 已带 `skill` 字段，查一次即可。

**导出**：只取 combat/dead/defend/attack_*，121 张 / 13MB。
**归一化基准是「人物本体高」不是画布高**——第一版按画布高归一（统一到 400），
结果十字军矮一截：它的 combat 帧举着长剑，剑尖把画布撑高 26%，
按画布归一等于**把剑算进身高**。改成从顶部扫第一个「有效像素宽 ≥ 最大宽 16%」的行
当头顶（跳过剑尖），`k = 400/本体高`，同职业所有帧共用。改完 k 落在 0.568–0.746，
十字军从 0.507→0.69，头顶齐平。**用户看图一句「以脑袋对齐」点出来的，逻辑零改动但观感差很多**。
槽位：`assets/art/units/<id>_<anim>.png`。

**布局**：卡片 → 站桩。敌地面 250（rank1 最左）、我地面 480（rank1 最右），
显示高 180，槽宽 170，血条在脚下 +8，面板下移到 530。交战线画在两军空档

## M39 出招动作（推翻"挑错帧"的猜测）

**现象**：M38 换帧后只有修女像在出招，其他人都像待机。

**验证 1**：包里 `attack_sword` / `2` / `3` / `4` 逐像素比对 —— **轮廓差 0、只有颜色差**，
是配色变体（A/B/C/D），不是动画帧。全包每动作恰好 4 个后缀，**没有第 5 帧**。
→ "按帧号查"这条路不存在。

**验证 2**：47 张并排看，`attack_sword` 是举剑侧转、`attack_charge` 是前倾冲刺 —— **图是对的**。

**根因（写了解析器才看清）**：DD1 英雄攻击 `attack_sword.skel` 只有 **5 根骨骼 / 2 个插槽**
（`shadow` + `attack_sword`，各挂一整张图）。攻击 = **一整张姿势图 + 对整张图的 translate/rotate**，
不是骨骼动画。导出包只给了图、没带变换 → 换图后站着不动。

修女"看起来对"是因为 `attack_lectionary` 姿势本身是举书施法，静态也读得出。

**修法**：前冲补间 `sin(prog*PI) * 26px` + 6% 放大，`POSE_TIME=0.42`。配合换帧才读得出"冲上去打一下"。

**`.skel` 解析器（`.tmp/spine/spinerender.py`，半成品）**：
- ✅ 头部/骨骼/插槽/皮肤/时间轴读通
- ⚠️ **关键坑：Spine 字符串长度写成 `len+1`（0=null）**，按 len 读会整体错位一字节
- ❌ 区域附件那段还有 1 字节偏移没对（浮点从 name+type 后第 2 字节开始）
- **现在不继续**：英雄用不上（整图+变换）；**怪物骨架是零件拼的**，才需要完整解析 + mesh 支持

**验证**：1310 全绿、自检 PASS；截图 `shots/m39_pose_3.15.png`（瘟疫医生明显冲出、持匕首前伸）。

## M41 1080 宽排版验收

**工具坑**：`--resolution 1080x760` **无效**——项目把 `window/size/viewport_width` 定成 1280
且没设 stretch，内容尺寸不跟窗口走，截出来还是 1280×760，等于测了假的。
新增 `--w=N`：在 `_ready` 末尾设 `get_window().size`，**并在截图时打印实际布局宽**。
没有那行打印，第二次还会以为在测 1080。

**最严重的发现**：`enemy_x0 = party_x0 + SLOT_W*3 + 20` 而 `SLOT_W` 写死 170 →
1080 下敌方 rank4 右边缘仍在 1250，**出屏 170px**。而且平时看不出来，
因为遭遇表多数 3 只怪、第 4 格空着。
改：`slot = clampf((size.x-80)/7, 120, 176)`（1280→171 视觉不变，1080→143 全部在画面内）。

**顺带修的**：
- 名字宽度写死 160（>格子 143）→ 跟格子走 `clampf(slot*1.06, 126, 186)`
- 技能按钮副标题**不截断**，1080 下直接溢出到隔壁列 → 加 `ellipsis`
- 状态标记 `gy+50` = 530 = 日志面板顶边 → 地面线 480→470、标记 50→47
- 建筑卡文字贴卡片下沿（bh-16/bh-3）→ 底条 34→40、文字 bh-22/bh-6、图 bh-42
- 英雄卡 1080 下只剩 119 宽 → 头像 36→32、文字列 50→46

**没修（记下）**：1080 下我方立绘互相遮挡——格子 143 而 houndmaster 这类缩放后宽 188。
要么缩图（破坏"头齐"）要么接受（DD1 前后排也遮）。建议将来 1080 下城镇 8 张建筑卡改 4×2 两行。

**验证**：1310 全绿、自检 PASS；四张截图 `m41_{town,battle}_{1080,1280}.png`。











## DD1 客户端资源盘点（核查结论）

源：`/d/Program Files (x86)/Steam/steamapps/common/DarkestDungeon`（Steam 262060，2.7G）。
**本体齐、DLC 缺**：15 英雄（无 shieldbreaker）、101 怪物、6 地下城（无 courtyard / farmstead）、
12 语言含 schinese、3 段 .ogv 过场、30 个多页位图字体（中文 SimSun 45px × 38 页 TGA，**无 ttf/otf**）、
5274 png（1210 张 anim 图集页 + 3772 张单图）、1369 skel + 1369 atlas、41 个 FMOD Designer bank（610M）。

**不能直接拿来用（三条硬门槛）**：
1. 骨骼是 **Spine 2.1.27**（2015），spine-godot 只支持 3.8/4.x，Godot 4.4 无兼容 runtime；
   只能离线烘序列帧或自写 2.1 解析器，且 Spine runtime 需商业授权。
2. 音频是 **FMOD Designer 4.x（RIFF/FEV FMT）**，不是 FSB5，现代 FMOD Studio 不读；
   需 fsbext 类工具解 FSB→wav，事件逻辑（随机变体/参数混合）要在 Godot 重建。
3. 图集页是拼合大图（如 2015×1186），必须按 .atlas 坐标切；字体是位图，不可缩放。

**可直接用（零改造）**：.ogv 过场、panels/icons/cursors/loading_screen 单图、
dungeons/* 的 corridor_wall/corridor_bg/door 可平铺贴图。
