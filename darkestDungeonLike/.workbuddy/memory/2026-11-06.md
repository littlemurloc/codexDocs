## M44 光照可见范围

**问题**：规则层光照（0–100 四档，影响怪物伤害 / 我方受压 / 侦察 / 被偷袭）在画面上
**一点表现都没有**，只有顶栏一行字。而光照是本作唯一「省资源换风险」的机制（省火把 = 更疼），
纯数值的风险靠一行小字传达等于没传达。

**做法**：`src/view/light_layer.gd` 代码生成两张径向渐变纹理（不入库、无版权）：
- `vignette` 256²，中心透明→边缘 0.94 黑；铺成比屏幕大一圈、中心对准光源
- `warm` 192²，**纯白**纹理 + 绘制时 modulate 上色（写死橙色就没法做「低光偏冷」）

**关键限制**：CanvasItem 的 `_draw` **没有擦除能力**，只能盖不能挖洞 →
「洞」必须是纹理的透明区，纹理要比屏幕大。这是整套做法的前提。

**参数**（`LightLayer.params(light)`）：`radius_k=1.02+0.4t`、`vignette=0.30+0.56(1-t)`、
`warm=0.20+0.8t`、`warm_tint=lerp(冷青,暖橙,t)`、`dim=0.22(1-t)`。
光源 = 我方四人水平中心 = `40 + _battle_slot_w()*2`，y = `GROUND_PARTY-90`。

**三个坑**：
1. **暖光范围比强度更影响观感**。第一版画在 `0.74r`（≈1817px）铺满全屏，
   看起来像橙色滤镜而不是一盏灯。缩到 `0.46r` 才成立。
2. **暗部压不下去**。基色已是 (20,22,26)，100 与 15 两档像素只差 10 个色阶。
   加 `dim`（整屏盖 0.22 黑）才是「火把快烧完」的直接表达。
3. **光源不能按屏幕中心算**。队伍只占左侧 40%，屏幕中心落在十字军身上、瘟疫医生在暗处。
   顺手把 `_battle_slot_w()` 抽成函数（站位/名字宽度原各写一遍同公式——M42 已教过一次）。

**平滑跟随**：`_light_vis = lerpf(..., 1-pow(0.02,delta))`，约 1.2 秒收敛；
点一次火把是渐亮而非数值跳变。`--dev` 每 0.25s 打印 `[light] vis=.. target=..`
——**静态截图无法区分瞬变与渐变**，这行打印是唯一可复现的证明。

**新增参数**：`--light=N`（固定光照，否则四档只有 100 能稳定复现）、`--no-light`（关整个光照层）。

**已知**：①顶栏被暗角轻微压暗 6 个色阶 ②漆黑档敌方名字几乎不可读（血条/轮廓仍在，可点选）
③**只有战斗屏有光影**——城镇是白天、地图本身就是平面图，往那两屏加暗角直接损可读性。

**验证**：1310 全绿、自检 PASS；截图 `m44_light_{100,55,30,10,0}.png`、
`m44_battle_1080.png`、`m44_nolight.png`。
**未 commit、未 push。**

## M49 背景音乐

**M43 的判断有一半是错的**。当时说「FSB5 字段顺序没对上」，实际是**少读了一个字段**：
FSB5 头是 6 个 uint32（version/num/hdrSize/nameSize/dataSize/mode），我从 +4 读 5 个，
把 dataSize 当成了 mode → numSamples=1、dataSize=1892 这种荒谬值。
判据：`60+hdr+names+data == 文件大小` 才叫读对。music.bank 是 num=64。

**编码不是 MPEG 也不是 Vorbis，是 FMOD FADPCM 4-bit**（vgmstream 一句话给出）。
所以：按 MPEG 帧扫扫不到、按 Vorbis 头解报「缺 VORBISDATA」——两个方向都在错假设上。
`mode=0x10` 不是标准 codec 值（FMOD 枚举只到 15），fsb5 库会直接抛。

**bank 是 RIFF/FEV，必须把 FSB5 块切出来**（`b[o:o+60+hdr+names+data]`）再喂 vgmstream，
直接喂整个 .bank 会 `failed opening`。

**可用工具链**（本机）：`pip install fsb5`（列名字/时长，不解码）、
下载 vgmstream-win64（解 FADPCM）、`pip install imageio-ffmpeg`（转 ogg）。
**`soundfile` 在本环境不可用**：`sf.read()` 和写 OGG 都让进程消失（exit 127 无输出），
但 `sf.info()` 和 `sf.SoundFile().read()` 正常——崩的是便捷入口，不是 Python。
遇到「无输出 exit 127」只能缩小范围定位再换工具，别修。

**接进游戏**：`src/view/music.gd`（class_name **BgMusic**，单通道 + 0.8s 淡入淡出 +
运行时设 `AudioStreamOggVorbis.loop`）。切歌放 `_process` 比对 `_music_for_state()`，
因为状态有 12 个、逐个挂钩必漏。5 首：menu/town/combat/weald/depths，
`camp` 导了但没接（扎营是 map 屏内一步完成，没有持续状态）。
`--dev` 打印 `[music] -> x` 是唯一验证方式。

**体积/版权**：5 首 5.9MB，`assets/audio/music/*.ogg` 已加 gitignore；
注意 `assets/audio/*.wav`（M43 原创占位）要入库，两条规则不能混。

**验证**：1310 全绿、自检 PASS；6 个 ogg 全部载入且 loop 可设；切歌序列实测正确。
**未 commit、未 push。**

## M50 真实音效（8/10）

**又一纠正**：音效 bank（`en_*` / `general` / `hero_*`）的 `mode=0xF` = **Custom Vorbis**；
只有 `music.bank` / `ambience.bank` 的 `mode=0x10` 才是 **FADPCM**。
同一批 bank 混着两种编码。M43 说「数据是裸 MPEG 流」是把 Vorbis 数据里偶然的 `0xFFFB` 当成了帧——
在 146MB 里 23 万次，比随机高但远远不构成帧。

**选音效的两个硬约束**：
①**不要人声**（库里有大量 `char_en_vo_*` / `char_al_*`，拿去做通用反馈每次都是同一个嗓子）
②**必须截断**（原版是 2–6 秒的完整动作音，本作出手只有 0.42s，会拖过下一个动作）→
统一截 0.85–2.5s + 末尾 120ms 淡出。**不能硬切在响处，会有「啪」声**。

映射：hit=`char_share_imp_sword`(en_shared#227) / crit=`char_share_crit_hero`(general#100) /
death=`gen_char_death_enemy`(#159) / stress=`gen_status_stress_up_comp`(#115) /
heal=`gen_status_heal_ally`(#142) / door=`gen_map_door_open_weald`(#129) /
torch=`gen_map_torchout`(#50) / victory=`Combat_Level2_Victory`(#65)。
输出单声道 22.05k q5，8 个共 85KB。

**没换的两个**：`click`（41 个 bank 里没有 UI 点击音，`ui_` 只有 mailinglist）、

## M52 怪物攻击声

**改法**：每组挑最多 3 个「像打人」的动作当变体（`atk/<family>_1..3`）。

**两套名字体系别混**：语音键=DD1 语音分组（`skel`/`swine_1`，一个组覆盖多只怪），

## M53 出手时的位移

**根因不是"做得不明显"，是从来没发生**：`skills[].move` 从 M0 就解析进动作字典
（`combatant.gd:273`），但全项目 `get("move")` 只命中 `move_action`（免费调整站位）。
所以 rank 变化一直只有"被推拉"一种来源，挨打才挪，出手不挪。

**方向语义靠三个行为已知的技能反推**，不是猜一个能对上就算：
`point_blank_shot [1,0]`=开完枪后退1、`holy_lance [0,1]`=圣枪突进、`light_fuse [3,0]`=退到队尾
→ **`[后退上限, 前进上限]`**，前进 = rank 减。

**插入点必须在目标循环之外**（`_apply_choice` 里 `for t in targets` 之后）：
`_resolve_action` 是逐目标调用的，放里面 AOE 会按目标个数挪 N 次，而且不报错。
**没打中照样挪**——`_resolve_action` 四条分支各自 return，插在任一分支都会变成"只在中了才挪"。
边界：顶到最前/最后时 `move_unit` 返回空→不发事件（否则日志写一句空话）；被反击死了不挪。

**规模**：英雄 12 个技能 / 怪物 **101 个**（土匪点燃引信退 3、猪人钩子每用一次退 1）。

**界面三处**：
1. 日志要区分"我自己冲"和"我被推"——`move` 事件加 `self` 标记，且这一支必须排在
   push/pull 之前，否则写成"被推到 2 号位"，看起来像挨打。
2. 出招补间：近战 26→**42px**（26px 在 1080 下只有 1/5 格，看不出来）、远程改成**后坐 9px**
   （原来开枪也往前撞）。种类用 M52 的 `Sfx.impact_slot` 反推，不重复判断技能类型。
3. **怪物原先出手完全不动**：`_pose_for_action` 没有姿势帧就 return，于是没有 `_pose` 记录。
   改成"帧为空也记 pose"（`_unit_anim` 会退回 combat），怪物才有冲的动作。
4. 技能按钮右上角 `进N`/`退N`：位移影响决策，但副标题在 1080 下只剩 144 宽已被截断。
   名字可用宽度要减 26px，否则连读成"圣枪突进1"。

**既有断言要修**：`test_move.gd` 的"20 场里被技能推动 N 次"统计 `skill != "move"`，
自发位移也满足→会把断言喂饱、测不出怪物推人。已排除 `self`。

**验证**：1322 全绿（+12）、自检 PASS；`.tmp/proof_move.gd` 可复现：
圣枪 4→3 位、零距离开枪 1→2 位、warrens 一场里 `hook_where_it_hurts` 退 2 次。
**角标没截到图**（十字军先攻 1 永远最后动，面板只显示当前等待的那个英雄），
`_move_badge` 已用直接调用验证 `[0,1]→进1 / [1,0]→退1 / [0,0]→空`。
**未 commit、未 push。**

**补充验证（同日）**：四区域各跑一趟真远征，自发位移实测出现——
`猪人砍杀者 后退 2→3→4 (hook_where_it_hurts)`、`邪教打手 前进 (brawler_claw)`、
**`强盗 后退 1→2 (point_blank_shot)`**。crypts/weald 两趟没出现是因为遇到的怪不会位移
（骷髅/狗/乌鸦），不是没生效。
**造「必空」测试的坑**：压 `atk` 到负数不行，`_resolve_action` 里 `atk<=0` 会被判成功能技、
连命中都不走；正确做法是把目标 `base_dodge` 顶到 5.0（`dodge()` 夹到 0.95）→ 命中率必为 0。
断言数 1322 → **1324**（+ 未命中仍位移）。

## M54 导出 Android APK

**先说教训：这台机器上早就有 Android 工具链**，`C:/Users/tuxu/AndroidTools/{jdk17,sdk}`
（build-tools 34.0.0 / platforms;android-34 / platform-tools 齐全），
Godot 编辑器设置 `editor_settings-4.7.tres` 里 `export/android/{java,android}_sdk_path` 早就指过去了，
`%APPDATA%\Godot\keystores\debug.keystore` 也在（数羊项目导出过）。
我第一次只看 PATH 里没有 `java`、默认 `AppData\Local\Android\Sdk` 不存在就判"缺工具链"，
白下了 1.1GB（已删）。
**判据要改**：找工具链先查 `C:/Users/tuxu/AndroidTools` 与 `editor_settings-4.7.tres` 里的 export/android 段。

**三处必须改才能导出**：
1. `rendering/textures/vram_compression/import_etc2_astc=true` —— Android 导出**强制**要求，
   否则直接报 "ETC2/ASTC texture compression is required"。开启后所有 PNG 重新导入一次。
2. `display/window/handheld/orientation=0`（横屏）。
3. Android 专用缩放写在 `_ready` 里（`OS.has_feature("android")` 才设 `content_scale_*`）：
   1280×760 + canvas_items + **expand**。桌面端**故意不动**——`--w=1080` 那套排版验收
   依赖"窗口多宽布局就多宽"，开了 canvas_items 会被缩回 1280 逻辑宽，验收就测了个假的。

**体积**：首版 161MB。`export_filter` 全资源会把 `shots/*`（截图）当纹理导入，
`.godot/imported` 吃 131MB。加 `exclude_filter="shots/*,bench/*,balance/*,tests/*,tools/*,*.md,*.html,*.py"`
之后 **57MB**（`balance/` 可排，因为 `DdDb._base` 默认是 `res://data`）。

**产物**：`build/DarkestLike.apk`，com.kongqiang.darkestlike / 标签"空腔" / minSdk24 target36 /
arm64-v8a / v2+v3 签名通过。音频在包里是 `oggvorbisstr`（549 个导入产物），源 .ogg 不入包。

**未验证**：没有真机或模拟器，**运行时没跑过**。触屏靠 Godot 的
`emulate_mouse_from_touch`（默认开）；空格=自动回合这类键盘功能在手机上不可用。
