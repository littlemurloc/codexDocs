## 顺手修掉的解析器 bug（重要）

`.tmp/spine/spinerender.py` 的 `R.shorts()` **读完不推进指针**（返回列表但 `self.i` 不动）。
凡是含 mesh 附件的文件，从这里开始整体错位，表现成 M39 记的
「区域附件差 1 字节 / unknown attachment type 8x」。

修法：记住起始位置、`self.i += 2*n` 后再解包。修完：
- heroes/*/fx 130/136、monsters/*/fx 219/257、fx/* 115/120 全部读通（464/513）。
- 剩 49 个失败是 skinnedmesh 分支（`int(r.flt())` 读到 NaN），未处理。

**结论修正**：M39 §6 里那句「区域附件还有 1 字节偏移没对上」是错的，
region 段落本来就是 name → type → path → 7 floats → color，一个字节都不差；
真正的锅是 mesh 分支里的 `shorts()`。

  → 导帧必须过黑名单：`rim_light / shadow / defend / attack_* / combat`。

### 关键坑：命令行参数必须写在 `--` 之后

`OS.get_cmdline_user_args()` 只返回 `**--**` 之后的参数。
写成 `godot --path . --start --battle` 什么都不发生（窗口开着、不报错、不截图），
正确写法是 `godot --path . -- --start --battle`。
之前半天以为是沙箱杀窗口 / 脚本死循环，全是这个。
旧文档里的命令都省了 `--`，照抄会浪费一整天。

### 原版受击反馈（查证结果，别再猜）

**原版没有任何受击/硬直动作**：1369 个 skel 的动画名里没有 hit/hurt/stagger/flinch。
英雄每职业固定 8 个通用动作（idle/combat/walk/investigate/camp/heroic/afflicted/defend），
怪物只有 4 个（combat/attack_melee/defend/dead）。数据里也没有 `.hitfx` 字段。

挨打 = 角色继续播 `combat` + 四层叠加：
1. `fx/attack_overlay`：全屏溅血，三变体 hit/crit/miss，0.79s，
   `.attack_overlay_pos 960 360`（配置在 `scripts/layout/screen.raid.battle.darkest`）
2. `blood_splatter` 命中点血溅
3. 数字 / 血条
4. 音效 + 痛叫

`defend` 不是受击动作，是主动防御姿态；我们有 9 个技能把它当姿势用
（antiquarian/cower、leper/withstand + 7 个怪物技能）。

### 已接：屏幕溅血层（M57 续）

`attack_overlay_hit` / `attack_overlay_crit` 导到 `assets/art/fx/`（12fps、scale 0.7、q50、共 1.6MB）。
`miss` 没导——它的 alpha 时间轴全是 0，原版就是不溅血。

- `_fx_overlay_play(kind, flip)` + `_fx_overlay_one()`：按高度贴合、居中、
  翻面用 `draw_set_transform` 负缩放并**立刻复位**（`draw_texture_rect` 没有 flip_h，
  漏复位会把日志/技能面板一起镜像）。
- 同一时刻只留一层（范围技会叠四张糊成红布）。
- 画在光照之后、UI 之前。
- 验收开关 `--fx-overlay=hit|crit[:flip]`。
- `--fx-check` 现在把这两层单独点名，127 个资源 PASS。

### 修正：特效「像贴纸」的三个真原因

1. 预览截图姿势不对（角色还是 combat 站姿）→ 新增 `--fx-pose=<anim>` 钉住出招姿势。
2. **真 bug**：`_draw_unit` 用 `cx + mo.x`（前冲 42px），`_fx_pos_of` 只用 `_anim_x`
   → 特效不跟着冲，错开半格。已把 `_pose_motion` 的位移和缩放算进去。
3. **混合模式错了**：`smite` 贴图平均 RGB (60,64,65)、alpha 186，
   是「暗灰+高透明」，只有**加法混合**才读成光。原版 `shaders/particle.glsl`
   就是 `tex0.rgb *= tex0.a` 后加法输出。
   → 新增 `src/view/fx_add_layer.gd`（Node2D + `BLEND_MODE_ADD` + modulate 2.2），
   manifest 里按「色度 < 30」标了 44 个走加法；血迹/烟雾仍走 alpha。
   加法层是 `expedition_scene` 的子节点，画在父 Control 之后（会盖 UI，可接受）。

**缩放本身是对的**：刀光宽 337 / 人物本体 411 = 0.82，屏幕 151/180 = 0.84。
别再去调 `_fx_draw_scale`。

屏幕溅血改成**按宽度贴合**（原版资产 1921 宽对 1920 舞台）。

## 竖屏移植：方案示意图（待核对，未动代码）

需求来自 `~/Desktop/竖屏小游戏 HUD 布局移植规范.md`：750×1334、按高度适配、

关键结论：
- **能改，且不用删任何功能信息**。代价只有日志从常驻变折叠（可点开）。

  7 个技能两边都放得下。（我先算成 2×3=6 说"放不下"，是错的。）

- 硬编码坐标必须改：`Rect2(880, dep_y-16, …)`（闲置一周）、地图的 510/566、
  战斗的 40/716/660。竖屏 750 下这些直接出屏。

## 要接进 Godot 的缺口

1. 没有 Spine 2.1.27 的现成运行时（spine-godot 只吃 3.8+/4.x），只能自己导帧或自己写运行时；
2. 导帧还缺：mesh 的三角形 + UV 贴图、FFD 顶点动画、slot 绘制顺序、additive 混合、COLOR 时间轴；
3. 现有 `render()` 只会画 region 附件，直接拿来渲特效会少一半图。
