## 修正：图标在格子里没撑满（FILL 80% → 97%）

用户指出「很多图标在方格里没撑满」（截的是圣水）。

根因是两层缩放叠在一起：
1. `import_ui_icons.py` 的 `FILL = 0.80` —— 内容最多占画布 80%（当时怕贴边被裁）；
2. 总览图里又把图缩到 88 塞进 118 的框 → 80% × 0.75 ≈ 59%。

**修法**：
- `FILL` 改 **0.97**（bbox 已裁紧，只留 3px 给抗锯齿，不需要 20%）；
- 总览图图标 88 → 110（框 118）；
- 各界面显示尺寸整体上调：技能 42→46 / 公会 40→46 / 抽屉 20→22 /
  内页 16→18 / 补给 34→40 / 货架 54→58 / 商店仓库 34→44 /
  饰品仓库 40→46 / 装备槽 30→34 / 抽屉饰品 28→30 / 地图 0.72→0.80。

**窄高物体（圣水、火把、钥匙）在正方形里宽度仍然只有 45%** —— 这是物体形状决定的，
长边撑满就是唯一不变形不裁切的方案。改填充率只是让长边真正吃到边。

**事故**：这轮用「行号批量覆盖」改尺寸，把抽屉里 `_text(技能名)` 那行
覆盖成了 `stx = x + 28.0`，技能名整行消失（截图里只剩图标和效果说明）。
已恢复。**教训：改多行代码别用行号覆盖，行号会随前面的插入漂移；
要么用唯一字符串，要么先 Read 再 Edit。**

空白变化：疗养院 600→170、铁匠铺 900→200、酒馆 600→300。剩下的不硬填。

**`_buff_line()` 的三个数据坑（都是实测出来的）**：
1. `attack_rating` 是**比例**（-0.1=命中-10%），`speed_rating` 是**绝对值**（-5=-5点）。
   混着按整数打 →「命中-0」。
2. `food_consumption_percent` 名字带 percent，值是**份数**（-1.0/+3.0）。
3. `amount==0` 的条目要跳过（数据里有「受压+15%；命中-0」这种占位）；
   `damage_low`/`damage_high` 同值要**去重**，否则「伤害+15%；伤害+15%」。

**最隐蔽的坑**：`QuirkLib.load_from()` 加载时就把 `buffs` 从 id 字符串**展开成字典**。
第一版用 `db.buff(str(bid))` 二次查表 → 每个怪癖效果都静默为空，不报错。
**判据：字段明明有数据但界面空 → 先查这字段在加载时有没有被改写形状。**

**事故**：用「_trinket_stat_bits 到 _trinket_summary」区间替换，把夹在中间的
`_buff_line` / `_quirk_effect_text` 一起删了（这是第二次踩同一个坑，上次是 dock 替换删了名册页）。
已恢复。**区间替换前先看区间里有什么函数。**
