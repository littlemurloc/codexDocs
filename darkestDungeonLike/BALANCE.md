# M2 · 数值生成器与手感测量

M1 证明了规则实现正确。M2 要回答另一个问题：**换成自己的数值之后，手感还在不在？**

关键判断：**不能把 DD1 的数字乘个系数**。那只是换了个量纲，玩起来一模一样。
真正要做的是「设计目标 → 生成器参数 → 数值」这条链，并且每一步都能验证。

## 交付了什么

```
tools/gen_balance.py       数值包生成器：旋钮 → 完整数值目录
tools/compare_balance.py   多套数值包的指标对比
tests/bench_battle.gd      战斗测量器：把手感变成 15 项数字
balance/faithful/          忠实复刻曲线（校准用）
balance/signature/         自研规格
balance/lethal_probe/      诊断用：检验测量器是否测得出危险度
bench/*.json               各规格的实测指标
```

## 跑一遍

```bash
python tools/gen_balance.py

godot --headless --path . --script res://tests/bench_battle.gd -- \
  --runs=200 --data=<项目>/balance/signature --out=<项目>/bench/signature.json

python tools/compare_balance.py dd1_baseline faithful signature
```

`--data=` 接受任意绝对路径，所以同一份规则代码可以加载任意数值包，规则一行不动。

## 为什么 faithful 规格必须存在

它是生成器的自检。生成后逐字段比对待原数据：

```
英雄数值字段 225 个，不一致 0 个
怪物生命字段 254 个，不一致 0 个
```

实测指标也证明同一件事——faithful 与 DD1 基线**逐项完全相同**：

| 指标 | dd1 | faithful | signature |
|---|---:|---:|---:|
| 战斗轮数 | 4.096 | 4.096 | **5.301** |
| 溢出伤害占比 | 0.121 | 0.121 | **0.085** |
| 暴击率 | 0.072 | 0.072 | **0.061** |
| 终局压力 | 19.3 | 19.3 | **17.9** |

如果这两列对不上，说明要么曲线抽错了，要么生成器写错了，这时后面所有结论都不可信。

## signature 规格：四条改动，各有理由

不是随手调参，每条都针对一个具体问题。

**1. 怪物生命 ×1.45 —— 战斗从 4.1 轮拉到 5.3 轮**

DD1 的普通交火偏短，往往一轮集火就结束了，玩家来不及做第二个决策。
拉长之后「控制 → 集火 → 补刀」这条链路才真正跑得起来。

**2. 伤害方差收窄到 0.62 —— 溢出伤害 11.5% → 8.1%**

武器区间 6–12 意味着单次攻击跨 2 倍，运气的权重过大。
收窄时**保持每阶均值不变**，只压缩宽度，所以整体强度没变，下限被抬高了。

**3. 暴击率 ×0.62、倍率 1.5 → 1.85**

期望加成验算：原 `crit × 0.5` ≈ 新 `0.62crit × 0.85 = 0.527crit`，几乎持平。
期望不变但方差变大 ——「平时平淡、偶尔爆发」的观感明显更强。
实测暴击率 7.7% → 6.3%，符合预期。

**4. 压力 ×0.7 —— 终局压力 19.3 → 17.9**

战斗变长 30% 之后，若不调低，单场压力会等比上涨，叠加多场远征就会失控。
压到 0.7 之后单场压力反而略低于基线，把压力预算让给「远征长度」而不是「单场战斗」。

> 这里踩过一个坑：一开始只改 `rules.json` 里的压力常量，结果压力不降反升。
> 因为单场压力的大头来自**怪物技能自带的效果压力**，战斗一变长这部分等比放大，
> 把规则侧的下调全吃掉了。必须同时缩放 `effects.json` 里的 stress 值（66 条）才有效。

## 测量器测什么

15 项指标，全部从战斗事件流里统计，不是拍脑袋：

| 类别 | 指标 |
|---|---|
| 节奏 | 轮数、轮数 P90、首杀轮次 |
| 效率 | 命中率、暴击率、溢出伤害占比、有效伤害/总血量 |
| 危险度 | 终局血量占比、最低血量水位、阵亡率、死门触发、团灭率 |
| 结果 | 胜率、存活人数、终局压力、超时率 |

其中**溢出伤害占比**最有诊断价值：它反映数值是不是「刚好够用」。
接近 0 说明伤害不足（打不死），超过 20% 说明伤害过剩（每次攻击都在浪费）。

## 一个必须说清楚的发现：危险度维度目前是钝的

连续三场遭遇、满编四只高难怪物、甚至**怪物伤害提高 60%**，实测结果都是：

```
阵亡率 0.000    死门触发 0.000    终局血量 94%+
```

原因不是指标坏了，而是两个真实的系统性问题：

1. **怪物单次伤害太低**（入门怪 2–7 点），英雄血量 22–33，比例悬殊
2. **治疗把累积伤害完全抵消了** —— 连续三场打完，英雄血量反而从 44 涨到 57

第 2 点尤其重要：**在这套系统里，压迫感不可能靠调伤害数值做出来**。
DD1 的死亡风险来自资源约束（无休整、口粮耗尽、火把熄灭）和心理压力，
不是来自单场战斗的伤害数字。想做危险的游戏，得在资源层做设计，而不是在伤害数字上做。

`lethal_probe` 规格就是用来证明这一点的：它把怪物伤害 ×1.6，
结果终局血量只从 95.6% 掉到 93.4%。**这个规格不是设计，是诊断。**

> **M3 已就此接手，并部分修正了这句话的措辞。**
> 伤害维度不是「钝」，而是缺少放大器：接上资源层之后，同一个 `lethal_probe`
> 在远征尺度上把英雄死亡率从 0.392 推到 0.850。
> 结论更准确的说法是：**单场战斗里压迫感来自伤害，危险度来自资源预算。**
> 细节见 [M3_EXPEDITION.md](M3_EXPEDITION.md)。

## 怎么用这套东西调自己的数值

1. 改 `tools/gen_balance.py` 里 `SPECS` 的旋钮，**先写清楚为什么改**
2. `python tools/gen_balance.py` 生成
3. 跑 bench 测量
4. `python tools/compare_balance.py dd1_baseline <你的规格>` 看差异
5. 目标区间在 `compare_balance.py` 的 `goals` 里，改成你自己的目标

规则代码一行都不用动 —— `DdDb` 是唯一数据入口，`DdRules` 是唯一常量入口。

## 已知局限

- **AI 是简化版**：只按期望伤害 + 控制价值打分，不会集火、不会保护治疗。
  所有对比都在同一个 AI 下做，所以相对差异有效，绝对值不代表 DD1 真实表现
- **场景偏少**：4 个遭遇组合，全部基于 weald 的 cultist 家族
- **未覆盖**：守护、反击、位移、召唤、压力崩溃与美德、光照、饰品怪癖
- **危险度维度在单场尺度上测不出差异** —— 已由 M3 的资源层补上，见 [M3_EXPEDITION.md](M3_EXPEDITION.md)
