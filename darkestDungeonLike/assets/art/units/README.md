# assets/art/units — 单位贴图槽位

> 文件名 = 单位 id。放进来就能用，不需要改代码、不需要登记、不需要同步尺寸表。

## 1. 槽位约定

```
assets/art/units/<unit_id>.png        # 方形头像/胸像（56px 显示）
assets/art/units/<unit_id>_full.png   # 全身立绘（战斗站桩用，高度自适配）
```

- `<unit_id>` 与 `data/heroes.json` / `data/monsters.json` 里的 `id` 一致
  （`crusader`、`plague_doctor`、`cultist_witch`……两边共用一套目录）；
- **任意尺寸的正方形**，透明背景，内容居中；
- 绘制端按「等比缩放到目标显示边长」处理：当前战斗卡里的显示边长是 **56 px**，
  所以 85×85 和 512×512 都能直接用，**不需要预先缩放**；
- 换美术时只替换这个 PNG，`src/view/unit_art.gd` 与界面代码一行都不用改。

缺少某个 id 的图不会报错，会退回程序化占位（阵营色圆牌 + 名字首字）。
这条是刻意的：**「没有图」是正常状态**，不是错误。

## 3. 为什么只有英雄、没有怪物

DD1 的怪物**没有静态图**。它们在游戏里是 Spine 2.1.27 骨骼动画，
`monsters/<id>/anim/*.sprite.combat.png` 是**部件图集页**（例如 305×1042
把头部、躯干、四肢平铺在一起），不是完整角色图。

要拼回一个完整形象必须解析 `.skel` 里的骨骼层级与槽位坐标——
`.atlas` 里的 `offset` 是裁剪信息（实测全为 `0,0`），不含摆放位置。
那是一个独立工具的工作量，且只为一帧，收益不划算（见 M36 文档 §3）。

**注意**：`_src` 里那个 197 MB 的素材包只包含 18 个英雄职业，
**没有任何怪物**。它里面的图是别人用 Spine 导出好的完整帧，
所以英雄有、怪物没有——不是我们漏做了，是这个来源本身没有。

补齐怪物的两条路：
1. 找到同样的「怪物完整帧」导出包（最省事）；
2. 自己写 `.skel` 2.1 解析器 + 导出器（2–3 天，一次性投入）。

所以怪物暂时全部走程序化占位。等有原创美术时，把
`assets/art/units/bloated_corpse.png` 放进来，占位自动消失。

## 4. 已知的规格限制

1. **动作帧按本体高归一**。`k = 400 / (画布底 - 头顶行)`，头顶行靠
   「有效像素宽度 ≥ 最大宽 16%」找，跳过剑尖/旗杆。同一职业所有帧共用这个 `k`。
   按画布归一会让举武器的职业显出「矮」（M38 §3 有前后对比）。
2. **`afflicted` / `heroic` 不是战斗帧**。它们是 2000×2000 的全屏插图
   （崩溃爆发、英雄觉醒），不要放进 `<id>_<anim>.png` 这套槽位。
3. **没有「攻击的第 2/3 帧」**。导出的是每个技能的**单帧**姿势，
   动作感靠换帧 + 补间（前冲/抖动）拼出来，不是逐帧动画。
4. **只有英雄**。怪物一张静态图都没有，走程序化剪影；
   将来 AI 出图时按同样的 `<id>_combat.png` 命名放进来即可。
