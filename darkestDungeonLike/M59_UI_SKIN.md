# M59 · 界面皮肤

> 目标：让自绘的纯色控件看起来像「同一套美术做的」，而不是浏览器里的 div。
> 不做全套重绘，只补**框架层**：面板底、边框、按钮。

## 1. 为什么不能直接扒原版

原版 `panels/` 里有 27 张图，但都是**成品布局图**，不是可复用边框：

- `panel_hero.png`（720×224）里直接嵌了红心图标、状态格子、名字栏
- 全库 grep `ninepatch` / `corner_size` / `sliced` **零命中** —— DD1 的 UI 是
  「一张图一个界面」，靠美术在整张图上排版，不是组件化九宫格

所以皮肤只能自己做。

## 2. 五个资产（程序化生成，共 18 KB）

| 文件 | 尺寸 | 用途 | 边框厚 |
|---|---|---|---|
| `panel.png` | 64×64 | **大面板**，带四角金饰 | 12px |
| `card.png` | 24×24 | **小卡片**，无角饰 | 8px |
| `btn.png` | 36×36 | 按钮 | 8px |
| `grain.png` | 128×128 | 可平铺颗粒（2px 块，alpha ≤ 11） | — |
| `stain.png` | 128×128 | 可平铺低频污渍 | — |

### 为什么分两级

第一版所有面板共用一张带角饰的图，结果**四张名册卡并排像挂了一墙相框**。
小卡片只保留边框 + 内阴影，角饰留给大面板（抽屉、地图信息区）。

判断写在 `_panel()` 里：

```gdscript
if r.size.x >= 380.0 and r.size.y >= 180.0:
    _draw_nine(_sk_panel, r, 24.0)   # 大面板，带角饰
else:
    _draw_nine(_sk_card, r, 8.0)     # 小卡片，只留边框
```

## 3. 边框到底画了什么

```
0px      黑        #030405      ← 和背景断开
1-2px    亮铁      #565d6a      ← 主要可见边（2px）
3px      深槽      #090b0e
4px      次亮线    #282d36
5-12px   内阴影    黑 alpha 96→0  ← 让面板「凹」进去
13px+    透明                    ← 底色 + 材质从这里透上来
四角     6-8px 暖金短线 + 2px 铆钉
```

第一版只有 `黑 → 亮线 → 暗槽 → 次亮线` 四条 1px 线，**总共 5px**，
在 750 宽的暗色界面上等于没有。厚度、内阴影、角饰是这一版加的三样东西。

## 4. 关键设计：中间透明

```gdscript
func _panel(r, bg, edge):
    draw_rect(r, bg)                        # 底色仍由调用方决定
    draw_texture_rect(_sk_stain, r, true)   # 材质平铺
    draw_texture_rect(_sk_grain, r, true)
    if edge:
        _draw_nine(_sk_panel, r, 24.0)      # 只有边框
```

- 换主题色（`PANEL` / `PANEL_DEEP` / `BTN_ACTIVE`）**不用重画任何贴图**
- 选中蓝框、危险红框照常画在最外层，皮肤不干扰状态语义
- 贴图中间是纯透明，所以「内阴影」只出现在四周，不会在拉伸后变成满屏渐变

`_tile()` 同理：皮肤只换边框，fill 仍由 `TILE_IDLE/HOVER/PRESS` 各自决定。
同一张 `btn.png` 用在普通按钮、区域卡、技能格上 —— 它们底色本来就不同。

## 5. 九宫格拉伸

`_draw_nine(tex, r, m)` 把 64×64 的图拉到任意尺寸：四角固定、四边单向拉伸、
中间拉伸（但中间是透明的，所以不显内容）。

一张图覆盖的全部尺寸（`shots/m59_skin_nine.png` 是实测图）：

| 尺寸 | 用在哪 |
|---|---|
| 40×22 | 音量条格子 |
| 150×184 | 名册卡 |
| 190×300 | 建筑卡 |
| 470×118 | 难度卡 |
| 702×720 | 英雄详情抽屉 |

**换皮肤 = 换这 5 个 png，一行代码不用改。** 尺寸比重不合适时只调 `_panel` 里的
两个 margin 常量（24 / 8），不碰其它任何调用点。

`shots/m59_skin_before_after.png`（左=无皮肤，右=有皮肤）、
`shots/m59_skin_pages.png`（城镇 + 抽屉）。

而不是原来的一根 1px 线。

## 7. 这一版做不到什么

**做不出 DD1 那种手绘磨损。** 程序化生成的上限是「规整的金属细框 + 均匀肌理」，
原版那种边缘不规则、局部掉漆、手绘阴影的效果，九宫格拉伸后会重复暴露。

要继续往上走，只有三条路：

| 方向 | 做法 | 代价 |
|---|---|---|
| 装饰件 | 从原版切角花/铆钉/纹章，贴到四角 | 中等，要先找可用的碎片 |
| 手绘边框 | 用 ImageGen 出整张手绘边框，再切九宫格 | 边缘拉伸会失真，需逐角修 |
| 标题条 | 顶部加一条木/铁质横幅（`panel_banner` 那种） | 小，观感提升明显 |

按性价比排序：**标题条 > 装饰件 > 手绘边框**。

## 9. 装饰件（第二轮）

边框解决的是「有没有框」，装饰解决的是「像不像同一套美术做的」。

### 9.1 标题横幅

每个屏顶部的 `_header()` 从「一条纯色 + 1px 线」换成一块**铁牌**：
纵向 `黑边 → 金线 → 渐变底 → 金线 → 黑边`，左右端有折角线和铆钉。

横向九宫格（`_draw_nine_h`）：左右各固定 36px，中段拉伸。
纵向整体不切 —— 横幅高度恒为 56，切了反而没意义。

```
96×56 源图，左右端各 36 固定
┌────┬──────────────────────────┬────┐
│折角│      纯纵向渐变，无花纹       │折角│
│铆钉│   （横向拉多长都不会变形）      │铆钉│
└────┴──────────────────────────┴────┘
```

九屏共用这一个函数，所以战斗/城镇/地图/公会/商店的横幅自动一致。

### 9.2 分隔线

抽屉里三条分区线从 `draw_line` 换成 `_divider()`：
中间一枚**菱形纹章**（外金内暗，两侧各一个小方块），两侧细线向外渐隐。

同样走横向九宫格，中间 18px 固定、两边拉伸，
所以线可以拉满 702 宽而菱形始终居中。

### 9.3 还能做什么

| 装饰 | 用在哪 | 难度 |
|---|---|---|
| 角花升级 | 大面板四角，现在是「短线 + 铆钉」 | 小 |
| 侧边镶条 | 抽屉/大面板左右两侧的竖向纹路 | 中 |
| 空状态纹章 | 名册为空、难度卡「带不动」时的图案 | 小 |
| 章节/区域印章 | 战役完成、首领讨伐进度的火漆章 | 中 |
| 按钮端头 | 普通按钮两端的斜切角 | 小 |

原则：**装饰只加在「结构转折处」**（顶栏、分区线、大面板四角、空状态），
不加在内容区中间 —— 内容区一花，文字就没法读了。

## 10. 试过出图工具（结论：能，但有明确边界）

用 ImageGen 生成了一张哥特铁艺角花（1024×1024，卷草纹 + 古铜色），
流程是「生成 → 抠图 → 缩放 → 接入」。结论如下。

### 10.1 透明背景不生效，要自己抠

传了 `background: transparent`，但产出的是 **RGBA 里 alpha 全 255 的 RGB 图** ——
棋盘格是「画进去」的假透明。

抠法是按亮度：棋盘格是「高亮度 + 低饱和」（亮度 230~255、饱和 < 14），
雕花是暗金（亮度 50~150、饱和高）。一条阈值就能分离：

```python
bg = (lum > 196) & (sat < 14)
alpha = where(bg, 0, 255)
```

效果干净，边缘没有白边，内部镂空也保留。

### 10.2 尺寸是硬约束

同一个角花缩到不同尺寸的可辨识度：

| 尺寸 | 结果 |
|---|---|
| 40 / 56 | 糊成一个金色 L 轮廓，细节全丢 |
| 72 | 勉强看出纹理 |
| **96 / 120** | 卷草纹清楚 |

手机 750 宽下，**96px 是有意义的下限**。

### 10.3 和当前边框厚度对不上（这次放弃的原因）

面板边框是 24px（`panel.png` 的 margin），雕花臂长要 96 才有细节。两种放法都不行：

| 放法 | 结果 |
|---|---|
| 画在内侧 | 84px 的角花直接压住头像和标题 |
| 骑在边框上（外移 1/3） | L 形和 24px 边框对不齐，像「漂在面板外的两个金角」 |

**不是画得不好，是厚度不匹配。** DD1 的面板边框有 30~40px 厚，
刚好装下一圈雕花；我们的界面信息密度高，边框只能给 24px。

`_draw_ornaments()` 和 `orn.png` 都留着，将来换厚边框设计时直接开。

### 10.4 出图工具适合做什么

| 适合 | 不适合 |
|---|---|
| 独立图形：纹章、火漆印章、空状态插图 | 九宫格结构件：边框、底板、按钮 |
| 尺寸 ≥ 96px、不需要拉伸 | 需要像素级对齐四角的东西 |
| 一次一张、不用批量生成 | 要反复调参数的模板件 |

因为「独立图形」不需要拉伸，AI 生成的不规则边缘反而是优点；
而结构件一旦拉伸，AI 画的不规则就会被放大成歪斜。

### 10.5 成本

一张约 5–10 积分。批量生成 10 张就是 50–100 积分，
而抠图、缩放、对齐还要人工过一遍 —— 所以先想清楚「用在哪」再生成。

实测图：`shots/m59_gen_ornament_test.png`（素材 + 两种失败用法）。

### 11.1 三个和规格不一样的地方

| 项 | 规格要求 | 实际交付 | 处理 |
|---|---|---|---|
| 画布 | 1024 × 1024 | **2048 × 2048** | 脚本改成按实际尺寸算格子 |
| A 表背景 | alpha 透明，或纯品红 | **jpg + 画上去的棋盘格** | 加 `--checker`，按「亮度 + 饱和」抠 |
| bg_town | 750 × 1334 单张竖构图 | **1536 × 2752，三段重复** | 取中间段，上下模糊延展 |
| 文件格式 | PNG | JPG | 脚本加扩展名回退 |

`ATLAS_B` 的品红底是对的（README 里也说明了要用 #FF00FF 键控）。

### 11.2 切图脚本改了三处

**① 尺寸自适应。** 原来写死 `cell=256`，2048 的图会被切成四分之一大小。
改成 `cw = w / cols` 浮点算再取整 —— 3 列时 2048/3 除不尽，累加取整会逐格偏移。

**② 抠图换成逐通道 BFS。** 这是最关键的一处：

```python
# 原来（错）
ImageDraw.floodfill(im, pt, (0, 0, 0, 0), thresh=52)
```

`ImageDraw.floodfill` 的 `thresh` 比的是**三通道差之和**，不是单通道。
棋盘格两档灰（252 / 220）单通道差 32，看起来「差不多」，sum 差却是 96，
于是只抠掉了角落那一格 —— 21 张图里 13 张带着一片白底。

改成自己写 BFS + 逐通道比较后，棋盘格按「亮度 > 196 且饱和 ≤ 16」判定。
用饱和而不是固定色值，是因为**大理石半身像**（icon_bust）也是浅灰：
它的饱和 20+，棋盘格是 0，能分开；而且它有黑色描边，BFS 进不去。

**③ 封闭区与残色。** 品红底有两个后处理：

- `seal_holes`：獠牙之间、墓碑与骨头之间的空隙被图案围住，从四角 BFS 进不去，
  会留一块亮品红。纯品红不可能出现在图标里，所以把「没连到边界」的同色块也填掉。
- **alpha 腐蚀 1px**：jpg 在「品红 → 黑描边」之间会留一圈紫红过渡，
  颜色差得远、阈值清不掉，只能连像素一起削。

> B 表那圈紫边有一半是**设计要求的**：区域徽记按区域色勾边
> （荒野绿 `#8fae6a`、墓穴紫 `#9d7bd8`、巢穴红 `#c8695f`、海湾蓝 `#3e5c76`），
> 出图方照做了，不该当残留删掉。只有空状态三张（B1~B3）的淡紫边是压缩残留。
> 腐蚀 1px 顺便把两者都收干净了。

### 12.2 C 表是纯黑剪影，必须提亮

出图方交的 15 个职业纹章是**纯黑剪影**：平均亮度 15、最亮 64。
放在 `#14161a` 的界面底色上等于隐形。

处理成「浅色版画」（`lift_silhouette()`）：

```python
t = clip((lum - 8) / (72 - 8), 0, 1)      # 原图亮度 8~72 拉伸到 0~1
v = (0.46 + 0.46 * t) * 255               # 输出 117~235
r, g, b = v, v*0.965, v*0.895             # 偏暖白
```

提亮后 113~226，均值 131 —— 在深底上清楚，而且**内部明暗起伏保住了**，
不是一块死白。`slice_atlas.py` 里对 `ATLAS_C` 自动生效（`--lift` 也可手动给）。

> 为什么不用 `modulate` 提亮：Godot 的 modulate 是**乘法**，纯黑 × 任何数还是纯黑。
> 只能改像素本身。

### 13.3 怎么验空状态：造三个存档

空状态在正常游玩里很难碰到，所以直接改存档造：

```python
import json, copy

# ① 名册全灭
e = copy.deepcopy(src)
for k in e['roster']:
    e['roster'][k]['alive'] = False
e['free_recruits'] = 3
json.dump(e, open('empty.json', 'w'), ensure_ascii=False)

# ② 带不动（见下面的坑）
b = copy.deepcopy(src)
for k in b['roster']:
    b['roster'][k]['resolve'] = 5      # 全员 5 级
for slot in b['board']:
    slot['level'] = 1                  # 任务板 1 级
json.dump(b, open('blocked.json', 'w'), ensure_ascii=False)

# ③ 战役完成
v = copy.deepcopy(src)
v['boss_cleared'] = {'weald': True, 'crypts': True, 'warrens': True, 'cove': True}
json.dump(v, open('won.json', 'w'), ensure_ascii=False)
```

存档目录：`%APPDATA%/Godot/app_userdata/DarkestLike/`，
用 `--save=user://empty.json` 启动。

三个档都留在那个目录里，以后改这几处可以直接 `--shot` 验。

**踩的坑**：第一版把 `board` 的 `level` 调成 9 想造「带不动」，结果界面显示
「5 级怪 · 够格 5 人」—— 因为 `level` 会被 `board_ceiling()` 夹到上限 5，
而且 `can_join()` 的判定是：

```gdscript
resolve_of(hid) - quest_level < REFUSE_GAP   # REFUSE_GAP = 2
```

**英雄等级低于任务永远能进**（负数一定小于 2）。只有**英雄等级高太多**才会被拒。
所以「带不动」的正确造法是「全员 5 级 + 任务板 1 级」，不是反过来。

### 14.3 造状态测试档的坑：疾病不是独立字段

想造一个「有病 + 有怪癖」的英雄，第一版写：

```python
m['roster'][hid]['diseases'] = ['creeping_cough']   # ❌ 没用
```

界面毫无变化。因为 `diseases_of()` 是从 `quirks_of()` 里筛出来的：

```gdscript
for q in quirks_of(hid):
    if quirk_lib.is_disease(str(q)):
        out.append(str(q))
```

`is_disease` 读的是 `data/quirks.json` 里那条记录的 `is_disease` 字段。
所以正确写法是**往 `quirks` 数组里塞疾病 id**：

```python
m['roster'][hid]['quirks'] = ['creeping_cough', 'wasting_sickness']  # ✅ 病 2
m['roster'][hid]['quirks'] = ['fragile', 'slow_reflexes']            # ✅ 怪癖
```

疾病 id 有 23 个（`bad_humours` / `creeping_cough` / `hemophilia` /
`the_runs` / `wasting_sickness` / `tetanus` …），直接从 `data/quirks.json`
筛 `is_disease == true` 拿。

测试档留在 `%APPDATA%/Godot/app_userdata/DarkestLike/status.json`。
