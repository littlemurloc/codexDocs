# M22 · 城镇建筑

> 一句话：原版八座建筑，我们原来把它们压成了「英雄卡上的两个按钮 + 右下角三个按钮」。
> 这一期把它们还原成建筑——其中三座（疗养院、修道院、酒馆）补的是**规则缺口**，
> 不是把按钮换个位置。
>
> **补记（M23）**：本文 §4 说「原版靠每周次数区分，我们没有周次系统」，
> §10 说「没有时间系统」——这两条在 M23 已经不成立：一趟远征推进一周，
> 进建筑占一周，所以「一周只能办一件事」这个原版限制现在有了。
> 原文保留，用来对照当时的设计边界。

## 1. 起点：动作散落在英雄卡上

M21 结束时城镇屏是这样：

```
名册 5 张卡（每张卡上：升阶按钮 / 招募按钮）
出发：区域选择 + 4 张难度卡
右下角：公会、饰品、商店 三个按钮
两行说明
```

问题不是「按钮多」，是**没有分层**：

- 一张英雄卡同时承担「显示状态」和「对他做点什么」两件事
- 「升级」这件事和「出发」在同一屏，玩家扫一眼看不出「现在该干什么」
- 招募按钮在每张死卡上各一份，价格一样但分散在五处

原版的做法是：城镇 = 建筑列表，进去才选人。这一期照这个改。

## 2. 八座建筑分两类

| 建筑 | 类型 | 来源 |
|---|---|---|
| 马车 | 换个入口 | `Campaign.recruit`（M5） |
| 铁匠铺 | 换个入口 | `Campaign.upgrade`（M5） |
| 公会 | 换个入口 | M19 已有，直接跳屏 |
| 商队 | 换个入口 | `S_TRINKET` + `S_SHOP`（M15/M16） |
| **疗养院** | **补缺口** | 新增 |
| **修道院 / 酒馆** | **补缺口** | 新增 |
| 墓园 | 展示 | 新增（只读） |

前四座的规则一行没改，只是把入口搬进建筑。
**这一期真正的答案是后三座**——它们补的是两个一直存在的洞。

## 3. 疗养院：让 `cure` 终于有人调用

M14 就实现了治病，但那条路只在**远征里**能走（奇物给的 `cure` 效果）：

```gdscript
# expedition.gd:1049
func cure_disease(hid: String) -> String:
```

README 从 M14 起就写着「`cure` 已实现但没有任何东西调用它（城镇没有医院），
疾病只能靠奇物清除」。现状是：一旦染病，玩家**没有任何主动手段**。

疗养院接上了这条线，但走的是元层自己的路径（`Campaign.treat_disease`），
不经过 `Expedition`——因为城镇没有 `exp` 对象，直接改 `roster` 更干净。

**一次只治一条**。这条不是随手定的：一次治全部的话，疗养院就退化成一个
「点一下"的按钮，而「先治哪条」正好是这个系统唯一有决策量的地方。

同理，清怪癖和治病是**两个价格**（350 / 600）：疾病更贵，因为它的影响是持续性的
（每趟都在结算），怪癖是局部的。

## 4. 减压：从写死 40 到两档选择

原来回城减压是 `cfg.get("town_stress_relief", 40)`——一个常数，
**而且 `campaign.json` 里根本没写这个键**，所以它一直用的默认值 40。

现在两座建筑：

| 建筑 | 减压 | 价格 | 每点成本 |
|---|---|---|---|
| 修道院 | 40 | 200 | 5.0 金 |
| 酒馆 | 70 | 450 | 6.4 金 |

便宜但少 vs 贵但多。原版靠「每周次数」区分，我们没有周次系统，
只能用性价比区分——**这条要写清楚，因为它是简化，不是等价**。

界面会直接算给你看：「当前压力 130 / 200 —— 待完这次是 60」。

## 5. 墓园：只展示，不编造

原版墓园记录「谁死在哪一趟、什么原因」。我们只有 `roster[h].deaths`
（一个计数），没有逐次记录。

所以墓园只显示：

```
十字军    阵亡 1 次 · 出征 1 次 · 已归队
强盗      阵亡 4 次 · 出征 9 次 · 已归队
```

**没有编造死因**。界面上写了一句「只记阵亡次数——谁死在哪一趟、什么原因，
需要结算时落盘，还没做」。真正的阵亡记录要在 `settle` 时 append 一条
`{hero, run, reason}`，那是另一期的事。先做一个半成品的墓园比没有更糟：
玩家会以为那些信息存在，只是自己没找到。

## 6. 城镇屏重排

八个建筑入口做成一行（每个约 146×44），英雄卡缩到 240 高、去掉按钮，
多出来的一行显示状态摘要：

```
怪癖 3（负 2）· 疾病 1
```

有病时整行变警告色——这是唯一需要**立刻**处理的状态，
而它原来藏在三个屏之外。

纵向重排后的顺序：资源 → 名册（纯状态）→ 出发（区域 + 难度）→ 建筑 → 说明。

## 7. 数据

价格写在 `data/campaign.json` 的 `buildings` 段，对齐 M13 重标定后的经济：

```json
"disease_cost": 600,
"quirk_cost": 350,
"rest": [
  {"id": "abbey", "name": "修道院", "relief": 40, "cost": 200},
  {"id": "tavern", "name": "酒馆", "relief": 70, "cost": 450}
]
```

参照系：一趟 short Lv1 约 3498 金、装备一阶 1000。所以治病 ≈ 半件装备，
清怪癖 ≈ 三次修道院。改这里就是改价格，不用碰代码。

## 8. 踩的坑

**同一个动作别留两个入口。**

把招募/升级搬进建筑之后，英雄卡上原来那两个按钮必须删掉。
理由不是「看着冗余」，是**改价格的时候只会改一处**——
另一处会变成旧数字，然后玩家发现两边的价格不一样。

这次是同一个人一次改完，所以没出问题；但这类「同一份逻辑两个入口」
正是 M13~M19 反复踩的坑（`finish_battle` 整份替换 state、火把同时存在于两处、
奇物给的食物吃不到）。

## 10. 没做的

- **阵亡记录**：墓园只读 `deaths` 计数，见 §5。
- **建筑升级**：原版建筑自己也能升级（多一个槽位、降价）。我们八座都是固定功能。
- **周次与排队**：原版「派英雄去减压 / 治疗，下周才回来」是核心节奏，
  我们没有时间系统，所以全部改成即时结算。这是**最大的简化**，
  也是「建筑感」最弱的地方——现在的八座建筑更像「八个功能面板」。
- **医院与疗养院的区别**：原版医院治病、疗养院治怪癖，是两座。
  我们合成了一座（价格分开），因为我们的疾病来源只有一条（奇物）。

## 11. 补记（M30）：八座建筑里只有公会能进

主人上手后第一句话是「底下这一排按钮，只有公会点进去有二级界面，其他都是点了没反应」。

原因是一行漏写，在 `_activate()` 的 `bld:` 分支里：

```gdscript
if bid == "guild":
    _state = S_GUILD          # 有改状态
else:
    _building = bid           # ← 只赋了变量
    _building_hero = ...      # ← 没写 _state = S_BUILDING
```

所以点马车/铁匠铺/疗养院/修道院/酒馆/商队/墓园，程序确实「处理」了这次点击
（赋了 `_building`、给了 hover 高亮），但**画面停留在城镇**——表现上和没响应一模一样。
公会那条分支恰好改了状态，所以只有它能进。

为什么两期没被发现：`--bld=<id>` 截图参数是直接赋状态进建筑的，**绕过了点击分发**；
而规则层单测根本不覆盖界面状态机。这类「接线断了但规则全绿」的问题，
和 M20 那个 `el\tif` 一样，只能靠人点出来。

修法与配套：

1. 补 `_state = S_BUILDING`（顺带清 `_fire_pending`，避免上一个建筑的解雇上膛带过来）。
2. 新增 `--click=<按钮 id>` 参数，走**真正的** `_activate()` 路径再截图，
   和 `--bld=` 形成互补：前者测接线，后者测画面。
3. 商队/墓园没有左栏名册，副标题不再写「左侧点人」。
4. 商队仓库为空时按钮文案改「饰品仓库 · 空（打一趟才会有）」——
   灰按钮不解释，玩家同样会当成"点了没反应"。

七座建筑的点击路径现在逐个验证过（`--click=bld:<id>` 打印状态切换，全部 `S_TOWN → S_BUILDING`），
截图 `shots/m30_{coach,smith,sanitarium,abbey,tavern,wagon,graveyard}.png`。
