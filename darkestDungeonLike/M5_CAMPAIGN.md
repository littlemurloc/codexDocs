# M5 · 元层：战利品、城镇、存档

> **已被 M13 修订（数字层面）。** 本文里的掉落常数（每场 9–17 金、30% 掉传家宝、
> 通关 45+22×场次）和价格梯度（40/90/160/260、招募 60）都是 M5 在没有解析
> 抽卡树时拍的，M13 换成真表后**同一段逻辑的量级全变了**：
> 真表一趟 short/Lv1 就有 3498 金，旧价格等于「打半趟升满全队」。
> 现值见 `data/campaign.json`，标定依据见 [M13_ITEMS_CURIOS.md](M13_ITEMS_CURIOS.md) §6。
> 下面保留原文，是为了记住当时的取舍，不是当前数值。

M4 结束时最刺眼的一条发现是：

> **撤退按钮没有存在感。** 它在界面上，逻辑也对（全员 +20 压力、远征判负），
> 但没有任何东西推动玩家去点它。撤退的收益是「保住剩下的人」，
> 可这一版没有跨远征的持久化——人死了就是死了，下一趟还是满编四人。于是撤退 = 纯亏。

M5 补的就是这一层。它不改任何战斗规则，只回答一个问题：
**这两趟之间，什么变了？**

## 交付了什么

```
src/core/campaign.gd        存档、账、名册、升级、招募、结算
data/campaign.json          战利品曲线与城镇开销（和 expedition.json 分开）
src/view/expedition_scene   新增城镇屏；结算屏加「本趟所得」；出图前按英雄装备阶装配
tests/test_campaign.gd      45 项断言（账/升级/存档/阵亡/破产保护）
```

## 四个后果

| 机制 | 具体规则 | 它解决的 M4 问题 |
|---|---|---|
| **战利品** | 赢一场 9–17 金币、30% 掉 1 个传家宝；走完全程另加 45 + 22×场次金币、1–3 个传家宝；撤退只保留已到手的 | 撤退从「纯亏」变成「少赚但保人」 |
| **永久阵亡** | 阵亡的英雄 `alive=false`，从出发名单消失 | 死人真的没了，撤退第一次有收益 |
| **招募** | 复活一个阵亡英雄要 60 金币 + 2 crest | 「带伤硬打」和「撤退」之间的取舍有了价格 |
| **装备升级** | 40 / 90 / 160 / 260 金币 + 传家宝，逐阶买到 4 阶 | 战利品有了去处，下一趟真的更强 |
| **压力跨远征** | 回城只减 40，剩下的带进下一趟 | 「这一趟该不该换人」变成真问题 |

装备阶不再是路线白送的：`Expedition.hero_gear` 按英雄各自的阶装配，
路线里的 `step.gear` 只作兜底默认值。这是「花钱升级在下一趟能看出来」的前提。

## 存档

一份 JSON，`user://campaign.json`，可读、可手改。

```json
{
  "version": 1,
  "gold": 483,
  "heirlooms": {"bust": 2, "portrait": 5, "crest": 1, "deed": 1},
  "roster": {
    "crusader": {"gear": 1, "skill": 1, "alive": false, "stress": 0.0, "runs": 3, "deaths": 1}
  },
  "expeditions": 3,
  "best_steps": 8,
  "free_recruits": 4
}
```

不用二进制、不用 `ResourceSaver`：调数值的阶段，能用记事本打开看比省几十字节重要得多。
`from_dict` 以配置里的名册为准补齐，旧档缺职业时不会少一个人。

## 三个真实问题

### 1. 阵亡在结算时被"复活"

`Expedition.state` 原先在每场战斗后整份替换成 `battle.capture_party_state()`，
而后者只包含**这一场参战的人**。于是前几场就阵亡的队友，在第三场的 state 里消失了；
结算读 `state[hid]["dead"]` 拿到空字典 → 当成活着。

实测表现是：一趟四人全灭的远征，名册只少了一个人。
**这个 bug 只在「多人先后死亡」时出现，单场测试永远抓不到。**

修法不是打补丁，而是把语义改对：state 改成**合并**而非替换，
并给 `Expedition.is_dead(hid)` 一个明确入口，让 Campaign 不必自己去挖内部结构。

### 2. 全员阵亡 + 没钱 = 死局

第一次跑长途 5 级队，第一场就团灭，金币 0。
名册空了、招募费付不起，存档不会自己回退——这档等于废了。

加了破产保护：**全员阵亡时发一批免费征召名额**，人数按名册补满。
一开始只发了「一个人」的免费额度，结果第二次跑出「单人出门必死、再补一个、再死」的循环——
看起来像保护，其实是在让玩家亲手把死循环演一遍。所以额度按人头一次性发满。

这条是 M5 里唯一一处「为了不让游戏卡死而增加的机制」，写在 `campaign.json` 之外
（`free_recruits` 字段），因为它不是数值设计，是容错。

### 3. 自检只补一个人，等于没测

`--selftest` 起初遇到空名册只招募一个英雄就出发，于是每次都团灭、每次都通过
（因为判定里 `end_reason == "wipe"` 也算过）。这类"绿灯假象"很危险：
测试在跑，但它测的是死循环能不能重复。

改成补满之后，才真正走到「恢复 → 再出发 → 有输有赢」的路径。

## 验证

```
全部通过：223 项断言
```

其中元层 45 项，覆盖：入账、付不起时不扣款、升级扣费与封顶、
存档往返一致、阵亡者不能升级、招募、破产保护额度一次性生效。

跨进程的闭环用 `--selftest` 连跑三次（同一份存档）：

| 趟次 | 开局 | 结果 | 结束金币 |
|---|---|---|---:|
| 1 | 新档，4 人，0 金币 | 完成 6/6 步 | 188 |
| 2 | 读档 188 金币，4 人 | 完成 8/8 步 | 434 |
| 3 | 读档 434 金币，4 人 | 团灭 7/8 步 | 483 |

第三条正好是想要的：团灭也带回了钱（前面打赢的场次已经入账），
但名册死了三个人——**"这一趟值不值"第一次有了两面**。

## 经济节奏

一趟短图（4–6 场）大约 190–250 金币、3–4 个传家宝；
一整条升级链是 40 + 90 + 160 + 260 = 550 金币/人。
四人满级约 2200 金币 ≈ 10 趟短图。

现在的手感是「两趟就能看到第一次升级」，这是刻意的：
原型阶段让人尽快看到循环成立，比让人刷十趟更值。

改数的地方只有一处：`data/campaign.json` 的 `loot` 与 `costs`，代码一行不用动。

## 一个副作用：中长途变成「必须先刷短图」

M4 之前，路线按地图等级白送装备（Lv3 → 2 阶、Lv5 → 4 阶），
所以中长途和短途的差别只是「场次多少」。

现在装备阶来自城镇，新档全员 0 阶。于是同一批自检里：

| 规格 | 0 阶队伍实测 |
|---|---|
| 短途 Lv1 | 9/9 步走完 |
| 中程 Lv3 | 第 2/10 步团灭 |
| 长途 Lv5 | 第 1/18 步团灭 |

**这是对的，但必须让玩家提前知道。** 城镇屏在「地图等级 − 平均装备阶 ≥ 2」时
会给出「装备不足，建议先打短图」的红字——没有这句提示，
中长途看起来和短途一样是个可点的按钮，点下去就是白送一趟。

## 怎么跑

```bash
GODOT="D:/XT/godot/Godot_v4.7.2-stable_win64_console.exe"

# 正常玩（存档在 user://campaign.json）
"$GODOT" --path .

# 换一份存档（不污染主档，测试/截图都用这个）
"$GODOT" --path . -- --save=user://test.json

# 端到端：出发 → 战斗 → 结算 → 入账 → 存档 → 读档校验
"$GODOT" --headless --path . -- --selftest --size=short --level=1 --save=user://t.json

# 只看结算屏
"$GODOT" --path . -- --to-result --save=user://t.json
```

## 已知局限

- **没有城镇建筑**。传家宝只有「升级装备」一个去处，DD1 里它还能盖建筑、招特殊职业。
- **没有饰品与怪癖**。这两样是 DD1 的主要 build 空间，现在英雄之间只有装备阶差异。
- **一次只能派固定四人**（名册就这四个职业），没有「带谁去」的选择。
- **升级不区分武器/护甲/技能**，三样一起涨。DD1 是三套独立的钱。
- **撤退仍然缺少提示**。它现在有收益了，但界面不会告诉你「再打下去大概率团灭」——
  这是下一层（战前情报）的事。
- **没有失败条件**。破产保护会一直兜底，游戏不会「输」，只是反复重来。
