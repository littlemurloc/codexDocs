# M37 · 战斗布局：让 rank 轴和画面轴对齐

> 一句话：**rank 变化必须在画面上是横向滑动**，否则位移技能玩家永远看不懂。
>
> 这是 M36 出图之后立刻暴露的问题。上一版是「上排怪物、下排英雄」，
> 两排各自从左到右排 1→4。看起来只是"排得整齐"，实际上错了两层。

---

## 1. 错在哪

### 第一层：纵向排列没有 rank 这条轴

规则层里 `rank` 是 0..3，**位移就是 rank±1**（推、拉、换位、自己调整站位）。
但画面上两排是上下分开的，横向位置只表示"这是第几张卡"。
于是「被推后一格」在画面上的表现是**卡片原地不动**，玩家只能从日志里读到「推」。

### 第二层：位置是按数组顺序算的，不是按 rank

```gdscript
# 旧代码
for i in en.size():
    var r := Rect2(ex + float(i) * (ecw + egap), 82, ecw, 104)
```

`i` 是数组下标。rank 变了以后卡片确实会重排（因为数组顺序变了），
但那是**瞬移**——没有过程，看起来像「两个人瞬间交换了位置」，
而不是「这个人往后挪了一步」。

修第一层不改第二层，等于白修。

## 2. 修法

### 2.1 rank 换算成 x，阵营决定 y

```
敌方（上排，靠右）：rank 1 在最左 ──► rank 4 在最右
我方（下排，靠左）：rank 4 在最左 ◄── rank 1 在最右
```

两军的 **1 号位在中间相接**，所以「前锋对前锋」是读得出来的；
后退一格 = 横向往自己这边缩一格。空位**保留**（3 人队不挤在一起），
否则「最前排」的位置会随人数变化，位移还是读不准。

```gdscript
func _battle_slot(u: Combatant, is_enemy: bool) -> Rect2:
    var rk: int = clampi(u.rank, 0, 3)
    if is_enemy:
        return Rect2(enemy_x0 + float(rk) * slot_w, BATTLE_Y, W, H)
    return Rect2(party_x0 + float(3 - rk) * slot_w, BATTLE_Y + H + ROW_GAP, W, H)
```

两组坐标的关系是算出来的，不是试出来的：让**我方 rank1 的左边缘 = 敌方 rank1 的右边缘**，
两军前锋就刚好接上：

```gdscript
var enemy_x0: float = party_x0 + slot_w * 3.0 - BATTLE_W
```

### 2.2 位置也要插值

`_battle_slot` 只给「应该在哪」。实际画的位置在 `_slot_anim`（uid → Vector2）里，
每帧朝目标插值：

```gdscript
var k_lerp: float = 1.0 - pow(0.0015, delta)   # 约 0.25 秒到位
_slot_anim[u.uid] = cur.lerp(goal, k_lerp)
```

这样位移是**滑过去**的，眼睛能跟上。顺带把受击抖动也从「只有头像抖」
改成了「整张卡抖」——两件事用同一个坐标系，才不会互相打架。

换一场战斗时 `_slot_anim` 必须清空（`_slot_anim_battle != _battle` 判断），
否则上一场的坐标会漏过来，卡片会从上一场的位置飞进新战场。

### 2.3 卡片必须收窄

横排 4 张 + 两军错开，200×104 的方形卡放不下（4×200+3×18 = 854，
两排错开还要再叠 350，一共 1200 > 1080）。改成 **160×84 的横向长条**：
头像 44 在左，文字列 96 在右。

由此带来两处连带改动：

- **「位 N」那行删了**。位置本身已经是 rank，再写一遍是重复，
  而且横排卡片没高度给它。改成右上角一个小号数字。
- **状态标记（死门 / DOT / 崩溃）移到底部整行**。它在长条卡里没有别的位置，
  而这一行本来就需要跨整张卡。

## 3. 现在的战场长什么样

```
                ┌────┬────┬────┬────┐
   敌方（右上）  │ 1  │ 2  │ 3  │ 4  │        ← rank 1 在最左
                └────┴────┴────┴────┘
  ┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈   交战线（淡虚线）
        ┌────┬────┬────┬────┐
我方     │ 4  │ 3  │ 2  │ 1  │              ← rank 1 在最右
（左下）  └────┴────┴────┴────┘
```

两军 1 号位在中间相接，虚线是两者之间的交战线。

## 4. 已知限制

1. **战线是虚线，不是"场景"**。这一版仍然是卡片，只是排对了方向。
   要做 DD 那种「人站在地上、光照成一个圈」，需要 `_draw_unit` 退成
   「单位图形 + 悬浮血条」，那是站桩重构（M36 §5 的方向 B）。
2. **敌方也可能有 5+ 单位**（召唤）。`clampi(rank, 0, 3)` 会把 rank 4 压到第 4 格，
   两个单位会叠在一起。目前遭遇表最多 4 只，没有触发，但这是个真实缺口。
3. **滑动没有"路径"**。换位是两个人直线对穿，会重叠一瞬。
   要做得更好的话得加一点弧线，但那是抛光阶段的事。
4. **阵亡单位不腾位**。死了仍然占着 rank 格（血条空、变灰）。
   这符合"尸体还在那儿"的直觉，但也意味着后面的人不会自动前移——
   规则层本来也不让他们前移，所以两边是一致的。
