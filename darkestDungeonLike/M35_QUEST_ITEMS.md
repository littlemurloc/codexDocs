# M35 · 任务物品与「带道具激活」

> 一句话：任务物品有了自己的容器，`inventory_activate` 接上——任务类型六种全开。
>
> 它看起来像「加一种任务」，其实是**给任务加了一个维度**：要不要用道具。
> 数据里两者压根不是两种类型，`inventory_activate_*` 的 goal `type` 写的就是 `activate`，
> 唯一多出来的是 `starting_items`。这个发现决定了整个实现的大小。

---

## 1. 起点：最后一类任务卡在一个容器上

M33 把 `gather` / `activate` 接上时，`inventory_activate` 被留在门外，
理由写在 `UNSUPPORTED_TYPES` 里：「它要求任务物品能进背包，属于道具系统」。

当时的判断是对的，但**估大了**。真实的数据形状是：

```json
{"id": "inventory_activate_corrupted_altar", "type": "activate",
 "starting_items": [{"type": "quest_item", "id": "holy_water", "amount": 3}],
 "data": {"curio_name": "corrupted_altar", "amount": 3}}
```

和 `activate_iron_maiden` 比，只多一个 `starting_items`。所以需要的不是
「道具系统」（装备、买卖、格子、拖拽），而是**一个每趟重置的计数器 + 一条消耗规则**。

四个区域各带一种物品：

| 区域 | 目标奇物（数据写的） | 任务物品 | 数量 |
|---|---|---|---|
| 荒野 weald | `infected_corpse` 腐尸 | `antivenom` 解毒剂 | 3 |
| 墓穴 crypts | `corrupted_altar` 腐化祭坛 | `holy_water` 圣水 | 3 |
| 巢穴 warrens | `animalistic_shrine` 兽性神龛 | `pickaxe` 镐 | 3 |
| 海湾 cove | `protective_ward` 护符 | `eldritch_lantern` 邪光提灯 | 3 |

---

## 2. 任务物品为什么**不**进补给

最省事的做法是往 `supplies` 字典里塞三件——现成的计数、现成的 UI。
没这么做，三条理由：

1. **有些任务物品根本不是补给**。`pickaxe` / `eldritch_lantern` / `beacon_light`
   不在 `inventory.json` 的 supply 列表里（那里只有铲子、火把、绷带、解毒剂、
   骷髅钥匙、药草、圣水、狗饼干、鸦片酊、柴火 10 种）。混进去会被商店
   当成在售补给。
2. **补给能被玩家自己处置，任务物品不能**。补给出发前可买、交互时可用、
   商店里可卖；任务物品丢一件任务就做不完，那不是「选择」，是陷阱。
3. **原版的任务物品本来就独立于补给栏**。

所以有 `Expedition.quest_items`：`id -> 剩余件数`，`set_location` 时按数据自动带上。

`quest_items` 和 `supplies` 各有一个 id 空间重合（`holy_water`、`antivenom`
两边都有），这是数据的实际情况，不是设计——所以查名字时
`DdNames.quest_item_name` 先看任务物品表，查不到再退回补给表。

---

## 3. 消耗：一次交互一个顺序问题

交互目标奇物时要做四件事：判断有没有道具 → 扣一件 → 计数 → 顺带结算奇物。

第一版把「判断」写在扣之后，于是**最后一件道具永远用不上**：
扣到 0 之后再问「还有没有」，答案是没有，那一次交互就不计数。
症状是「带 3 件、图上 3 个奇物，只能激活 2 次」——而它只在正好用光时出现。

正确顺序（`_resolve_curio_table` 里）：

```
1. qitem   = QuestGoal.required_item(quest_goal)      # 这件任务要不要道具
2. has_qitem = qitem 非空 and quest_items[qitem] > 0   # ← 先记下来
3. _note_quest_curio(cid, step)                        # 扣一件、计数 +1
4. use_item = has_qitem and 该奇物接受 qitem ? qitem : 自动选补给
5. cl.resolve(cid, use_item, rng)
6. 结果要扣道具时：use_item == qitem 就跳过 take_supply（第 3 步已经扣过）
```

第 6 步是第二个坑：`out["item"] != ""` 分支原本无条件调 `take_supply`，
而任务物品不在 `supplies` 里，`take_supply` 会失败——不 branch 的话，
表面上没报错，实际是「圣水被用掉了但计数没扣」，玩家能多用几次。

---

## 4. 唯一的那个重合：四个区域只有一个用对了道具

第 4 步里「该奇物接受 qitem」是数据说了算（`curios.json` 的 `items` 表），
不猜。实测四个区域：

| 区域 | 解析出的目标奇物 | 它接受的道具 | 任务物品 | 吻合 |
|---|---|---|---|---|
| 墓穴 | `altar_of_light` 光照祭坛 | `holy_water` | `holy_water` | **是** |
| 荒野 | `ancient_coffin` 古棺 | （无） | `antivenom` | 否 |
| 巢穴 | `occult_scrawlings` 秘教涂鸦 | `holy_water` | `pickaxe` | 否 |
| 海湾 | `bas_relief` 浅浮雕 | `shovel` | `eldritch_lantern` | 否 |

**只有墓穴一个重合。** 原因是老问题：数据里的四个目标奇物
（腐化祭坛/腐尸/兽性神龛/护符）本身不存在，我们用 M33 的标签把它们
解析成了同区域的等价奇物，而那些等价奇物的 `items` 表是它们自己的，
和任务物品没有关系。

所以「用对道具」这件事目前只在墓穴成立。其余三个区域里，
任务物品只是**计数凭证**：照样要带、照样消耗，但不改变奇物结果。

不打算为此硬编「让每个目标奇物都吃任务物品」——那是假造数据。
等真的任务奇物定义进了数据，这张表自然就对上了（见 M33 §5 的两条路）。

## 5. 数值

带道具激活（巢穴 medium Lv1 ×5）：

| 完成 | 激活 | 物品用 | 缺道具 | 结果 |
|---|---|---|---|---|
| 5 / 5 | 3/3 | 3 | 0 | 3 次通关，2 次任务做完后团灭 |

「缺 0」说明地图上正好投放了 3 个目标奇物、没多到让道具不够用。
这种情况由 M33 的投放规则保证：`need` 个奇物对 `amount` 件道具，一比一。

任务类型全景：

| 任务 | 判据 | 状态 |
|---|---|---|
| 探索 | 走到出口 | ✅ |
| 首领 | 杀死终点首领 | ✅ |
| 清剿 | 清光图上全部战斗房 | ✅ M32 |

| 激活 | 在铁处女上交互 | ✅ M33（仅墓穴） |
| **带道具激活** | **用任务物品激活 3 次** | ✅ **M35** |

## 6. 已知限制

1. **玩家不能手动选道具**。交互时自动优先任务物品、其次补给。
   原版也是自动的（任务物品遇到对应奇物就用），所以这不是缺陷；
   但「带错道具」这件事因此不存在，M13 那 46 条道具映射仍然只有
   「自动挑一个能用的」这一种用法。
2. **四个区域只有一个能对上**（§4）。其余三个区域的任务物品只是凭证。
3. **道具用完没有任何界面提示**。`stats["quest_items_missing"]` 和
   `{"t":"quest_item_missing"}` 事件都有，但地图屏只在物品行显示 `×0`。
   玩家看到 ×0 才明白，早了没有预警。
4. **`beacon` / `teleporter` 两个目标仍然没接**：前者属于至暗之地（没开），
   后者是传送器（本作没有跨层传送）。
5. **任务物品不写进存档**。它只在一趟远征内存在，回城即弃——
   这是对的（任务物品本来就是这一趟的凭证），但也意味着
   「中途撤退再进」得重新领。
6. `quest.exit_penalty` / `quest.restriction` / `quest.plot_quests`
   三块数据仍然没接（撤退惩罚、任务限制、剧情任务线）。

## 8. 下一步

任务这一层到此**六种类型全开**：

```
数据（quests.json：6 类型 / 48 目标）        ← M0 抽出来
判据（QuestGoal：解析 / 进度 / 完成）        ← M32
地图（按任务投放目标奇物）                   ← M33
道具（任务物品容器 + 消耗）                  ← M35
```

剩下的活按「离玩家的距离」排：

1. **美术**。四个区域的内容已经稳定了，可以开始画。这是唯一一件
   不做就永远是黑框白字的事。
2. **道具的手动使用**（§6 第 1 条）。它解锁的不是新玩法，是让 M13 那 46 条
   映射真的被看见——但优先级低于美术，因为自动用已经能玩。
3. **任务奖励**。现在完成任务只给经验和掉落，没有「任务本身额外的报酬」。
   `quests.json` 里有这方面的数据（`quest_rewards` 那一段），
   是下一块没读过的表。

倾向 **1**：再往规则里加东西，边际收益已经明显下降了。
