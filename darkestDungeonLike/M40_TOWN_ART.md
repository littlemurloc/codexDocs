# M40 · 城镇屏接图（a 档：建筑 + 头像）

> 一句话：城镇是玩家停留最久的一屏，之前是纯文字色块，和战斗屏的立绘放在一起很割裂。
> 这一期把它接上——**素材全是现成的**，成本主要在布局重排。

---

## 1. 素材：8 栋建筑全有，但不是"建筑外观"

`campaign/town/buildings/<id>/<id>.character.png` 有 **162 张**图，
我们需要的 8 个建筑一个不缺：

| 本作 id | DD1 目录 | 尺寸 |
|---|---|---|
| coach | stage_coach | 149×220 |
| smith | blacksmith | 221×220 |
| guild | guild | 197×220 |
| sanitarium | sanitarium | 164×220 |
| abbey | abbey | 158×220 |
| tavern | tavern | 193×220 |
| wagon | nomad_wagon | 285×220 |
| graveyard | graveyard | 148×220 |

**关键发现**：`character.png` 是**建筑主人 NPC 的半身像**（修道院的执事、铁匠、酒馆老板…），
不是建筑外观。

这不是问题，反而更好——在 146 宽的卡片里，半身像的辨识度远高于一张远景，
而且它替玩家回答了「进去会遇到谁」，这比「这是一栋房子」有用。

导出规则：按 alpha 裁到内容、统一高度 220、存 `assets/art/ui/buildings/<本作id>.png`
（本作 id 与 DD1 目录名不同，映射在这一步就展开成文件名，代码里不用查表）。

## 2. 皮肤层：薄到只做一件事

```gdscript
class_name UiSkin
func texture(kind, id) -> Texture2D     # res://assets/art/ui/<kind>/<id>.png
func building(id) -> Texture2D
var enabled: bool                        # --no-skin 关掉
```

没有排版、没有九宫格、没有回调。**只把「图从哪来、没有图怎么办」收敛到一处。**

抽太厚会变成另一套要和现有 100 处绘制调用对齐的框架，收益抵不过风险——
这一层的目的不是抽象，是**让第二屏不用再手工接一次**。

`--no-skin` 的意义不是开关好玩：它是验证「退化路径还能不能看」的唯一办法，
也是将来换原创美术时逐个槽位替换的退路。

注意它**只管界面贴图**：单位立绘（`UnitArt`）不受影响，那是战斗层的资源。

建筑卡 146×132：图 96 高居中，底部 34px 一条暗色底条兜住名字与说明——
不加底条的话文字直接压在卡片下沿，看起来像溢出而不是「图下面有字」。

英雄卡左侧加了 36px 头像，文字列整体右移 42，最长的一行

## 4. 已知限制

1. **1080 宽没验过**。8 张卡在 1280 下是 146 宽，1080 下只有 119——
   英雄卡的名字（4 字 52px）勉强，建筑卡的说明可能要截。
   项目约定按 1080 验排版，这一项**还没做**。
2. **建筑卡底部文字偏小**。132 高的卡里，图 96 + 文字 34，`FONT_TAG` 9px
   是唯一放得下的字号。想更大就得加高卡片，而 236..372 只有 136 可供。
3. **`--no-skin` 下建筑卡是 132 高的空面板**。高度不跟着缩回 52——
   因为一缩就会把下面几行的位置全挪一遍，那就没法用它对照
   「是不是贴图造成的布局问题」。
4. **任务卡还是纯色块**。区域头图（`loading_screen.*.png` 1920×1080）留给 b 档。
