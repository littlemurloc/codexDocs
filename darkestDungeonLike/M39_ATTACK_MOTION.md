# M39 · 出招动作：为什么"换帧"看起来像待机

> 一句话：DD1 的攻击**不是骨骼动画**，是「一整张姿势图 + 对整张图的位移/旋转」。
> 导出包给的是姿势图本身、没带变换，所以只换图 = 站那儿不动。

---

## 1. 现象

M38 接上「按 `art.anim` 换帧」之后，截图里只有修女像在出招，其他人还是站姿。

第一反应是「挑错帧了」——以为每个动画有多帧，应该挑打击那一帧。

## 2. 验证：包里每个动作只有 1 帧

`crusader.sprite.attack_sword.png` / `2` / `3` / `4` 四张，逐像素比对：

| 对比 | 轮廓差 | 颜色差 |
|---|---|---|
| `attack_sword` vs `2` | **0** | 9714 |
| `attack_sword` vs `3` | **0** | 20194 |
| `idle` vs `idle2` | **0** | 15035 |

**轮廓差为 0、只有颜色差** → 这 4 张是**配色变体**（A/B/C/D），不是动画帧。
全包统计：每个动作恰好 4 个后缀（空 / 2 / 3 / 4），**没有第 5 帧**。

所以「按帧号去查」这条路不存在——包里每动作只有一张图。

## 3. 再验证：姿势图本身是对的

把十字军 47 张动作帧并排（`shots/m38_crusader_anims.png`）：

- `attack_sword` —— 举剑斜指，身体侧转（**和 `combat` 的竖举剑不同**）
- `attack_charge` —— 明显前倾冲刺，剑向前刺出
- `dead` —— 倒地，剑拄地

图是对的。问题不在图。

## 4. 根因：解 `.skel` 才看出来

写了 Spine 2.1.27 二进制解析器（`.tmp/spine/spinerender.py`），读 `attack_sword.skel`：

```
版本 2.1.27   尺寸 324.2 x 306.1
骨骼 5 根
插槽 2 个: shadow(att=shadow) / attack_sword(att=attack_sword)
```

**只有 2 个插槽，每个挂一整张图**。也就是说 DD1 的英雄攻击是：

```
一张姿势图  +  对整张图的 translate / rotate / scale 关键帧
```

不是"头、手、腿各自动"，而是"整张图甩出去"。

导出包导出的是**姿势图本身**，变换没跟着出来。所以我们换图之后，人换了姿势但站着不动——看起来就像待机。

顺带解释了为什么修女"看起来对"：她的 `attack_lectionary` 姿势本身就是举书施法，动作幅度小，静态也读得出。

## 5. 修法：把变换补上

不需要继续啃 `.skel`（对英雄没必要）。只补一段前冲：

```gdscript
var k := sin(prog * PI)          # 0 → 1 → 0，冲出去再收回来
var dir := -1.0 if is_enemy else 1.0
offset = Vector2(dir * 26.0 * k, k * 0.06)   # x 位移 + 轻微放大
```

配合换帧，读起来就是"冲上去打了一下"。时长 0.42 秒（`POSE_TIME`）。

## 6. 顺带记下：`.skel` 解析器的状态

写了一半，停在一个**可复现的坑**上，留给将来做怪物时接手：

- ✅ 头部、骨骼、插槽、皮肤、动画时间轴都读通了（`hash(28B) → version → width/height → nonessential → bones → slots → skin`）
- ✅ 关键坑：**Spine 的字符串长度写成 `len+1`**（0 表示 null）。按 `len` 读会整体错位一字节，版本串变成 `"2.1.27C"`、width 变成 3e23
- ❌ 区域附件那一段还有 1 字节偏移没对上（实测浮点从 `name+type` 之后第 2 个字节开始），需要继续对

**为什么现在不做完**：英雄攻击是整图 + 变换，用不上全身解析；而**怪物**的骨架是零件拼的（头/手/腿分槽位），才真正需要完整解析 + mesh 支持。那是另一个工作量级。
