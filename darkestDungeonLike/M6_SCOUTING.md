# M6 · 战前情报

M5 之后城镇里能看到的东西只有「队伍 4 人」和一句「装备不足」的警告。
玩家必须在完全不知道前方是什么的情况下，决定带几根火把、什么时候休整、要不要撤退。
那不是决策，是赌。

M6 把「看得见多远」变成资源的一部分。

## 机制

```
revealed   前多少个节点已知（走过的必然知道）
侦察率     base_chance + 光照加成
```

每走一步，先让视野跟上脚步（走过的必知），再掷一次侦察判定：
成功就把视野往前推一格。

**光照在这里是第三次出场**，而且这次的数据不是我们编的：

```
rules.darkness[].value.player_scouting_increase
  明亮 +15%   微光 +7.5%   昏暗 0   漆黑 0   无光 0
```

这条字段从 M0 就解析出来了，一直没人用——在此之前光照只影响「挨打更疼」和
「压力涨得更快」，玩家很容易算出「省火把只多挨一点」，于是火把永远省着不用。
现在它还决定你能提前看见多少，且**看得见**这件事直接改变决策质量。

## 给到什么粒度的信息

已知节点显示：**类型（战/饥）+ 敌人数量 + 敌方总血**。

```
战  4敌·65      ← 知道「这场不小」，够决定要不要先休整
饥  饥饿
？  未知        ← 连「是战还是饥饿」都不透露
```

**刻意不给怪物名字。** 知道「四只、共 65 血」已经足够做决定；
知道具体是谁，等于提前抄答案，压力就没了。
未知节点也不带任何颜色暗示——只要颜色泄露了类型，情报就等于没做。

## 四个预设的差异

| 预设 | 出发可见 | 基础侦察率 | 手感 |
|---|---:|---:|---|
| lenient | 3 | 0.75 | 一路看得清，火把可有可无 |
| standard | 2 | 0.50 | 看得见脚下与下一步，再往前靠掷骰 |
| tight | 1 | 0.35 | 只看得见脚下，火把不够就摸黑 |
| brutal | 0 | 0.25 | 完全摸黑，每一步都是赌 |

参数在 `data/expedition.json` 的 `scouting` 段，和补给、崩溃参数放在一起——
它们都是「一趟路里的策略」，换个预设就能做整组对照。

## 一个必须守住的工程约束

侦察每步都要掷骰，如果它和战斗共用随机源，**所有历史基线都会漂移**：

```
bench/battle/*.json    单场指标
bench/exp_*.json       远征指标（完成率、压迫指数…）
```

所以侦察和战利品一样用**独立随机源**（`seed * 53 + 7`）。
实测验证：加了侦察之后重跑远征 bench，四个预设的压迫指数
`0.835 / 1.448 / 2.725 / 3.278` 与 M3 记录的**完全一致**。

这不是洁癖——M2 那次「只改压力常量却毫无效果」就是因为没意识到
压力大头在 effect 数据里；随机流一旦混用，之后所有对比都失去意义，
而且不会报错，只会让结论慢慢失真。

## 验证

```
全部通过：235 项断言
```

新增 12 项，覆盖侦察的三条底线：

- 走过的路一定知道（视野不落后于脚步），且不越界
- 不同预设的初始视野确实不同（否则旋钮等于没有）
- **光照必须真的影响它**：明亮 0.65 vs 昏暗 0.50，差值恰好等于数据里的 +15%

`step_enemy_hp()` 也有断言，保证情报面板上的数字不是写死的。

## 界面

地图屏顶栏加了 `视野 2/11（65%）`：`65%` 是当前光照下的侦察率。
不显示这个数的话，玩家点一根火把只是「感觉亮了」，买到了什么是不透明的。

## 已知局限

- **侦察揭露的是节点序列，不是空间**。真正的地图层（房间、走廊、岔路、奇物位置）
  还没做，`dungeons.json` 里 25 个地图参数目前只用了 4 个。
  等地图层落地，"侦察"应该改为揭露一片区域，而不是「往前推一格」。
- **奇物与陷阱没有接入**，所以情报里也没有它们的条目。
- **撤退仍然只看得到「前面几步」**，看不到「离出口还有多远值不值得走」。
  那是地图层的目标房间（`goal_room_number`）该解决的问题。
- **侦察不受饰品/怪癖影响**。DD1 里侦察主要来自装备，这里只有光照。
