# M9 · 站位：让一段死代码开始工作

M9 不是加功能，是先发现三样东西全都摆着、但一次都没执行过：

```gdscript
# 1. 位移算出来了，没人消费
if e.has("push") or e.has("pull"):
    out["move"] = -int(e.get("push", 0)) + int(e.get("pull", 0))
    return out                      # 这个 move 从头到尾没人读

# 2. 重排函数写好了，只在开局调用一次
battle.gd:69    _relayout()         # setup 里，之后再也没有

# 3. 位置限制生效了，但没人能换位
if launch_mask > 0 and (launch_mask & (1 << actor.rank)) == 0:
    return false                    # 位置不对不能放——可位置永远不变
```

还有第四个：`heroes.json` 里每个英雄都有 `move_skill`，M0 就抽出来了，从没解析过。

所以「站位」在这之前是个空概念：4 个英雄永远在 1/2/3/4 号位，敌人也一样，
任何一场战斗里没有任何一格位置会变。`launch_mask` / `target_mask` 写得再对，
输入永远不变，输出也就不变。

## 一、做了什么

### 1. 位移真的移动

```gdscript
func move_unit(u: Combatant, delta: int) -> Dictionary:
    var arr: Array = party if u.side == SIDE_PARTY else enemies
    var from: int = arr.find(u)
    var to: int = clampi(from + delta, 0, arr.size() - 1)
    arr.remove_at(from)
    arr.insert(to, u)          # 中间的人自然顺移一格
    _relayout()
```

阵型是一条没有空格的线：抽出来、插进去，沿途的人依次让位。到边界停在边界，
不会有人被挤出去，也不会有人叠在同一格。

### 2. 英雄能主动换位

`move_skill` 现在被解析成独立的 `move_action`，不塞进 `actions`——
移动的目标是**位置**不是单位，混进技能列表会让 `_legal_targets` 和评分全都要写特例。

界面上是一行按钮，点了切到落点列表：

```
调整站位（当前 1 号位）      ← 平时在「跳过本回合」上方
    ↓ 点击
挪到哪个位置？换位会消耗这一回合
[ 移到 2 号位 ]
[ 取消，回到技能 ]
```

### 3. AI 也会移动

`best_move_plan()` 的做法是**临时把 rank 改掉，再走一遍正常的可用性判断**，
然后恢复。这是唯一能准确回答「挪过去之后到底能做什么」的办法——
手工推演 mask 一定会和 `_can_use` / `_legal_targets` 的实际规则走偏。

移动要占掉一整个回合，所以用 `MOVE_DISCOUNT = 0.75` 打折：
**换个位置能做的事，要比现在高三分之一以上，才值得花这个回合。**

## 二、一个必须查清的数据语义

`move_skill` 的值长这样：

| 英雄 | move |
|---|---|
| crusader / vestal / plague_doctor | `[1, 1]` |
| highwayman | `[2, 2]` |
| hellion / leper | `[0, 1]` |

只出现 0/1/2 三个值。如果它是「目标位置」（1–4 号位），
那 crusader 只能去 1 号位、highwayman 只能去 2 号位，
而 vestal（治疗）和 plague_doctor（远程）也只能去 1 号位——站在最前面。

这不成立。所以它只能是**一次能移动的格数范围**，`0` 表示「可以原地不动」。
按这个解释，方向由玩家选，每个格数给出前后两个落点。

**这是推断，不是从源码确认的。** 依据是值域只可能是 0/1/2，
以及「治疗站前排」在战术上说不通。

## 三、AI 到底动了几次

200 场 × 三档装备：

| 场景 | 移动次数 | 每场 | 谁在动 |
|---|---:|---:|---|
| tier1（0 阶） | 0 | 0.000 | — |
| tier2（2 阶） | 57 | 0.285 | 全是 plague_doctor，3→2 |
| tier3（4 阶） | 200 | 1.000 | 全是 plague_doctor，3→2 |

**只有瘟疫医生会动，而且每场恰好一次**，从 4 号位挪到 3 号位。
原因是它站在 4 号位时部分技能被 `launch_mask` 挡住，往前一格就能用。

这条数据同时验证了两件事：
1. 移动是**有理由的**（不是随机抖动）
2. **不震荡**（每场 1 次，不是来回横跳）

三档的差异说明它跟装备等级相关——技能等级越高，位置带来的收益差越大。

## 四、基线变化（这次是真的动了地基）

M7/M8 都是「新增一条路径，旧基线一个数不动」。M9 不是。

### 单场（200 场 × 4 场景）

| 指标 | M8 | M9 | 变化 |
|---|---:|---:|---:|
| 战斗轮数 | 4.121 | 4.096 | −0.6% |
| 溢出伤害占比 | 0.115 | 0.121 | +0.006 |
| 暴击率 | 0.074 | 0.072 | −0.002 |
| 终局压力 | 19.5 | 19.3 | −0.2 |
| 终局血量 | 0.956 | **0.941** | −1.5 个点 |

**终局血量掉了 1.5 个点**，不是因为 AI 变笨，而是因为「变强的代价」：
瘟疫医生为了用更强的技能往前站了一格，3 号位挨打的概率比 4 号位高。
**换位置换来了输出，代价是站得更危险。** 这正是站位应该有的取舍。

### 远征（weald / medium / Lv3 / 60 趟）

| 预设 | 完成率 M8 → M9 | 压迫指数 M8 → M9 |
|---|---|---|
| lenient | 0.867 → 0.867 | 0.773 → 0.787 |
| standard | 0.733 → 0.783 | 1.385 → 1.303 |
| tight | 0.233 → 0.283 | 2.767 → 2.810 |
| brutal | 0.017 → 0.000 | 3.297 → 3.340 |

**单调性完好**（四个预设的压迫指数仍然严格递增）。
整体变化在 ±0.05 的量级——AI 移动对**一整段远征**的影响，远小于对单场的影响。
原因很直接：一趟远征只有一场战斗里那一次移动，摊到 10 步、4 场战斗上就稀释了。

## 五、踩到的坑

**1. `push` 的符号是反的。** 原实现 `-push + pull`，push 一格算出 −1。
消费方按「往后推」解读就会把人往前拉。这种错不会报错，
只会让推拉看起来「作用了但方向不对」。改成 `+push - pull`（正 = 往后）。

**2. 测试写对了逻辑、写错了断言。** 第一次写「推 1 格后，`enemies[1]` 应该是原本 2 号位的怪」——
但 `remove_at(0)` + `insert(1)` 之后，`enemies[1]` 就是被推的那个单位本身。
断言红了两轮才反应过来。

**3. 统计移动次数时数到 0。** `run_round()` 每次开头 `events = []`，
所以 `run_until_over()` 之后拿到的只有最后一轮的事件。
第一版统计因此得出「200 场 0 次移动」，而实际上 tier3 每场都在动。

**4. 对照实验的开关必须真的能关。** 为了定位「基线为什么变了」，
加了 `move_ai_enabled` 开关，结果关掉后基线精确回到 4.1213——
这一步才把「是移动造成的」和「是别的改动造成的」分开。

**5. 报告里三行同名。** `compare_expedition.py` 把所有 data 包都标成 `data(dd1)`，
于是短图 Lv1、短图 Lv3、中图 Lv3 在表里显示成三行一模一样的名字。
表能算出来，读的人分不清哪行是哪份，等于没用。

## 六、已知局限

- **只有英雄能主动移动**。怪物的 `move_skill` 没有解析，它们不会为了追人而换位。
  （原文这里写的是「没有任何怪物技能带 push/pull」——**这句是错的**，
  实际有 41 只怪、46 个技能带着位移效果。真正断的是另外三层：
  位移不判抗性、洗位没人解析、AI 不给位移估值。 → **M11 已实现，
  见 [M11_MONSTER_MOVE.md](M11_MONSTER_MOVE.md)**）
- **移动不做「连续移动」**。DD1 的移动可以一路挪到目标位置，这里一次一回合。
- **没有尸体位移**。死人仍然占位，和 M1 一样。DD1 里尸体是单独的格子概念。
- **`move [2,2]` 的语义仍有疑问**。highwayman 只能移 2 格、不能移 1 格，
  按「格数范围」解释是自洽的，但玩起来会觉得它比谁都笨重。
- **AI 只会在「当前放不出好技能」时移动**，不会主动去保护后排或躲开高威胁位。
  这是评分函数的能力上限，不是移动机制的问题。
- 守护（替队友挨打）和反击都还没做。它们要等站位真的会动之后才有意义，
  现在是做它们的时候了。 → **M10 已实现，见 [M10_GUARD.md](M10_GUARD.md)**

```bash
"$GODOT" --path . -- --auto --fast
"$GODOT" --path . -- --auto --fast --show-move
```
