# M36 · 美术接入层（第一版：战斗屏的单位）

> 一句话：把「美术资源」接进一个零素材的自绘界面，先打通**链路**，再谈画面。
>
> 这一期不是"画美术"，是**给美术留位置**。判定标准只有一条：
> 把 `assets/art/units/crusader.png` 换成任何一张 256×256 的原创图，
> 代码一行不改，画面立刻变。这条成立，后面的美术投入才不会返工。

---

## 1. 起点：盘点的硬事实

M0~M35 全程自绘，`src/` 里没有一个 `Sprite2D`、`TextureRect`、`AudioStreamPlayer`。
所以在讨论"用什么美术"之前，先把 DD1 那边**到底有什么**查清楚
（来源：`D:/Program Files (x86)/Steam/steamapps/common/DarkestDungeon`，app 262060）。

| 类别 | 实际内容 | 能不能直接用 |
|---|---|---|
| 英雄头像 | `heroes/<id>/<id>_A/<id>_portrait_roster.png`，**85×85** | 能，但太小，放大就糊 |
| 英雄战斗形象 | `anim/<id>.sprite.combat.png`（645×548 **部件图集页**） | 不能，要按骨骼摆位 |
| 怪物 | 只有图集页（如 305×1042），`portrait` 数量 = **0** | 不能，没有静态图 |
| 大图 | 1920×1080 加载图 | 是场景背景，不是立绘 |
| 面板/图标/光标 | `panels/`、`icons_ability/`、`cursors/` 单图 | 能，但会推翻现有排版 |

**最关键的一条**：DD1 没有"战斗立绘"这个东西。人物和怪物都是 Spine 2.1.27 骨骼，
图集页里是一个个拆开的部件。拼回完整形象必须解析 `.skel`（骨骼层级 + 槽位坐标）——
`.atlas` 里的 `offset` 是**裁剪信息**，实测全是 `0,0`，不含摆放位置。

所以「原版人物用立绘 + 补间」这个方案，**"原版立绘"这一半不存在**。
但它的两个真实目的——「看到战斗画面表现」和「换同规格美术零障碍」——
不需要原版立绘也能成立。这一期就按这个前提做。

## 2. 资源接入层：一个约定，没有登记表

```
assets/art/units/<unit_id>.png        # 任意尺寸正方形，透明底，内容居中
```

没有 manifest、没有注册表、没有尺寸表要同步。`<unit_id>` 就是
`heroes.json` / `monsters.json` 里的 id，英雄与怪物共用一套目录。

`src/view/unit_art.gd` 只做一件事：按 id 找图，找不到返回 null。
绘制端按「等比缩放到目标显示边长」处理，所以 85×85 和 512×512 走同一条代码路径。

**缺图不是错误。** 缺了会退回程序化占位（阵营色圆牌 + 名字首字）。
这条是刻意的：怪物现在一张静态图都没有，如果缺图算错误，那这一屏天天都在报错。

当前入库 15 张英雄头像（580 KB，原图未修改），来源与授权限制写在
`assets/art/units/README.md`，PNG 已被 `.gitignore` 排除——**目录结构入库，图不入库**。

## 3. 战斗屏改了什么

原来每张单位卡是 152×104 的纯文字牌。现在是：

| 项 | 改前 | 改后 |
|---|---|---|
| 卡片宽度 | 152 | **200**（152 放不下「图 + 名字 + 血条」） |
| 左侧 | 无 | 56×56 单位格：底板 + 阵营色描边 |
| 文字列 | 从 x+10 起，宽 132 | 从 x+72 起，宽 118 |
| 状态标记 | 和「压力」同列，差 8px | **横跨卡片最底行**（最多 5 项） |

四段补间（全部是状态驱动，没有序列帧）：

| 动效 | 触发 | 表现 |
|---|---|---|
| idle | 常驻 | 上下浮动 1.6px，每张牌相位错开（否则七个人一起浮，像整块画面在抖） |
| 出手 | `awaiting_input` | 放大到 1.08 并轻微脉动——「轮到谁」最快的信号 |
| 受击 | 掉血飘字 | 左右抖动 3.2px + 一次红闪，0.22 秒 |
| 阵亡 | `u.dead` | 灰度 + 顺时针转 90° + 半透明 |

受击的触发点是 `_spawn_float`（掉血飘字），没有另开一条事件流：
飘字本来就是「这一下打在这个人身上」的唯一统一出口，两条流迟早对不上。

## 4. 踩的三个坑

1. **改绘制的顺手把变量声明删了**。重写 token 绘制时把
   `var tex := _art.texture_of(...)` 一并替换掉，`tex` 未声明 → 解析报错。
   表现是**进程直接退出、没有任何输出**（不是红色报错），
   靠 `--check-only` 才看到真实的 `Parse Error`。

2. **状态标记和「压力」挤在一起**。卡片加宽后文字列从 132 变 118，
   原来只差 8px 的两行开始重叠。把它们移到底部整行——顺带能从 4 项放到 5 项。

3. **上浮的飘字被误认为排版错乱**。截图中名字行出现一团红字，
   第一反应是「名字和某个标签叠了」，实际是受击飘字正经过那个高度。
   教训：**静态截图判断动效区域要小心**，飘字、抖动、渐变都会在某一帧造成"看起来坏了"。

## 5. 现在到哪了：效果与天花板

有图之后，战斗屏从「四张灰卡」变成「四张带人像的卡」。但要说清楚天花板在哪：

- **变好的是识别**：一眼能看出谁是谁，血条/压力/状态的位置没变。
- **没变的是构图**：这仍然是「两排卡片」，不是「双方在场景里对峙」。
- 卡片式其实是本作自己的设计（原版是横排站桩），保留它有辨识度优势；
  但它也意味着**再多的美术投入，画面感的上限就是"卡牌游戏"**。

所以下一步是一个真正的分叉，不是打磨：

| 方向 | 做什么 | 成本 | 得到什么 |
|---|---|---|---|
| **A. 卡内打磨** | 头像提亮、边框材质、卡片底纹、技能图标 | 1–2 天 | 精致的卡牌战斗 |
| **B. 站桩重构** | 战场地面 + 左右对峙 + 光照圈 + 站位连线，卡片退成悬浮血条 | 3–5 天 | 接近 DD 的画面感 |

B 会推翻 M31 给战斗屏定的排版（卡片尺寸、日志与技能面板的位置），
但**不动规则层**，也不动另外三屏。

> **后续（M37）**：出图之后先修的是一个更基础的问题——
> 两排卡片把 rank 藏进「第几张卡」、位置还按数组下标算，导致位移读不出来。
> 现在已改成 rank 换算成 x、阵营决定 y，位置带插值。
> 上面这个 A/B 分叉因此变成「在横向 rank 布局上继续打磨」还是「退成站桩」。见 [M37_BATTLE_LAYOUT.md](M37_BATTLE_LAYOUT.md)。
